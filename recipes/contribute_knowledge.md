# 贡献知识

## 目标

把一条有来源、有适用范围的工程知识放到仓库中的正确位置，并确认它能通过检查和查询。

## 适用场景

- 新增仓库还没有的知识；
- 修改已有知识卡；
- 合并重复卡片；
- 拆分包含多个主题的卡片；
- 废弃错误或过时的结论；
- 信息不足，决定暂不落库。

## 不适用场景

- 只修改 `docs/`、`recipes/` 或其他说明文档；
- 修改字段定义、受控值、校验规则或 Skill；
- 保存算子工程、模型代码、整份上游文档或临时记录；
- 来源不能公开或不能支持准备写入的结论。

## 前置条件与输入

- 一条准备沉淀的工程结论；
- 可以完整阅读和核对的来源；
- 目标领域、技术、平台和必要的版本信息；
- 已安装 contributor 能力和开发依赖；
- 已检查工作区中的现有修改。

## 步骤

1. **先搜索已有知识。** 使用 `knowledge-query` 搜索相同主题并阅读候选卡。不要只比较标题，还要比较内容范围和来源。
2. **选择处理方式。** 明确本次是 create、update、merge、split、deprecate 还是 defer。如果无法判断，先不要写文件。
3. **选择保存位置。** 根据领域、技术和知识类型选择路径。只有不依赖单一技术的结论才能放进 `shared`。
4. **整理来源。** 完整阅读并固定来源。区分来源中明确写出的事实、合理推导和仍需验证的内容。
5. **编写知识卡。** 使用 `knowledge-ingest` 或人工编辑。通常写清结论、适用条件、限制和验证方法，更新已有卡片时不要整体覆盖；Registry 固定归档的官方 API/Guide 则按声明过滤导航页和冗余章节，保留其余来源正文，只修改链接目标并添加 Frontmatter/可选的普通链接。
6. **人工检查内容。** 检查标题、路径、文件开头的结构化信息、正文、来源和链接。脚本运行成功不代表内容正确。
7. **更新导航和日志。** 新增、删除或移动卡片时更新各级 `index.md`。实质知识变更需要记录当天日志。
8. **运行全库 Lint。** 修复路径、字段、导航、链接、来源和日志问题。
9. **验证查询结果。** 使用真实的平台和技术条件查询，确认新知识能被找到，也不会出现在错误范围中。当前 Query 不按 CANN 版本过滤，版本边界需要在命中正文中核对。
10. **运行完整检查。** 确认仓库质量门禁通过。不要自动提交、推送或发布。

## 预期产物

可以使用下面的格式记录结果：

```text
处理方式：<create / update / merge / split / deprecate / defer>
知识范围：<领域、技术、知识类型、平台和版本>
来源：<支持结论的材料>
文件变化：<知识卡、导航、链接和日志>
检查结果：<全库 Lint、目标查询和完整门禁>
剩余问题：<来源、范围或兼容性限制>
```

如果选择 defer，应说明缺少什么信息，不要创建占位卡片。

## 验证方式

- 写卡前已经搜索并阅读相同主题的知识。
- 处理方式有明确理由。
- 路径正确表示领域、技术和知识类型。
- `shared`、跨技术知识和技术专属知识没有混用。
- 来源能够支持正文结论和适用范围。
- 正文写清结论、适用条件、限制和验证方式。
- 相关 `index.md`、链接和日志已经更新。
- 全库 Lint 通过，目标查询能够找到新知识。
- 完整质量门禁通过。

## 失败与停止条件

- 无法判断新增还是更新：停止写入，先检查已有卡片的职责。
- 无法确定路径或知识类型：先查看治理规范。
- 除保留了可消费轨迹证据、按规则允许 `sources: []` 的 Runbook 外，`stable`（稳定）结论缺少可靠来源或明确平台时，保留为 `draft`（草稿）或选择 defer。
- 规则文件、程序行为和文档互相矛盾：先修复规则体系。
- Lint 失败或目标查询找不到新知识：不能认为贡献已经完成。
- 材料包含密钥、账号、内网地址、私有路径或不可公开数据：停止写入并清理敏感内容。
