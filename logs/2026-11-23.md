### Details

- 构造器改为接收 `auth_code_store`、`token_store`（jti 台账）、`token_authority` 与可选 `resource_server_url`（缺省回退 `SelfIssuedTokenAuthority._default_audience(None)`），与 `CannbotTokenVerifier` 的注入风格一致；注册面两方法语义不变，测试随构造器签名更新。
- `authorize(client, params)`：`AuthCodeStore.create` 铸一次性授权码并绑定 redirect_uri/code_challenge/state/resource（resource 去尾斜杠与手写 authorize 端点同规），随即用现有 `bind` 的 compare-and-swap 语义绑定身份；当前无登录腿，资源主体暂绑固定公共客户端 id（接线票挂授权页/GitCode 登录腿后改绑已验证用户名，同手写 confirm 腿）。返回 `construct_redirect_uri(redirect_uri, code, state)` 回跳，与手写 allow 腿产物一致；空 challenge 抛 `AuthorizeError("invalid_request")` 失败关闭。

- `exchange_authorization_code`：先 `take` 原子消费（重放/竞态只见空，失败校验同样烧码，同 consume 次序），再依次校验过期、身份绑定、challenge 在档、client_id、loopback redirect（复用 `server._loopback_redirect_match`）与 PKCE——对象带 verifier 时全量 S256 摘要比对（同 consume 计算），不带时比对呈现 challenge 与铸码时存档（SDK handler 已证 S256(verifier)==呈现 challenge，链条闭合）；通过后 `token_authority.sign` 签 access+refresh（aud=授权时 resource 或 resource_server_url），新 refresh 的 jti 按全生命周期登记 `jti:<jti>`→"live"，返回 `OAuthToken(access_token/refresh_token/expires_in/token_type="Bearer")`。拒绝一律抛 `TokenError("invalid_grant")`（mcp.server.auth.provider 的规范异常类，该 SDK 版本 errors.py 无异常类），不以 None 当错误。
- `load_refresh_token`：本地验签（签名、refresh 类型、exp，锚定 token 自身 aud——SDK handler 丢弃请求 resource 指示，沿用"新旧同 aud 换发"现状语义）+ jti 台账 peek；垃圾/access 类型/已消费返回 None。`exchange_refresh_token`：重验后用 `take_if_equal(jti:<jti>, "live")` 一次性消费（重放 invalid_grant），换发对保持同 aud，新 jti 再登记；`scopes` 参数仅保签名兼容（自签 JWT 不携带 scope）。
