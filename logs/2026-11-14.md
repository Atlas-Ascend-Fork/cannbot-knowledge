## [11:35] skill | knowledge-query 新增可选中英双搜（Issue #19）

### Summary

`knowledge-query` search 新增可选 `--alt-query` 双搜入口，解决纯中文查询漏召回英文卡片（或反向）的跨语言缺口。默认流程（不带 `--alt-query`）行为与请求指纹保持逐字节不变。

### Details

- 动机：主干 552/7044 张卡标题与摘要为纯英文，词项匹配无中英语义转换，Issue #19 复现纯中文查询目标卡 Top10 外。
- 实现：`knowledge_query.py` 提取 `text_query_scores` / `result_entry` 复用既有打分；`--alt-query` 与原查询共享全部过滤条件与 Scope 跑两趟完整文本检索，按名次交错融合（original 优先、路径去重、不加原始分数）。实测 RRF(k=60) 会让双路平庸卡压过改写腿头部命中，改用名次交错。
- 契约：仅允许 `--match text`；改写与原查询规范化后必须不同、不得为空；输出 schema 升为 `knowledge-search.v6`（新增 `alt_query`、`fusion`、每命中 `bilingual` 名次与得分）；request/receipt 记录双查询与融合结果，`retrieval_state.py` 的 `REPLAY_FIELDS` 增加 `alt_query`、`fusion` 参加重放比对。
- 验证：原 75 条检索用例基线（recall@5=0.582 / MRR=0.490 / p95=5003.6ms）与改动后默认路径（0.582 / 0.490 / 4958.5ms）一致，无回归；双搜评分耗时约 1.9x（约 +420ms，10k 卡索引，仅显式启用时发生）。新增 5 条双搜契约用例（zh→en / en→zh / 混合标识符 / literal 拒绝 / 同串拒绝）与 `BilingualSearchTests` 7 项单测；`evals.test_retrieval_index evals.test_retrieval_preflight` 50 项通过。未改 MCP 适配层（caller 侧能力，后续按评测结论决定是否暴露）。
