## [16:04] fix(mcp) | Claude Code 重连 401 根因修复：resource 尾斜杠规范化

### Summary

Claude Code 真实复测抓到 13c 后首个真缺陷：授权成功拿到的令牌在 /mcp 被拒（"Got new credentials, but ... rejected them on reconnect"）。根因是 RFC 8707 resource 参数的尾斜杠不匹配——授权/换码侧铸入带斜杠的 aud，验证侧推导无斜杠的 aud，字符串比对失败。

### Details

- 根因链：Claude Code 从自己配置的 server URL（http://127.0.0.1:8092/mcp）推导 resource 参数得 "http://127.0.0.1:8092/"（带尾斜杠）→ 授权码换码把 resource 原样铸进 aud → /mcp 验证侧用 Host 头推导 "http://127.0.0.1:8092"（无斜杠）→ 严格字符串比对失败 → no_match。白盒解码客户端存储的令牌确认 aud="http://127.0.0.1:8092/" 且签名有效，未过期——排除密钥/时间问题，直指斜杠。
- 修复：/oauth/authorize 与 token 端点接受 resource 时 .rstrip("/") 规范化（refresh 分支同修）。验证侧保持严格比对不放松——服务器控制铸/验两侧，斜杠规范化后两侧一致，安全性无损。授权码会话内存储的 resource 已是规范化值，refresh 带斜杠也能对上。
- 复现探针 /tmp/slash_regression.py：完整模拟 Claude Code 行为（带斜杠 resource 的 authorize/换码/refresh + /mcp 验证），修复前 aud 带斜杠且 /mcp 401，修复后五步全绿；audience_binding 存量测试（非根 resource）不受影响。
- 验证：全量 233 passed（3 连跑稳定）；8092 重启后探针通过。
- 测试意义：这是 32 项回归测试和全部进程内测试都覆盖不到的缺陷——只有真实客户端的 resource 推导习惯能暴露。业界对齐：RFC 8707 允许 resource 带或不带斜杠，成熟 AS 均在受入侧规范化。
