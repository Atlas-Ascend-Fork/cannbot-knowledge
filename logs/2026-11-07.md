## [12:05] refactor | PR–Issue 关联扫描改为分阶段判定：先看 Issue 声明，再做双向匹配

### Summary

把 `scan_pr_issue_links.py` 从"两侧证据对称合并"改为按证据强度逐级下降的四阶段判定：① Issue 明确声明修复 PR → ② Issue 仅提及 PR → ③ PR 侧反向引用 → ④ 标题相似。上一级命中即不再上报下一级；只有 ① 且 `merged_at` 非空才进入关单候选。原因是原实现对"引用"和"声明"平权，会把 `在 PR #68 上建索引`、`与 PR #100 互补` 判成"建议闭环"。

### Details

- Issue 侧证据拆成 `declare` 与 `mention` 两级：`关联 PR:`/`对应 PR:` 模板字段、`已提交 PR #N`、同句"本 Issue/该问题 + 已修复/已合入"判为声明；其余 `PR #N`、PR 链接、同句裸引用判为提及。
- 新增四阶段分类：`可直接闭环（Issue 已声明）`、`PR 进行中（Issue 已声明）`、`PR 已关闭未合入（Issue 已声明）`、`PR 已合并，待核对闭环（Issue 仅提及）`、`PR 已合并，待核对闭环（PR 侧引用）`、`疑似匹配，需人工判断` 等。`CLOSABLE_CLASSES` 只含声明阶段。
- 报告新增漏斗表，五项 Issue 计数之和应等于扫描总数；正文按四阶段分组。
- 修正三处误判：`本 Issue： #225` 中的 `#225` 被 `Issue #N` 正则误标为 Issue 编号而丢失；`原 PR #99 已并入 PR #100` 被当成"本 Issue 由 #100 修复"（新增主语是 PR 的前缀排除）；`pairs.update()` 让第二阶段覆盖第一阶段的同键条目，把声明降级为反查（改为共用同一累积字典，phase 以先写入者为准）。
- 已声明但 PR 未合入的 Issue 现在也会进入 PR 侧反查与相似度回退，此前此类 Issue 被排除在目标集合之外。
