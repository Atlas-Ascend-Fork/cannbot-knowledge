# 性能优化策略：逐元素标量构造 → 整数域纯算术向量化（掩码/惩罚向量生成）

> **单一优化点：** 当一段代码用**逐元素标量三连**（`GetValue` → 标量比较/条件 → `SetValue`）构造一个长度为 N 的掩码/惩罚/指示向量时，改为**全向量指令**构造。关键做法：把判定放在**整数域**用 `Adds/Maxs/Mins` 压成 0/1 指示量，再 `Cast` 到目标 dtype 后 `Muls` 成最终值——**全程不碰 `Compare`/`Select`**，从根上绕开 mask 位序（bit-wise vs byte-wise）这一类历史坑。
>
> **为什么值得单列：** 这类标量循环常常是"为绕过某个 API 坑而临时写的退化实现"，写下时是正确性修复，之后就沉淀成永久的性能债。它的代价随 N 线性增长（实例 N=512/1024，即每次调用上千次标量往返），在标量已是瓶颈的核上尤其致命。
>
> **已验证锚点：** A5(Ascend950DT) SparseFlashAttention 的 causal mask penalty 构造。原实现为逐列 `GetValue+比较+SetValue`（历史上为绕过 `Compare`/`Select` 的 mask 布局问题而引入）。改为整数域向量化后：`s256 1358.1→478.6µs (2.84x)`、`s1024 11210.3→~4200µs (2.67x)`、`mtp 102.4→~52µs (~2x)`，精度 37/37。
>
> **线索来源（方法论）：** 该病灶不是从 profiling 直接看出来的，而是从**两个 shape 完全相同、仅 `is_causal` 不同的用例差 2.9x** 这一矛盾反推出来的——causal 语义上只该让计算变**少**，不该变慢。见 §1.1。

本策略只替换"掩码/惩罚向量的构造方式"。不改变掩码语义、不改变其消费方式（仍逐行 `Add`）、不改 tiling、不动同步结构。

## 1. 优化原理

### 1.1 如何发现这类病灶（比 profiling 更早的线索）

profiling 只会告诉你 `scalar_ratio` 高，不会指出是哪一段。更快的线索是**语义矛盾**：

> 找一对**其它维度完全相同、只有一个开关不同**的用例。若"本该让计算变少"的那个开关反而让耗时**大幅上升**，则该开关的实现路径上必有退化代码。

实例：`case_1(is_causal=true)` 与 `case_20(is_causal=false)` 的 shape 逐字段相同，耗时却是 1419µs vs 495µs（2.9x）。causal 只是把一部分位置 mask 掉，**只该减少有效计算**。这个矛盾直接定位到 `ApplyCausalMask`。

**推广：** 任何"可选特性开关"（causal、alibi、dropout、padding mask）都应做这个对照。开关打开后若耗时增幅远超其语义应有的代价，就去看它的实现。

### 1.2 性能问题模式（通用）

```cpp
// 退化实现：逐元素标量三连
for (uint32_t c = 0; c < cols; ++c) {
    int32_t v  = idxUb.GetValue(c);                    // 标量装载
    float   pv = (v > thr) ? MASK_NEG : 0.0f;          // 标量比较 + 条件
    penaltyUb.SetValue(c, pv);                         // 标量写回
}
```

`cols` 常等于 topK/序列长度（512、1024…），即**每次调用上千次标量往返**。在 `aiv_scalar_ratio` 已达 0.6~0.8 的核上，这是纯粹的浪费。

这类代码的**来源**通常是：曾用 `Compare`+`Select` 实现，但踩了 mask 位序坑（`Compare` 产出 bit-wise mask，`Select` 期望 byte-wise，或反之），导致掩码取反/错位；为了赶紧修正确性，改成标量循环绕过。**正确性修好了，性能债留下了。**

### 1.3 本策略的做法：整数域纯算术，不碰 Compare/Select

目标：`pen[c] = (idx[c] > thr) ? MASK_NEG : 0`

```text
d   = idx - thr            // int32 Adds :  invalid(idx>thr) ⇒ d ≥ 1 ;  valid ⇒ d ≤ 0
d   = max(d, 0)            // int32 Maxs :  invalid ⇒ ≥1     ;  valid ⇒ 0
d   = min(d, 1)            // int32 Mins :  invalid ⇒ 1      ;  valid ⇒ 0      ← 0/1 指示量
pen = float(d) * MASK_NEG  // Cast + Muls:  invalid ⇒ MASK_NEG ; valid ⇒ 0
```

只用 `Adds / Maxs / Mins / Cast / Muls` 五条算术指令，**完全不出现 `Compare`/`Select`**，因而不存在 mask 位序问题。

结果与原标量实现**逐位等价**：invalid 位恰为常量 `MASK_NEG`，valid 位恰为 `0`。

## 2. 两个关键的数值决策（都是踩过才定下来的）

### 2.1 判定必须放在整数域，不能先 Cast 再比较

一个看似更直接的写法是先把索引 `Cast` 成 float 再做比较：

```text
idxF = float(idx)          // ← 有风险
t    = max(idxF - thr, 0)
...
```

**实测失败**：`Cast(int32→float32)` 的舍入行为依赖 `RoundMode`，用 `CAST_NONE` 时**边界列判定发生翻转**，5 个 causal 用例出现 `mismatch 0.01%~0.23%` 的精度偏差。

**正确做法**：判定全部在 int32 域完成（`idx` 与 `thr` 本就是整数语义，整数比较是精确的），压成 0/1 之后再 `Cast`——此时 Cast 的输入**只有 0 和 1**，任何舍入模式都精确无歧义。

### 2.2 必须先压成 0/1 再乘，不能直接用差值乘

```text
pen = (idx - thr) * MASK_NEG      // ← 溢出风险
```

`idx - thr` 最大可达序列长度量级（如 8192），而 `MASK_NEG` 常取 `-1e38`。`8192 × (-1e38)` **溢出为 `-inf`**。

若下游 softmax 的设计前提是"mask 为**有限值**"（例如依赖 `exp(MASK - CLAMP) = exp(-1e38 + 1e30) ≈ 0` 来防 NaN），那么一旦出现 `-inf`，**全 mask 行**会算出 `(-inf) - (-inf) = NaN`。

压成 0/1 后再乘，invalid 位恰为 `MASK_NEG`（有限），与原实现逐位相同。

## 3. 适用条件与泛化边界

必须**同时**满足：

| 条件 | 要求 |
|---|---|
| 代码形态 | 存在逐元素 `GetValue`/`SetValue` 构造向量的循环 |
| 长度 | 循环长度 N 足够大（实例 512~1024）；N 很小时收益有限 |
| 可算术化 | 判定条件能用比较+算术表达（阈值比较、区间判定、符号判定等） |
| 整数语义 | 参与判定的量具有整数语义（或能无损映射到整数域） |
| 无跨元素依赖 | 第 c 个元素的结果不依赖第 c-1 个 |
| 瓶颈 | 该核 `scalar_ratio` 高 |
| 数值边界 | 目标常量与中间量不会溢出（见 §2.2） |

优先适用：

- 代码注释里写着"为绕过 X 问题改用标量循环"的地方（历史欠账的标志）。
- causal/padding/alibi 等可选掩码的构造。
- 任何 `for c: out[c] = cond(in[c]) ? A : B` 形态。

不适用：

- 判定含无法算术化的复杂控制流（查表、递归、跨元素状态机）。
- N 很小（<32），向量指令的固定开销占比过高。
- 该向量构造不在热路径。

## 4. 实施步骤

### 4.1 写出目标表达式并做代数化

把 `out[c] = cond ? A : B` 改写成 `out[c] = B + ind[c] * (A - B)`，其中 `ind ∈ {0,1}`。
常见的 `B = 0` 情形简化为 `out[c] = ind[c] * A`。

### 4.2 在整数域构造 0/1 指示量

| 判定 | 整数域构造 |
|---|---|
| `x > thr` | `min(max(x - thr, 0), 1)` |
| `x >= thr` | `min(max(x - thr + 1, 0), 1)` |
| `x < thr` | `min(max(thr - x, 0), 1)` |
| `x == thr` | `1 - min(abs(x - thr), 1)`（需 `Abs`） |

### 4.3 Cast 与缩放

```cpp
Cast(outF, indI, RoundMode::CAST_NONE, alignCols);   // 输入仅 0/1，精确
Muls(outF, outF, TARGET_CONST, alignCols);
```

### 4.4 对齐尾段处理

- 向量指令按对齐长度 `alignCols` 整段计算，会带入 `[actualCols, alignCols)` 的**未初始化脏数据**。
- 若下游有兜底（如后续统一 mask 尾列）**仍建议显式清零**——不要依赖"调用顺序"这种隐式契约。
- 清零只需 ≤ (align-1) 个元素，开销可忽略。

### 4.5 buffer 归属

- 中间指示量与最终向量所用的片上 buffer，**不得与并发阶段共用**（见策略 05）。
- 若原标量实现复用了某个公共临时区，向量化后的活跃期变长，冲突风险上升——应分配专用 buffer。

---

## 5. 正确性红线

### 5.1 判定域

- 判定必须在**精确域**（整数）完成；不得依赖浮点舍入行为（§2.1）。
- `Cast` 的输入应只有 0/1。

### 5.2 溢出

- 任何"差值 × 大常量"的写法都要检查溢出（§2.2）。
- 目标常量若被下游当作**有限值**使用，则必须保证结果有限。

### 5.3 逐位等价

- 向量化后 valid 位必须恰为原值（通常 0），invalid 位必须恰为原常量。
- 精度应**完全不变**；任何偏差都说明构造式错了。

### 5.4 对齐尾段

- 显式处理 `[actualCols, alignCols)`（§4.4）。

### 5.5 中间 buffer 的活跃期

- 向量化引入的中间量（指示量）活跃期与最终向量不同，需确认二者不互相覆盖，也不与并发阶段冲突（策略 05）。

## 6. 已知陷阱

### AP-001：先 Cast 再比较导致边界翻转

问题：`Cast(idx)→float` 后再与阈值比较。
症状：**边界元素**判定翻转，`mismatch` 极低（0.01%~0.2%）但确实错，且看起来像"精度噪声"。
修复：§2.1，判定放整数域。

### AP-002：差值直接乘大常量导致 -inf / NaN

问题：`(x - thr) * MASK_NEG`。
症状：全 mask 行出现 NaN（`-inf - -inf`）。
修复：§2.2，先压 0/1。

### AP-003：对齐尾段脏数据

问题：按 `alignCols` 整段算，尾段带入 `DataCopyPad` 未写区的脏值。
症状：偶发错值，与 `cols` 是否对齐相关。
修复：§4.4 显式清零。

### AP-004：中间 buffer 与并发阶段冲突

问题：向量化后复用了公共临时区（如 softmax 工作区），或与另一并发阶段共用索引缓冲。
症状：**精度随机漂移**——失败用例集合每次都变、误差在数量级间跳。
修复：分配专用 buffer（策略 05）。

> **诊断签名（重要）**：数值逻辑错会**稳定**失败在固定用例上；
> 失败集合**每次都变**、误差量级跳变 ⇒ 是**竞争/未初始化**，不是公式错。
> 本实例正是靠这条签名，在第三次尝试时才把方向从"数值等价性"扭到"内存争用"。

### AP-005：只改一处调用点

问题：被替换的 buffer/索引在**多处**被读（如 gather 与 mask 各读一次索引），只改了一处。
症状：另一处读到未填充数据，大面积精度失败。
修复：grep 全部使用点，同步修改。

## 8. 禁止事项与回退条件

禁止：

- 用 `Compare`/`Select` 重写（本策略的价值之一就是绕开它；若要用，须先验证该平台的 mask 位序语义）。
- 在浮点域做判定（AP-001）。
- 差值直接乘大常量（AP-002）。
- 忽略对齐尾段（AP-003）。
- 复用并发阶段的公共 buffer（AP-004）。
- 改变掩码语义或其消费方式。

回退或缩小策略的条件：

- 精度**稳定**失败在固定用例 → 构造式错误，查 §2.1/§2.2。
- 精度**随机漂移**（失败集合变动）→ 是 buffer 竞争，转策略 05，不要改构造式。
- 判定无法算术化 → 放弃本策略。

## 9. 验收标准

最小验证：

```bash
bash <build> --soc=<soc> --op=<op> --wheel 2>&1 | grep -cE "error:"   # 须为 0
source <set_env> && pytest <op>/test/test_<op>.py -q                   # 重复 ≥2 次
```

精度：**必须完全不变**（逐位等价变换）。

性能（profiling 归因）：

- 该核 `scalar_time` 显著下降、`vec_time` 小幅上升（工作从标量搬到向量）；
- 端到端下降（实测 **2~2.8x**，当该标量循环是主要瓶颈时）；
- **仅开启该特性的用例受益**，关闭该特性的用例应纹丝不动——这构成天然对照，用于印证归因。

边界：开关 on/off 各测；不同 N（含非对齐 N）各测。

性能结论须写清：

```text
本策略把 O(N) 标量往返替换为 O(1) 条向量指令，收益随 N 与调用频次线性放大。
仅"开启该特性"的用例受益，关闭的用例不变——以此作为归因对照。
判定必须在整数域；必须先压 0/1 再乘常量（否则溢出为 -inf 导致 NaN）。
精度必须逐位不变；随机漂移说明是 buffer 竞争（策略 05）而非公式错。
```

## 检索卡（短卡）

动作：将逐元素标量条件写入改写为整数指示量驱动的纯算术向量表达式。
适用：存在逐元素 GetValue/SetValue 构造向量的循环。
限制：条件判定须在整数精确域完成，不得依赖浮点舍入；Cast 输入只能为 0/1。
范围：长度为 N 的逐元素构造循环。
检索词：scalar_ratio、GetValue、SetValue、整数域、指示量、向量化。
机会：循环中反复出现 GetValue、标量比较或条件、SetValue 三连。
