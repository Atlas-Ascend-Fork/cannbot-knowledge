# 性能优化策略：片上 buffer 容量回收与再分配（收紧过量分配 → 投入高 ROI 性能杠杆）

> **单一优化点（两阶段）：**
> **(1) 回收**——把既有片上 buffer（UB/L1）中按宽松常量分配、超出"已证明最大工作集"的部分，收紧到解析上界，回收冗余容量预算。
> **(2) 再分配**——把回收的预算投入到当前瓶颈下 **ROI 最高的容量受限性能杠杆**（放大分块 tile / 加深缓冲深度 / 扩大批量累加器 / 片上复用驻留 / 加宽向量化 chunk 等），从而**直接提升整体性能**。
>
> **独立定位：** 本策略自成体系，核心是"容量预算的回收 + ROI 驱动再分配"。回收本身不直接产生性能收益（总量不变），**性能收益来自再分配**——用回收的预算解锁/放大一个原本受容量钳制的性能杠杆。算子/管线无关，UB 与 L1 均适用。

本策略只做"回收过量分配 + 再分配到性能杠杆"。不改变数据语义/数值、不改跨核同步协议、不引入新算法。再分配目标本身（放大 tile / 加深缓冲 / 扩大批量 / 片上复用 / 加宽 chunk）按瓶颈择优，**不绑定任一具体优化**。

---

## 1. 优化原理

### 1.1 容量与性能的耦合（通用）

片上 buffer（UB/L1/L0）总量是硬上限（910B：UB 192KB / L1 512KB / L0A·L0B 各 64KB / L0C 128KB）。许多性能杠杆都**受容量钳制**：

- 放大分块 tile（M/N/K）→ 更少外层迭代、更少 GM 搬运、更高 L0/UB 利用率，但要更大工作块 buffer。
- 加深缓冲（double→triple）→ 更好的搬运/计算重叠，但每多一级多一份 buffer。
- 扩大批量（batch）→ 更少批次、更少跨管线同步，但要更大累加器 buffer。
- 片上复用驻留（数据常驻）→ 更少 GM 重读，但要常驻 buffer。
- 加宽向量化 chunk → 更少 UB pass，但要更宽 buffer。

容量不够时，这些杠杆被迫停在低档；而既有 buffer 里又常藏有"按宽松上界分配"的冗余。本策略把冗余回收、再投到杠杆上，**在不增加总容量的前提下把杠杆推高一档**。

### 1.2 两阶段机制

| 阶段 | 动作 | 关键约束 |
|---|---|---|
| (1) 回收 | 把过量分配 buffer 收紧到"已证明最大工作集 + 最小余量"，累计回收预算 `R` | 上界必须解析可证、覆盖全相位/全 shape；耦合 buffer 同步处理 |
| (2) 再分配 | 选 ROI 最高的杠杆，用 `R` 把它推高一档（或新增所需 buffer） | 杠杆的"下一档"容量需求 ≤ `R`；再分配后合计 ≤ 硬件上限 |

核心流程：

```text
R = 0
for each 既有 buffer:
    actualMax = derive(tile, chunk, dtype, 深度, 耦合)          # 解析上界
    if actualMax + margin < alloc:
        alloc = actualMax + margin; R += (old - new)            # 回收
lever = SelectLeverByROI(bottleneck, profiling, R)              # 择优
lever.alloc += needed_for_next_step(≤ R)                        # 再分配
assert sum(所有 buffer) ≤ 硬件上限
```

## 2. 适用条件与泛化边界

必须**同时**满足：

| 条件 | 要求 |
|---|---|
| 容量压力 | 存在至少一个"想放大但被容量卡住"的性能杠杆（当前因 buffer 不够而停在低档） |
| 过量分配存在 | 至少一个既有 buffer 的分配 > 其真实最大工作集（可证） |
| 工作集可推导 | 该 buffer 的 max 工作集能由 tiling/chunk/dtype/耦合解析上界 |
| 全相位覆盖 | 收紧后尺寸 ≥ 该 buffer **所有使用相位**（含时分复用）与**全 shape** 的最大工作集 |
| 杠杆可量化 | 再分配目标的"下一档容量需求"与"预期收益"可由 profiling/tiling 估算 |

优先适用：

- UB/L1 合计接近上限，且存在按通用常量分配的 buffer。
- profiling 已定位瓶颈，且该瓶颈对应一个容量受限杠杆（如搬运次数多→放大 tile；同步多→扩批量/加深缓冲；GM 重读多→片上复用）。

不适用或需先重构：

- 无过量分配、所有 buffer 已紧贴工作集 → 无预算可回收；需改 tiling/算法。
- 瓶颈在算力（cube MAC / vector 算力已打满）且无容量杠杆可缓解 → 再分配无助，用算力优化策略。
- 工作集运行时变化、无法解析上界 → 不能安全收紧（陷阱 4）。
- 再分配目标与容量无关（如纯指令调度）→ 非本策略。

## 3. 阶段一：回收规则

### 3.1 工作集上界推导

```text
bufferMaxBytes = tileM(或 chunkRows) * tileN(或 cols) * sizeof(dtype) * 缓冲深度
```

### 3.2 耦合钳制推导

buffer 的真实工作集常被**另一约束**钳到低于通用常量：

- 输出/Cast buffer 的 tileSize ≤ 其**输入或暂存 buffer 容量 / dtype 比例**。
  - 例：暂存 buffer 容量为 S 字节、按 float 使用，输出为半精度（2B）时，输出 tileSize 上界为 `S/sizeof(float)×2B = S/2`，超出 `S/2` 的分配即冗余。
- 工作块 buffer 受 tiling 上界钳制（如 `chunkRows ≤ 某固定行数上限`）。
- 时分复用 buffer 取**各相位最大值**，非各相位之和（串行复用）。

### 3.3 收紧尺度

```text
newAlloc = bufferMaxBytes + margin
margin：证明强（解析硬上界）→ 小；证明弱（依赖 shape 不变量）→ 保守余量
R = Σ(oldAlloc - newAlloc)
```

---

## 4. 阶段二：再分配目标（性能杠杆菜单）

回收的预算 `R` 投到哪个杠杆，由**瓶颈定位 + 容量性价比**决定。下表为通用菜单（择优，非穷举）：

| 性能杠杆 | 再分配用法 | 适用瓶颈（profiling 信号） | 容量需求估算 |
|---|---|---|---|
| 放大分块 tile | 把工作块 buffer（M/N/K 维）加大一档 | 外层迭代多、GM→L1/UB 搬运次数多、L0/UB 利用率低 | `Δtile 维 × 另一维 × sizeof × 深度` |
| 加深缓冲 | TQue 深度 +1（double→triple） | 某管线 wait 占比高、搬运/计算未重叠 | `+1 × 单 tile 字节` |
| 扩大批量累加器 | 累加器/暂存 buffer 行数加大 | 跨管线同步密集、scalar 主导 | `Δbatch × rowLen × sizeof` |
| 片上复用驻留 | 常驻 buffer（数据驻留少重读） | 某数据被多次从 GM 读取 | `驻留量 × sizeof` |
| 加宽向量化 chunk | UB chunk 行/列加宽 | 向量管线未占满、UB pass 多 | `Δchunk × 另一维 × sizeof` |

选择规则：

```text
for each 可行杠杆 lever:
    need = lever 下一档所需额外容量
    gain = 由 profiling/tiling 估算的预期收益（搬运次数↓ / 同步数↓ / 重读↓）
    if need ≤ R: 候选; score = gain / need
选 score 最大者；R 还有余则继续投下一个；总需 ≤ R
```

## 5. 实施步骤

### 5.1 修改位置

| 位置 | 修改 |
|---|---|
| `InitBuffers` | 阶段一：收紧过量 buffer 的 `InitBuffer` 尺寸；阶段二：扩大/新增目标杠杆 buffer |
| 常量/注释 | 显式写出"解析上界公式"与"再分配去向 + ROI 依据"，便于复审 |
| 相关 kernel 逻辑 | 若再分配杠杆涉及 tile/batch/深度变化，同步改对应循环步长/缓冲深度（属杠杆本身的实现） |
| tiling/host | 通常不改；若上界依赖 tiling 字段则绑定 |

### 5.2 流程

```text
1. profiling 定位瓶颈 → 选定候选性能杠杆。
2. 列出所有 buffer 当前分配与使用相位（含时分复用）。
3. 阶段一：对每个候选收紧 buffer，按 §3 推导真实 max 工作集，收紧，累计 R。
4. 阶段二：按 §4 菜单 + ROI，把 R 投到选定杠杆（放大 tile / 加深缓冲 / 扩批量 / 复用 / 加宽 chunk）。
5. 重算合计 ≤ 硬件上限（手算 + 注释）。
6. 全 shape / 全相位 重测精度与性能，确认收紧未越界、再分配兑现收益。
```

## 6. 正确性红线

### 6.1 上界证明覆盖全相位/全 shape（阶段一）

- 收紧后尺寸 ≥ 该 buffer 在**所有使用相位**与**所有支持 shape** 下的最大工作集。
- 上界若依赖 tiling 不变量（如 `chunkRows ≤ 上界`、`tileSize ≤ 某比值`），须写明并确保 tiling 侧不违反。
- 仅按主用例收紧而忽略大 shape/尾块 → 大 shape 越界（陷阱 1）。

### 6.2 耦合一致性（阶段一）

- 容量耦合的 buffer（A sized = B，或 A 上界由 B 钳制）须同步收紧或显式解除耦合并各自证明。
- 单边收紧 → 配对相位越界（陷阱 2）。

### 6.3 再分配后上限校验（阶段二）

- 再分配后**必须**手算合计 ≤ 硬件上限；不靠"编译过"代替（陷阱 3）。
- 再分配杠杆若改变 tile/batch/深度，须重算所有受影响 buffer 的容量（放大 tile 会让工作块、暂存、L0C 等同时变大），不能只看杠杆 buffer 本身。

### 6.4 数值正确性

- 收紧阶段不改计算；再分配阶段若改变 tile/batch，须保证数值语义不变（累加顺序、mask、有效行列截断不变），仅改搬运/迭代编排。

## 7. 已知陷阱

### 陷阱 1：按主用例收紧，大 shape/尾块越界

问题：用主 shape 推导上界，某 tiling 下工作集更大，收紧后越界。
症状：大 shape/特定 tiling 精度失败/踩踏。
修复：上界按 tiling 不变量**最坏值**推导；全 shape 回归。

### 陷阱 2：耦合 buffer 单边收紧

问题：耦合的 buffer 只收紧一方。
症状：配对相位越界。
修复：耦合双方同步收紧或显式解除。

### 陷阱 3：再分配后合计超上限未手算

问题：只收紧一个 buffer 就放大杠杆 buffer，未重算合计；或放大 tile 时未算连带变大的其它 buffer。
症状：编译失败或运行踩踏。
修复：§6.3，重算所有受影响 buffer，合计 ≤ 上限。

### 陷阱 4：运行时不定工作集当解析上界

问题：buffer 工作集依赖输入数据/运行时长度，却当解析常量收紧。
症状：特定输入越界。
修复：只对可解析上界的 buffer 收紧。

### 陷阱 5：再分配选错杠杆（瓶颈不匹配）

问题：把预算投到与瓶颈无关的杠杆（如瓶颈是同步却去放大 tile），收益不兑现。
症状：性能未提升，甚至因更大 tile 增加单次开销而劣化。
修复：先 profiling 定位瓶颈，按 §4 信号匹配杠杆；ROI = 预期收益 / 容量需求择优。

### 陷阱 6：误判回收即收益

问题：只做了阶段一收紧，未做阶段二再分配，期望直接提速。
澄清：回收本身不直接提速（总量不变）；收益来自再分配解锁的杠杆。两阶段缺一不可。

## 9. 禁止事项与回退条件

禁止：

- 只做回收不做再分配（陷阱 6），或反之（无预算硬放大 → 超上限）。
- 仅按主用例收紧、忽略大 shape/尾块/全相位（陷阱 1）。
- 耦合 buffer 单边收紧（陷阱 2）。
- 不手算合计、不算连带 buffer、靠"编译过"代替上限校验（陷阱 3）。
- 对运行时不定工作集强收紧（陷阱 4）。
- 脱离瓶颈选杠杆（陷阱 5）。
- 改变数值语义（累加顺序/mask/有效截断/dtype）。

回退或缩小策略的条件：

- 无可证明冗余 → 无预算可回收，改用 tiling/算法策略。
- 再分配后某 shape/相位精度失败且无法补强上界 → 恢复相关 buffer 原尺寸。
- 合计仍超上限 → 缩小再分配幅度或选容量需求更小的杠杆。
- 再分配后性能未提升 → 杠杆与瓶颈不匹配（陷阱 5），重新 profiling 选杠杆。

## 10. 验收标准

最小验证：

```bash
bash <build> --soc=<soc> --op=<op> && bash <build> --soc=<soc> --op=<op> --wheel
source <set_env> && pytest <op>/test/test_<op>_*.py
```

精度：全 shape（含大 shape、尾块、各 tiling 分支）与基线一致——收紧最易在大 shape 暴露越界。

容量（阶段一判据）：

- 过量 buffer 收紧到已证明上界；冗余回收到预算 `R`。
- 耦合一致；全相位/全 shape 工作集 ≤ 收紧后尺寸。

性能（阶段二判据，**本策略的核心收益**）：

- 再分配杠杆兑现预期：对应瓶颈指标下降（搬运次数↓ / 同步数↓ / GM 重读↓ / 向量利用率↑）。
- 整体 `Task Duration` 不劣化，且当杠杆所在路径是关键路径时明显下降。

边界 shape：最大支持 shape（触发最大工作集）、各 tiling 分支、时分复用的所有相位、不同 dtype（影响字节换算与上界）。

结论须写清：

```text
本策略是"回收 + 再分配"两阶段；回收本身不直接提速，性能收益来自再分配解锁的容量杠杆。
判据：阶段一看"合法收紧 + 全 shape 精度不退"，阶段二看"瓶颈指标下降 + 整体提速"。
杠杆按 profiling 瓶颈择优，不绑定任一具体优化。
```

## 检索卡（短卡）

动作：先把过量片上buffer收紧至工作集上界，再把回收容量分配给目标杠杆。
适用：至少一个目标杠杆想放大却受片上buffer容量限制。
限制：受片上总量硬限制；收紧后容量仍须覆盖所有相位、所有支持shape的已证明最大工作集。
范围：既有UB/L1片上buffer及目标杠杆的容量配置。
检索词：UB、L1、L0、InitBuffer、容量回收、解析上界、容量再分配。
机会：目标杠杆因buffer不足停在较小配置。
代价：若目标杠杆与瓶颈不匹配，更大tile可能增加单次开销。
