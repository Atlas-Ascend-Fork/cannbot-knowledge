# 性能优化策略：有序数据不变量驱动的 O(1) 快路径（边界探针 + 通用顺序慢路径回退）

> **单一优化点：** 当循环对一段连续元数据/控制数据（索引、掩码、长度、标志位等）的处理依赖一个**全局谓词**（如"是否存在 -1/无效元""是否全部有效""是否存在 0 长度"），而该数据满足一个**已知的有序不变量**（升序/降序、或单调，极值/哨兵位于已知端）时，用**探针一个边界元素（通常为末元素）**把 O(N) 谓词判定塌缩为 O(1)；谓词不成立时走**快路径**（省掉冗余的逐元素工作），谓词成立时走**慢路径**（任意顺序都正确的通用处理）。
>
> **算子/管线/数据类型无关：** 适用于任何 AscendC kernel 里"先扫描一段范围决定全局性质、再据此分支处理"的模式，不限于 FlashAttention、不限于稀疏索引数组。

本策略只把"O(N) 全局谓词判定"塌缩为"O(1) 边界探针 + 快/慢路径"。不改变数据语义/数值、不改跨核同步、不引入新算法。

---

## 1. 优化原理

### 1.1 性能问题模式（通用）

低效基线先 O(N) 扫描范围决定全局性质，再据此逐元素处理：

```text
# 模式 A：仅判定（如"是否存在无效元"）
has = false
for i in 0 .. N:
    if pred(data[i]): has = true; break        # O(N) 标量扫描

# 模式 B：判定 + 据此分支处理（如"全有效⇒统一处理，否则逐元素条件处理"）
for i in 0 .. N:
    if elemNeedsSpecial(data[i]):
        <特殊处理（清零/掩码/分支）>             # 每元素一次条件 + 特殊工作
```

当 N 较大（如数百量级）且**主用例谓词不成立**（无特殊元）时，O(N) 扫描与逐元素条件/特殊工作都是纯浪费。

### 1.2 本策略利用的机制

| 机制 | 利用方式 |
|---|---|
| 有序不变量 | 数据满足已知顺序（升序/降序/单调），极值或哨兵位于已知端 ⇒ 全局 ∃/∀ 谓词由一个边界元素决定 |
| 边界探针 | O(1) 读一个边界元素（通常末元素）即可判定整段谓词 |
| 快/慢路径分流 | 谓词不成立（主用例）⇒ 跳过 O(N) 扫描与逐元素特殊工作；谓词成立 ⇒ 通用 O(N) 处理（任意顺序正确） |

核心改动（通用）：

```text
# 判定：O(N) → O(1)
hasSpecial = (data[N-1] == sentinel)            # 升序、sentinel 在尾 ⇒ 末元素探针

# 处理：快/慢路径
if !hasSpecial:                                 # 快路径（主用例）
    <统一处理所有元素（无逐元素条件/特殊工作）>    # 特殊元用安全兜底（如 clamp）+ 下游忽略
else:                                           # 慢路径（谓词成立）
    <通用 O(N) 处理，任意顺序正确>                # 清零/掩码/逐元素条件，与原逻辑一致
```

## 2. 适用条件与泛化边界

必须**同时**满足：

| 条件 | 要求 |
|---|---|
| 全局谓词 | 循环依赖一个 ∃/∀ 性质（存在/全部满足某条件），而非逐元素独立判定 |
| 有序不变量 | 数据满足**已知顺序不变量**（升序/降序/单调，极值或哨兵在已知端），且为**输入契约**（数据生产方/上游保证） |
| 探针可靠性 | 存在**可靠的边界探针规则**：边界元素值 ⇒ 整段谓词（须可证明，见 §3） |
| 主用例偏向 | 谓词"不成立"（无特殊元）是高频主用例，否则快路径命中率低、收益小 |
| 慢路径可得 | 存在任意顺序都正确的通用处理作为回退（谓词成立或不变量未保证时） |
| 基线稳定 | 修改前 build/精度/性能可重复 |

优先适用：

- N 较大、谓词判定或逐元素特殊工作是 scalar/指令开销来源（profiling 显示 `aiv_scalar`/`aic_scalar` 或标量循环占比高）。
- 数据天然有序（如已排序的 TopK 索引、单调长度数组、连续掩码段）。
- 主用例大量"无特殊元"（如有效元个数等于批量上限、全有效）。

不适用或需先重构：

- 数据**无序且无法保证不变量** → 探针不可靠，必须 O(N)（或先排序，代价通常更大）。
- 谓词是**逐元素独立**性质（每个元素各自决定处理，无全局 ∃/∀）→ 无可塌缩的全局判定。
- 探针规则不可证明可靠（哨兵非极值、或特殊元可在任意位置）→ 不能用。
- 主用例谓词频繁"成立"（特殊元常在）→ 快路径命中率低，收益不抵分支开销。
- 收益来自搬运/算力（用 01/02/03/04）——本策略只降 scalar/扫描开销。

## 3. 不变量与探针规则（正确性核心）

### 3.1 不变量是输入契约

- 有序不变量（如"升序、-1 在尾"）**必须由数据生产方/上游/测试桩保证**，不是本算法自己建立的。
- 必须在代码注释与契约文档中**显式声明**该不变量及其来源（如上游数据生成方按升序产出、哨兵置于尾部）。
- 若上游可能破坏不变量，必须先在入口校验或排序，否则快路径不安全。

### 3.2 探针规则的可靠性证明

探针"边界元素 ⇒ 整段谓词"必须**可证明**：

- 升序 + 哨兵为最小值且全在尾：`last >= 0 ⇒ 整段无 -1`（因升序中 -1 必在首部连续段，若 last 非 -1 则全段非 -1）✓。
- 反例：若 -1 可出现在任意位置（非尾），`last >= 0 ⇏ 整段无 -1` ⇒ 探针不可靠。
- 必须确认：哨兵是**极值**、且不变量把所有哨兵**聚到被探针端**。

### 3.3 快/慢路径语义等价

- 快路径与慢路径必须产生**相同可观测结果**；快路径只是省掉"谓词不成立时的冗余工作"。
- 若快路径对"潜在特殊元"采用**安全兜底**（如无效索引 `clamp(min=0)` 取第 0 行）而非显式特殊处理，必须保证：
  - 兜底值无害（下游按谓词 mask/忽略这些元），**且**
  - 下游 mask 的正确性不反向依赖被本快路径影响的判定（避免循环依赖，见 陷阱 4）。

---

## 4. 快/慢路径设计

### 4.1 快路径（谓词不成立 / 主用例）

- 跳过 O(N) 扫描与逐元素条件/特殊工作。
- 对所有元素统一处理；潜在特殊元用安全兜底（clamp/默认值）+ 下游忽略。
- 例：全部有效时统一 gather 全部行（潜在无效元 clamp 到安全行），由下游 mask 掉。

### 4.2 慢路径（谓词成立 / 通用回退）

- 任意顺序都正确的通用处理：逐元素条件、显式清零/掩码。
- 例：存在无效元时先清零累加器（单缓冲复用防残留），再仅处理有效行。

### 4.3 判定落点

- 探针在范围已知后、处理循环前执行一次。
- 空范围（N==0）须短路（不探针、不处理，或按语义给默认谓词值）。
- 单元素范围：探针即该元素，规则仍成立。

## 5. 实施步骤

### 5.1 修改位置

| 位置 | 修改 |
|---|---|
| 含 O(N) 谓词扫描/逐元素条件处理的 kernel 函数 | 插入边界探针；按谓词分流快/慢路径 |
| 契约注释 | 显式声明有序不变量及其来源、探针可靠性证明 |
| 数据生产方/上游/tiling | **通常不改**；除非不变量需上游保证，则在契约中标注并加入口校验 |

### 5.2 流程

```text
1. 识别 O(N) 全局谓词判定与据此分支的逐元素工作。
2. 确认数据有序不变量（输入契约）+ 探针可靠性（§3）。
3. 探针：O(1) 读边界元素 → 谓词值。
4. 快路径：谓词不成立 ⇒ 统一处理 + 安全兜底 + 下游忽略。
5. 慢路径：谓词成立 ⇒ 通用 O(N) 处理（保留原逻辑）。
6. 全用例（含谓词成立、空范围、单元素、不变量边界）回归精度。
```

## 6. 正确性红线

### 6.1 不变量必须为保证的输入契约

- 快路径正确性**依赖**有序不变量（直接依赖，或经下游 mask 传递依赖）。
- 不变量须由上游保证；若不可保证，必须入口校验/排序，或**禁用快路径**（只留慢路径）。
- 不在注释/契约中声明 ⇒ 后人破坏不变量时静默出错（陷阱 1）。

### 6.2 探针必须可证明可靠

- 边界元素 ⇒ 整段谓词的推理须严格（哨兵极值 + 聚到被探针端）。
- 探针不可靠时不得使用（陷阱 2）。

### 6.3 快/慢路径语义等价 + 下游耦合

- 两路径可观测结果一致；快路径的兜底值须被下游 mask/忽略。
- 若下游 mask 依赖另一处探针（如下游阶段的同谓词判定），两处探针须基于**同一不变量、一致判定**，否则循环依赖出错（陷阱 4）。

### 6.4 边界

- N==0 短路；单元素范围正确；哨兵恰在边界的取值正确。
- 慢路径对"不变量被违反"的输入也应正确（作为兜底），除非契约明确禁止。

### 6.5 数值正确性

- 不改变有效元的值、mask 语义、有效计数、dtype。仅改变判定与处理编排。

## 7. 已知陷阱

### 陷阱 1：不变量未保证/未声明，快路径静默出错

问题：上游数据实际无序（或 -1 不在尾），探针误判，快路径处理错。
症状：特定输入 mismatch，常呈"主用例对、边角用例错"。
修复：§6.1——不变量作为输入契约显式声明；不可保证时入口校验/排序或禁用快路径。

### 陷阱 2：探针规则不可靠

问题：哨兵非极值、或特殊元可在任意位置，边界探针不蕴含整段谓词。
症状：谓词误判，错路径。
修复：§3.2 严格证明；不可证则不用。

### 陷阱 3：快路径漏处理特殊元

问题：快路径跳过了对特殊元的处理，且下游未 mask/忽略，导致特殊元以兜底值（或残留）流出。
症状：特殊元位置数值错误。
修复：§3.3/§4.1——快路径兜底值须无害且下游忽略；否则不能跳过。

### 陷阱 4：多处探针判定不一致（循环依赖）

问题：A 处快路径依赖下游 B 的 mask；B 的 mask 又依赖另一探针；两探针基于不同假定或其一出错。
症状：谓词与下游 mask 失配，特殊元未被 mask。
修复：§6.3——所有相关探针基于同一不变量、一致判定；或集中到单一谓词源。

### 陷阱 5：慢路径单缓冲残留

问题：慢路径"仅处理有效元"时，累加器/buffer 单缓冲复用，未处理槽位残留上轮数据。
症状：无效/缺元位置出现脏数据。
修复：慢路径批首清零未用槽位（与策略 03/04 的单缓冲处理一致）。

### 陷阱 6：主用例谓词频繁成立，快路径反成负担

问题：特殊元常在，快路径命中率低，额外分支探针反增开销。
诊断：profiling 显示快路径几乎不命中。
修复：确认主用例偏向后再用；否则不用本策略。

## 9. 禁止事项与回退条件

禁止：

- 在不变量未保证/未声明时启用快路径（陷阱 1）。
- 使用不可证明可靠的探针（陷阱 2）。
- 快路径漏处理特殊元且下游未忽略（陷阱 3）。
- 多处探针基于不一致假定（陷阱 4）。
- 改变有效元数值/mask 语义/有效计数/dtype。

回退或缩小策略的条件：

- 数据无序且无法保证不变量 → 不用本策略（保留 O(N)）。
- 探针不可证明可靠 → 不用。
- 精度失败且无法定位到不变量（陷阱 1）/探针（陷阱 2）/下游耦合（陷阱 3/4）单一原因。
- profiling 显示快路径命中率低、`aiv_scalar` 未下降 → 主用例不偏向，回退（陷阱 6）。

## 10. 验收标准

最小验证：

```bash
bash <build> --soc=<soc> --op=<op> && bash <build> --soc=<soc> --op=<op> --wheel
source <set_env> && pytest <op>/test/test_<op>_*.py
```

精度：**必须覆盖谓词成立与不成立两类用例**——快路径（无特殊元）与慢路径（有特殊元）都要测；含空范围、单元素、哨兵在边界、不变量边界。慢路径对任意顺序输入都应正确。

性能（profiling 归因）：

- 谓词判定所在 scalar/扫描时间下降（如 O(N) 谓词扫描变 O(1) 探针、跳过逐元素条件/特殊工作）。
- 主用例（谓词不成立）整体 `Task Duration` 不劣化，且该扫描在关键路径时下降。
- 慢路径用例性能与基线持平（通用回退不劣化）。

边界 shape：全有效（快路径）、含无效/特殊元（慢路径）、全无效、空范围、单元素、不同 dtype。

结论须写清：

```text
本策略收益相对"O(N) 全局谓词扫描"基线；判据是 scalar/扫描时间下降（主用例）。
正确性强依赖有序不变量（输入契约）+ 可靠探针 + 快慢路径语义等价。
不变量不可保证时禁用快路径，只留慢路径。
```

## 检索卡（短卡）

动作：用单个边界探针判定全局谓词，并据此分流快慢路径，替代 O(N) 谓词扫描
适用：循环依赖全局存在／全称谓词，而非逐元素独立判定
限制：有序性必须是输入契约，且极值或哨兵位于已知端。
范围：连续索引、掩码、长度或标志位处理循环
检索词：有序不变量、边界探针、全局 ∃／∀ 谓词、极值、哨兵
机会：先 O(N) 扫描确定全局性质，再逐元素处理
