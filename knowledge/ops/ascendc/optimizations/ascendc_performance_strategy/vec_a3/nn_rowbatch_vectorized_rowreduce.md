# 性能优化策略：行并行归一化算子的多行分块批处理与跨行向量化逆缩放

单一优化点：把「逐行 GM↔片上搬运 + 每行独立的标量同步求逆缩放因子」改为「多行组成一个 tile 批量搬运，并把逐行归约结果保留在片上向量槽中、对整 tile 的所有行做一次跨行向量化逆缩放」，从而消除随行数线性膨胀的 per-row DMA 建立开销与 per-row 向量→标量同步/开方停顿。

## 1. 原理

行并行（按行切多核、每核处理若干行、每行沿最后一维做归约）的归一化类 kernel，若按「逐行」组织流水——每行一次 GM→片上读、一次片上计算、一次片上→GM 写，且每行都把归约结果与开方结果通过向量→标量同步取回标量再用于该行缩放——则其固定开销与行数成正比：

- **per-row DMA 建立开销**：每行单独一次小粒度搬运会带来与搬运数据量无关的启动开销；行数巨大（如百万级行）时，DMA 次数本身成为墙钟主导。
- **per-row 向量→标量同步停顿**：每行若为「取归约标量」「取开方标量」各做一次向量→标量同步，且每行的开方/倒数用 per-row 的小向量指令 + 流水屏障完成，则同步次数与屏障次数都随行数线性增长，流水频繁停顿。

改进为多行批处理 + 跨行向量化：

1. **多行 tile**：把若干行组成一个 tile，用支持「块数=行数」的批量搬运一次读入/写出整 tile，DMA 次数从正比于行数降到正比于「行数除以 tile 行数」。
2. **跨行向量化逆缩放**：每行的归约结果不下沉为标量，而是写入片上一个「每行一个块大小 fp32 槽」的暂存区（结果落在槽首元素）；整 tile 所有行的槽连续排列后，对全部槽做**一次**跨行向量化运算（乘均值系数 / 加 epsilon / 开方 / 除以全 1 缓冲）即同时得到所有行的逆缩放因子；最后再逐行取回各自的因子并施加缩放。这样把 per-row 的开方/倒数指令与屏障从正比于行数压到正比于「行数除以 tile 行数」（每 tile 仅若干次跨行向量指令），向量→标量同步也从每行两次降为每行一次（仅最终取因子时）。

## 2. 性能问题模式

- kernel 按「逐行」组织：Process 循环里每行单独 CopyIn/Compute/CopyOut。
- 每行内部为求逆缩放因子，存在「向量→标量同步取归约和」「向量→标量同步取出开方结果」两处标量回读。
- 每行的开方/倒数用 per-row 小向量指令（仅填满一个块）+ 流水屏障实现。
- 在「行数巨大（行数 ≫ 核数）」或「每行元素较少、per-row 固定开销占比高」的用例上墙钟明显偏高；放大 tile 行数、并把开方/倒数跨行向量化后墙钟显著下降，说明 per-row 开销是主要放大因素。

## 3. 正确性红线

- **行间对齐**：多行 tile 的片上 buffer 中，每一行的起始地址必须按硬件对齐粒度对齐（fp32 路径按 fp32 块对齐；半精度路径按半精度块对齐）。因此行间步长须取「每行元素数向上取整到对齐粒度」，**不能**用裸的每行元素数作行间步长，否则未对齐行的向量访存会触发 vector core 异常。fp32 工作区与原 dtype 的输入/输出区行间步长可能不同（元素大小不同），须分别计算。
- **片上容量预算**：tile 行数须按「占用片上 buffer 最多的 dtype/路径」为最紧约束计算：输入/输出 staging（tile 行数 × 对齐步长 × 元素大小）+ 各计算 buffer（tile 行数 × 对齐步长 × 元素大小）+ 归约槽暂存（tile 行数 × 块大小 × fp32）+ 全 1 缓冲（同前）+ 一次性 buffer（如可复用的权重、归约 scratch），总和 ≤ 片上容量并留余量。小每行元素数时对齐步长会显著放大每行占用，须用对齐后的步长算预算（否则 tile 行数会被高估导致片上越界）。
- **尾 tile**：末 tile 行数可能小于 tile 行数，搬运块数、跨行向量运算元素数、逐行施加循环都须按实际行数处理，不得假设整 tile。
- **归约槽语义**：每行归约只保证槽首元素有效，槽内其余元素为残留；跨行向量化运算会处理全部槽（含残留），但因运算为逐元素、无跨元素依赖，残留不影响槽首有效值；逐行施加时**只读每行槽首元素**。
- **跨行向量运算的安全性**：开方/除法对槽内残留（可能为负或未定义）逐元素执行，结果只取每行槽首；不得将残留值用于任何跨行归约或累加。
- **逐行施加的同步**：逐行取逆缩放因子（向量→标量）后施加缩放，须保证跨行向量化运算已落定（向量→标量同步），且标量进入标量寄存器后再启动该行的向量乘法（标量→向量同步）。
- **dtype 一致性**：半精度路径须在 fp32 工作区完成平方/归约/缩放后再回 cast，与原逐行实现同精度路径（含 bf16 的舍入模式）。

## 4. 泛化条件

适用：
- 行并行、每行独立沿最后一维归约、且需逐行计算一个标量缩放因子（如由归约和与 epsilon 经开方/倒数得到）的归一化类 kernel。
- 当前按逐行组织流水，且每行存在向量→标量同步取因子。
- 行数远大于核数（多 tile 场景），或每行元素较少使 per-row 固定开销占比高。
- 每行元素可整行装入片上（无需沿该维再切分）。

不适用：
- 每行元素过多、单行已占满片上（无多行放大空间；应改用沿该维切分的策略）。
- 行数与核数同量级且每行元素很大（多行批处理收益被计算时间淹没）。
- 归约/缩放因子天然跨行耦合（非逐行独立），无法把逐行运算跨行向量化时。

## 5. 实施步骤

1. 列出该 kernel 所有同时存活的片上 buffer 及元素大小，按「最紧 dtype/路径」求 tile 行数上限：tile 行数 ≤ (片上容量 − 一次性 buffer − 余量) / (每行对齐后占用字节数)；每行占用须用对齐步长（非裸元素数）计算。
2. 计算两种行间步长：原 dtype 的输入/输出区按其块对齐粒度；fp32 工作区按 fp32 块对齐粒度。片上 buffer 按「tile 行数 × 对应对齐步长」分配。
3. 把「逐行搬运」改为「块数=tile 行数、每块=每行字节数」的批量搬运（读入与写出对称）。
4. Compute 改三阶段：
   (a) 逐行：平方（半精度先 cast 到 fp32 工作区），再把该行归约到「每行一个块大小 fp32 槽」的槽首（折叠归约 + 整块归约，结果留片上向量内存，**不**下沉标量）；
   (b) 跨行向量化：对全部槽做乘均值系数 / 加 epsilon / 开方 / 除以全 1 缓冲，每步仅一次跨行向量指令 + 一次流水屏障；
   (c) 逐行：取该行槽首因子（向量→标量同步）→ 标量→向量同步 → 该行乘因子 → 乘可复用权重 → （半精度）回 cast。
5. tiling 函数把 tile 行数随其它参数下发到 kernel；末 tile 行数由 kernel 按实际剩余行数处理。
6. 复核：行间步长对齐、片上预算按对齐步长、尾 tile、槽首-only 读取、逐行施加的两处同步。

## 6. LLM 前置问题

- 当前 kernel 是否按逐行组织流水（每行单独搬运 + 每行向量→标量同步取缩放因子）？
- 每行的缩放因子是否由「该行归约和 + epsilon 經开方/倒数」得到、且逐行独立（可跨行向量化）？
- 占用片上 buffer 最多的 dtype/路径是哪个？按对齐步长算每行占用是多少？tile 行数上限多大？
- 每行元素能否整行装入片上（决定适用多行批处理而非沿维切分）？
- 行间步长是否已按硬件对齐粒度取齐（fp32 区与原 dtype 区分别计算）？

## 7. 验收标准

- 编译通过，安装包可用。
- 精度：与基线在共享评测用例集上逐用例一致，须覆盖非对齐每行元素数、半精度/bf16、特殊值（零/极值）、高维与巨量行数用例。
- 性能：墙钟 mean 相对基线下降；高行数用例下降幅度大于低行数用例；部分用例反超参考实现。
- tile 行数随片上预算自适应（小每行元素数时自动放大）；片上 buffer 总占用在容量预算内（不越界）。

## 检索卡（短卡）

动作：把逐行 GM↔片上搬运+每行标量同步求逆缩放因子，改为多行 tile 批量搬运、归约结果留片上槽并跨行向量化逆缩放。
适用：行并行、每行沿末维归约且需逐行标量缩放因子的归一化 kernel；行数≫核数或每行元素较少；每行可整行装入片上。
限制：行间步长按硬件对齐粒度取整（fp32 与原 dtype 分别算）；片上预算按对齐步长算；尾 tile 按实际行数；逐行只读槽首。
范围：行并行归一化类 kernel 的逐行归约+缩放环节。
检索词：多行 tile、批量搬运、跨行向量化、归约槽、槽首元素、对齐步长、向量→标量同步、流水屏障。
机会：Process 循环逐行 CopyIn/Compute/CopyOut，per-row DMA 建立开销与向量→标量同步累积。
代价：归约槽与全1缓冲新增片上占用，半精度需 fp32 工作区往返 cast。
