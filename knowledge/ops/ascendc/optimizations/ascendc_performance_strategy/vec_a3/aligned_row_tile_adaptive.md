# 性能优化策略：列对齐时增大行块以减少元数据预取同步

单一优化点：按列对齐性自适应调整行块大小——列对齐时放大行块减少元数据预取同步屏障，列非对齐时保持较小行块避免片上间接访问退化。

## 1. 原理
逐行处理类算子常按"行块"批量预取索引/路由元数据，并在每次预取后插入同步屏障。
行块越大，预取次数与同步屏障越少。但当被处理的列维度（隐藏维）非基本块对齐时，
大行块下的间接索引布局会使片上访问低效。因此行块大小应随列对齐性自适应：
列对齐时放大行块，列非对齐时保持较小行块。

## 2. 性能问题模式
- 固定的较小行块导致大规模行数下预取与同步屏障次数过多，同步开销累积。
- 一刀切放大行块在列非对齐时反而退化（片上间接访问低效，实测可见回归）。

## 3. 正确性红线
- 行块上限受片上容量约束（索引/元数据缓冲随 行块×路由数×每元素字节数 增长），
  不得超过可用片上预算。
- 行块不得超出行总数；尾部行块取剩余行数。
- 列对齐判定用"列数 mod 每基本块元素数 == 0"；判定错误会触发非对齐退化或越界。

## 4. 泛化条件
- 适用：逐行处理、按行块批量预取索引/元数据、且列维度对齐性可由 host 判定并传入的算子。
- 不适用：无行块预取同步的算子；列维度始终非对齐且无对齐分支的场景。

## 5. 实施步骤
1. 在 host tiling 计算"列对齐性"（列数 mod 每基本块元素数）。
2. 列对齐时把行块上限设为基准值的若干倍；列非对齐时保持基准值。
3. 行块 = min(行总数, 上限)；保证 行块×路由数×每元素字节数 在片上预算内。
4. kernel 主循环按行块批量预取 + 同步；行块自适应值由 host 传入，kernel 不需分支。

## 6. LLM 前置问题
- 算子是否按行块批量预取索引/元数据并插同步屏障？
- 列维度对齐性如何在 host 判定？放大行块是否仍在片上预算内？
- 非对齐列下放大行块是否被实测验证为退化（需回退到基准行块）？

## 7. 验收标准
- 编译通过；精度不变。
- 列对齐的大规模形状墙钟改善；列非对齐形状不退化（必要时按列对齐性分流）。

检索词：列对齐性、行块、元数据预取、同步屏障、片上间接访问
