# 性能优化策略：均匀小窗口的末轴归约改用「相邻对求和」批量指令

> 单一优化点：当末轴窗口等长且为 2（或 2 的幂）时，用「相邻对求和」批量指令替代「每输出一次」的末轴段归约。

## 1. 原理

当一个「逐输出元素的末轴段归约」需要为每一个最末轴输出单独发起一次归约指令时，指令数等于
「输出数」。若输出数很大（例如最末轴被高度下采样后仍有大量输出），即便每次归约都很快，总
指令数也会成为瓶颈。当这些末轴窗口「等长」且长度为 2 的整数倍（尤其长度为 2）时，一条
「相邻对求和」类向量指令可以一次把一整行最末轴输入折叠成一半长度的「相邻对之和」，从而用
几条指令替代原先成千上万次「每输出一次」的归约。

## 2. 性能问题模式

- 末轴窗口等长、且很小（如长度 2，即最内轴被 2 倍下采样），但实现仍为「每个最末轴输出调用
  一次单输出归约」，导致指令数 ≈ 末轴输出数，在大输出场景下主导耗时。
- 已完成「读一次 + 片上累加」后，末轴仍逐输出归约，使末轴成为新的瓶颈。

症状：算子整体已接近带宽上界，唯独末轴归约段的指令数随末轴输出数线性膨胀，拖慢大输出用例。

## 3. 正确性红线

- 仅当末轴窗口「严格等长」且长度恰为 2（或可由若干次「相邻对求和」级联得到的 2 的幂）时
  使用；非等长或非 2 的幂的窗口必须回退到「按位掩码段归约」。
- 每次相邻对求和后长度减半，需保证源行缓冲在「单次指令的最大跨度」内不越界（按需把行缓冲
  尾部补足到一次指令处理的元素数）。
- 求和结果除以窗口元素数时，窗口元素数对该行所有输出恒定，应使用标量乘以倒数（避免逐输出
  的标量写回与跨流水线同步）。
- 低精度累加须在更高精度累加器里完成「相邻对求和」，再回转目标精度。

## 4. 泛化条件

适用：

- 末轴窗口等长、长度为 2（或 2 的幂，可级联多次），且最内轴长度是「单次指令处理元素数」的
  整数倍（否则仅对齐部分用本指令、尾部用段归约兜底）。

不适用：

- 末轴窗口非等长（自适应非整除），或长度不是 2 的幂。
- 最内轴不连续。

## 5. 实施步骤

1. 判定末轴是否等长：最内轴尺寸能否被末轴输出数整除；若能，窗口长度 = 最内轴尺寸 / 末轴输出数。
2. 若窗口长度 == 2 且最内轴尺寸是「单次相邻对求和指令一次处理元素数」的整数倍：
   - 对每个已完成片上累加的行，用一条「相邻对求和」指令把整行折叠为一半长度的「相邻对之和」，
     直接得到该行全部末轴输出的归约和。
3. 若窗口长度为 2 的更高次幂，级联多次「相邻对求和」（每次长度减半），中间结果在片上缓冲间
   乒乓。
4. 不满足上述条件时，回退到「按位掩码从一个对齐基址做段归约」的逐输出路径。
5. 用标量乘以倒数完成除法，回转目标精度，写回输出行。

## 6. LLM 前置问题

- 末轴窗口是否等长？长度是否为 2 或 2 的幂？
- 最内轴尺寸是否为「相邻对求和指令一次处理元素数」的整数倍？尾部是否需要兜底？
- 该算子是否已先完成「读一次 + 片上累加」，使末轴成为剩余瓶颈？

## 7. 验收标准

- 构建：算子可编译构建并注册到已安装算子包。
- 精度：选定性能用例与参考实现逐元素比对全部通过既有阈值。
- 性能：在「末轴等长小窗口 + 大输出」用例上，相比「逐输出段归约」路径有显著提升；整体平均
  墙钟不劣化。
