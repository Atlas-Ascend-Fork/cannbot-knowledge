# 性能优化策略：动态UB预算驱动的批量边界压缩流水

> 组合优化点：用动态共享 UB 统一承载多切片的分桶统计、边界候选及稳定整理状态；按资源预算联合配置切片数与协作线程数，让逐位细化从原始 GM 扫描转入局部边界集合，最后分批有序输出。
> 数据流范围：精确有序候选筛选、按位边界细化及有限状态批量输出。已验证硬件范围为 Ascend 950（A5），要求目标入口支持所需动态共享 UB 和 SIMT 操作。

## 1. 原理

该策略是经过组合验证的数据流组织，不把动态分配、分桶、压缩或输出逆变换各自声明为独立获益策略。

设同时驻留 R 个独立切片，每切片的预算 S 包括直方图、容量 C 的候选键和整数索引、容量 Q 的边界双缓冲、稳定整理双缓冲、计数器及对齐。必须满足：

`R × S(C,Q,键宽,索引宽) + 公共暂存 ≤ 当前入口真实可用UB − 缓存/栈/其它保留空间`

布局按键、索引分离的数组组织，宽键遵守其对齐要求。R 与每切片协作线程数 T 联合调节，线程总数 R×T 受入口和设备限制。动态数组与分配器不能重复占用同一物理区。特定接口的地址窗口上限不能当成硬件 UB 容量；任何固定字节数、线程数及桶容量都不是本策略的通用阈值。

对可精确映射为单调整数键的数据，按高位向低位统计直方图，并由累计数量找到目标边界桶。已确定应保留的桶写入当前候选集合；只对边界桶继续细化。边界数量不超过 Q 时，将其压缩到 UB 双缓冲，后续只扫描该局部集合；超过 Q 时继续从原输入按已确认前缀过滤，禁止截断边界集合。完全相同的前导位仅在对整个活动集合证明一致后跳过。

对已确定的候选使用稳定低位逐位整理，输出完整有序批次。保留数超过 C 时，以已输出的完整比较键作为严格续取边界，再处理下一批；边界包括接口要求的原始索引次序，避免相同数值跨批次重复或遗漏。稳定散布可以是已验证的串行局部实现，不暗示存在并行稳定原子散布。

## 2. 性能问题模式

- 原实现采用有限固定暂存，每个小任务单独调用，多切片的工作不足以摊薄启动、初始化和同步。
- 每轮逐位细化都重扫完整 GM 输入，即使真正待判定的边界集合已很小。
- 候选需要中间 GM 暂存和再次读回，而目标动态 UB 入口有经核验的可用空间。

新组织减少有效扫描集合和中间 GM 往返，但引入直方图、压缩与稳定整理成本；短输入、边界长期不收缩或资源占用过高时可能退化。

## 3. 正确性红线

- 键变换必须精确保留接口顺序。宽整数不得先转浮点；键与索引分开存储，不能把完整宽键和索引塞入不足位宽的整数。正负零、NaN、无穷及重复值规则必须明确。
- 压缩前先得到完整计数并检查容量；计数器、前缀和、地址乘积及索引不得溢出。写入位置与读区生命周期明确，压缩失败必须保留完整集合重新扫描。
- 多位整理必须稳定；普通原子分配位置不能证明稳定。比较键与原始索引保持配对，跨批次续取按完整严格边界进行，不能只用数值阈值。
- 只在变换可逆且位型语义已证明时由键恢复输出。NaN规范化等可能丢失原始位型时，按已选索引回读原值；正负零及窄类型恢复另验。逆变换是组合内可选出口，不是已独立证明获益的必要步骤。
- 每个切片拥有独立计数器和暂存区；块内屏障必须由要求参与的线程一致执行，空任务线程不能提前越过仍需参与的屏障。异步消费者结束前禁止复用缓冲。

## 4. 泛化条件

适用条件：多个独立切片可共同驻留；存在精确单调键及明确次序；动态 UB 与所需 SIMT 入口已验证；完整缓冲布局、线程数与缓存保留均满足预算。

不适用或需回退：动态共享 UB 不可用；键语义不成立；切片不足；直方图或稳定整理代价超过省下的扫描；边界集合不收缩；较大驻留状态挤占缓存导致整体退化。

跨步布局可将相邻线程优先分给相邻切片的内层坐标，连续布局可将协作线程优先分给同切片的相邻元素；两种映射都必须验证所有权与屏障参与。与通用递归分桶的区别，是把动态 UB 预算、多切片并发、边界局部压缩、稳定整理和跨批次续取串成同一资源受控流水。

## 5. 实施步骤

1. 固定比较契约和正确性对照，确认目标动态 UB 入口与实际可访问空间；从真实分配清单推导 S、R、T、C、Q。
2. 按对齐要求划分每切片直方图、键/索引、边界双缓冲和整理空间，校验总预算及所有权。
3. 实现高位分桶、精确边界计数、满足容量才压缩及超容量原域重扫；逐级验证集合既不丢失也不重复。
4. 实现稳定低位整理与完整比较键的严格续取，覆盖跨批次相等值；输出默认保持原值，逆变换须单独证明语义。
5. 联合调整驻留切片数、每切片线程数和容量；按布局选择映射。对短输入、少切片或边界退化域保留原路径。
6. 冻结候选源码与构建，先验精度，再同轮交替配对测量全部受影响域，并记录资源占用与负收益域。

## 6. LLM 前置问题

- 当前瓶颈是 GM 重扫、启动同步、边界整理还是缓存压力？动态 UB 真正可用预算是多少？
- 键序能否证明覆盖所有 dtype 与特殊值？相同值如何用索引保持跨批次严格边界？
- 边界数量超过容量时如何完整回退？稳定散布的证明是什么？
- R、T、C、Q 如何影响并发度和缓存保留？连续与跨步布局分别采用什么线程映射？
- 是否仅凭组合收益就把某个子步骤标为独立有效？若需单独选用，最小消融入口是什么？

## 7. 验收标准与证据边界

覆盖容量上下界、跨批次输出、全相等、重复值、极端整数、NaN、无穷、正负零、非整除尾部、多切片和路由两侧；验证值、索引范围、索引互异、回读一致和接口次序，不放宽原容差。

已归档的同设备、同输入、同编译配置 BAAB 两对测量证明组合实现相对冻结前版有效，精度检查全部通过。历史总集合的几何平均加速约 3.09 倍，属于组合实现及该输入集合；动态 UB、批量调度、前缀跳过、边界压缩、稳定整理和出口逆变换未分别消融，不对任一子步骤承诺该收益，也不外推到其它架构。

迁移后按输入域比较 device Task Duration，报告逐域均值、跨域几何平均和总耗时；若需单独采用子步骤，应增加独立候选配对验证。若容量溢出、稳定性失败、缓存压力增加或总耗时退化，先修复、缩小资源/路由范围或回退。

## 检索卡（短卡）

动作：用动态UB联合承载多切片分桶、边界压缩及稳定整理，边界缩小后局部续扫，按完整比较键分批输出。
适用：A5动态共享UB与SIMT入口可用；多切片独立；精确键序成立；驻留状态及缓存保留满足预算。
限制：超容量不得截断；散布须稳定；跨批次含索引严格续取；保留特殊值语义；子步骤未独立消融。
范围：精确有序候选筛选、按位边界细化、有限状态批量输出。
检索词：动态UB、SIMT、MSD、LSD、边界压缩、稳定散布、严格续取。
机会：逐位细化反复重扫GM；小任务调用密集；候选中间落盘后再次读回。
代价：增加直方图、双缓冲及同步；切片数与协作线程需联调，驻留过大可能挤占缓存。
