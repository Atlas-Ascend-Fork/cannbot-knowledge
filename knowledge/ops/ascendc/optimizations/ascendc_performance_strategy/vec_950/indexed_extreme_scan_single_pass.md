# 性能优化策略：带位置输出的极值归约改为单趟 lane 扫描

> 单一优化点：需要同时输出"极值 + 其首次出现位置"的归约，不要用"先按段做跨 lane 归约求极值，
> 再回到获胜段回溯找位置"的两段式；改成 **lane 内运行态（值 + 位置 + NaN 位置）反向逐段扫描，
> 每个 tile 只做一次跨 lane 定案**。反向扫描 + 比较极性让并列自然落到最小位置，NaN 折进
> 同一取用谓词，彻底去掉回溯与"多趟读"。

---

## 1. 原理

两段式的成本结构：

1. **每段一次跨 lane 归约**（`Reduce<MAX/MIN>` 一类）：归约是对数级 shuffle 链，段越小越亏；
   若段长只有几十个元素，这条链的周期数远超"比较 + 选择"本身；
2. **回溯**：归约只给"获胜段"，位置还要再读一次该段（若段有多个元素则再扫一遍），
   并且需要一次额外的向量调用与一次 V→S 同步；
3. 归约结果只发布在 **lane 0**，要做逐 lane 决策还得再广播一次。

单趟扫描的成本结构（每个 256B 向量段）：

```
载入 1 次
take = (src > run) | (src == run & ...)        // 或用 GT(run,src) 的反极性表达
Select(runValue, src, runValue, take)          // 值
Select(runIndex, pos,  runIndex, take)         // 位置
（浮点）Select(runNan,  pos, runNan, nanMask)  // 首个 NaN 位置
位置向量 += 段步长
```

**每个 tile 只做一次跨 lane 定案**：`跨 lane MAX` → **广播**（归约只出 lane 0）→ 逐 lane `EQ` →
`Select(位置, BIG, eq)` → `跨 lane MIN` 得到"极值的最小位置"。定案里必须按"先值后位置"的次序，
否则并列时取到的可能是任意一个位置。

**反向扫描的作用**：并列时取"先被扫描到的元素"（即更小的位置）。正向扫描要靠"不小于"或额外的
`==` 判断才能保住首现；反向 + 严格比较极性可以一条谓词搞定，且逻辑更直观。

**NaN 语义**：若契约要求"NaN 视为最大（或最小）且取首个 NaN"，必须**显式携带** NaN 位置：
比较指令对 NaN 通常返回 false，不会把 NaN 纳入运行极值。用自比较（`NE(x,x)` 或
`LE(x,x)` 取反，具体取决于目标平台的有序/无序语义）得到 NaN 谓词，反向扫描覆盖 → 首个 NaN。

瓶颈类型：vec/issue（每元素指令多）/ 同步往返（每段一次 VF + 同步）。

## 2. 性能问题模式

- 归约轴很长、每段元素很少，profile 显示向量发射饱和而有效带宽/吞吐上不去；
- 代码里存在"归约求极值 + 二次扫描/回溯"的结构，或每段一次 "VF 调用 + V↔S 同步"；
- 热循环里出现逐元素的除法/取模/查表（位置需要按元素算），或标量循环逐元素比较；
- 每个输出只对应很少的工作量，但每份工作量都要付一次固定同步。

## 3. 正确性红线

1. **并列必须取首次出现**：反向扫描 + "新元素获胜"的极性；`Select` 的 src1/src2 语义要写清
   （`mask ? src1 : src2`），写反会退化成"永不更新"且不报错。
2. **跨 lane 归约只保证 lane 0 有效**：定案前必须广播到全 lane，再做逐 lane `EQ`。
3. **越界/无效 lane 必须 no-op**：尾段不足一个向量，或用固定块尾读时，越界 lane 会读到下一行的
   数据/填充；必须先 `Select(值, 值, 运行值, mask)` 归一，或在比较后显式
   `And(take, take, mask, ALL)` 收口——否则越界的"位置"可能赢下归约（典型症状：输出位置 = 轴长）。
4. **NaN 不能依赖比较指令的默认行为**：有序比较对 NaN 恒 false；要按契约显式携带首个 NaN 位置，
   并在最终定案里让它优先于普通极值。
5. **位置载体跨数值域时要核对语义**：若位置以"整型位模式"存进浮点域，则只有非负下标可用
   `MIN` 归约（位模式作为正数单调）；同时确认该平台的下标归约不 flush denormal。
6. **尾段 mask 逐段更新**：`UpdateMask(剩余元素数)` 必须在每段按真实剩余量刷新，不能只在首段算一次。

## 4. 泛化条件

- **适用**：需要"极值 + 首次出现位置"的归约，归约轴长 ≫ 向量宽度；浮点（含 NaN 语义）与
  整型域；单输出元素的工作量足够覆盖一次逐 lane 定案。
- **不适用 / 收益低**：
  - 归约轴很短（只有一两个向量段）：跨 lane 定案的固定开销占比过高，应改用"多行/多项批处理"
    把定案摊薄；
  - 需要 top-k / 排序 / 稳定分区（有专门的压缩与排序通路）；
  - 需要位精确的 64-bit 选择操作（32-bit 平面方案只适合"比较"语义）。
- **可叠加**：多行批处理（一条描述符覆盖多行、一次调用内循环多行）、行内循环展开提升访存并行、
  输入流水加深。

## 5. 实施步骤

1. 明确契约：并列取首次还是最后？NaN 是最大还是最小？是否要"首个 NaN"位置？先写成断言。
2. 选定域宽：以比较域的 lane 宽度为准（16-bit 数据通常先无损拓宽到 32-bit 再比较，避免窄域
   的 mask/索引位宽错配）。
3. 建立运行态：值、位置、NaN 位置三组寄存器，初始化为域最小值/0/BIG；位置用"整型域"构造，
   必要时以位模式复用给比较域。
4. 反向逐段扫描：载入 → 无效 lane 归一 → 计算取用谓词（含 NaN）→ 三个 `Select` → 位置向量
   按段步长回退。
5. 定案：跨 lane MAX → 广播 → `EQ` → `Select(位置, BIG, eq)` → 跨 lane MIN（NaN 路径单独取
   MIN 后再比较"是否 < 轴长"）。
6. 发布：把（值、位置、NaN 位置）写到 32B 对齐的槽位，lane 0 有效；上层只读需要的那几个槽。
7. 删除原先的回溯调用、其 V→S 同步与二次读；确认 set/wait 成对、无遗留事件。

## 6. LLM 前置问题

- 归约轴长与向量宽度之比是多少？每段元素数是否少到"跨 lane 归约链"成为主导？
- 现在的实现是否"先归约再回溯"？能否直接删掉回溯那一趟与它的同步？
- 并列的取值规则（首次/最后）与 NaN 规则是否明确？浮点域是否需要显式携带首个 NaN 位置？
- 尾段处理：是否用"固定块尾读"？越界 lane 是否已归一/收口？
- 位置载体放在哪个数值域？跨域时 `MIN` 归约是否仍单调（负下标不可用）？
- 归约只发布 lane 0 这一前提是否已在定案里用广播处理？

### 与相邻策略的关系

- "多行/多项批处理"负责摊薄**每项的固定开销**；本策略负责把**每个 tile 内的指令数**压到最低。
  两者叠加才有意义：只压指令数而不摊薄固定开销时，小项场景仍然受同步/描述符支配。
- "宽整数拆 32-bit 平面字典序比较"解决的是**比较域宽度**问题，与本策略正交，可同时使用。

## 检索卡（短卡）

动作：把分段跨 lane 归约求极值加获胜段回溯的两段式改为 lane 内运行态反向单趟扫描，每 tile 只做一次跨 lane 定案。
适用：需输出极值与其首次出现位置的归约，归约轴远长于向量宽度，指令数随元素线性增长成为瓶颈。
限制：跨 lane 归约只出 lane0 须先广播；尾段越界 lane 须归一或显式 And 尾 mask，否则越界位置会赢；并列取首现靠反向扫描加极性。
范围：带位置输出的极值归约（分段最值、逐行逐列最值）。
检索词：lane 扫描、反向扫描、跨 lane 归约、广播、UpdateMask、Select、NaN 自比较、首现位置。
机会：每段一次跨 lane 归约加一次获胜段回溯，向量发射饱和而单位元素吞吐低。
代价：定案与掩码逻辑变复杂，短归约轴上定案固定开销占比升高。
