# 性能优化策略：多核铺核（宏块任务分区 + 设备侧分组边界解码 + 分区粒度自适应）

> 单一优化点：分段/分组类算子若按「每个分组整块交给一个核」分配，分组数少于物理核数时大量核空转、大分组又被单核串行；改为把所有 (分组, 行块, 列块) 计算单元摊成全局逻辑序列、按启核数取模认领（round-robin 轮询），分组边界表在设备侧流式解码（主机只用形状算启核上界、不回读边界取值，零设备到主机同步）；并按「任务数是否铺满核」自适应选择分区粒度——任务数不足时沿列维补拆提并行，充足时退回粗粒度省跨核同步。
>
> **算子/管线无关性：** 适用于任何「按累计和边界分段、段大小运行时才可知、段内输出可按行/列切块」的多核算子（分组矩阵乘及其量化、门控点态融合变体，变长收集/散布类）。核心是「任务分区方式 + 边界解码位置 + 分区粒度判据」，不依赖具体算子、数据类型或核型组合。

---

## 1. 原理

先定义术语：

- **分组边界表**：一张单调非降的累计和表，第 i 项给出前 i+1 个分组的累计行数；相邻两项相等即空分组。它由输入数据决定，主机读它的取值必须先把数据搬回主机（设备到主机回读同步）。
- **行块 / 列块**：把一个分组的输出矩阵沿行、列两个方向按固定块尺寸切出的子块。
- **宏块**：一个分组内沿输出列方向切出的一条块列，即 (分组, 列块) 二元组；它跨该分组所有行块复用同一份右操作数列段。
- **启核数**：一次内核启动实际参与的逻辑核数。

基线按「分组」这一最粗粒度分配核：启核数 = min(物理核数, 分组数)。物理核数为分组数的数倍时，多数核全程空闲；单分组很大时又被整块塞给单核串行。

| 机制 | 利用方式 |
|---|---|
| 块级取模认领 | 任务粒度从「分组」细化到「(分组, 行块, 列块)」，全局逻辑序号对启核数取模等于本核号即认领；启核数升到 min(物理核数, 总块数上界)，激活核数贴近物理核 |
| 设备侧流式解码边界 | 边界表是数据依赖，主机读值要回读同步；改为核内逐分组读表差分行数，空分组在设备侧自然跳过，主机全程只用形状上界 |
| 启核数上界公式 | 上界 = (总行数上界 ÷ 行块高 + 分组数) × 列块数，与物理核数取小；只可高估（多启的核认领不到块、空转无害）不可低估（漏块） |
| 分区粒度自适应 | 行方向任务数不足核数时把列维纳入分区（块数成倍上升补并行）；行方向任务数已够时退回按行块的粗粒度、块内列方向串行，避免逐列块一次跨核同步信号使同步开销翻倍 |
| 列维分区的搬运红利 | 列维参与分区后每核只持有单个列块的右操作数列段，从「每核搬整条右操作数、同分组每个行块还重复搬」降到「每个列块被一个核搬一次」，右操作数总搬运量近似全量一遍 |

定性归因（相对基线）：剖析中实际参与计算的核数从分组数升到接近物理核数，矩阵核利用率指标显著抬升；单分组大形状的耗时不再随其规模近线性劣化。这是判断本策略是否对症的主判据。

## 2. 性能问题模式

低效基线：主机读边界表算分配（回读同步）+ 每核整包一个分组串行到底：

```python
# host（低效）：读边界表算块数，按分组数启核
group_rows = read_group_table()                    # ← 设备到主机回读，打断异步下发
core_count = min(physical_cores, group_count)      # 分组数 < 物理核数 → 核空闲
# device（低效）：每核串行处理一个分组的全部行块 × 列块
for group in range(core_count):
    for row_block in row_blocks(group):
        for col_block in col_blocks(cols):
            run_pipeline(group, row_block, col_block)   # 单核串行，其余核围观
```

开销源：

- **核空转**：物理核数减分组数个核全程空闲，矩阵核利用率极低。
- **单核串行大分组**：单分组行数 × 列数很大时，耗时近似线性堆在一个核上。
- **回读同步**：每次调用一次设备到主机拷贝，打断主机侧异步流水。
- **右操作数每核全量加载**（分组数越少越重）：每个核为它的分组加载整条右操作数，同分组每个行块还重复加载同一份。

典型症状：剖析显示参与核数 = 分组数、矩阵核利用率低；分组越少、单分组越大，与同形状库实现的差距越大。

## 3. 正确性红线

### 3.1 块唯一归属与空分组
每个 (分组, 行块, 列块) 恰好被一个核处理，不重不漏。空分组（行数为零）不产生块、**不推进全局块序号**，但**行边界的累计推进必须在跳过之前完成**，否则下一分组的起始行错位。启核数宁可高估：多启的核认领不到块自然退出，唯一要保证的是其参与的中转信号预置不阻塞活跃核。

### 3.2 取模相位的跨分组延续（最易翻车）
全局块序号跨分组连续递增。若不三层全展开、而按「每个分组一个局部窗口」实现，必须维护滚动相位：进入分组时相位 = 累计块数 mod 启核数，离开时把相位带往下一分组；本核在该分组内的首块定位与步进都必须以相位窗口为基准换算。相位算错的后果是漏块或重复块——某些块不算或算两遍，数值直接错。分组末尾相位必须再次取模，否则累计超过启核数后窗口语义崩塌。

### 3.3 混排形态下的核索引口径
矩阵核与向量核混排、且向量核一个物理核内含两条子块线程的形态下，向量核拿到的原始编号是子块粒度的线性展开值，必须除以每核子块线程数才能还原到矩阵核口径；两条向量线程与矩阵核必须算出**同一个**核号，否则矩阵侧产出与向量侧消费的中转槽错位——死锁或数值错。诊断指纹：单核验证通过、多核大面积错。

### 3.4 同核生产者/消费者认领一致
每核内有「矩阵核生产 → 中转槽 → 向量核消费」闭环时，两路对同一块集合必须执行**同一个**认领判定；一侧认领、另一侧跳过，中转信号计数失配即死锁。

### 3.5 列分区引入的跨核归约
列维参与分区后，同一行的不同列块散到不同核，任何逐行归约（逐行最大值、逐行缩放因子等）都无法在单核内完成，必须改为两阶段：阶段一各核写中间结果到全局内存并做全局同步；阶段二按行对启核数取模分配（与阶段一块分配解耦），跨列块归约。归约类指令的写回通常是异步的：消费其结果的紧邻向量指令前必须全排空；连续多次归约写不同目标时不得「攒着出循环再同步一次」（前几次写回会被共享的归约暂存覆盖丢失）。

### 3.6 分区粒度切换的槽位布局一致
粗/细两种粒度下每核中转槽数量与布局不同（粗粒度：每核多条槽对应块内串行的多个列块；细粒度：每核一条槽）。主机下发的环形缓冲总尺寸与设备侧布局推导必须两侧一致，否则跨核覆盖。粒度判据只用形状上界计算，不读边界取值。

### 3.7 已知陷阱
- 启核数固定写死物理核数，小块数场景空转核白付启动开销。
- 空分组忘了跳过仍推进块序号，后续所有块认领错位。
- 输出块之间存在写交叠（跨块归约、同行跨块累加）时未加全局同步就铺核，写竞争。

## 4. 泛化条件

适用（满足前两条即值得尝试）：

- 算子按累计和/偏移量表分段，段大小主机不可预知（数据依赖）。
- 基线按段分配核（启核数 = min(物理核数, 段数)）或固定启核数，多段/小块场景核空转明显。
- 段内输出可按行/列切块，总块数上界能达到物理核数。
- 每核具备独立的生产-消费闭环与中转缓冲，或纯矩阵核无跨核信号。

分区粒度判据（「分区该多细」的判别式）：

- 行方向任务数（分组数 × 行块数上界）< 物理核数 → 细粒度：列维纳入分区，块数 = 行块数 × 列块数，把核铺满。
- 行方向任务数 ≥ 物理核数 → 粗粒度：按行块（或宏块）分区，块内列方向串行；此时细粒度只会让跨核同步次数翻倍、无并行收益。

不适用 / 需退回（负向边界，可判定）：

- 分组数 ≥ 物理核数：分组轴已铺满，再切行列徒增同步，不适用。
- 段边界主机已知且静态（编译期或由形状直接推出）：直接主机预算块清单，设备解码是多余复杂度，不适用。
- 单块已占满单核片上缓冲（再切破坏分形对齐或爆缓冲）：不适用，块尺寸问题另议。
- 输出需跨块归约且无法承受两阶段全局同步的结构性代价：列维分区分支不适用（行维分区仍可）。
- 每核任务数恰为 1：粒度自适应退化为常量，无收益也无害。

## 5. 实施步骤

### 5.1 修改位置
- 主机侧（调度参数构造）：启核数 = max(1, min(物理核数, 总块数上界))；新增分区粒度二值字段，每核槽数与环形缓冲总尺寸随粒度一并下发。
- 设备侧（工作循环）：外层逐分组流式解码边界 → 块级取模认领 → 块内计算。
- 不改单块内的计算与数值语义、不改块尺寸常量。

### 5.2 语义伪代码（前/后对比）

```python
# 后（host）：只用形状上界，零回读
row_tiles = ceil(rows_upper / row_tile)
col_tiles = ceil(cols / col_tile)
fine = (groups * row_tiles) < physical_cores        # 行向任务不足 → 列维补拆
task_upper = row_tiles * col_tiles if fine else row_tiles
core_count = max(1, min(physical_cores, groups * task_upper))

# 后（device）：流式解码 + 全局序号取模认领
flat = 0
start_row = 0
for group in range(groups):
    end_row = read_group_end(group)                 # 设备侧读累计和表
    rows_here = end_row - start_row
    start_row = end_row                             # 空分组也必须先推进行边界
    if rows_here <= 0:
        continue                                    # 空分组不产块，flat 不动
    for row_block in row_blocks(rows_here):
        inner = col_tiles if fine else [none]       # 粗粒度块内串行列块
        for col_block in inner:
            mine = (flat % core_count) == core_id
            flat += 1
            if not mine:
                continue
            run_pipeline(group, row_block, col_block)
```

替代实现：不想三层全展开时，可按分组维护滚动相位窗口（见 3.2），两者语义等价。

### 5.3 退回路径（必须保留）
- 粒度字段允许写死粗或细，作为回退开关。
- 多启的核在设备侧认领不到块自然退出。
- 行/列尾块按有效行列数处理，认领逻辑不因尾块改变。

## 6. LLM 前置问题

应用本策略前，LLM 应回答：

1. 算子是否按累计和/偏移量表分段？基线启核数是否等于 min(物理核数, 分组数)？主机是否在读边界表取值（回读同步）？
2. 分组数与物理核数各是多少？单分组行数、列数各能切多少行块、列块？总块数上界能否达到物理核数？
3. 分区粒度判据：行方向任务数是否可能低于物理核数？（是 → 细粒度补并行；否 → 粗粒度，细粒度反而同步翻倍）
4. 混排形态下向量核原始编号是否需要除以每核子块线程数还原口径？矩阵核与向量核能否对齐同一核号？
5. 每核是否有独立生产-消费闭环？两路认领判定是否同源？
6. 列维分区后是否出现逐行跨块归约？若有，两阶段结构与全局同步是否已就位？
7. 输出块之间是否严格无写交叠？
8. 修改前的构建/精度/性能基线值；剖析中实际参与核数是多少？

第 1、2、4、5 项任一无法回答，不实施。

## 7. 验收标准

- **精度**：全部用例通过，必须覆盖空分组、行尾、列尾、单分组、分组数等于物理核数；不得出现任何新失败用例。
- **核激活**：剖析中实际参与计算的核数 = 新启核数（而非旧分组数）；矩阵核利用率显著抬升，接近同形状库实现水平。
- **规模曲线**：单分组大形状的耗时不再随规模近线性劣化（中大形状改善显著大于极小形状）。
- **零回读**：执行区间不再出现因读取边界表取值而引入的设备到主机拷贝。
- **粒度两分支都验**：细粒度与粗粒度路径精度都通过，且各自目标形状（行向任务不足 / 充足）方向性改善。
- **无死锁**：多块长任务流不超时；空转核提前退出不影响活跃核。
- **归因方法**：参与核数未升，说明分组数已达物理核数或行列不可再切，重新归因，不要继续调参。

## 检索卡（短卡）

动作：由主机回读边界并按整组分核，改为宏块任务分区并在设备侧解码分组边界
适用：按累计和或偏移量表分段，且段大小由数据决定、主机不可预知
限制：每个分组、行块、列块组合必须恰由一个核处理，不重不漏
范围：累计和或偏移量分段的分组类算子
检索词：分组边界表、宏块任务分区、设备侧边界解码、回读同步、多核铺核
机会：分组数少于物理核数导致核空转，同时大分组由单核串行处理
