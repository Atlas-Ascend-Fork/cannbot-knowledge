# 性能优化策略：向量核收尾段批量化（整块读写 + 整块类型转换 + 屏障塌缩 + 系数向量广播）

> 单一优化点：向量核收尾段（从中转槽读中间结果块、点态运算、类型转换、写回输出）若逐行循环——每行一笔小额搬运、逐行转换指令、逐行写回、每行多次流水屏障，再叠每行一次标量取值与整行重复广播——屏障与标量开销随行数线性堆积、向量流水无法跨行重叠；改为按行块批量：一笔整块读、逐行廉价点态、一笔整块转换、按行连续写回，屏障从每行数次塌缩到每块数次；行系数从「逐行标量取值 + 重复广播」改为「按行块向量加载 + 二维广播相乘」。
>
> **算子/管线无关性：** 适用于任何「从全局内存中转区读中间结果 + 行间无依赖的点态/缩放/转换 + 写回」的向量核收尾段：偏置加与类型转换、反量化、门控点态融合、逐行逐列双系数缩放等。核心是「搬运合并 + 指令合并 + 屏障塌缩 + 系数广播方式」，不依赖具体算子与数据类型。

---

## 1. 原理

先定义术语：

- **收尾段**：矩阵核产出之后由向量核执行的后处理（偏置、缩放、反量化、点态融合、类型转换及其组合）。
- **行块**：一次批量处理的连续若干行；行块大小受向量核片上缓存容量约束。
- **整块搬运**：一次搬运指令覆盖整个行块（二维：行数 × 行长），替代逐行小搬运。
- **二维广播**：按行的系数向量与行块相乘（每行乘同一份列系数、每列乘同一份行系数），替代逐行标量广播。

基线逐行循环时，每行付出：一笔碎读（入搬运）、若干逐行向量指令、一笔碎写（出搬运）、多次向量流水屏障。行数增多时屏障次数与标量开销线性爆炸，向量流水被切成行粒度的碎片，无法跨行重叠。

| 机制 | 利用方式 |
|---|---|
| 源连续 → 整块读 | 槽内行在全局内存连续（行步长等于行长）时，一笔二维整块读替代逐行多笔碎读 |
| 整块类型转换 | 整个行块一次转换指令，替代逐行转换 |
| 屏障塌缩 | 逐行每行多次向量流水屏障 → 每块数道（整块读后、点态后、转换后、尾部全排空） |
| 逐行点态保留 | 行间无依赖的点态（如加偏置）仍逐行下发——指令级无需屏障，远廉于搬运与屏障，不必强行向量化 |
| 系数向量广播 | 列系数按列一次加载、跨行广播（行间相同）；行系数按行块一次向量加载（含尾行截断）、与行块二维广播相乘——消除逐行标量取值与整行重复广播 |
| 队列式依赖管理 | 搬运 → 计算、计算 → 写回的流水依赖用多级队列出入队原语维护，不用裸缓冲加手动标志 |

定性归因（相对基线）：剖析中向量核标量/同步类管道耗时（屏障与标量取值堆积）显著下降；入搬运管道耗时（碎读）显著下降；计算管道密度上升。这是判断本策略是否对症的主判据。

## 2. 性能问题模式

低效基线的两种典型形态（常叠加出现）：

```python
# 前一：逐行读 + 逐行转换 + 逐行写 + 每行多次屏障
for row in range(valid_rows):
    copy_in(slot_row(row))                    # 一笔碎读
    add_bias(row)                             # 逐行点态
    convert_type(row)                         # 逐行转换
    copy_out(row)                             # 一笔碎写
    barrier(); barrier()                      # ← 每行两道，行数越多越爆炸

# 前二：逐行标量取值 + 整行重复广播（双系数缩放类收尾）
for row in range(valid_rows):
    factor = scalar_at(row_scales, row)       # ← 每行一次标量取值
    fill_row(factor)                          # ← 每行一次整行广播
    multiply_row(row, factor)
```

开销源：

- **屏障堆积**：每行多次流水屏障，行数乘屏障数为纯同步开销。
- **碎搬运**：逐行读写 payload 小，搬运带宽利用率低。
- **标量开销**：逐行标量取值与重复广播随行数线性增长。
- **流水碎片化**：逐行串行使向量流水无法跨行重叠。

典型症状：多核铺开、矩阵核已加速之后，向量核收尾段反成关键路径——标量/同步与入搬运管道耗时突出。

## 3. 正确性红线

### 3.1 整块读的行连续前提
槽内行在全局内存必须连续（行步长等于行长）才可零间隙整块读。行间有填充时必须按填充步长参数读，否则读错行；行完全不连续（散布布局）则整块读不成立，先聚拢或保留逐行。

### 3.2 搬运长度参数的单位与方向形态
不同搬运接口的块长参数单位不同（字节与元素两种口径），混用会只搬运几分之一数据、全错。且读方向（全局内存到片上）与写方向（片上到全局内存）的接口形态不同，不可互相照搬参数结构。

### 3.3 流水依赖不得省略，且须用队列原语管理（最易翻车）
整块读（搬运流水）→ 点态（向量流水）→ 写回（搬运流水）之间必须有同步：向量写未完成时写回流水读片上即读旧值。**用裸缓冲加手动跨流水标志管理这段依赖不可靠**——在含跨核交接信号的融合内核中排不正确「跨核槽写」与「本地读」的先后序，会读到无效值。存在跨核交接的内核一律用多级队列出入队原语（其内部正确处理流水依赖）；纯单核向量的手动标志写法不可照搬进融合内核。

### 3.4 整块转换的对齐
整块转换指令的长度须满足向量对齐要求。行数非对齐倍数时长度补齐到块边界，尾部补出的垃圾元素由有效列写回截断，不得写出界。

### 3.5 系数乘法顺序与舍入模式
多组系数（列系数 × 行系数）不得预乘合并成一个系数——两步乘法（先列后行）与参考实现的数值序一致，预合并在宽精度累加结果上数值不等价，精度回归。输出类型转换的舍入模式（就近舍入与截断）必须与参考一致。

### 3.6 尾处理
- 行系数尾行不越界：行块覆盖到行尾时按 min(行块高, 剩余有效行) 读系数向量。
- 写回按有效列字节数，不按对齐宽写，否则污染相邻块。

### 3.7 行块容量
行块高 × 列数 × 最宽参与类型的大小不超过向量核片上缓存，并与消费队列深度协调；装不下整块时分块批量，仍远少于逐行屏障。

### 3.8 已知陷阱
- 搬运块长单位按元素填（实际按字节）→ 只读几分之一，全错。
- 手动跨流水标志管理读缓冲 → 融合内核读到无效值。
- 行系数按行块高读满（未按有效行截断）→ 尾行越界。
- 写回按对齐宽而非有效列宽 → 污染相邻块。
- 预合并两组系数 → 精度回归。

## 4. 泛化条件

适用：

- 收尾段从全局内存中转区读中间结果、做行间无依赖的点态/缩放/转换、写回输出。
- 中间结果行在全局内存连续，可整块读。
- 基线为逐行循环（逐行搬运/转换/屏障，或逐行标量取值广播）。

不适用 / 需保守（负向边界，可判定）：

- 行不连续（散布布局）：整块读不成立；先聚拢成连续或保留逐行（转换与写回仍可对连续段批量）。
- 行间有依赖（后行依赖前行结果）：整块转换不成立，须逐行。
- 收尾段已被高阶接口内部融合、无法拆出行循环：无从下手。
- 行数极小（一两行）：批量化无收益，徒增复杂度。
- 片上缓存装不下任何有意义行块：分块批量后收益仍存，但须评估。

## 5. 实施步骤

### 5.1 修改位置
- 收尾段主循环：逐行循环改为行块循环；行块高按片上容量与对齐反推。
- 搬运：整块二维读（按行数 × 行长，注意行步长参数）；写回按行连续、按有效列字节。
- 依赖管理：读缓冲与写缓冲挂入队/出队式队列；不用裸缓冲加手动标志。
- 系数：列系数按列一次加载跨行广播；行系数按行块向量加载（尾行截断）二维广播。
- 不改矩阵核侧、不改中转信号机制、不改乘法顺序与舍入模式。

### 5.2 语义伪代码（前/后对比）

```python
# 后：整块读 + 逐行廉价点态 + 整块转换 + 连续写（屏障塌缩到每块数道）
for block in row_blocks(valid_rows, block_rows):
    copy_in_block(slot, block)                     # 一笔二维整块读
    for row in block:                              # 逐行点态，无屏障
        add_bias(row)
    convert_type_block(block)                      # 一笔整块转换
    copy_out_block(block, valid_cols)              # 按有效列写回
    drain_tail()                                   # 每块尾部一次全排空

# 后：双系数缩放的系数向量广播（乘法两步序不变）
for block in row_blocks(valid_rows, block_rows):
    copy_in_block(slot, block)
    col_scales_bcast()                             # 列系数按列广播，跨行相同
    row_vec = load_vector(row_scales, block)       # 行系数按行块向量加载，尾行截断
    multiply_block(block, row_vec)                 # 二维广播乘（先列后行两步序不变）
    convert_type_block(block)
    copy_out_block(block, valid_cols)
```

### 5.3 退回路径（必须保留）
- 片上装不下整块 → 缩小行块高分块批量（屏障仍远少于逐行）。
- 行不连续 → 读退逐行，转换与写回仍对连续段批量。

## 6. LLM 前置问题

应用本策略前，LLM 应回答：

1. 收尾段结构：是否为「读中间结果 + 行间无依赖点态/转换 + 写回」？基线是否逐行循环？
2. 中间结果行在全局内存是否连续（行步长等于行长）？有无填充？
3. 行间是否有依赖？行数分布如何（极小行数用例多不多）？
4. 有几组系数？乘法顺序能否改动？输出类型转换的舍入模式是什么？
5. 基线是否含逐行标量取值与重复广播？
6. 向量核片上缓存容量（按目标芯片硬件表取）与行块高、列数、最宽类型的预算关系？
7. 所在内核是否含跨核交接信号体系？（是 → 依赖管理必须用队列原语）
8. 行尾、列尾如何处理？写回按有效列还是对齐宽？
9. 修改前的构建/精度/性能基线值；向量核各管道耗时分布？

第 1、2、6 项任一无法回答，不实施。

## 7. 验收标准

- **精度**：全部用例通过；整块转换与逐行转换在同舍入模式下位等价；系数保持两步乘法序；必须覆盖单行、满行块、多行块、行尾（有效行非块高倍数）、列尾（有效列小于对齐宽）、多种输出类型。
- **性能方向**：向量核标量/同步类管道耗时显著下降（屏障塌缩、标量取值消除）；入搬运管道耗时显著下降（碎读合并）；计算管道密度上升。判据：标量与搬运双降，收尾段不再是关键路径（与矩阵核活跃时段对比）；若未降，说明收尾段非瓶颈或已带宽受限，重新归因。
- **依赖正确**：读 → 计算 → 写回各环节同步完整，无旧值/无效值消费。
- **不越界**：行系数尾行截断、写回有效列字节，相邻块无污染。
- **归因方法**：用剖析工具分别看向量核标量、搬运、计算三条管道的耗时变化，而非只看总耗时。

## 检索卡（短卡）

动作：将收尾段逐行循环改为行块循环，批量二维读写并整块完成点态运算与类型转换。
适用：收尾段处理行间无依赖的点态、缩放或转换，且中间结果行连续可整块读。
限制：零间隙整块读要求槽内行连续，行步长等于行长。
范围：矩阵核产出后的向量核后处理与输出写回
检索词：向量核收尾段、行块、整块搬运、二维读、类型转换、行步长
机会：收尾段主循环仍按行执行搬运、转换和写回。
代价：行块大小受向量核片上缓存容量约束。
