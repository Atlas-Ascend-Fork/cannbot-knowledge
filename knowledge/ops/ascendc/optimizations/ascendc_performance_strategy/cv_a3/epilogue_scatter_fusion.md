# 性能优化策略：scatter 宽度与 cube 内部 tile 宽度解耦（相邻列块融合 handoff slot）

> 单一优化点：在「cube 矩阵乘 → 向量核反量化/缩放 → 逐行 scatter 写出」的融合管线里，把相邻的输出列块融合成一个更宽的 cube 到向量核 handoff slot（cube 内部仍按原窄宽度做矩阵乘，cube 私有缓冲不变），向量核读更宽的 slot，对整行做单次反量化加单次逐行 scatter，把逐行 scatter 操作数减半（或更多），且不增加 cube 缓冲压力。
>
> **算子/管线无关性：** 适用于任意「矩阵计算单元产出中间结果 → 向量核 epilogue 反量化/缩放 → 逐行 scatter-add 写出到输出」的融合内核，不限具体算子。前提：向量核标量开销由逐行 scatter 操作数主导、cube 与向量核共享列块宽、输出列方向块数较多。

**术语**：

- **handoff slot**：cube 把矩阵乘结果交给向量核的中转缓冲槽，每行容纳若干列的中间结果；本策略只加宽它。
- **列块宽（W）**：cube 单次矩阵乘覆盖的输出列数，也是基线里 handoff slot 的行内宽度。
- **scatter-add**：按行索引把一行数据累加进输出矩阵对应行的操作；单次 scatter 覆盖的列越宽，标量开销越低。

---

## 1. 原理

向量核侧的标量开销常由**逐行 scatter 操作数**主导：scatter 操作数 ≈ 行数 × 输出列方向块数（总列数 ÷ 列块宽）。

cube 与向量核通常**共享同一个列块宽**。想减少 scatter 操作数（加宽每次 scatter 的列），直观做法是加宽这个共享宽度——但它同时是 cube 单次矩阵乘的宽度，加宽会直接撑爆 cube 私有缓冲（矩阵乘操作数缓冲/累加缓冲），或迫使行块高减半、cube 块数翻倍、cube 标量开销上涨。向量核省下的时间被 cube 多花的时间吃掉，端到端反而恶化。

**解耦**：cube 内部矩阵乘仍用原窄宽度（私有缓冲不变），只把**相邻两段输出列块的结果回写到同一个两倍宽的 handoff slot** 的左半/右半（slot 行步长 = 2W）。块分配改为每个处理块拥有一个「列对」，总块数减半，cube 总矩阵乘次数不变。向量核读更宽的 slot：把两段的缩放系数拼成单个全宽系数向量，对整行做**单次**反量化加**单次**逐行 scatter 写整行 → scatter 操作数减半，cube 开销不变。

| 机制 | 利用方式 |
|---|---|
| handoff slot 加宽（两倍） | 相邻列块结果写进同一 slot 的 [0:W] 与 [W:2W]，slot 行步长 2W |
| 列对分配 | 每个处理块拥有相邻列对，总块数减半，cube 总矩阵乘次数不变 |
| 单次反量化加单次 scatter | 向量核读两倍宽 slot，拼接缩放系数后单次全宽反量化加单次全宽 scatter，操作数减半 |

定性归因（相对基线）：向量核**标量开销**大幅下降（scatter 操作数减半）；cube **标量/乘加开销**基本不变（解耦达成，未把开销转嫁给 cube）；向量核搬运/向量计算开销略降或持平。这是判断本策略是否对症的关键判据。

## 2. 性能问题模式

低效基线：cube 与向量核共享列块宽，向量核逐窄块加载 → 逐行反量化 → 逐行窄宽 scatter：

```text
# 基线：向量核逐窄列块（宽 W）反量化 + 逐行 scatter
对每个归属列块 c:
  对每个归约块: 矩阵乘(宽 W) 累加到私有累加缓冲
  结果回写 slot[:, 0:W] <- 累加缓冲              # slot 行步长 = W
  对每个归属行:
    反量化(该行, scale[c])                        # 窄行反量化
    scatter_add(out[目标行, c*W:(c+1)*W], 该行)    # 逐行窄宽 scatter
```

开销源：

- **scatter 操作数 = 行数 ×（总列数 ÷ W）**：每行一次窄宽 scatter，标量索引/地址计算逐行重复；总列数大、列块窄时操作数可达数千至数万。
- **cube 与向量核宽度耦合**：想加宽共享列块宽 → cube 私有缓冲溢出，或行块高被迫减半、cube 块数翻倍 → cube 开销上涨。

典型症状：profiling 显示向量核侧标量开销主导（且随总列数/行数增长），cube 侧标量/乘加开销正常；曾尝试加宽共享列块宽时端到端反而恶化（耦合证据）。

## 3. 正确性红线

### 3.1 反量化要求 dense 行主序源（最易翻车）

向量核反量化原语通常要求 dense、行主序的源数据。**禁止**把更宽的 slot 拆成两段、按列偏移分别反量化——第二段源会**跨行读取**导致精度错误（实测曾大面积精度失败）。**必须**把两段的逐通道缩放系数拼成单个全宽系数向量，对 dense 全宽源做**单次**反量化。

### 3.2 slot 布局精确

相邻两段结果分别写到 slot 的 [0:W] 与 [W:2W]，slot 行步长 = 2W；向量核按此步长读，不能错位。

### 3.3 列对分配一致

cube 与向量核必须用同一套「列对」分配（同一处理块拥有同一列对的两段），否则 handoff slot 错配（数据错位）。

### 3.4 cube 总矩阵乘次数不变

融合只改 handoff slot 宽度与分配，**不改 cube 内部单次矩阵乘宽度与总次数**——这是与「直接加宽共享列块宽」的关键区别，后者会触发 cube 缓冲/块数问题。

### 3.5 向量核片上缓冲配平

向量核 slot 变宽两倍，需把向量核行批大小减半，使各输入/输出/广播缓冲不超片上容量（缓冲按 行批 × 宽度 估算）。

### 3.6 尾列对处理

总列数不被 2W 整除时，最后一个列对可能只有一段，需按有效宽度处理（掩码/填充），不污染结果。

### 3.7 已知陷阱

- **拆两段分别反量化**（头号陷阱）：按列偏移把宽 slot 拆两段分别反量化 → 第二段跨行读 → 精度错误。修复：拼接缩放系数，单次全宽反量化。
- **slot 行步长错**：行步长仍用 W（原宽）而非 2W → 两段重叠/错位。修复：行步长 = 2W。
- **列对分配错配**：cube 与向量核用不同列对分配 → 数据错位。修复：统一列对分配。
- **误改 cube 单次矩阵乘宽**：真加宽了共享列块宽 → cube 私有缓冲溢出或行块高减半、块数翻倍 → cube 开销涨、端到端恶化。修复：cube 内部宽 W 不变，只加宽 slot。
- **向量核缓冲溢出**：行批未减半配平 → 宽 slot 撑爆片上缓冲。修复：行批减半。
- **尾列对污染**：总列数不被 2W 整除时未处理尾列对 → 越界/污染结果。修复：尾列对按有效宽度掩码/填充。

## 4. 泛化条件

必须**同时**满足：

| 条件 | 要求 |
|---|---|
| scatter 形态 | 融合 cube→向量核，向量核侧有逐行 scatter-add epilogue，其标量开销由 scatter 操作数主导 |
| 共享切分 | cube 与向量核共享列块宽，加宽它会触发 cube 缓冲/块数问题 |
| 列块数 | 输出列方向块数较多（总列数大、列块窄 → scatter 操作数大） |
| 绑定极 | 向量核侧是端到端的绑定瓶颈（或之一） |
| 基线稳定 | 修改前构建/精度/性能基线可重复 |

优先适用：总列数大加列块窄 → scatter 操作数大；profiling 显示向量核标量开销高、cube 标量/乘加正常；加宽共享列块宽曾使端到端恶化（耦合证据）。

不适用或需先重构（负向边界）：

- 向量核标量开销不由 scatter 操作数主导（已由带宽/搬运主导）。
- 输出列方向块数已很少（scatter 操作数本就不多，收益小）。
- 无逐行 scatter 的纯矩阵乘（epilogue 无 scatter）。
- cube 侧是唯一绑定瓶颈且向量核大量空闲（解耦收益不显现）。

## 5. 实施步骤

### 5.1 修改位置

| 位置 | 修改 |
|---|---|
| cube 侧 | 每个处理块拥有相邻列对；仍按原宽逐段矩阵乘，两段结果回写到同一更宽 slot 的 [0:W] 与 [W:2W]（slot 行步长 2W）；总块数减半，cube 总矩阵乘次数不变 |
| 块分配 | cube 与向量核统一用「列对」分配 |
| 向量核侧 | 读更宽 slot；拼接两段缩放系数成单个全宽向量，对 dense 全宽源单次反量化；逐行 scatter 写整行（2W 宽，单次） |
| 向量核行批 | 减半配平片上缓冲 |
| host 侧 | 中转区尺寸按新 slot 宽度（行块 × 2W）重算 |
| 计算算法 / dtype / scatter 语义 | **不改**（仍逐行原子累加） |

### 5.2 数据流（前/后对比）

```text
# cube 侧：内部列块宽 W 不变，handoff slot 宽 = 2W
对每个归属列对 (c, c+1):
  对每个归约块:
    矩阵乘(宽 W) 累加 local[c]
    矩阵乘(宽 W) 累加 local[c+1]                # cube 私有缓冲不变
  结果回写 slot[:, 0:W]  <- local[c]             # slot 行步长 = 2W
  结果回写 slot[:, W:2W] <- local[c+1]

# 向量核侧：单次反量化 + 单次 scatter，行批减半配平
scale_full = 拼接(scale[c], scale[c+1])           # 全宽缩放系数
对每个归属行:
  dequant_row = 单次反量化(slot 该行, scale_full)   # dense 全宽，禁拆两段
  scatter_add(out[目标行, 0:2W], dequant_row)      # 单次 2W 宽
```

> **通用性说明**：上文以「两倍宽 / 列对」为例。泛化后即「把若干相邻列块融合成 M 倍宽 handoff slot」（M ≥ 2，M 与块数按片上缓冲配平），M=2 是常用最小情况。核心不变：**cube 内部窄宽矩阵乘 + 更宽 slot + 向量核单次反量化/scatter**。

### 5.3 实施顺序

1. 引入独立的向量核 handoff 宽度（= 2 × cube 列块宽），cube 内部矩阵乘宽不变。
2. 改 cube：列对归属；两段结果回写到同一 slot 的 [0:W] 与 [W:2W]。
3. 改块分配：cube 与向量核统一列对。
4. 改向量核：拼接缩放系数，单次全宽反量化加单次全宽 scatter。
5. 向量核行批减半，配平片上缓冲。
6. host 侧中转区按新 slot 宽重算。
7. 不改 scatter 语义（仍逐行原子累加）、不改 dtype、不改 cube 单次矩阵乘宽。

## 7. 验收标准

精度：与基线一致（本策略精度中性，只改 slot 宽度与分配）；不得出现任何新失败用例。若精度失败，按单一原因排查：拆段反量化 / slot 步长 / 分配错配 / 尾列对。

性能（用 profiling 归因，方向性判据）：

- 向量核**标量开销显著下降**（scatter 操作数减半）。
- cube **标量/乘加开销基本不变**——关键判据：证明收益来自 scatter 数减半，而非 cube 改动。
- 若向量核标量未降 → 向量核非 scatter 主导（重新归因）；若 cube 标量上涨 → 误改了 cube 单次矩阵乘宽（见 3.7 第 4 条陷阱）。

边界 shape（必测）：

- 总列数被 2W 整除（无尾列对）与不整除（尾列对路径）。
- 总列数小（scatter 操作数本就少，收益小——验证不误伤）。
- 大行数（scatter 操作数大，收益大）。
- 不同 dtype / 行宽组合。

回退或缩小条件：向量核标量未降、或 cube 开销上涨、或精度失败无法定位到单一原因、或 cube 是唯一绑定瓶颈（收益不显现）。

与其它策略的关系：只改 handoff slot 宽度与向量核 epilogue，不改多核负载划分、操作数复用、搬运调度，互不冲突，可叠加。
