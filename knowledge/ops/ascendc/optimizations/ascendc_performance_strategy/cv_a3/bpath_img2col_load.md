# 性能优化策略：右矩阵 img2col 类单指令加载（替代归约维窄分形循环）

> 单一优化点：矩阵计算单元侧右矩阵 B 的"片上缓冲→计算单元私有缓冲"加载，若当前是沿归约维的窄宽度分形循环（每个分形块发一条窄宽度转置加载指令，共"归约维长度÷分形边长"条），改成一次 img2col 类单指令搬运整个分形面，把 B 路加载指令数从"归约维分形块数"降到 1。
>
> **算子/管线无关性：** 适用于任意"右矩阵 B 从片上缓冲沿归约维分形循环加载进矩阵计算单元"的矩阵乘/分组矩阵乘/GEMM 管线，不限算子。前提：芯片支持 img2col 类单指令加载、B 在片上是标准 NZ 分形布局、归约维分形块数 ≥ 4。

---

## 1. 原理

术语（先定义后用）：

- **img2col 类单指令搬运**：硬件级 image-to-column 加载指令——一条指令把片上缓冲中的一个二维块搬入矩阵计算单元私有缓冲，并顺带完成布局适配。
- **分形边长**：NZ 分形布局最小分形的边长，随 dtype 与芯片而定。"归约维分形块数 = 归约维长度 ÷ 分形边长"。
- **分形描述寄存器**：img2col 指令读取的输入空间形状描述（空间维、通道维、填充），设置一次供后续指令复用。
- **NZ 分形布局**：矩阵按固定边长的分形重排后存放的片上布局，是矩阵计算单元要求的输入形态。

右矩阵 B[归约维 K × 列 N] 从片上缓冲加载进计算单元私有缓冲，若 K 较深（归约维分形块数达几十），窄宽度转置加载需沿 K 每个分形块一条指令，加载指令数随 K 线性增长。

img2col 类单指令**一次搬整个 [K 一段 × N 一段]**，把 B 路加载指令数从"K÷分形边长"降到 1，总搬运字节不变。

| 机制 | 利用方式 |
|---|---|
| img2col 单指令 | 一次搬 [K 段 × N 段]，指令数从 K÷分形边长 → 1 |
| 分形描述寄存器 | 配置 img2col 的空间描述（空间维 + 通道维 + 填充），设一次供后续指令用 |
| 标准 NZ 布局 | B 的片上副本须是 ND→NZ 布局转换产生的标准 NZ，归约维方向分形步进 = K 段长度 |

**关键：img2col 的输入空间映射。** 右矩阵 B[K,N] 视作输入特征图时：**空间维 = K（归约维），通道维 = N（列维）**，即"高度=K 段、宽度=1"。这是最容易配错的地方（第 3 节反模式一）。

定性流水归因（相对）：B 路加载流水时间大幅下降（指令数锐减）；矩阵计算时间不变（未改计算量）；标量时间略降（循环簿记消失）。"加载流水降 + 计算不变"是判断本策略是否对症的关键判据。

## 2. 性能问题模式

低效基线对 B 路"片上→计算单元私有缓冲"用归约维分形循环：

```text
# 基线：沿归约维每个分形块一条窄宽度转置加载
for step in range(reduce_len // fractal_len):      # 归约维分形块数，深 K 时达几十
    load_narrow_fractal(private_area[step * row_pitch],
                        on_chip_area[step * block_pitch])
```

归约维深 + 分形边长小 → 分形块数大，开销源：

- **加载指令数 × 分形块数**：每条转置加载有发射/完成固定开销，指令多 → 该搬运流水时间线性涨。
- **循环簿记**：分形块数次的地址/参数计算（标量开销）。

典型症状：profiling 显示片上→计算单元的搬运流水占比偏高且随 K 增大；矩阵计算时间正常（计算量未到瓶颈）。

## 3. 正确性红线

### 3.1 img2col 空间方向 = 归约维（头号陷阱）
分形描述寄存器必须按"空间维 = K 段、宽度 = 1"（即空间维=归约维、通道维=列维）配置。**禁止**配成"空间维 = 1、宽度 = K 段"——空间方向搞反会按错维读取，数据整体错乱，误差极大（全量用例崩）。

### 3.2 img2col 参数对齐
通道维 = 对齐后列宽；空间延展 = 对齐后 K 段长度；列延展 = 对齐后列宽；分形描述寄存器配在**右矩阵**一侧（非左矩阵）。对齐单位按 dtype 对应的分形边长查芯片手册，不同 dtype 边长不同。

### 3.3 B 的片上副本须是标准 NZ
须由 ND→NZ 布局转换产生，且归约维方向分形步进 = K 段长度。非标准布局先单独验证（img2col 按标准 NZ 读取，布局不符会错位）。

### 3.4 分形描述寄存器每宏块设一次即可
K 段长度全局不变；重复设置无害但浪费标量。若该寄存器会被其他路径覆写（如左矩阵侧交替使用），须在每次 img2col 前重设。

### 3.5 不改计算语义
乘加参数（m/n/k）、私有缓冲总数据量、dtype 全不变。唯一变化：B 路加载指令从"分形块数"条 → 1 条。

### 3.6 反模式清单（实战级）
- **反模式一（空间方向搞反）**：空间维=1、通道维=K → img2col 按错维读 → 数据全错、误差极大、全量用例崩。修复：严格"空间维=K 段、宽度=1"。
- **反模式二（参数对齐错）**：通道/空间延展/列延展未按芯片分形边长对齐，或空间延展与列延展弄反 → 读错尺寸/错位。修复：通道=列宽对齐、空间延展=K 段对齐、列延展=列宽对齐。
- **反模式三（描述寄存器配错侧）**：配到左矩阵一侧 → img2col 用错空间描述。修复：描述寄存器只配右矩阵。
- **反模式四（片上 B 非标准 NZ）**：布局转换的分形步进不等于 K 段长度 → img2col 读错位。修复：先验证布局转换参数。
- **反模式五（描述寄存器被覆写）**：循环内被其他路径覆写而未重设 → 偶发错位。修复：设一次 + 确认无覆写，或每次 img2col 前重设。

## 4. 泛化条件

必须**同时**满足：

| 条件 | 要求 |
|---|---|
| B 路形态 | 片上→计算单元私有缓冲是归约维窄宽度转置加载循环（第 2 节模式） |
| 归约维深度 | 归约维分形块数 ≥ 4（循环开销显著，否则收益小） |
| 芯片 | 支持 img2col 类单指令加载（查芯片手册；仅支持普通二维加载的芯片不可用） |
| B 布局 | 片上 B 是标准 NZ（ND→NZ 转换产生，归约维分形步进 = K 段长度） |
| 基线稳定 | 修改前构建/精度/性能可重复 |

优先适用：归约维深（分形块数更多）；profiling 显示该搬运流水主导矩阵核侧、矩阵计算未到瓶颈。

不适用或需先重构：B 路已是 img2col 单指令（无循环）；K 很浅（分形块数 ≤ 1）；芯片不支持 img2col 类加载；片上 B 非标准 NZ（需先转布局，可能不划算）。

## 5. 实施步骤

### 5.1 修改位置

| 位置 | 修改 |
|---|---|
| B 路"片上→私有缓冲"加载处 | 把分形循环替换为一次 img2col 类单指令（5.2 骨架） |
| 每宏块/分块开始处 | 配一次右矩阵的分形描述寄存器（空间维=K 段、宽度=1、无填充） |
| 乘加调用 / 私有缓冲分配 / host 侧 | **不改**（计算语义、缓冲、切分零改动） |

### 5.2 数据与参数骨架

```text
# ① 每宏块开始：配右矩阵分形描述，空间维=K（归约维），通道维=N（列维）
set_fractal_map(space=reduce_span, width=one, padding=none)   # 高度=K 段、宽度=1

# ② B 路（片上 NZ → 计算单元私有缓冲）：一次 img2col 类单指令替代分形循环
img_block_load(private_area[0], on_chip_area[0],
               channel=aligned_cols,      # 通道维 = 列宽（对齐后）
               m_ext=aligned_reduce,      # 空间延展 = K 段（对齐后）
               k_ext=aligned_cols,        # 列延展 = 列宽（对齐后）
               use_fractal_map=yes)       # 读分形描述寄存器
```

实施顺序：

1. 确认芯片支持 img2col 类加载 + 片上 B 是标准 NZ（归约维分形步进 = K 段长度）。
2. 用单指令替代分形循环（搬运量/计算量与循环相同 → 性能收益真实）。
3. 每宏块配一次分形描述寄存器（空间维=K 段、宽度=1）。
4. **性能先行验证**：先测性能（有收益——该搬运流水时间下降——才继续），再修精度。
5. 精度修复：若崩，按顺序查空间方向（反模式一）→ 参数对齐（反模式二）→ 描述寄存器侧（反模式三）。

## 7. 验收标准

精度：与基线一致（本策略精度中性，只改加载指令形态，不改数据与计算）。不得出现任何新失败用例。

性能（用 profiling 归因，相对）：

- B 路"片上→私有缓冲"搬运流水时间显著下降（指令数从分形块数降到 1）。
- 矩阵计算时间不变——这是关键：证明收益来自加载指令数减少，不是计算变了。
- 标量时间持平或略降。
- **判据**：搬运流水降 + 计算不变。若搬运流水未降，说明 B 路非瓶颈或已带宽受限，重新归因。

边界形状（必测）：归约维分形块数取多档（验证收益随深度增长）；列宽不同对齐档（验证通道/列延展对齐）；K 不整除分形边长的尾块（验证空间延展对齐与尾处理）；不同 dtype（分形边长不同 → 对齐单位不同）。

回退或缩小策略的条件：该搬运流水时间未降（重新归因）；矩阵计算时间变化（改了计算量，非本策略）；精度失败且无法定位到空间方向/参数对齐/寄存器侧的单一原因；芯片不支持 img2col 类加载。

与其它策略的关系：只改 B 路加载指令形态，与权重片上复用、多核切分、反量化收尾优化等互不冲突，可叠加。
