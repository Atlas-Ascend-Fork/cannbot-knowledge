# 性能优化策略：bias 进矩阵乘累加器初始值（消除收尾加法与中间缓冲中转）

> 单一优化点：带加性偏置（bias）的矩阵乘融合 kernel，bias 原本在向量核收尾段里加（矩阵计算单元把浮点累加结果写全局内存中间缓冲 → 向量核读回 + 加 bias + 类型转换 + 写回输出），多一次中间缓冲中转开销与一段向量核加法。改为把 bias 经「全局内存→片上→累加器 bias 表」两级搬运（顺带完成布局转换与类型转换）后，作为矩阵乘**累加器的初始值**进入首轮乘加（累加器不清零、初值来源切到 bias 表），后续轮正常累加；向量核收尾段只剩类型转换。
>
> **算子/管线无关性：** 适用于任意「矩阵乘 + 逐列加性偏置」的融合 kernel，只要芯片支持把 bias 表作为累加器初值。核心动作是两级搬运 + 初值切换 + 跨流水同步，不限于任何具体算子形态。

---

## 1. 原理

术语（先定义后用）：

- **bias 表**：矩阵计算单元内供乘加指令读取累加器初值的专用缓冲，是两级搬运的目的端。
- **收尾段（epilogue）**：矩阵乘主体之后在向量核上做的收尾处理（加偏置、类型转换、写回）。
- **中间缓冲（workspace）**：矩阵计算单元与向量核之间经全局内存交接的缓冲，是本策略要压缩的中转环节。
- **跨流水事件同步原语**：指明「源流水线 → 目的流水线」的轻量同步。区别于**同流水 barrier**：只保证单条流水线内部有序，对跨流水依赖不生效。

| 机制 | 利用方式 |
|---|---|
| 累加器初值可配置 | 首轮乘加的累加器不取零而取 bias 表内容，bias 加法变成乘加流水的一部分 |
| 两级搬运顺带转换 | 全局内存→片上顺带做 ND→NZ 布局转换；片上→bias 表顺带做类型转换（偏置 dtype → 累加 dtype） |
| 压缩中间缓冲路径 | 矩阵计算单元直接产出「已含 bias」的累加结果，向量核收尾段只剩类型转换 |

数学形态：首轮「C = bias + A·B 首段」，后续轮照常累加——与「先乘完再加 bias」在加法交换意义下等价（浮点下舍入次序有差异，验收时须与基线比对）。

实测结论（泛化）：bias 加法被乘加流水**完全吸收**——含 bias 用例与无 bias 用例耗时持平，零新增计算段；dtype 组合不支持时分流回收尾段，精度不受损。

## 2. 性能问题模式

低效基线：bias 在向量核收尾段加：

```text
# 基线：矩阵计算单元写中间缓冲，向量核收尾段加 bias + 类型转换
mm_block(..., middle_store)                  # 浮点累加结果（不含 bias）写全局内存中间缓冲
vec_epilogue(middle_store, global_bias, out)  # 向量核：读回 + 加 bias + 类型转换 + 写回
```

开销源：

- **中间缓冲一写一读**：浮点结果经全局内存往返，流量与延迟双开销。
- **向量核多一段加法**：收尾段除类型转换外还要逐元素加 bias，拉长向量核关键路径。
- 症状：profiling 中向量核收尾段占比可观；全局内存流量含中间缓冲往返。

## 3. 正确性红线

### 3.1 正确路径五环节（缺一不可）

1. **全局内存 → 片上（布局转换）**：bias 搬运要做 ND→NZ 布局转换，必须用支持布局转换的搬运原语。某「带 padding 的拷贝原语」在矩阵核路径上对「全局内存 → 片上」不生效——不报错，但后续读到的是垃圾。
2. **跨流水事件同步（第一次）**：「布局转换搬运完成 → 片上拷贝开始」的先后依赖必须用跨流水事件同步原语表达（搬运流水到搬运流水）。
3. **片上 → bias 表（类型转换搬运）**：这条搬运顺带类型转换；其搬运长度的单位是 **64 字节块**——不是元素个数，也不是常规对齐字节，要按「偏置字节数向上取整到 64 字节块」来传。
4. **跨流水事件同步（第二次）**：「bias 表写入完成 → 首轮乘加读 bias 表」的依赖同样必须跨流水事件同步（搬运流水到计算流水）。
5. **首轮乘加的初值语义（最易翻车点）**：首轮乘加必须**关掉「累加器清零」语义**，并把初值来源切到 bias 表。若保留清零语义，bias 初值被清掉，结果 = 纯乘积无 bias——症状是误差恰好等于 bias，输出形态看似正常，最易漏判。

### 3.2 dtype 组合分流（硬约束）
「片上 → bias 表顺带类型转换」支持的源/目的 dtype 组合按芯片查证——实测有的芯片支持半精度→浮点、却不支持 bf16→浮点。不支持的组合必须**整体分流**回收尾段加 bias，不能换个转换方式硬凑。

### 3.3 同流水 barrier 对跨流水不生效（最致命坑）
两次跨流水依赖都不能换成同流水 barrier：barrier 只约束单条流水线内部顺序，跨流水依赖必须用跨流水事件同步原语（或等价的队列机制）表达。误用 barrier 的典型症状是矩阵核读到垃圾（误差达数据量级）。全量排空虽能兜底但代价过大，不作为方案。

### 3.4 bias 表缓冲必须正规分配
bias 表缓冲要用正规的缓冲对象并做容量初始化（按芯片 bias 表容量），不要手工拼裸地址——裸地址形式下搬运长度与同步行为都不可靠。

## 4. 泛化条件

适用（须同时满足）：

| 条件 | 要求 |
|---|---|
| 偏置形态 | 逐列偏置向量（输出的每一列加同一个标量），非逐元素偏置矩阵 |
| 芯片支持 | 累加器初值可来自 bias 表，且偏置 dtype → 累加 dtype 的转换组合在芯片支持列表内 |
| 瓶颈归因 | 基线瓶颈确含「中间缓冲中转 + 收尾段加法」（profiling 佐证） |
| 基线稳定 | 修改前构建/精度/性能可重复 |

三分支互斥（与「结果随路转换直出」策略的关系，按输出路径整体决策）：

| 分支 | 条件 | 走法 |
|---|---|---|
| 一 | 无 bias | 走「结果随路转换直出」：回写流水直接产出目标类型，向量核不参与 |
| 二 | 有 bias 且 dtype 组合支持 | **本策略**：bias 进累加器初值 + 向量核只做类型转换 |
| 三 | 有 bias 但 dtype 组合不支持 | bias 与类型转换都留在向量核收尾段（基线形态） |

不适用：偏置非逐列向量；芯片不支持初值来自 bias 表；bias 需要与其它逐元素运算在同一段融合完成。

## 5. 实施步骤

### 5.1 修改位置

| 位置 | 修改 |
|---|---|
| 矩阵计算封装 | 增加偏置两级搬运入口（加载 bias）+ 首轮乘加初值切换 |
| kernel 主流程 | 偏置加载调用点（有 bias 且 dtype 组合支持时）；向量核收尾段按分流裁剪加法 |
| host/切分 | 偏置使能标记下传（通常已有） |

### 5.2 骨架（两级搬运 + 初值切换）

```text
# ① 全局内存 → 片上：ND→NZ 布局转换原语（勿用「带 padding 的拷贝原语」）
copy_with_layout_cast(on_chip_bias, global_bias, layout=nd_to_nz, cols=valid_cols)
# ② 跨流水事件同步（布局转换完成才可继续）
cross_pipe_wait(first_move_done)
# ③ 片上 → bias 表：顺带类型转换；长度单位 = 64 字节块
copy_with_dtype_cast(bias_area, on_chip_bias,
                     len_in_blocks=ceil_bytes(valid_cols * elem_size, sixty_four))
# ④ 跨流水事件同步（bias 表就绪才可乘加）
cross_pipe_wait(second_move_done)
# ⑤ 首轮乘加：累加器不清零、初值来源 = bias 表；后续轮照常累加
first_pass: acc_init_from_bias(bias_area, a_fractal, b_fractal)    # C = bias + A·B 首段
other_pass: acc_keep_accumulate(a_fractal, b_fractal)             # C += A·B 后续段
```

### 5.3 分流与退回路径

- 分流：偏置 dtype 组合不支持时，整体走收尾段加 bias（分支三），不要只换转换方式。
- 退回：把偏置加载调用点收紧为恒不执行 → bias 全走向量核收尾段，与基线同构，作为精度对拍与回退基准。

## 6. LLM 前置问题

| 问题 | 必填内容 |
|---|---|
| 偏置 dtype | 偏置是什么 dtype？芯片「片上→bias 表」转换组合是否支持它到累加 dtype（半精度→浮点？bf16→浮点？）不支持 → 分支三 |
| 跨流水同步 | 两次先后依赖（布局转换→拷贝、拷贝→乘加）是否都用跨流水事件同步原语，而非同流水 barrier？ |
| 初值语义 | 首轮乘加是否关掉「累加器清零」且初值来源切到 bias 表？ |
| 长度单位 | 片上→bias 表的搬运长度是否按 64 字节块（字节数向上取整），而非元素数？ |
| 布局转换 | 全局内存→片上是否用支持布局转换的原语（非「带 padding 的拷贝原语」）？ |
| 缓冲分配 | bias 表是否用正规缓冲对象 + 容量初始化（非裸地址）？ |
| 基线 | 中间缓冲往返与收尾段在 profiling 中的占比？ |

任一项无法回答，不实施。

## 7. 验收标准

精度（方向性判据）：

- 支持的 dtype 组合走融合路径，误差与基线持平；不支持的组合分流回收尾段，同样达标。
- 特别检查「误差恰好等于 bias」的症状（首轮清零语义未关，第 3.1 节环节五）。
- 不应出现数据量级的整体大误差（有则查跨流水同步，第 3.3 节）。

性能（方向性判据）：

- 含 bias 用例与无 bias 用例耗时**持平**（bias 加法被乘加流水吸收，这是本策略成立的标志）。
- 向量核收尾段只剩类型转换（加法消失）；若含 bias 用例明显慢于无 bias，查两次同步的开销是否吞掉收益。

回退条件：dtype 组合不支持（整体分流收尾段）；含 bias 用例耗时明显劣化（未吸收，重新归因）；精度崩且定位不到五环节中的单一原因（退回基线形态对拍）。

## 检索卡（短卡）

动作：将向量核收尾段的bias加法前移为矩阵乘累加器初始值。
适用：偏置为逐列向量，即输出每列加同一标量；不适用于逐元素偏置矩阵。
限制：须核对芯片支持；bias搬至片上做ND→NZ转换，仅首轮乘加切换累加初值。
范围：带加性逐列bias的矩阵乘融合kernel。
检索词：bias表、累加器初值、epilogue、两级搬运、ND→NZ布局转换。
机会：矩阵乘先写不含bias的浮点累加结果，随后由向量核收尾加bias。
