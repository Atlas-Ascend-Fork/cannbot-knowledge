# 性能优化策略：右操作数跨内层循环片上复用（含片上预算守卫回退与任务分组前提）

> 单一优化点：矩阵乘类内核若把「左操作数行段」放外层循环、「右操作数列段」放内层（等价地，每个 (行段, 列段) 组合都重新从全局内存加载右操作数列段），同一列段被行段数次重复搬运；把循环重排为「右操作数列段在外、左操作数行段在内」，右操作数列段一次加载驻留矩阵核侧片上缓存、跨该列段的所有行段复用，右操作数全局内存读取从「行段数 × 列段数」次降到「列段数」次；配片上预算守卫（驻留需求超可用容量自动回退逐块加载），并以「任务按分组聚拢」为启用前提。
>
> **算子/管线无关性：** 适用于任何「右操作数（权重/B）体积大、会被多个左操作数行段重复使用」的矩阵乘内核：分组矩阵乘的权重列段、普通稠密矩阵乘的 B 驻留、卷积权重块复用同构。核心是「循环重排 + 片上驻留 + 预算守卫 + 分组前提」，不依赖具体算子与数据类型。

---

## 1. 原理

先定义术语：

- **左操作数 / 右操作数**：矩阵乘的激活侧（按行段切块、逐段变化）与权重侧（按列段切块、跨行段不变）。
- **驻留**：一次加载到片上后留在原地，跨多次内层迭代复用（区别于逐块即用即弃的加载）。
- **片上预算守卫**：进入驻留快路径前先算驻留需求与可用片上容量，超限则回退逐块加载路径的自保机制。
- **分形布局**：矩阵计算单元取数要求的固定小块摆放格式，块内含对齐填充元素。

基线（及任何未驻留的路径）在每个 (行段, 列段) 组合上重新把右操作数列段从全局内存搬入片上。右操作数单块体积通常大于左操作数单块（列段跨整个归约维），复用右操作数的收益大于复用左操作数。

| 机制 | 利用方式 |
|---|---|
| 循环重排 | 列段在外、行段在内，右操作数列段的复用距离从 1 个行段扩大到全部行段 |
| 片上驻留缓冲 | 右操作数列段（整个归约维）驻留矩阵核侧一级片上缓存；内层行段计算时矩阵计算单元直接从驻留缓冲取右操作数，无全局内存读 |
| 片上预算守卫 | 驻留需求 = 归约块数 × 单块元素 × 类型宽度；可用 = 片上总量 − 常驻双缓冲等固定占用（按目标芯片硬件表取）；超限自动回退逐块路径，杜绝越界崩溃 |
| 任务分组前提 | 驻留收益依赖「同一列段的多个行段集中到同一核」；任务分配跨分组交错时每核要处理多分组，预加载多分组右操作数反而多搬 |

定性归因（相对基线）：矩阵核「全局内存到片上」搬运管道耗时显著下降（读次数从行段数 × 列段数降到列段数），矩阵计算管道耗时不变（计算量没变）。搬运降、计算不变，是判断本策略是否对症的主判据。

## 2. 性能问题模式

低效基线：行段在外、列段在内，每个组合重搬右操作数列段：

```python
# 基线：行段外、列段内 → 右操作数列段每行段重读
for row_block in row_blocks(rows):
    for col_block in col_blocks(cols):
        load_right(col_block)                     # ← 每个组合都从全局内存搬整条列段
        for piece in reduce_pieces():
            load_left(row_block, piece)           # 左操作数逐块（可双缓冲）
            multiply_accumulate(row_block, col_block)
        hand_off(row_block, col_block)            # 交向量核收尾
```

开销源：

- **右操作数重复搬运 × 行段数**：同一条列段在每个行段上重读一遍，搬运量 ≈ 行段数 × 右操作数体积。
- **矩阵核搬运受限**：搬运管道耗时远大于计算管道——瓶颈不在算而在搬。

典型症状：剖析显示矩阵核搬运管道耗时高且随行段数线性增长、计算管道正常；总搬运量 ≈ 行段数 × 右操作数体积。

## 3. 正确性红线

### 3.1 循环重排不改累加语义
每个 (行段, 列段) 的归约维累加仍完整：首次归约块初始化累加器、后续块累加；跨列段（外层切换）必须重置初始化，忘重置即累加脏值。重排只改遍历顺序，不改任何一块的计算内容。

### 3.2 产出顺序变化与交接对齐
重排后产出顺序从「行段连续」变为「列段连续」。若存在矩阵核到向量核的中转交接，消费侧若仍按旧顺序等槽即死锁或错位——中转槽的生产/消费顺序必须按新遍历序对齐，必要时调整环形深度覆盖新的复用距离。

### 3.3 驻留加载形态：逐块搬运 + 显式偏移（最易翻车）
驻留缓冲由多个归约块拼成时，**必须逐归约块搬运、每块写入显式块偏移**（偏移按块内完整元素数计——含分形填充——而不是归约步长），并保证块摆放与矩阵计算单元取数布局严格一致，错位即数值错。特别地，**分形最小单元较小的数据类型（如双字节浮点）禁止用「单条搬运一次载多个归约块」的形态**：大列数下硬件会把各块在片上错位放置，数值崩；加全流水排空反复锤无效——这是布局错误而非同步竞争。分形单元较大的类型（如单字节整型）不易触发，但不能因此照搬到窄类型。

### 3.4 片上预算守卫（防越界崩溃）
驻留需求超可用容量必须回退逐块路径，否则片上越界崩溃（大归约维形状必炸）。守卫在初始化阶段算一次即可。可用容量的计算**只计真正落在该级片上缓存的缓冲**：更内层的暂存（矩阵计算单元私有的暂存级）不占该级容量，误把它们计入会导致可用量过度保守、白白放弃驻留。

### 3.5 驻留缓冲的生命周期
驻留缓冲只在列段边界（切到下一列段/下一宏块）才允许覆盖。下一驻留加载（搬运流水写）不得早于本列段最后一次取数（矩阵计算单元读）完成——用多级队列的入队/出队天然保序，或用跨流水事件同步原语显式排序。

### 3.6 归约维等长前提
驻留快路径假设归约维被等长分块。归约维不是块高整数倍且未在主机侧补齐（存在尾块）时，必须回退逐块路径（带尾块处理），不得走驻留路径。

### 3.7 行尾有效数的语义边界
行尾块的有效行数**只约束全局内存读取的行数**（搬运侧把有效行补齐到块高），不改变矩阵块形状——矩阵核恒按完整块高计算，补齐行的结果由向量侧按有效行掩码丢弃。把有效行数误当矩阵块高传入计算，尾块即漏算或多算。

### 3.8 调度开关必须显式初始化
驻留开关经调度参数缓冲下发时，若该缓冲不是零初始化的（未写入即读到残留值），漏置会把垃圾值当「开」——驻留缓冲按错误尺寸分配导致片上越界异常。关闭态必须显式写零值。

### 3.9 已知陷阱
- 驻留需求没做预算守卫，大归约维形状崩溃。
- 驻留块偏移按归约步长而非块内完整元素数算，计算单元读错归约块。
- 窄数据类型照搬宽类型的单条多块搬运形态，大列数数值崩。
- 跨列段忘重置累加初始化，脏值累加。

## 4. 泛化条件

适用：

- 右操作数列段会被两个以上行段复用，且右操作数单块体积大于左操作数单块（复用收益大）。
- 任务分配已让同一列段的行段集中到同核（依赖铺核类前置策略的宏块/分组聚拢分配）。
- 驻留需求不超过可用片上容量（守卫判定通过）。

不适用 / 需退回（负向边界，可判定）：

- **任务分配跨分组交错（每核处理多分组）**：预加载全部所需分组的右操作数反而比逐块多搬，负收益，禁用。反转条件：任务改为按分组聚拢（每核只处理少数分组/宏块）后方可启用。
- 右操作数沿行段维不可复用（每个行段用不同列段），无驻留收益。
- 归约维极大、驻留需求必然超容量：守卫自动回退，策略退化为无害的逐块路径。
- 归约维有尾块且未在主机侧补齐：走逐块回退路径。
- 右操作数复用已由高阶接口内部完成：重复实现无收益。

## 5. 实施步骤

### 5.1 修改位置
- 计算主循环：把「行段外、列段内」重排为「列段外、行段内」（或引入显式的驻留外层）。
- 驻留加载：进入外层列段时逐归约块搬运、写显式块偏移，一次驻留；内层行段复用。
- 初始化阶段：算驻留需求与可用容量（只计落在该级片上缓存的缓冲），设驻留可行标志。
- 交接逻辑：产出顺序按新遍历序对齐。
- 不改块尺寸常量、不改数据类型分派、不改收尾段计算。

### 5.2 语义伪代码（前/后对比）

```python
# 前：行段外、列段内 → 右操作数列段每行段重读
for row_block in row_blocks(rows):
    for col_block in col_blocks(cols):
        load_right(col_block)
        for piece in reduce_pieces():
            load_left(row_block, piece)
            multiply_accumulate(row_block, col_block)

# 后：列段外、行段内 → 驻留复用（守卫不通过则整体回退前一行路径）
resident_ok = resident_need() <= resident_available()   # 初始化阶段算一次
for col_block in col_blocks(cols):
    if resident_ok:
        load_right_resident(col_block)                  # 逐归约块搬运 + 显式块偏移，一次驻留
    for row_block in row_blocks(rows):
        for piece in reduce_pieces():
            load_left(row_block, piece)                 # 左操作数仍逐块（可双缓冲）
            if not resident_ok:
                load_right(col_block)                   # 回退：逐块即用即弃
            multiply_accumulate(row_block, col_block)
        hand_off(row_block, col_block)
```

### 5.3 退回路径（必须保留）
- 守卫不通过 → 逐块加载路径（带尾块、有效行处理），精度不降级。
- 归约维尾块 → 同上回退，不进驻留快路径。
- 驻留开关支持显式关闭（并显式写零值，见 3.8）。

## 6. LLM 前置问题

应用本策略前，LLM 应回答：

1. 当前循环结构是行段外还是列段外？右操作数被重复加载几次（约等于行段数）？
2. 剖析基线：矩阵核搬运管道与计算管道耗时各多少？是否搬运受限（搬运远大于计算）？
3. 任务分配是否让同一列段的行段集中同核？是否存在跨分组交错（是 → 先改任务分配，否则禁用本策略）？
4. 驻留需求（归约块数 × 单块元素 × 类型宽度）与可用片上容量（按目标芯片硬件表取）各多少？固定占用（双缓冲等）有哪些？更内层暂存是否被误计入？
5. 数据类型的分形最小单元多大？是否窄类型（是 → 必须逐块搬运，禁单条多块形态）？
6. 归约维是否等长分块或已在主机侧补齐？有无尾块？
7. 行尾块的有效行语义在「搬运补齐」与「向量侧掩码」两侧是否一致？
8. 是否存在矩阵核到向量核交接？重排后消费顺序是否需要重排对齐？
9. 调度参数缓冲是否零初始化？驻留开关是否显式写值？
10. 修改前的构建/精度/性能基线值。

第 1、3、4 项任一无法回答，不实施。

## 7. 验收标准

- **精度**：全部用例通过，必须覆盖大归约维、大列数、行尾、列尾、行段数为 1；窄数据类型大列数不得崩（验证逐块搬运形态）。
- **性能方向**：矩阵核「全局内存到片上」搬运管道耗时显著下降，计算管道耗时不变（计算量未变）。判据：搬运降 + 计算不变；若搬运未降，说明右操作数非瓶颈或已被复用，重新归因。
- **稳定性**：最大归约维形状不崩溃（守卫生效）。
- **回退正确**：人为构造超长归约维与归约尾块用例，回退路径精度仍全部通过。
- **不误伤**：行段数为 1（无复用收益）的形状与基线持平。
- **归因方法**：用剖析工具对比搬运/计算两条管道的耗时变化，而不是只看总耗时。

## 检索卡（短卡）

动作：将行段外、列段内重排为列段外、行段内，使右操作数片上驻留复用，并加片上预算守卫回退。
适用：右操作数列段被至少两个行段复用、其单块大于左块，且同列段的行段已集中到同核。
限制：循环重排不得改变累加语义；每个行段、列段组合的归约维累加须完整。
范围：矩阵乘类内核的计算主循环。
检索词：左操作数、右操作数、列段驻留、片上复用、归约维、循环重排。
机会：每个行段、列段组合都会重新搬运右操作数列段。
