# 性能优化策略：矩阵核到向量核交接流水（环形加深 + 屏障精确化 + 条件等待 + 批量信用同步）

> 单一优化点：矩阵核产出中间结果、经全局内存中转槽交给向量核消费的融合内核，若环形槽浅（深度二及以下）、每次交接前做全流水排空（把与本次交接无关的、后续任务的搬运与计算一起等掉）、或逐任务严格握手（深度一交替），两核相互拖住；组合四件事：环形加深（生产者领先消费者多个任务）、屏障精确化（交接前只排空「槽数据写回全局内存」所依赖的那一条流水）、条件等待（初始化预释放的前几个槽不必等释放信号）、批量信用同步（就绪信号逐任务一比一，释放信号按环形深度批量）。
>
> **算子/管线无关性：** 适用于任何「生产核 → 全局内存中转槽 + 跨核信号 → 消费核」的逐任务流水，典型为矩阵核算、向量核做收尾（反量化、类型转换、点态融合等）。核心是「环形深度 + 排空范围 + 等待条件 + 信号粒度」，不依赖具体算子；对任何「两类核分工 + 槽式交接」的管线同构。

## 1. 原理

先定义术语：

- **交接**：生产核把中间结果写入自己的中转槽并置「就绪」跨核信号；消费核等就绪、读槽、处理、置「释放」跨核信号。
- **环形槽队列**：每核一组循环复用的中转槽，深度即槽数；生产者领先消费者的距离受深度限制。
- **流水排空（屏障）**：等待指定流水线上已下发指令全部完成的同步原语。全流水排空会连其它流水（后续任务的入搬运、矩阵计算）一起等，把两核串行化。
- **信用批量同步**：生产者每任务发一次就绪、攒满一个深度才等一次释放；消费者镜像对称。区别于深度一严格交替（每任务一发一等）。
- **条件等待**：槽在初始化阶段被预释放（预置就绪/空置信号）时，生产者首轮前若干任务可跳过等待。

| 机制 | 利用方式 |
|---|---|
| 环形加深 | 深度提升后生产者领先窗口变大：下一任务的入搬运与消费者处理当前槽重叠，摊薄逐任务的信号等待 |
| 屏障精确化 | 槽数据落全局内存只依赖写回那一条搬运流水；交接前只排空它，生产核其余流水继续流动，不再被全流水排空钉死 |
| 去冗余屏障 | 若调用路径在置释放信号前已排空必需流水，释放路径内的重复屏障可去；跨核信号本身必须保留 |
| 条件等待 | 初始化预释放前深度个槽 → 生产者前深度个任务不等释放；用跨任务连续的全局任务计数器判定 |
| 批量信用同步 | 逐任务交替握手 → 每深度一次等待/释放，双端等待摊薄；槽按核内任务序号索引，不用任务全局号或列块号直接散列 |
| 消费侧队列加深 | 消费核入/出队深度提升，读上一块与算/写下一块跨任务重叠 |

定性归因（相对基线）：剖析中生产核与消费核的活跃时段交叠度上升（原先近乎交替串行）；每次交接的全流水排空次数下降；双端等待停顿显著缩短。这是判断本策略是否对症的主判据。

## 2. 性能问题模式

低效基线：浅环 + 每次交接全流水排空 + 逐任务严格握手：

```python
# 前：深度浅（二以内）+ 每次交接全流水排空 + 逐任务交替
for task in tasks:
    wait_freed()                     # 等消费者释放槽（首轮也在等）
    produce(task)                    # 矩阵核算 + 写槽
    drain_all_pipes()                # ← 全流水排空：把下一任务的搬运/计算一起等掉
    signal_ready()
# 消费者镜像：等就绪 → 处理 → 全流水排空 → 发释放
```

开销源：

- **全流水排空过宽**：交接只需要槽写回完成，却排空了所有流水——生产者无法流水化地进入下一任务。
- **深度不足**：生产者最多领先一两个任务，消费者稍慢即反压。
- **逐任务握手**：每任务一次「等释放」，等待停顿随任务数线性累积。
- **首轮空等**：槽明明被初始化预释放，生产者前几个任务仍在等释放信号。

典型症状：剖析时间线上两核活跃段近乎交替而非交叠；生产核的标量/同步管道耗时占比高；任务越多与同形状库实现差距越大。

## 3. 正确性红线

### 3.1 可见性边界（最易翻车）
跨核槽写必须在置就绪信号**之前**完成提交——即先排空写回那一条流水再发信号。绝对禁止把这条排空也删掉（只留信号）：消费核会读到半写槽，数值错。最小必需排空 = 写回流水；全流水排空是它的超集，正确但慢。收紧屏障只允许收窄范围，不允许取消这次排空。

### 3.2 去冗余屏障的前提
释放路径去掉屏障，仅当调用方在置信号之前已排空必需流水（例如写槽路径自带写回排空，且两者紧邻、中间没有插入其他全局内存写）。中间一旦插入其他全局内存写，必须补回排空。消费侧同理：其释放路径去屏障依赖处理尾部有全排空（覆盖槽读与结果写回）。

### 3.3 信号与屏障是两回事
去掉的是冗余屏障，跨核信号一次不能漏发——漏发即计数失衡死锁。混排形态下消费核一个物理核内的两条子块线程共享按核粒度聚合的信号：一次生产侧置位满足两条线程的等待；释放信号仍按核粒度发，不得因去屏障而少发。

### 3.4 槽复用安全与深度选择
生产者写某槽的前提是消费者已释放该槽（由信号计数保证）。深度必须大于生产者想领先的任务数；深度不足只亏性能（生产者阻塞）不死锁。深度过大受预算约束：核数 × 深度 × 单槽大小应落在最外层片上缓存内（按目标芯片硬件表取），超预算槽落到远端内存，交接反而变慢。

### 3.5 条件等待的成立前提
只有初始化真正预释放了前深度个槽，生产者前深度个任务才可跳过等待。判定计数器必须用跨结构边界连续的全局任务计数，不得用每队列局部头指针——跨宏块/分组边界时局部指针归零，会误判「又是首轮」而漏等，覆盖未读数据。

### 3.6 批量信用的深度下界与配对完整性
当生产者内部存在**跨任务复用的片上驻留缓冲**（如右操作数驻留）时，深度一会让上一任务的驻留读取与下一任务的驻留写入在同槽边界竞争——读到旧数据、归约累加错、下游缩放/量化系统性偏差。禁止以「每核任务数少」为由退深度一；唯一合法的深度一场景是每核确无跨任务复用（如单任务）。信号配对必须完整：就绪一比一（生产者每任务发、消费者每任务等）；释放按批（消费者每深度发、生产者每深度等）——批量化只改释放节奏，不改就绪节奏。环形槽索引必须用「核内任务序号 mod 深度」；不得用任务全局号或列块号直接取模（同一核可能连续命中同一索引，覆盖未读数据）。

### 3.7 已知陷阱
- 把写回排空连着信号一起删，消费核读半写槽。
- 释放路径去屏障但调用方前面没排空，槽未提交就发信号。
- 加深后中转槽总预算超最外层缓存，槽落远端内存，交接不升反降。
- 小规模形状（每核任务行数不足）深环引入搬运抖动，需按规模自适应退深度一（前提见 3.6）。

## 4. 泛化条件

适用：

- 生产核 → 全局内存中转槽 + 跨核信号 → 消费核的逐任务交接，每核独立环形槽。
- 基线环形深度浅（二及以下）、或交接前全流水排空、或深度一严格交替。
- 消费核处理尾部有（或可加）覆盖槽读与写回的排空，供释放路径借力。
- 每核任务数不少于二（加深与批量化有意义）。

不适用 / 需保守（负向边界，可判定）：

- 不经全局内存中转的直连路径（片上直通）：无环形槽可加深，本策略不适用。
- 中转预算紧（加深即溢出最外层缓存）：只做屏障精确化与条件等待，不加深。
- 调用路径在置释放信号前无排空且无法补：不去释放屏障，保留全排空。
- 消费节奏被外部依赖卡死（如下游全局同步、消费核只做一次批量处理）：加深与批量信用无收益。
- 生产者每核单任务：深度一即正确形态，无优化空间。

## 5. 实施步骤

### 5.1 修改位置
- 主机侧：环形深度 = 按规模自适应（小规模退一，否则取每核任务数上界与上限中较小者）；中转区总尺寸按 核数 × 深度 × 单槽 下发。
- 生产核：写槽路径的排空收窄到写回流水；释放等待改为每深度一次（条件等待跳过首轮）；全局任务计数器跨结构连续。
- 消费核：就绪等待逐任务；释放信号攒深度批量发；环形槽按核内任务序号索引。
- 不改单任务内的计算语义、不改槽数据布局。

### 5.2 语义伪代码（前/后对比）

```python
# 后：深度 d 的批量信用 + 条件等待 + 精确排空
preset_freed(d)                          # 初始化预释放前 d 个槽
produced = 0
for task in tasks:
    if produced >= d and produced % d == 0:
        wait_freed_batch()               # 只在批边界等一次释放
    produce(task)                        # 内部：算 → 写槽 → 只排空写回流水 → 置就绪
    signal_ready()                       # 就绪逐任务一比一
    produced += 1
# 消费者：每任务等就绪 → 处理（尾部全排空）→ 计数达 d 才发释放批
```

批内任务使用预释放/上一批释放的 credit，不得每任务等待；否则 d=2 时任务 3 会等一个只有消费任务 3 才会发出的释放。若实现选择逐任务等待，则消费者也必须逐任务释放，二者必须配对。

### 5.3 退回路径（必须保留）
- 深度字段可写死为一（仅当确认无跨任务驻留复用）。
- 若调用路径变化导致释放前置排空缺失，释放路径内补回写回排空。
- 小规模形状按规模判据自动退深度一。

## 6. LLM 前置问题

应用本策略前，LLM 应回答：

1. 交接是否经全局内存中转槽 + 跨核信号 + 每核环形队列？基线深度多少？
2. 交接前的排空是全流水还是只排空写回流水？写槽是否置释放信号前最近的一次全局内存写？
3. 消费核处理尾部有无覆盖槽读与写回的全排空？
4. 中转预算：核数 × 深度 × 单槽大小是否落在最外层片上缓存内（按目标芯片硬件表取）？
5. 每核任务数上界多少？是否达到二以上？
6. 生产者内部有无跨任务复用的片上驻留缓冲？（有 → 深度一下界受限，见 3.6）
7. 初始化是否预释放槽？条件等待的计数器是否跨结构边界连续？
8. 混排形态下消费侧信号是否按核粒度聚合？两条子块线程是否共享等待？
9. 修改前的构建/精度/性能基线值；两核活跃时段交叠度如何？

第 1、2、4 项任一无法回答，不实施。

## 7. 验收标准

- **精度**：全部用例通过（多任务流、空分组、尾块），不得出现消费半写槽或旧槽数据；与基线在同等舍入语义下一致。
- **交叠度**：剖析时间线上生产核与消费核活跃时段交叠度明显上升，整体耗时向同形状库实现水平靠近。
- **同步开销**：每次交接的全流水排空次数下降；生产核标量/同步类管道耗时下降；双端等待停顿缩短。
- **无死锁**：长任务流不超时；信号配对完整（就绪一比一、释放按批）；空转/单任务场景不卡死。
- **不退步**：小规模形状经自适应深度一救回，无抖动退步。
- **归因方法**：若交叠度未升，先查中转预算是否超限（槽落远端内存）、消费尾部是否缺排空导致去屏障被迫回退，再重新归因。

## 检索卡（短卡）

动作：按规模加深环形中转槽，交接时排空写回流水；满足预释放和连续全局计数条件才跳过等待。
适用：仅初始化已预释放前若干槽时，生产者对应任务可跳过等待。
限制：置就绪前须提交槽写并排空写回流水；跳等须预释放前深度槽，计数须跨结构边界连续，禁用局部头指针。
范围：矩阵核经 GM 中转槽向向量核交接的融合内核。
检索词：环形槽队列、就绪信号、释放信号、跨核交接。
机会：交接采用二槽以内浅环、逐任务交替且每次全流水排空。
代价：小规模需降低深度；其余受每核任务数上界和深度上限约束。
