# 性能优化策略：host 按 shape 与 dtype 自适应 tile 参数（行块高 / 列块宽 / 归约块深，含精度边界）

> 单一优化点：把切分参数（行块高、列块宽、归约块深）从编译期固定值改为 host 侧在切分计算时按输入 shape 分布（分组平均行数、块内有效行数、归约长度）与 dtype 特性（字节宽度、累加精度边界）运行时分档选取；kernel 从切分参数结构运行时读取，片上缓冲尺寸全部跟随。
>
> **算子/管线无关性：** 适用于任意「切分参数运行时可配（kernel 读切分参数结构而非编译期常量）的分块矩阵乘/分组矩阵乘」。行块高、列块宽、归约块深是同一模式的三个参数维度实例。

**术语**：

- **切分参数（tiling 参数）**：host 计算并下发给 kernel 的分块尺寸（每维一次迭代处理多少行/列/归约长）。
- **行向尾块（尾部行）**：分组内有效行数小于行块高时，块内被无效填充行占掉的部分；浪费比例 = (行块高 − 有效行数) ÷ 行块高。
- **分形对齐下界**：矩阵计算单元单次矩阵乘各维的最小对齐粒度（随 dtype 与芯片代次不同，须查目标芯片规格确认，不得写死）。
- **归约块深**：沿归约维单块覆盖的归约长度；加大它会改变单次矩阵乘的累加跨度。

---

## 1. 原理

统一模式：host 在切分计算里**运行时**选 tile 参数，依据是「输入 shape 分布 + dtype 精度/字节特性」，kernel 侧从切分参数结构读取（片上缓冲尺寸跟随），从而 per-case 配置**无需重编译**。三个参数维度是同一模式的实例：

| 参数维度 | shape 派生判据 | dtype 派生判据 | 收益来源 |
|---|---|---|---|
| 行块高分档 | 平均组行数（总行数 ÷ 分组数）低于默认行块高 → 用较小档砍行向尾块浪费；接近或超过 → 保持默认档避免每块固定开销上升 | 字节越宽，块高上限越紧 | 尾部行浪费 = (行块高 − 有效行数) ÷ 行块高；小档把浪费占比压低 |
| 行块高组内收窄 | 块内有效行数向上取整到分形对齐下界，且不超过行块高 | 分形对齐下界随 dtype 取值 | 尾块时矩阵乘行数、左操作数搬运行数、结果回写行数同步收窄，砍无效行 |
| 列块宽分档 | 列方向块数与向量 epilogue 宽度配平 | 同上 | 同模式可直接推广 |
| 归约块深分档 | 归约长度大 → 深档减少归约循环次数、提高计算/搬运比（每块固定搬运一次操作数，深块摊薄） | **精度边界（见 3.3）与片上容量双重约束**：低精度 dtype 加深有累加顺序风险；宽字节 dtype 加深撑爆片上源缓冲 |

关键机制：

| 机制 | 利用方式 |
|---|---|
| kernel 运行时读切分参数 | host 可 per-case 配置，无需重编译；缓冲初始化尺寸 = f(参数) 跟随 |
| 尾块浪费压缩 | 小行块高档把尾部无效行占比从「大半」压到「小半」甚至零 |
| 归约循环减次 | 深归约块使归约循环次数按比例减少，单次矩阵乘跨度更大，计算/搬运比抬升 |

定性归因：行向尾块场景的 cube **乘加开销**下降（无效乘加减少）；形状对齐场景持平（仍用默认档）。归约深档场景的 cube **搬运开销**下降（循环次数减少）。

## 2. 性能问题模式

低效基线：切分参数是编译期常量，所有 shape 与 dtype 统一使用同一组值：

```text
# 基线：固定参数，所有 case 统一
host: 行块高 = 默认常量; 归约块深 = 默认常量        # 不看 shape/dtype
kernel: 片上缓冲初始化尺寸 = 编译期常量推导          # 写死

# 症状 1（行向尾块）：组内有效行数远小于行块高
#   cube 算满行块高，尾部行全部无效填充 → 乘加大半浪费
# 症状 2（归约长）：归约块深固定较浅
#   归约循环次数多，每块固定搬运一次操作数 → 搬运开销压过计算
```

典型症状：分组/变长输入下，小行数组、长归约组的 case 明显落后同量级对齐 case；profiling 显示 cube 乘加或搬运开销偏高，但纯计算量与参考实现一致（说明浪费在切分不在算法）。

## 3. 正确性红线

### 3.1 运行时读取是前提（最易翻车）

kernel 的片上缓冲初始化必须用**运行时读到的参数值**推导尺寸。若 kernel 仍按编译期常量初始化缓冲，host 改参数后缓冲尺寸与实际分块不符 → 越界/崩溃。改造前先确认「kernel 读切分参数结构」这条链路成立。

### 3.2 对齐与整除约束

- 行块高、归约块深必须是**分形对齐下界**的整数倍（随 dtype 取值），host 自适应值须过对齐 guard，非法值回退合法档。
- 行块高须能被向量侧 lane 数整除（向量侧子块高 = 行块高 ÷ lane 数），且子块高不低于向量对齐下界 → 行块高有下限。

### 3.3 归约深度的精度边界（重要判据，不只是容量问题）

加大归约块深会改变**单次矩阵乘的累加跨度与硬件并行累加顺序**：

- 归约块深越大，单次矩阵乘跨越多级分形，硬件并行累加的归约顺序越不确定。
- 低精度 dtype（如半精度浮点）输入含**接近表示上限的极值**时，中间乘积可能溢出为无穷大；相消元素的无穷大符号会随累加顺序**随机翻转** → 精度复检出现**非确定性失败**（同一输入两次运行结果不一致）。
- 较浅档的累加分段更接近逐段串行参考，无穷大符号稳定，临界舍入差异也更小。

判据：选深档前必须回答「输入是否会触及该 dtype 的极值/强相消场景」。**存疑一律选保守档**（累加顺序确定）；仅当确认输入不会触及极值时才允许最深档。此外宽字节浮点 dtype（四字节）加深会直接撑爆片上源缓冲 → 运行时异常，强制最浅档。

### 3.4 容量预算重核

参数变化 → cube 操作数/累加缓冲、片上源缓冲、中转区、向量侧子块缓冲尺寸全部跟随。选**更小**档通常预算更宽松；选**更大**档必须守片上上限（尤其累加缓冲随 行块高 × 列块宽 × 累加精度字节 增长，宽字节 dtype 上限骤降）。

### 3.5 尾部处理逻辑不消除

自适应分档只减尾块浪费，**不消除**尾部处理：块内有效行数仍可能小于行块高，清零填充/有效行截断逻辑必须保留。组内收窄同理：收窄值用**组内有效行数**（分组边界内的行数），不是全局越界保护用的拷贝行数。

### 3.6 组内收窄三处一致

块内行数收窄后，**矩阵乘行数、左操作数搬运行数、结果回写行数**三处必须用同一个收窄值；任何一处仍用行块高原值都会错位。

### 3.7 覆盖通道回退到自适应值

若提供环境变量覆盖通道（供扫描/调试），覆盖值也须过对齐与预算 guard；非法覆盖值回退到**自适应算出的值**，而不是编译期默认值——否则尾块场景在用户传非法值时被强制回大档，功能仍对但静默丢失收益。

### 3.8 已知陷阱

- kernel 把参数当编译期常量（缓冲初始化写死）→ 尺寸错配 → 越界/崩溃。
- 自适应值未经对齐 guard（非分形对齐下界整数倍）→ 分形错位 → 数值崩。
- 归约深度只看容量不看精度边界 → 低精度极值 case 出现非确定性失败。
- 宽字节浮点用了深档 → 片上源缓冲溢出 → 运行时异常。
- 收窄只改了矩阵乘行数，搬运/回写仍用行块高 → 错位。
- 覆盖通道非法值回退到编译期默认而非自适应值 → 尾块收益静默丢失。

## 4. 泛化条件

适用（须同时成立）：

- 切分参数运行时可配（kernel 从切分参数结构读取，非编译期常量）。
- 输入 shape 分布不均（分组/变长导致行向尾块）或归约长度跨度大，固定参数导致浪费或搬运比低。
- 候选档位全部通过对齐 guard、容量预算、精度边界检查。

不适用或需保守（负向边界）：

- 参数是编译期常量（kernel 写死）→ 无法 host 自适应，需先重构 kernel 读切分参数结构。
- shape 恒对齐、无尾块、归约长度恒短 → 自适应无收益（恒选默认档，无害但无意义）。
- 输入可能触及低精度 dtype 极值/强相消 → 归约深度锁定保守档（精度边界优先于性能）。
- 宽字节浮点 dtype → 归约深度锁定最浅档（容量上限）。
- 想引入比默认更大的行块高档 → 必须重核片上累加缓冲上限，超限则不引入。

## 5. 实施步骤

### 5.1 前提改造（若尚未成立）

kernel 侧确认片上缓冲初始化尺寸全部由**运行时读到的参数值**推导；host 侧把参数写进切分参数结构下发。

### 5.2 host 侧分档算式

```text
# host 侧切分计算（分档 + guard）
avg_rows = total_rows / group_count
row_height = small_height if avg_rows < default_height else default_height
if dtype 为宽字节浮点:
    reduce_depth = shallow_depth            # 片上容量强制最浅
elif 输入可能触及 dtype 极值或强相消:
    reduce_depth = medium_depth             # 累加顺序确定，保符号稳定
elif reduce_len >= deep_gate:
    reduce_depth = deep_depth               # 归约长且精度安全，收益最大
else:
    reduce_depth = medium_depth
row_height = align_up(row_height, fractal_min_rows)     # 对齐 guard
reduce_depth = align_up(reduce_depth, fractal_min_k)
if not 片上预算够用(row_height, reduce_depth, dtype):
    降一档重试，直至默认档
```

### 5.3 kernel 侧组内行收窄（三处一致）

```text
valid_rows = 组内有效行数
narrow_rows = min(align_up(valid_rows, fractal_min_rows), row_height)
矩阵乘行数 = 左操作数搬运行数 = 结果回写行数 = narrow_rows
```

### 5.4 覆盖通道与退回

- 覆盖通道：环境变量可强制指定档位（供扫描/调试），值过对齐与预算 guard。
- 非法覆盖值回退到自适应算出的值（不是编译期默认）。
- 精度复检出非确定性 → 归约深度退保守档；尾块收益不足 → 行块高回默认档。

### 5.5 不改动项

计算算法、dtype 转换路径、epilogue 语义、尾块清零/截断逻辑均不改；本策略只动「参数怎么选」，不动「按参数怎么算」。

## 7. 验收标准

精度（方向性判据）：

- 全量用例通过与基线一致（含行向尾块、组内收窄、各归约深度档位路径）。
- **精度复检确定性**：低精度 dtype 的极值/相消用例重复运行结果一致（深度档不引入非确定性）。
- 无越界/崩溃：各档位片上缓冲不溢出（尤其宽字节 dtype 走最浅档）。

性能（方向性判据）：

- 行向尾块场景（平均组行数小于默认行块高）：cube 乘加开销下降，端到端改善。
- 形状对齐场景：不回退（仍走默认档）。
- 长归约场景（深度档启用且精度安全）：归约循环次数减少，cube 搬运开销下降。
- 覆盖通道可强制指定档位（同时验证 kernel 真运行时读切分参数）。

回退条件：精度复检非确定性（退保守深度档）、对齐场景明显回退（行块高回默认档）、宽字节 dtype 异常（锁定最浅档）。
