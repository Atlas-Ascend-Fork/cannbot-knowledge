# 性能优化策略：原生 Cast 加索引 Gather 替代软件位重建

> 库内状态：`active`。已在 A5 完成全量精度与稳定配对验证，进入可选择策略库。

> 单一优化点：交错存储的低精度系数若通过长串位运算手工重建浮点值，改用硬件原生 Cast 完成数值转换，再用预生成偏移表和 Gather 做解交错。

## 1. 原理

软件位重建通常包含掩码、移位、指数修正、尾数拼接和多次屏障，本质上模拟硬件转换。先对整段交错输入做原生转换，再把转换结果按固定字节偏移聚集成多个连续向量，可显著减少向量指令和同步。偏移表在启动时构造一次并复用。

## 2. 性能问题模式

- 低精度到高精度转换由大量位操作模拟。
- 两类或多类系数交错排列，转换后仍需拆分。
- 该链在缓存未命中路径频繁执行，向量流水占主导。
- 同一内核已有相同数据类型 Cast 与 Gather 的可靠先例。

## 3. 正确性红线

- 原生 Cast 的舍入、非正规数、零、无穷和 NaN 语义必须与可观察的基线契约一致。
- Gather 偏移的基址、相对/绝对语义、字节单位、计数和源区上限必须从接口确认。
- 偏移表中不参与写回的尾项仍要指向合法地址。
- 转换缓冲与聚集目标不得重叠造成在飞覆盖。
- padding 值变化只有在能证明下游不可观察时才允许。

## 4. 泛化条件

适用：固定交错布局、软件位重建链长、硬件支持对应 Cast 和索引 Gather、缓存未命中频繁。

不适用：基线依赖非标准位级语义；偏移不规则且无法预生成；Gather 范围或数据类型不受目标架构支持。

## 5. 实施步骤

1. 对所有可观察输入证明软件位公式与硬件 Cast 等价。
2. 构造并验证解交错偏移表，做“偏移编码到实际地址”闭合检查。
3. 整段 Cast 到独立缓冲，再按类别 Gather 到连续区域。
4. 保持后续广播、算术、缓存键和跨核协议不变。
5. 覆盖两种低精度类型、边界值、padding 和缓存命中/未命中路径。

## 6. LLM 前置问题

1. 软件位重建是否只是标准数值转换的等价实现？
2. 原生 Cast 对边界浮点值的行为是否满足契约？
3. Gather 的偏移单位、计数与可寻址范围是什么？
4. 交错模式是否固定并可由一次性表表达？
5. 该链在关键路径上每次调用减少多少指令与屏障？

## 7. 验收标准

- 全量精度通过并覆盖边界浮点值及所有目标低精度类型。
- 来源验证整体验证加速比 `1.1214x`，全部验证形态同向改善。
- 至少两组平衡交替配对结果一致；缓存命中路径无稳定回退。
- 剖析确认软件位运算链和中间屏障被消除，向量流水占比下降。
