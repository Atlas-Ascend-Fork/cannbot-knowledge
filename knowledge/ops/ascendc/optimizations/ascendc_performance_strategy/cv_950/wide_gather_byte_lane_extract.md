# 性能优化策略：宽粒度索引收集与纯移位抽道

> 库内状态：`active`。已进入可选择策略库并纳入自动路由。来源为一批 A5 向量核任务的独立探索轨迹第四方向脱敏归档：单一 Campaign 内完成构建（1 修复）、全量精度（22/22，1 修复后逐位等价）与正式稳定配对验证（2 对平衡交替、同 shape、溯源干净），全集相对加速 1.1259。修复轮约束已并入 §3 红线；验证记录见 §7。

> 单一优化点：字节粒度逐行收集（每次调用携带固定的偏移预处理微码链 + 逐元素微码率）主导转置段成本时，把收集原语的访问宽度提升四倍：源按四字节视图重释（行距四字节对齐前提），每四个连续输出行组发一次宽粒度收集，随后对四个字节道用「移位零扩展 + 截断窄化」抽出；非整除尾部与宽元素类型路径回退字节粒度收集。

---

## 1. 原理

- **收集单元宽度是杠杆**：字节粒度收集每次调用携带约十条偏移预处理微码（索引窄化/打包/选择链）与逐元素微码率；四字节粒度收集每次调用约四条微码，且一次收集同时取回四个输出行的字节——指令数与收集元素数同时除以四。收益上界 = 收集调用数 ÷ 4，仅在行组满宽摊薄充分时兑现。
- **道抽取必须是纯元素级移位 + 截断窄化**：整数窄化转换的饱和语义会把高位非零值饱和到输出类型最大值（特征签名：成片最大值脉冲）。先把目标字节道经移位零扩展到窄化安全值域，再窄化即可无损截断；无符号按位与的向量形式不可用时，移位网络是通用替代（跨元素字节重排在逐元素向量管上不可表达，移位抽取不依赖跨元素重排）。
- **索引表复用**：宽粒度收集的偏移表与字节粒度同源（偏移按字节单位），仅基地址按组距缩放；无需重算。
- **负向边界**：每调用固定微码链在非满宽形态摊薄不足时净负——全量（不分派满宽条件）应用宽路径已被同域先例一致回退证伪；必须按「整除且满宽」形态门控分派。

## 2. 性能问题模式

低效形态：

```python
# 前：每输出行一次字节粒度收集（per-call 固定预处理链）
for w in out_rows:
    gather_b8(dst_row(w), src, byte_idx_table, base=w)

# 后：每 4 行组一次宽粒度收集 + 移位抽道（仅整除满宽形态）
for j4 in range(out_rows // 4):
    w32 = gather_b32(buf, src_u32view, byte_idx_table, base=4*j4)  # 4 行字节打包
    for b in range(4):
        lane = (w32 << (24 - 8*b)) >> 24        # 零扩展目标道
        cast_u8(dst_row(4*j4 + b), lane)        # 截断窄化无损
# 尾部（非整除）与宽元素类型：回退字节粒度收集路径
```

指纹：

- 收集调用数 = 输出行数/块，每调用固定成本显著（剖析或「每调用固定 + 每元素斜率」回归模型给出固定分量占比大）。
- 行数对四整除的满宽形态占主体。
- 已有字节粒度收集通路（本策略是其宽度提升，不改变装载/写回契约）。

## 3. 正确性红线

### 3.1 饱和窄化陷阱（最易翻车）

整数窄化转换的饱和语义：直接窄化高位非零的宽值会得到成片最大值脉冲（精度门表现为逐块脏值）。必须先移位把目标道零扩展到窄化安全值域再窄化；分部窄化链若公共接口不可表达非饱和语义，一律走移位网络。

### 3.2 行距四字节对齐前提

源按四字节视图重释要求行俯仰是四的倍数（对齐取整到固定粒度的俯仰天然满足，仍须显式验证）；不满足即整卡不适用。

### 3.3 端序前提

「宽值内字节道 ↔ 输出行」的对应依赖小端序；大端布局需重排道序。

### 3.4 形态门控与回退

仅「元素单字节且行数对四整除」的满宽形态走宽路径；非整除尾部与宽元素类型（每列本就是宽访问，加宽无收益）必须回退字节粒度路径，且两条路径共用索引表不得重算出错。

### 3.5 数值等价

宽收集 + 移位抽道是纯重排：输出与基线逐位等价；差异优先排查 3.1/3.3。

## 4. 泛化条件

必须同时满足：

- 收集段主导可变成本，且每调用固定微码链可见（回归模型固定分量占比证据）。
- 元素为单字节类型；行距四字节对齐；行数对四整除的满宽形态是主体。
- 宽粒度收集原语的偏移表与基地址字节单位语义与原通路一致。

禁止条件（任一即不实施）：

- 非满宽形态强行走宽路（摊薄不足净负，同域先例证伪）。
- 宽元素类型路径套用（无收益，徒增精度风险面）。
- 行距不对齐或端序前提不成立且无重排方案。
- 收集段不在关键路径。

## 5. 实施步骤

1. 建立「每调用固定成本 + 每元素斜率」回归模型，确认固定分量占比与收益上界（调用数 ÷ 4）。
2. 验证行距四字节对齐与小端前提；核算宽收集偏移上界。
3. 增加宽路径：四字节视图 + 每 4 行组一次宽收集 + 移位零扩展 + 截断窄化抽道。
4. 形态门控（整除且单字节）分派；尾部与宽类型回退原字节粒度路径（共用索引表）。
5. 保持装载/写回/槽布局/双槽流水契约零改动。
6. 覆盖尾部、极窄、宽类型、多 dtype 的精度（预期逐位等价）与平衡交替配对性能验证。

## 6. LLM 前置问题

1. 收集段的每调用固定成本与每元素斜率各是多少？满宽形态占比多少？
2. 所用窄化转换的饱和语义是什么？移位零扩展是否覆盖全部道？
3. 行距是否四字节对齐？端序前提是否成立？
4. 哪些形态走回退路径？回退与宽路径的索引表共用是否核对？
5. 收集偏移在宽视图下的最大值与位宽余量是多少？

## 7. 验收标准（验证记录）

- **构建**：目标硬件编译通过（来源 Campaign 1 修复内通过；枚举/类型约束为常规修复）。
- **精度**：全量用例逐位等价（来源 Campaign 22/22，1 修复；饱和窄化红线见 §3.1）。
- **性能**：正式配对口径相对加速 1.1259（2 对平衡交替；收集主导的大形态用例接近「调用数 ÷ 4」上界量级约 2 倍；2 个非收益形态用例在预登记平坦带内）。
- **归因**：收集调用数与收集元素数同除四有指令面证据；装载/写回零改动。
- **回滚**：撤除宽路径分派即回滚（回退路径本就保留）。
