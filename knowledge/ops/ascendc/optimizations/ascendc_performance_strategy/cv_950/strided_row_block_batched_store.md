# 性能优化策略：行块级带源步距批量写

> 库内状态：`active`。已进入可选择策略库并纳入自动路由。来源为同批 A5 自动探索的脱敏归档（见 `AUTO_EXPLORATION_ARCHIVE_20260909.md`）：单一 Campaign 内完成构建、全量精度（22/22，两轮修复后通过）与正式稳定配对验证（2 对平衡交替 + 采纳后确认、全部性能用例一致改善、饱和控制用例无回退），相对加速 1.1445；正确性红线见下文。

> 单一优化点：向量侧尾段把逐行小额 GM 写（每行对一或多个目标数组各发一笔标量宽度写）合并为行块级每数组一笔带源步距的批量写，按行数等比例收缩 MTE3 事务数与逐行标量发射；每行数值、每行目标地址与总字节不变。

---

## 1. 原理

逐行碎写的典型结构：源侧片上缓冲因广播/归约类布局带大步距，目的侧 GM 行间本已连续，碎片化纯源于发射形态——每行付出地址计算、参数装载、入队等标量发射，事务数与发射链随行数线性增长。

带源步距批量写用一笔指令描述整个行块：块数 = 行块行数，块长 = 单行字节数，源步距 = 相邻行在源侧的距离（按源侧步距单位编码），目的步距 = 0 或目的侧行距。效果：

- 每数组每行块一笔事务替代每行一笔，事务数收缩一个数量级。
- 逐行地址式与参数发射消失，写发射段不再卡在相邻段之间。
- 源侧大步距布局不需要重构（若源不满足步距搬运契约才需紧缩，见 3.3）。

定性归因（相对基线）：MTE3 事务数与向量核标量/发射类管道耗时显著下降，写通道不再为发射链绑定；行数大的家族收益最大。这是判断本策略是否对症的主判据。

## 2. 性能问题模式

- 尾段每行对一或多个 GM 目标数组各发一笔单行标量宽度写。
- 每行重复付出地址式、搬运参数装载与入队发射。
- 每 Tile 累积数百笔微事务，MTE3 事务数与标量发射随行数与 Tile 数线性堆积。
- 时间线：MTE3 事务数巨大而单笔字节数极小；写发射段夹在相邻段屏障之间不可重叠，成为尾段绑定点。
- 多行、多 Tile 家族对该链最敏感；饱和计算类用例不受影响。

## 3. 正确性红线

### 3.1 步距单位不对称（最易翻车）

**读写方向的步距单位可能不对称**：一侧可能按字节、另一侧按固定粒度单位（如 32B）并向上取整。UB/GM 两侧的单位与对齐取整规则**必须从目标架构头文件/接口契约确认，不能照搬字节值**，也不能把一侧的单位惯例套到另一侧。

典型误编码症状（可判定签名）：**首行正确、后续行脏读/NaN**——源步距被按错误单位解释后放大数倍到数十倍，第二行起读到越界或旧数据。精度失败呈现该签名时，先定位步距单位契约，再改参数。

### 3.2 步距换算必须闭合

源步距编码值按契约单位反算回字节，必须唯一还原实际源行距（含取整规则参与）；不能闭合说明单位理解错误。参数确定后应做一次「编码—反算」自检再上线。

### 3.3 向量紧缩降级路径的对齐约束

若源布局不满足步距搬运粒度契约、需先用向量操作把行值紧缩到连续段再整段写出：紧缩指令仍受**向量操作数最小对齐约束**（如 32B 量级），单标量粒度的逐行紧缩可能架构不可实现（设备错误）。降级前必须核对最小对齐，并保留逐行写回退路径。

### 3.4 数值与地址不变性

合批只改发射形态：每行数值、每行目标地址、总字节逐项不变；多目标数组的行归属与写出次序不变。任何数值差异都是实现错误，优先排查 3.1/3.2。

### 3.5 尾块

行块内有效行数不足整块时，块数按有效行数截断；末行不越界、不污染相邻块。目的侧仍按有效字节写，不按对齐宽写。

### 3.6 同步语义保持

写前后的跨流水事件对（向量→写回通道的反向依赖）保持按块配对；批量写仍须落在其覆盖之内，不得因合批提前释放槽位。

## 4. 泛化条件

适用：向量侧逐行小额 GM 写、目的侧行间连续（或规则步距）、源侧片上带规则步距的布局；行数与事务数大、写通道或标量发射绑定关键路径。

不适用 / 需保守（负向边界，可判定）：

- 目的侧行间不规则（散布地址）：批量写不成立。
- 源侧行距不规则，且向量紧缩降级不满足最小对齐约束。
- 行数极小（一两行）：合批无收益，徒增参数复杂度。
- 写不在关键路径（计算或读侧绑定）：先治理绑定段。
- 源步距单位契约无法从目标架构确认：不实施（3.1 红线前置）。

## 5. 实施步骤

1. 用时间线确认写发射链绑定（MTE3 事务数与标量发射证据）。
2. 从目标架构头文件/接口契约确认读写两侧的步距单位与取整规则。
3. 推导块数/块长/源步距/目的步距参数，做「编码—反算」闭合自检。
4. 保持每行数值与目标地址不变；尾块按有效行数截断、按有效字节写。
5. 若步距搬运不可行，核对最小对齐后评估向量紧缩降级，否则保留逐行写。
6. 覆盖首行、尾行、尾块、单行块与多行块、多种 dtype 的精度与稳定配对性能验证。

## 6. LLM 前置问题

1. 逐行写的笔数与事务占比？写通道是否为绑定瓶颈？
2. 目的侧行间是否连续或规则步距？源侧布局与相邻行距是多少？
3. 所用搬运接口读写两侧的步距单位与取整规则（从头文件/契约确认）各是什么？
4. 源步距编码反算是否唯一闭合到实际行距？
5. 向量紧缩降级是否满足向量操作数最小对齐约束？
6. 尾块与末行如何截断？写出按有效字节还是对齐宽？
7. 修改前的构建/精度/性能基线值？

第 1、3、4 项任一无法回答，不实施。

## 7. 验收标准

- **精度**：全量用例通过；重点覆盖首行正确性、尾行、尾块——**首行正确而后续行脏读/NaN 是步距单位误编码的特征签名**，出现时定位到单位契约再修，不做数值侧兜底。
- **性能**：稳定配对测量 + 采纳后确认；全部性能用例一致改善或无超噪声回退，饱和控制用例无回退；MTE3 事务数下降有剖析佐证。
- **归因**：只改写出发射形态，禁止把读侧、向量链或流水改动混入同一归因。
- **回退**：还原逐行写即回滚；紧缩降级路径按独立子集验收。
