# 性能优化策略：链式原地计算的输出宿主槽轮转（消除段间整阵回拷）

> 库内状态：`active`。已进入可选择策略库并纳入自动路由。来源为一批 A5 向量核任务的自动探索脱敏归档：单一 Campaign 内完成构建（0 修复）、全量精度（与基线逐位一致，0 修复）与正式稳定配对验证（2 对平衡交替、同 shape、溯源干净，两对比值一致为正），全集相对加速 1.1974；无链段用例按机制预测持平。正确性红线见下文，验证记录见 §7。

> 单一优化点：链式原地算法的每段计算把输出写到临时槽、再整阵拷回权威槽（全局内存级往返 + 逐行栅障串行段）时，若计算原语的输出缓冲本可参数化、且存在生命周期已结束或全程闲置的可复用槽，则改为「输出直写本逻辑流的下一个宿主槽」：两条逻辑流各自在一对宿主槽间轮转，全程消除段间回拷；workspace 不扩容，数值逐位不变。

---

## 1. 原理

- **回拷机械的冗余性**：链式迭代（自乘 + 累乘类结构）每段执行「计算(输入A, 输入B) → 临时槽 → 整阵拷回权威槽」。若计算原语的输出槽本是参数，且**输出宿主与两输入宿主不相交**，则「临时槽周转 + 回拷」与「直写下一宿主」语义等价——回拷整体冗余。
- **回拷的真实成本结构**：由逐行搬运发射 + 逐行全流水排空的串行段主导，而非数据量本身；小数据量用例的实际增益会显著超出按流量的外推（逐行栅障的固定开销被 M² 流量模型低估）。
- **别名初始化不是免拷贝的充分条件**：以纯别名（R := A）替代首段拷贝后，别名槽在首次消费前只读；若基流继续在原宿主对间轮转，第二次自乘即覆写别名值——必须把基流**重映射**到与别名落点不相交的另一宿主对（宿主重映射，而非仅建立别名）。
- **容量不增**：第二宿主优先复用同 workspace 内「该路径全程闲置」或「其他路径尾部已将其内容拷出（值已死）」的槽；两类槽都要求生命周期证明。

## 2. 性能问题模式

低效形态：

```python
# 前：每段计算后整阵回拷权威槽（逐行小搬运 + 逐行全流水排空，完全串行零掩盖）
while 链未结束:
    if 累乘位:
        result = compute(result, base) -> tmp; copy_whole(result, tmp)
    if 还有下一位:
        base = compute(base, base) -> tmp; copy_whole(base, tmp)

# 后：双流宿主轮转，输出直写本流下一宿主（输出宿主 ∉ 两输入宿主）
while 链未结束:
    if 累乘位:
        result_host, base_host = rotate(result_host, base_host)
        result = compute(result@cur, base@cur) -> result@next   # 直写
    ...
consume(result@final_host)
```

指纹：

- 剖析中非计算残差主体是「整阵拷回」段；链段数多的用例显著慢。
- 回拷实现为逐行小搬运 + 每行多次全流水排空，段间零掩盖。
- 计算原语已把输出缓冲作为参数（或可低成本参数化）。
- workspace 存在闲置槽或「其他分支尾部拷出后即死」的槽。

## 3. 正确性红线

### 3.1 输出宿主不相交不变式（最易翻车）

每段计算的输出宿主（对）必须与该段两个输入宿主（对）都不相交；两条逻辑流的宿主集合在任意时刻互斥。必须以轮转状态机层面的枚举证明（覆盖首段别名建立、基流宿主重映射、链尾读取各边界与全部链形/位距），不得依赖「碰巧不冲突」。

### 3.2 别名建立的宿主重映射

纯别名落点在首次消费前只读；基流必须换到不相交的宿主对轮转，否则第二次自乘覆写别名（隔段才消费别名的链形是暴露该错误的典型形态）。

### 3.3 数值逐位一致

只改输出落点，不改任何计算的操作数值、累加序与尾处理。精度预期与基线逐位一致；任何数值差异都是状态机越界的信号，不是容差问题。

### 3.4 复用槽的生命周期证明

复用「已死」槽必须证明其值在复用点之前已被消费或整体拷出；复用「全程闲置」槽必须证明当前路径不触达依赖其内容的任何分支。证明不了宁可扩容或退回部分轮转。

### 3.5 下游按最终宿主寻址

链尾消费者必须按状态机记录的最终宿主读取，不能假设固定权威槽地址。

## 4. 泛化条件

必须同时满足：

- 链式/多段原地算法，段间存在整阵级「临时槽 → 权威槽」回拷，且回拷段在关键路径（剖析证据）。
- 计算原语输出缓冲可参数化。
- 可用宿主槽数覆盖每条逻辑流两个宿主（可含生命周期合法的复用槽），不扩容或扩容在预算内。
- 链段数 ≥ 2（单段无轮转意义）。

禁止条件（任一即不实施）：

- 输出槽被原语/框架固定为特定地址，不可参数化。
- 无可复用槽且不可扩容。
- 外部契约要求结果驻留固定权威地址且无链尾重定向机会。
- 段间回拷不在关键路径（收益低于噪声）。

## 5. 实施步骤

1. 列出每段计算的输入/输出槽映射与回拷点，用时间线确认回拷串行段绑定关键路径。
2. 清点 workspace 槽生命周期，标注全程闲置槽与「值已死」槽，为每条逻辑流选定宿主对。
3. 设计轮转状态机：定义各流 (当前宿主, 下一宿主) 与迁移规则；显式处理别名建立的宿主重映射与链尾最终宿主记录。
4. 以枚举/不变式证明「输出宿主与两输入宿主不相交」覆盖全部链形与位距。
5. 删除全部段间回拷；链尾消费者改读最终宿主。
6. 保持计算原语、数值路径、tiling 与 host 协议零改动。
7. 全量精度（预期逐位一致）+ 平衡交替配对性能验证；无链段用例核查持平。

## 6. LLM 前置问题

1. 每段计算的原语是否已把输出缓冲作为参数？回拷段绑定关键路径的证据是什么？
2. 两条逻辑流各需要哪些宿主对？哪些槽可复用，其生命周期证明是什么？
3. 别名建立点在哪里？基流重映射到哪一对？隔段消费别名的链形是否被枚举验证？
4. 链尾消费者从哪里读取最终结果？状态机如何传递最终宿主？
5. 哪些用例不含链段、预期持平？回退条件是什么？

## 7. 验收标准（验证记录）

- **构建**：目标硬件编译通过（来源 Campaign 0 修复）。
- **精度**：全量用例与基线逐位一致（来源 Campaign 全量通过，0 修复）。
- **性能**：正式配对口径（两级聚合 geomean）相对加速 1.1974（2 对平衡交替、两对比值 1.1973/1.1975 一致为正、溯源干净）；绝大多数含链用例改善，小数据量用例增益显著超出流量外推；无链段（恒等路径）用例持平，与机制预测一致。
- **归因**：只删段间回拷与逐行栅障段；计算原语、tiling、host 协议零改动。
- **回滚**：恢复「临时槽 + 整阵回拷」原语义即回滚。
