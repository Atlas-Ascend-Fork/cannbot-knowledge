# 性能优化策略：同核相邻 Tile 操作数驻留复用

> 库内状态：`active`。已在 A5 以两种实现形态完成全量精度与稳定配对验证，进入可选择策略库。

> 单一优化点：同核连续处理共享同一操作数面板的相邻输出 Tile 时，让该面板在 L1 中跨 Tile 驻留，或成对计算两个 Tile 共用一次装载，消除重复的全局内存到片上搬运。

## 1. 原理

相邻 Tile 若只在另一输出维不同，某一操作数面板完全相同。让调度保持这些 Tile 同核相邻，首个 Tile 装载面板，后续 Tile 只更新另一操作数。可采用持久驻留加令牌轮转，或双累加器成对计算；两种形态都只改变数据复用和发射组织，不改变单 Tile 的乘加链。

## 2. 性能问题模式

- MTE2 绑定，重复装载字节随相邻 Tile 数线性增长。
- 缓存命中仍占用搬运流水，无法消除发射成本。
- 每核至少处理两个共享面板的 Tile。
- 共享关系被轮转调度打散或在每 Tile 末尾无条件释放。

## 3. 正确性红线

- 只有字节完全相同、只读且生命周期互斥的面板可以复用。
- 不能跨行、跨组或跨核复用语义不同的面板。
- 双累加器必须为不同输出 Tile 分配独立槽位，初始化和写回逐 Tile 闭合。
- 归约尾段若不能证明切片和事件链正确，必须由形状守门回退原路径。
- 驻留面板、双累加器和其他队列的对齐后容量要按目标硬件重算。

## 4. 泛化条件

适用：同核连续 Tile 共享左或右操作数，MTE2 为关键瓶颈，片上容量允许驻留或双累加器，且每核有足够连续任务。

不适用：每核单 Tile；共享面板会被修改；调度无法保证邻接；尾分段事件链未闭合；容量不足。

## 5. 实施步骤

1. 计算每个面板的重复装载放大倍数并确认 MTE2 绑定。
2. 调整 Tile 顺序，使共享面板的任务同核且相邻。
3. 选择持久驻留或成对双累加器实现，并画出槽位生命周期。
4. 保持每个 Tile 的归约次序、初始化与写回路径不变。
5. 对奇数 Tile、chunk 边界、归约尾段和容量临界形态设置回退。

## 6. LLM 前置问题

1. 哪一侧操作数在相邻 Tile 间字节完全相同？
2. 调度能否保证共享 Tile 同核连续？
3. 驻留面板和额外累加器的峰值容量是多少？
4. 尾分段的切片、事件和释放是否有语义证明？
5. 每核多 Tile 的覆盖比例和预计减少字节数是多少？

## 7. 验收标准

- 全量精度通过；纯复用路径预期逐位一致。
- 两种来源形态的整体验证加速比分别为 `1.1079x` 和 `1.0536x`。
- 稳定配对显示 MTE2 绑定形态一致改善，小任务和守门回退形态无稳定回退。
- 剖析确认共享面板的实际装载次数下降，而不是仅由缓存命中掩盖。
