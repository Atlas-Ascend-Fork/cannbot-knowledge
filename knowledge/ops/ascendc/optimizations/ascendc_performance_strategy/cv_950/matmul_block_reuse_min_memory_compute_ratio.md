# 性能优化策略：选最小访存计算比的矩阵乘基本块——单核分块复用

> 单一优化点：搬运 pipe 占比高、矩阵计算利用率不足（如两成以下）时，增大二维基本块让数据驻留片上被对侧维度复用，按「访存计算比最小」原则在片上容量约束下选块，减少每个操作数块从全局内存的重复搬入。放大 baseM/baseN 前必须过「多核并行度守门」红线（见 §3.1）。

---

## 1. 原理

矩阵计算路径的数据流是全局内存→（搬运）→L1→（装载）→矩阵计算单元→（写回通路）→全局内存。基本块取得小时，每个操作数基本块都要从全局内存重复搬入，搬运次数按复用倍数放大。

分块复用让一个驻留块（L1 中的左矩阵块或右矩阵块）被对侧多个基本块消费，全局搬运次数同比下降。选块的核心原则是**访存计算比最小**：在计算量相同的情况下，需要访存的数据量最小。

块大小的选取方法：固定归约维步长下，二维块每增大，搬入数据量按两维边长之和线性增长、计算量按两维乘积二次增长，访存计算比单调下降；累加中间结果驻留在硬件管理的矩阵累加缓冲中不回写，直到归约维遍历完由写回通路一次搬出。因此大块在带宽压力上占优，但受三级片上缓冲容量约束，须在容量内枚举候选并按公式选最小比值。

该比值是**单核视角**的下界——只反映单核内搬运与计算的配比，不包含放大块导致的核间并行度损失，不能单独作为选块依据（守门条件见 §3.1）。

块不是越大越好：容量顶满即失效，且开双缓冲后缓冲份数翻倍须重算。

## 2. 性能问题模式

适用时通常同时出现以下指纹：

- 剖析中搬运 pipe 占比高（如七成），矩阵计算占比低（不足两成）。
- 增大基本块后搬运时间骤降、计算占比上升（历史行为佐证）。
- 全局内存到片上的搬运主导耗时，计算单元大量空闲。

**指标采集口径**：pipe 级占比须用 msOpProf（`msopprof` / `msprof op`）上板采集，读取其 `PipeUtilization.csv`（`aic_mte2_ratio`/`aic_mac_ratio` 等字段）。msprof 系统级采集（torch_npu.profiler 的 `kernel_details.csv` 等）与 analysis.db 无 pipe 级分解，不能用于本条准入/验收判定；且 PipeUtilization 计数器是采样的，单次很短 kernel 上会取不到数据——无法走 msOpProf 口径时，改用可计算口径：kernel Duration 显著高于「理论搬运量 ÷ 有效带宽」的估算（搬运主导判据），理论搬运量按候选块参数直接计算。

低效形态可抽象为：

```python
for a_block in small_m_blocks:        # 小块：每个 A/B 块都从 GM 重复搬入
    for b_block in small_n_blocks:
        load_gm_to_l1(a_block); load_gm_to_l1(b_block)
        mmad_accumulate(a_block, b_block)
```

调整后（Level 2 驻留重排形态，Level 1 参数档位形态见 §5）：

```python
# 选块：在 L0A/L0B/L0C 容量内枚举 (baseM, baseN, baseK)，
# 取 访存计算比 = (baseM*baseK + baseN*baseK) * dtype字节 / 计算cycle 最小者，
# 且放大后总块数 >= 物理 AIC 核数一半（§3.1 守门）
for a_block in resident_m_blocks:     # 驻留侧
    load_and_reside(a_block, L1)
    for b_block in n_blocks:
        load_gm_to_l1(b_block); l1_to_l0(); mmad_accumulate()
    release(a_block)
```

## 3. 正确性红线

### 3.1 多核并行度守门（核间切分维红线）

host tiling 以 base 块为切分粒度时（blockDim = min(物理核数, ceil(M/baseM)·ceil(N/baseN))），**放大 baseM/baseN 前必须核验放大后的总块数不低于物理 AIC 核数的一半；不足时保持原块**。baseK 是核内串行归约维，放大不减少总块数、无此约束（与 M/N 本质不同）。

放大二维块本身就会制造多核切分瓶颈，不是只在「瓶颈已在多核切分」时才需要考虑的外生条件。实测反证（baseN 64→128 无守门，arch35 / matmul_mish_mish）：M=128 单 M 块 case 劣化 +29%~+42%（块数 32→16，半数 AIC 闲置）；加守门后零劣化且收益全保留（-14.9%~-24.9%）。

### 3.2 基本块组合须同时装进三级片上缓冲

三边乘积组合须分别核算进左操作数、右操作数与累加缓冲的容量；后续开双缓冲时缓冲份数再乘二，须重算。

### 3.3 Vector 侧 UB 与 GM workspace 也在核算范围（CV 融合算子）

Vector lane 从 Fixpipe/环形缓冲消费的 tile 尺寸 ∝ baseM×baseN，须核算每 AIV 独立的 UB 容量（运行时以 `GetCoreMemSize` 为准）；与 baseM·baseN 成正比的 GM workspace 同验。

### 3.4 组合最坏值重算

与其他块参数优化叠加时（如同时放大 baseN 与粗化 baseK），容量必须按叠加后的最坏参数组合重算；各策略单独核算可能双双通过、组合后爆容。

### 3.5 尾块按实际有效维度走分支

三维权重的尾块按实际值走独立分支，块内循环边界用实际值，不得按满块读越界。

### 3.6 驻留块的覆写时机（仅 Level 2 驻留重排形态）

多块「驻留—消费」交替时，覆写驻留块前必须确认消费者已完成（事件/队列语义），不得提前覆写。Level 1（host tiling 档位调整）不涉及本条。

### 3.7 对齐与 dtype 约束

选块须兼顾写回地址对齐与 dtype 字节数（不同 dtype 推荐块不同，换 dtype 重算）；对齐粒度按目标设备资料取。

## 4. 泛化条件

满足以下条件时可以进入候选：

- 剖析确认搬运占比高、计算利用率低的形态（msOpProf 口径，或理论带宽估算判据）。
- 片上容量内有比当前更大的可行块（容量枚举有解），且放大后总块数仍 ≥ 物理核数一半（§3.1）。
- 矩阵乘沿归约维分块、输出分块可独立计算。

以下情况不适用：

- 放大后总块数 < 物理核数一半，且搬运节省不能补偿并行度损失（如 M=128 单 M 块 × 中小 N；此场景应改走补并行度类策略，而不是继续放大块）。
- 已接近带宽或容量上限，增大块后驻留块与复用块不能共存；或 Vector 侧 UB / GM workspace 在组合最坏参数下越界。
- 矩阵计算利用率已高（非搬运主导），放大块无收益空间。
- shape 本身极小，任何分块都只有一块。

### 4.1 回退面（2026-09-22 新增，与受益面同等重要）

- 本策略收益**高度集中于带宽受限的大 case**；多数中小 case 在噪声带内（8 轮实测仅 2 轮有效）。
- 放大块会制造多核并行度瓶颈（§3.1）：M=128 单 M 块等形态劣化 +29%~+42%。
- 个别 shape 回退幅度可达 **-34%**，几何平均会被拖负；选路前须评估**受益 case 占比是否足以拉动 geomean**，占比不足则不选。

## 5. 实施步骤

实施分两级，优先 Level 1，Level 1 无档位可调或收益不足时才走 Level 2：

- **Level 1（host tiling 档位调整，首选）**：只改 host 侧 tiling 的 base 块封顶档位（含 §3.1 守门条件），kernel 零改动，不存在驻留块覆写时机问题。须先过守门红线与容量核算（§3.2/3.3/3.4）。
- **Level 2（kernel 内驻留循环重排，侵入式）**：无 tiling 档位可调或 Level 1 收益不足时，改造 kernel 外层循环为驻留侧重排；此时才涉及覆写时机红线（§3.6）与事件同步成本。

1. 采集占比数据确认搬运占比与计算占比（msOpProf 口径，或理论带宽估算判据），判定本条适用。
2. 按目标硬件片上容量枚举候选基本块，逐个算访存计算比。
3. 用容量约束（含 Vector UB/workspace/组合最坏值）加写回对齐过滤，再叠加 §3.1 总块数守门，取最小比值。
4. Level 1 改 tiling 档位；Level 2 外层循环按块推进：驻留块上做完对侧维度全部累积计算再释放。
5. 尾块单独分支；复测搬运 pipe 时间与矩阵计算占比（或同 case A/B 的 kernel Duration）。

## 6. LLM 前置问题

以下问题任一无法回答时，不实施：

1. 当前搬运 pipe 与计算占比分别是多少，块大小是多少？须先声明采集口径（msOpProf PipeUtilization，或理论带宽估算）；走估算口径时必须列出算式（理论搬运量 ÷ 有效带宽 vs 实测 kernel Duration），不得省略或臆造占比数字。
2. 候选块的访存计算比各是多少，最小者在哪？放大候选相对当前块的 GM 搬入量绝对减少量是多少（与问题 8 的上界估算衔接）？
3. 目标硬件三级片上缓冲容量从何处查询，候选块按字节核算后余量多少？Vector 侧 UB 与 GM workspace 余量多少？
4. 目标算子全部典型 shape 的「放大后总块数」分布如何？哪些落入守门关闭分支（< 物理 AIC 核数一半，§3.1）、走原块路径，回退分支是否验证（同一算子的不同 case 常落在守门两侧）？
5. 写回地址对齐要求是什么，块参数如何满足？
6. 与已叠加的其他块优化组合后的最坏参数组合是什么，容量是否仍通过？
7. 尾块按实际有效维度走分支的处理是什么（Level 1 与 Level 2 均适用：Level 1 改档位后尾块行为同样变化）？
8. 收益上界估算：本次改造的理论可省搬运时间 ÷ 实测 kernel Duration 是多少？上界低于噪声或 <5% 时不值得开工，应直接放弃或改选其他策略。

覆写时机（§3.6）仅 Level 2 驻留重排形态涉及，走 Level 2 时追加自问：覆写驻留块前如何确认消费者已完成？

## 7. 验收标准

- **构建**：编译通过，块参数在三级缓冲容量内（含双缓冲系数、Vector UB、GM workspace、组合最坏值）。
- **精度**：整除、非整除、最小尾块用例全部满足既有误差标准。
- **性能**：搬运 pipe 时间下降、矩阵计算占比上升（msOpProf 口径），或同 case A/B 的 kernel Duration 下降；端到端改善。
- **零劣化**：全部既有 case 的最差回归不超出噪声水平（均值改善会掩盖个别 case 显著劣化）。
- **收益域探针**：按机制推导收益 shape 域（如 M、N 足够大、放大后总块数仍 ≥ 核数一半、K 足够长），构造预测 shape 实测验证；现有用例不含收益 shape 时，探针命中即可确认策略有效，避免用例分布偏斜导致误判不适用。
- **归因**：数学计算量与输出语义不变，收益可归因于重复搬运消除。
- **回退**：容量不足、对齐不满足或守门不过的 shape 走原块路径。

## 8. Level 2 专章附录：驻留重排的深层红线（迁移自 cv-A3/02，已激活，目标任务仍需 A5 复测）

> **状态说明**：本附录材料来自 cv-A3 已验证策略 `02-operand-persistent-onchip`（A3 库评分 0.7，requires = mn_multicore_partition——驻留收益依赖任务按宏块/分组聚拢分配），现作为策略 02 的 active 实施红线。该状态表示可被 A5 选择器使用，不表示跨架构免验证；每次应用仍须在目标 A5 任务上完成容量核算、精度验证与 A/B/A 稳定性能复测。正文 §3.6（驻留块覆写时机）与 §5（Level 2 流程）是本附录第 4、6 条的泛化表述，本附录给出全套细节。

### 8.1 启用前置：任务按分组聚拢

驻留收益依赖「同一列段的多个行段集中到同一核」。任务分配**跨分组交错**（每核处理多分组）时，预加载全部所需分组的右操作数反而比逐块多搬——负收益，禁用本 Level 2 路径；反转条件：任务改为按分组聚拢（每核只处理少数分组/宏块，配合 `03-mn-multicore-partition` 的宏块/分组聚拢分配）后方可启用。

### 8.2 红线清单

1. **循环重排不改累加语义**：每个 (行段, 列段) 的归约维累加仍完整——首次归约块初始化累加器、后续块累加；**跨列段（外层切换）必须重置初始化**，忘重置即累加脏值。重排只改遍历顺序，不改任何一块的计算内容。
2. **产出顺序变化与交接对齐**：重排后产出顺序从「行段连续」变为「列段连续」。存在矩阵核到向量核的中转交接时，消费侧仍按旧顺序等槽即死锁或错位——中转槽生产/消费顺序必须按新遍历序对齐，必要时调整环形深度覆盖新的复用距离。
3. **驻留加载形态：逐归约块搬运 + 显式块偏移**：驻留缓冲由多个归约块拼成时，必须逐归约块搬运、每块写入**显式块偏移**（偏移按块内完整元素数计——含分形填充——而不是归约步长），并保证块摆放与矩阵计算单元取数布局严格一致，错位即数值错。**分形最小单元较小的数据类型（如双字节浮点）禁止「单条搬运一次载多个归约块」的形态**：大列数下硬件会把各块在片上错位放置，数值崩；加全流水排空反复锤无效——这是布局错误而非同步竞争。此条在 A3 实测确立，**A5 上须按 arch35 装载/分形语义复验后再引用**。分形单元较大的类型（如单字节整型）不易触发，但不能因此照搬到窄类型。
4. **片上预算守卫（防越界崩溃）**：驻留需求超可用容量必须回退逐块路径，否则片上越界崩溃（大归约维形状必炸）。守卫在初始化阶段算一次即可。可用容量的计算**只计真正落在该级片上缓存的缓冲**：更内层的暂存（矩阵计算单元私有的暂存级）不占该级容量，误计会使可用量过度保守、白白放弃驻留。
5. **驻留缓冲生命周期**：驻留缓冲只在列段边界（切到下一列段/下一宏块）才允许覆盖。下一驻留加载（搬运流水写）不得早于本列段最后一次取数（矩阵计算单元读）完成——用多级队列的入队/出队天然保序，或用跨流水事件同步原语显式排序。（正文 §3.6 覆写时机即本条在单块驻留—消费交替上的表述。）
6. **归约维等长前提**：驻留快路径假设归约维被等长分块。归约维不是块高整数倍且未在主机侧补齐（存在尾块）时，必须回退逐块路径（带尾块处理），不得走驻留路径。
7. **行尾有效数的语义边界**：行尾块的有效行数**只约束全局内存读取的行数**（搬运侧把有效行补齐到块高），不改变矩阵块形状——矩阵核恒按完整块高计算，补齐行的结果由向量侧按有效行掩码丢弃。把有效行数误当矩阵块高传入计算，尾块即漏算或多算。
8. **调度开关必须显式初始化**：驻留开关经调度参数缓冲下发时，若该缓冲不是零初始化的（未写入即读到残留值），漏置会把垃圾值当「开」——驻留缓冲按错误尺寸分配导致片上越界异常。关闭态必须显式写零值。
9. **已知陷阱汇总**：驻留需求没做预算守卫 → 大归约维崩溃；驻留块偏移按归约步长而非块内完整元素数算 → 计算单元读错归约块；窄数据类型照搬宽类型的单条多块搬运形态 → 大列数数值崩；跨列段忘重置累加初始化 → 脏值累加。

### 8.3 验收注意（叠加本附录时）

走 Level 2 并叠加本附录红线后，除正文 §7 外追加验证：人为构造超长归约维与归约尾块用例，回退路径精度仍全部通过；窄 dtype 大列数不崩（验证逐块搬运形态）；「行段数为 1（无复用收益）」形状与基线持平（不误伤）。

## 检索卡（短卡）

动作：增大二维基本块让驻留块被对侧维度复用，按「访存计算比最小」在片上容量约束下选块，减少操作数块从 GM 重复搬入。
适用：搬运 pipe 占比高、矩阵计算利用率低；片上容量内有更大可行块且放大后总块数≥物理核数一半。
限制：总块数不得低于物理核数一半；Level2 驻留重排须任务按分组聚拢、跨列段重置累加、超容量回退逐块路径；收益仅带宽受限大 case，个别 shape 回退可达 -34%，须评估受益 case 占比
范围：矩阵乘类算子的基本块选取与 GM→L1 搬运环节。
检索词：访存计算比、驻留块复用、baseM、baseN、L0A、L0B、L0C、PipeUtilization、msOpProf、驻留重排。
机会：搬运 pipe 占比高（如七成）矩阵计算不足两成，每个操作数基本块从 GM 重复搬入，计算单元大量空闲。
代价：大块顶满容量即失效；开双缓冲后缓冲份数翻倍须重算。
