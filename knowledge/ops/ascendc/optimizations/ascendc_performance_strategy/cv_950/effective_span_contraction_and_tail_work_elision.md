# 性能优化策略：按有效跨度收缩尾块计算与向量工作域

> 库内状态：`active`。已在 A5 的矩阵与向量路径分别完成正确性和稳定性能验证，进入可选择策略库。

> 单一优化点：物理块或面板为对齐而按最大跨度分配时，执行计数、矩阵乘维度、转置网格和清零范围只覆盖对齐后的真实有效区，避免尾块继续计算或搬运整块填充区。

## 1. 原理

布局容量可以保持满块，执行跨度不必等于满块。将真实有效行列向上取到指令要求的最小对齐，分别驱动矩阵乘维度、片内搬运步距、写回源跨度、向量 count、转置子网格和清零区。满块输入退化为原路径，尾块只跳过不会被任何消费者读取的填充工作。

## 2. 性能问题模式

- 小尺寸或尾块仍按基本块满跨度执行乘加。
- 向量 count、转置网格或清零区域与真实行列数解耦。
- 有效数据很少时，固定的填充区工作成为主成本。
- 满块场景性能正常，尾块比例越高越慢。

## 3. 正确性红线

- 执行跨度必须满足矩阵、向量和搬运指令各自的最小对齐。
- 源布局的物理步距与收缩后的目标步距要分别推导，不能把逻辑宽度当物理 pitch。
- 后续若会满宽读取 padding，则被跳过区域必须预先置为语义安全值。
- 写回严格按有效字节截断，不能因内部对齐扩大写出范围。
- 归约轴的计算顺序与精度契约不属于本策略的改动面。

## 4. 泛化条件

适用：块级布局固定、真实有效跨度运行时可知，且尾部填充计算或搬运在剖析中占比显著。

不适用：硬件指令只能处理固定满块；下游依赖填充区的确定值；收缩后引入的步距与分形转换不合法。

## 5. 实施步骤

1. 区分逻辑有效跨度、指令对齐跨度和物理布局跨度。
2. 用对齐有效跨度驱动计算 count 或矩阵维度。
3. 保持源侧物理 pitch，独立重算片内目标 pitch 与写回跨度。
4. 对转置、清零和辅助表采用同一有效网格，证明未覆盖区不可观察。
5. 满块路径做恒等性检查，尾块覆盖最小、临界与最大有效跨度。

## 6. LLM 前置问题

1. 哪些循环或指令仍使用满块跨度？
2. 有效跨度的来源和最小合法对齐是什么？
3. 源、目标与累加器的物理 pitch 是否会随执行跨度变化？
4. padding 是否可能被下游满宽消费？
5. 省掉的工作是否位于关键流水？

## 7. 验收标准

- 满块路径与基线控制流或生成参数一致。
- 尾块精度通过，重点覆盖最小有效跨度、非整除边界和 padding 消费。
- 矩阵路径来源验证整体验证加速比 `1.0496x`；向量面板的尺寸自适应与批量化组合来源验证加速比 `1.6730x`。
- 剖析确认无效乘加、转置子块或向量元素数按有效跨度下降。
