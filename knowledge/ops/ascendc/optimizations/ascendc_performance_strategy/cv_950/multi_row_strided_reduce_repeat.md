# 性能优化策略：多行步距归约 Repeat 合批

> 库内状态：`active`。已在 A5 完成全量精度与稳定配对验证，进入可选择策略库。

> 单一优化点：多行独立归约若逐行发射一次归约并逐行插入屏障，改用带 repeat 和行步距的归约指令一次描述整批行，把标量发射与屏障从按行缩减为按行块。

## 1. 原理

行间无数据依赖且片上布局具有固定行距时，一条 repeat 归约可以让每个 repeat 对应一行、结果按固定目标步距落入独立槽。向量引擎内部完成多行归约，只需在整批结果被消费前建立一次依赖。

## 2. 性能问题模式

- 每行一条归约 API，伴随标量回读或逐行屏障。
- 行数大时向量流水利用率不高，但标量和同步开销线性增长。
- 输入行距规则，输出每行只需少量标量结果。

## 3. 正确性红线

- mask、repeat 数、源 repeat 步距和目标 repeat 步距必须按接口单位分别推导。
- 每行有效长度与物理行距不可混用；尾元素不得进入归约。
- 输出槽必须互不覆盖，并满足打包结果的对齐要求。
- 合批后的单次屏障必须覆盖归约写回到后续消费者的真实依赖。
- 超出 repeat、地址范围或片上容量上限时分块执行。

## 4. 泛化条件

适用：多行独立、等长或可统一 mask、固定片上行距、逐行归约发射和屏障主导。

不适用：行长或地址完全不规则；行间有依赖；接口不支持所需数据类型、mask 或步距。

## 5. 实施步骤

1. 从目标架构接口确认 repeat 和步距的单位与上限。
2. 将每行映射为一个 repeat，推导源行距和目标标量槽距。
3. 尾行按有效行数截断，尾列由 mask 截断。
4. 合批归约后只在首个消费者前建立一次必要同步。
5. 对单行、最大 repeat、尾列和多批边界做精度覆盖。

## 6. LLM 前置问题

1. 逐行归约和屏障各发射多少次，是否位于关键路径？
2. 源行距、有效长度与目标槽距分别是多少？
3. 接口的 mask、repeat 和步距单位及上限是什么？
4. 结果写回由哪条流水完成，消费者前需要什么事件？
5. 超上限时的分批边界是否保持行唯一归属？

## 7. 验收标准

- 全量精度通过，覆盖单行、尾列、最大批次和跨批边界。
- 来源验证整体验证加速比 `1.0662x`，两组平衡交替配对同向。
- 剖析确认归约指令数与屏障数按行块收缩，标量发射占比下降。
