# 性能优化策略：整面板搬运与片上索引转置（逐列发射链坍缩 + 三引擎双槽流水）

> 库内状态：`active`。已进入可选择策略库并纳入自动路由。来源为一批 A5 向量核任务的独立探索轨迹第三方向脱敏归档：单一 Campaign 内完成构建（1 修复）、全量精度（22/22，1 修复后逐位等价）与正式稳定配对验证（2 对平衡交替、同 shape、溯源干净），全集相对加速 2.5717（22/23 用例改善，1 个极窄形态用例在预登记守卫带内）。修复轮约束已并入 §3 红线；验证记录见 §7。

> 单一优化点：每 tile 的逐列/逐行搬运发射链（搬运指令数随 2×列数增长、数据块数为行×列个 sub 对齐粒度小块，发射开销主导稳态成本）坍缩为整面板数据通路：一笔行面板二维装载（块数 = 行数、块长 = 有效列字节、源步距 = 行距−有效宽）→ 片上向量管逐输出行索引收集完成转置（一次仿射索引表 + 每输出行一次收集）→ 一笔二维面板写（含尾部补零一笔二维零写）→ 双槽轮转配每槽事件对，使装载/向量/写出三引擎重叠。

---

## 1. 原理

- **发射计数坍缩（主杠杆）**：逐列通路每 tile 发射约 2×列数条搬运指令、产生行×列个 sub 对齐粒度数据块；整面板通路每 tile 仅 2–3 笔指令、行数+列数个宽块。每列稳态成本平坦、随并行度不摊薄（跟踪块宽而非字节量）的形态，在面板化后关键路径坍缩到 tile 级个位数发射。
- **布局分工**：装载侧一笔连续行面板（片上俯仰 = 对齐取整(有效列字节)）；转置移入片上（每输出行一次索引收集，行俯仰 = 对齐取整(有效行数)——收集微码以行为批、无逐块栅障，区别于被移除的微码转置原语）；写出一笔二维面板（源步距 = 0、目的步距 = 补齐宽−有效宽），尾部补零一笔二维零写。
- **三引擎双槽流水（次要增强）**：面板槽 A/B 轮转，每槽独立事件对（装载完成/向量完成/写出完成）；下一面板装载在当前面板向量转置发射后、其完成等待前发射——装载/向量/写出重叠；尾部逐已用槽排空。

**定性归因**：每 tile 搬运指令数与数据块数可计算地坍缩（数量级下降）；跨管等待链从列数级降到每 tile 个位数。这是判断本策略是否对症的主判据。

**语义去重边界**：
- 与「归约循环操作数整 Tile 批量装载」卡不同：彼卡在同一装载路径上合并发射粒度、布局语义不变；本卡重构数据通路分工——装载形态变化使转置从全局侧跨距收集移到片上收集，装载/转置/写出的布局契约须协同重推导。
- 与「行块级带源步距批量写」卡不同：彼卡只合并写出发射形态；本卡写侧合并是整面板重构的一个面，且与装载/转置协同。
- 与「AIV Chunk 级双缓冲流水」卡不同：双槽事件环是通用流水骨架；本卡单点是发射链的平方级坍缩（骨架可叠加复用）。
- 与「转置折入搬运描述符」卡互为反相方案：彼卡把转置留在搬运描述符（逐列组装载 + 逐行散写）；本卡把转置收回片上收集、搬运恢复连续面板形态——当逐列/逐行发射链本身成为墙时选本卡。

## 2. 性能问题模式

低效形态：

```python
# 前：每列一笔装载 + 每行一笔写（指令数 ~2×列数，块数 行×列 sub 粒度）
for tile in tiles:
    for col in cols:  gather_load_2d(col_block)      # 每列一笔
    transform()
    for row in rows:  scatter_store_2d(row_block)    # 每行一笔

# 后：每 tile 2–3 笔 + 片上收集转置 + 双槽三引擎流水
for t, tile in enumerate(tiles):
    load_panel_2d(slotA[t%2], blocks=rows, blocklen=valid_cols, srcstride=pitch-valid_cols)
    build_affine_index(); for j in out_rows: gather(dst_row(j), panel, idx, base=j)
    store_panel_2d(dst, blocks=out_rows, blocklen=valid_rows, dststride=padw-valid_rows)
    zero_store_2d(pad_region) if padw > 0
```

指纹：

- 每列稳态成本平坦且不随并行任务数摊薄（跟踪搬运块宽而非字节量的特征）。
- 搬运指令数/事务数随列数、行数乘积堆积；时间线上发射链绑定关键路径。
- 列数大的用例显著慢；单列极窄用例面板深度最小（守卫对象）。

## 3. 正确性红线

### 3.1 二维零写的源区尺寸（最易翻车）

二维批量零写的源俯仰是步距语义：单块长度的零源会使第 2..N 块越界读。零源区必须按 (块数−1)×源步距 + 块长 分配（或等价满幅零区）。

### 3.2 收集偏移位宽上界

单面板最大偏移 (行数−1)×面板俯仰 + 最大行内偏移必须 < 收集偏移寄存器位宽（半字形态 2^16）；tile 网格放大须重核算并守门。

### 3.3 索引表尾行保护

索引表长度覆盖物理行数，有效行之外的表项恒零（初始化零化 + 缩放只写前缀），防止收集掩道越界读。

### 3.4 引擎步距量化不对称

全局侧步距字节粒度、片上侧固定粒度取整；装载俯仰与写出源俯仰各自按所属引擎量化推导，不得互套。

### 3.5 全局内存读写各一次契约

面板化不得破坏「有效区恰读一次、有效+补零区恰写一次」契约；宽元素类型的低位折叠并入收集基地址（字节偏移）时需端序前提复核。

### 3.6 数值等价

数据只被重排（收集微码）与按位折叠：输出与基线逐位/逐字节等价；差异优先排查 3.2/3.4/3.5。

## 4. 泛化条件

必须同时满足：

- 逐列/逐行搬运发射链主导稳态成本（指令数/块数证据、每列成本平坦特征）。
- 行面板可整装：行距规则、单面板（含双槽两份）落在片上预算内。
- 收集偏移上界成立；片上俯仰满足两引擎量化与最小对齐。
- 三引擎可异步重叠（事件预算 ≥ 2 槽 × 每槽对数）。

禁止条件（任一即不实施）：

- 面板超片上容量且无分块方案。
- 收集偏移上界越界。
- 转置不在关键路径或收集微码吞吐证伪。
- 极窄单列形态为主（面板深度最小，走守卫回退路径）。

## 5. 实施步骤

1. 用指令/块数统计与每列成本平坦证据确认发射链主导。
2. 推导装载俯仰、收集行俯仰、写出来源俯仰三者的量化闭环（分别按所属引擎）。
3. 把逐列装载改为一笔行面板装载；逐行写改为一笔二维面板写 + 尾部一笔二维零写。
4. 构造仿射索引表（尾行恒零保护），以每输出行收集完成片上转置。
5. 面板双槽轮转 + 每槽事件对组织「装载(t+1) 与 转置(t)/写出(t) 重叠」；尾部逐槽排空。
6. 保持 host tiling/分配与读写一次契约零改动。
7. 覆盖尾组、尾行、非整块、极窄形态、多 dtype 的精度与平衡交替配对性能验证。

## 6. LLM 前置问题

1. 每 tile 当前搬运指令数与数据块数是多少？每列稳态成本是否平坦（发射链主导证据）？
2. 三层俯仰（装载/收集行/写出源）各自的量化取整与最小对齐如何闭环？
3. 收集偏移最大值是多少，相对位宽上界余量多少？
4. 二维零写的源区尺寸如何按步距公式分配？
5. 双槽 × 每槽事件对是否在事件预算内？哪些极窄形态走守卫回退？

## 7. 验收标准（验证记录）

- **构建**：目标硬件编译通过（来源 Campaign 1 修复内通过；二维零写源区约束并入 §3.1）。
- **精度**：全量用例逐位等价（来源 Campaign 22/22，1 修复）。
- **性能**：正式配对口径相对加速 2.5717（2 对平衡交替、两对逐侧均值一致；22/23 用例改善；1 个极窄形态用例微回退在预登记守卫带内，须显式登记）。
- **归因**：每 tile 搬运指令数从列数量级降到个位数有指令面证据；三引擎重叠有时间线证据。
- **回滚**：恢复逐列装载 + 逐行写通路即回滚；极窄形态按守卫独立回退。

## 检索卡（短卡）

范围：tile 级数据通路（装载-转置-写出）重构。
