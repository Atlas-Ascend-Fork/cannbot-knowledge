# 性能优化策略：核亲和面板复用与跨 Tile 流水

> 库内状态：`active`。已进入可选择策略库并纳入自动路由。来源为另一批 A5 matmul 任务自动探索的脱敏归档：单一 Campaign 内完成构建（0 修复）、全量精度（24/24，all scope 逐位一致，0 修复）与正式稳定配对验证（2 对平衡交替、同 shape、溯源干净，两对 geomean 比值 1.1360/1.1352 一致为正），全集相对加速 1.1356；一个非启用分段归约用例存在约 2% 量级微回退，登记为 residual risk。正确性红线见下文。

> 单一优化点：多核矩阵乘把输出 tile 按跨步轮转均匀撒到各核时，共享同一操作数面板的相邻 tile 落在不同核、被各自从全局内存重复读取，聚合读流量随 tile 网格放大、多核聚合带宽争用超线性增长；改为连续块核亲和指派（共享面板的相邻 tile 同核，面板驻留片上被后续 tile 复用），同时把累加器队列加深为双槽使前一 tile 的写回与后一 tile 的矩阵计算跨 tile 重叠，并移除 tile 间全屏障；可选地按最小串行成本门做自愿配对减核。只改「哪个核算哪个 tile / 写回如何重叠」，不改任何 tile 的数值路径。

> ⚠️ **库内状态：降级为「部分可实施」（原 4 子机制中 3 个被自身红线封死）**。7 轮实测 **0 轮有效**。子机制可实施性分级：
> - ① **连续块核亲和指派** = **可独立实施**（本卡唯一可落地子机制，实测收益约 2.4%）。
> - ② **累加器双槽跨 tile 流水** = 受 §3.2「双槽轮转槽回收事件序须有语义证明」前置约束，本栈上多数情况无法证明 → 默认不实施。
> - ③ **tile 间全屏障移除** = 受 §3.2/§3.6 约束，分段归约族无收益甚至微回退 → 仅限无跨核同步的纯 tile 串行族。
> - ④ **自愿配对门** = 受 §3.5 负向边界封死 → 不实施。
> **采纳时默认只做 ①；②③④ 须各自独立立项验证，不得打包实施**（打包会导致 4 个子机制互相否决、整卡失败）。

## 1. 原理

四个互相独立、可分别验证的子机制，共同作用于「多核聚合带宽争用 + tile 边界串行」：

- **核亲和连续块指派**：跨步轮转把 tile 按步长撒开，共享 A 面板（同行）或 B 面板（同列）的 tile 被分到不同核同时执行，面板按对侧 tile 数被重复读取（A 按 N-tile 放大、B 按 M-tile 放大），聚合读流量成倍增长。连续块指派（chunk=ceil(units/coreNum)，每核处理一段连续 tile 区间）让共享面板的相邻 tile 落在同一核：第一个 tile 装入的面板驻留片上，第二个 tile 直接复用，消掉一份重复的聚合 GM 读流。chunk=1（每核单 tile）时每核单元集合与原调度等价，无多 tile 的 case 调度不变。
- **累加器双槽跨 tile 流水**：累加器队列（L0C 类）深度为 1 时，tile n 的写回排空阻塞 tile n+1 的装载与矩阵计算，tile 边界被串成链。加深到 2 槽按槽号轮转后，tile n 的写回（读槽 n%2）与 tile n+1 的矩阵计算（写槽 (n+1)%2）跨 tile 重叠。容量约束：2 × 单 tile 累加器必须落在目标硬件 L0C 容量内。
- **tile 间全屏障移除**：计算块尾部每 tile 一次的全流水屏障把所有流水排空成串行点，其自身即构成每 tile 一次的亚微秒级固定开销。槽位回收若已由队列框架「写回完成事件 → 生产者」的事件序保证，该屏障是冗余的；移除后所有逐 tile 串行的 case 普遍受益，不限于每核多 tile 形态。
- **自愿配对门（可选）**：块数充足且每单元只有一个归约段时，减半参与核数、每核顺序计算两个相邻 tile，用最小并行度代价换面板重读减半与发射核数减半。串行加倍成本随每单元归约段数线性增长，门必须按「单归约段 + 块数阈值 + 核数合法区间」收紧（见 3.5）。

定性归因（相对基线）：聚合 GM 读流量按 tile 网格可计算地下降；写回与矩阵计算在时间线上交叠；每 tile 固定屏障开销消失。多核大流量家族（每核多 tile、面板重读放大倍数大）收益最大。这是判断本策略是否对症的主判据。

## 2. 性能问题模式

- 输出 tile 按 M/N 网格切分、多核轮转指派；多核 case 实测时长显著超出单核模型外推，超额随聚合 GM 流量超线性增长（有效带宽膝特征）。
- 同核负载隔离证据：每核流量相同的两个 case，核数多、聚合流量大者显著更慢——排除每核工作量因素，锁定聚合带宽/延迟争用。
- 面板重读放大可计算：A 面板读取量 ×N-tile 数、B 面板读取量 ×M-tile 数，均高于唯一面板体积。
- 累加器单槽 + 每 tile 尾部全屏障：装载、矩阵计算、写回无法跨 tile 重叠，tile 序列串行。
- 每核 tile 数越多、面板共享越强的家族越慢；单核 / 无面板共享的 case 只可能从屏障移除子机制获益。

## 3. 正确性红线

### 3.1 指派面不得改变数值路径

只改「哪个核算哪个 tile、面板从哪里读」。每个 tile 的计算、累加序、写回路径必须逐位不变；tile 之间不得引入任何数值交互。本策略的精度预期是**逐位一致**，出现任何数值差异都是实现越界的信号，不是容差问题。

### 3.2 双槽轮转的槽回收必须由队列事件序保证

移除全屏障后，槽位回收正确性完全依赖所用队列抽象在双槽轮转下建立的「写回完成 → 生产者可写」事件序。必须从队列接口语义确认该序存在且覆盖跨 tile 场景，不能用「精度碰巧通过」替代语义证明；证明不了就保留屏障、只取指派面收益。

### 3.3 零余量容量方案

2 × 单 tile 累加器恰好占满 L0C 容量属于零余量方案：编译器临时缓冲、对齐膨胀或后续任何加深都可能击穿。启用前必须按目标硬件真实容量核算对齐后字节数；即使片上其他队列已有同类零余量先例，也要按本次参数重新核算，并把零余量登记为脆弱前提。

### 3.4 面板复用与首段初始化语义

后一 tile 复用同核驻留面板时不得引入对面板的写（只读复用）；累加器首段初始化（如首段覆盖语义）在双槽轮转下必须对每个 tile 独立成立，不得被跨 tile 重叠搅动时序。

### 3.5 自愿配对门不得放宽（负向边界，可判定）

减半核数使每核串行计算两个 tile，串行成本随每单元归约段数线性增长。仅当每单元只有一个归约段（串行加倍成本最小）且块数达到阈值、折算核数落在合法区间内时允许配对。多归约段形态已被串行成本模型否决——串行加倍成本超过可回收的争用超额；不要按「面板共享更多」的直觉放宽门。

### 3.6 已有跨核同步协议保持不变

本策略移除的只是核内 tile 间全屏障；核间同步（如分段归约的跨核屏障）不属于改动面，必须原样保留。分段归约形态下尾部屏障移除无收益甚至微回退（负向边界）：目标含该族时，评估为其保留针对性屏障而不是全局恢复。

## 4. 泛化条件

适用：

- 多核矩阵乘 / tile 网格调度，tile 数不少于核数或每核多 tile。
- 面板重读放大可计算（A 按 N-tile、B 按 M-tile），聚合 GM 流量接近或超过带宽膝，且有同核负载隔离或超额-流量标度证据。
- 2 × 单 tile 累加器可驻留 L0C（或零余量前提被明确接受并登记）。
- tile 数值路径相互独立，指派面可自由重排。

不适用 / 需保守：

- 单核或每核单 tile 且无面板共享：指派面无收益，仅屏障移除子机制可能有小收益。
- 每单元多归约段的自愿配对（3.5 负向边界）。
- 写通路独占饱和：读流量削减收益减半，只剩跨 tile 流水与屏障移除收益，预期应下调（仍可为正）。
- 分段归约尾部由跨核同步主导的 case：屏障移除对该族无收益甚至微回退。
- 队列抽象无法证明双槽轮转事件序（3.2 前置失败）。

## 5. 实施步骤

> **实施范围收紧（2026-09-22）**：默认只做步骤 3（连续块核亲和指派）。步骤 4/5/6 分别对应子机制 ②③④，**须拆成独立轮次单独立项、单独验收**，不得与步骤 3 混在同一次改动内。

1. 用单核模型外推 + 多核实测差做超额-流量标度，并用同核负载隔离（每核流量相同、核数不同）排除每核因素，确认聚合带宽争用为瓶颈。
2. 统计 tile 网格的面板重读放大（A ×N-tile、B ×M-tile），估算连续块指派可消除的重复读流量与预期收益区间。
3. 把跨步轮转指派改为连续块指派（chunk=ceil(units/coreNum)，核 c 处理连续区间）；确认 chunk=1 的 case 调度逐字节不变。
4. 按对齐后字节核算 2 × 单 tile 累加器与 L0C 容量，登记零余量前提（如适用），再加深队列到双槽按槽号轮转。
5. 从队列接口语义确认双槽轮转的槽回收事件序后，移除计算块尾部每 tile 全屏障；证明不了则保留屏障。
6. 若每单元单归约段且块数达到阈值，按串行成本模型评估自愿配对门（减核成对指派），门参数写入形状门控。
7. 精度按逐位一致验收；性能做平衡交替配对测量，机制启用 case 与仅屏障移除受益 case 分开归因，非启用族核查无超噪声回退。

## 6. LLM 前置问题

1. tile 网格与面板共享结构如何？A/B 面板各被对侧 tile 数放大多少倍？
2. 多核超额随聚合 GM 流量如何标度？带宽膝与同核隔离证据是什么？
3. 2 × 单 tile 累加器的对齐后字节数与目标 L0C 容量差多少？零余量是否被接受并登记？
4. 所用队列抽象在双槽轮转下的「写回完成 → 生产者」事件序是否有语义证明？
5. 每单元归约段数是多少？自愿配对的串行成本模型输出是否为净正？
6. 哪些 case chunk=1 调度不变？哪些 case 启用？分段归约族是否需要针对性屏障？回退条件是什么？

第 2、3、4 项任一无法回答，不实施。

## 7. 验收标准

- **精度**：全量用例逐位一致（纯指派 / 槽位 / 屏障面改动）；任何非逐位差异先查 3.2/3.4，不做数值侧兜底。
- **性能**：至少 2 对平衡交替配对比值一致为正、同 shape、溯源干净；机制启用 case 与屏障移除受益 case 分开归因；非启用族无超噪声回退，分段归约族微回退须显式登记。
- **归因**：只改指派顺序、累加器槽深与 tile 间屏障；禁止混入块大小、数值路径或跨核协议改动。
- **安全性**：槽回收事件序、L0C 对齐后容量、配对门参数均有可审计证据；零余量前提显式登记。
- **回退**：恢复轮转指派 / 单槽 / 尾部屏障即回滚；自愿配对门按 case 形态独立开关，门不满足即走原核数路径。

## 检索卡（短卡）

动作：把跨步轮转 tile 指派改为连续块核亲和指派（共享面板相邻 tile 同核复用），累加器队列加深双槽使写回与计算跨 tile 重叠，移除 tile 间全屏障。
适用：多核 tile 网格、tile 数不少于核数；面板重读放大可算、聚合 GM 流量近带宽膝；2×单 tile 累加器可驻留 L0C。
限制：tile 数值路径须逐位不变；双槽回收须由队列事件序证明否则保留屏障；零余量容量须登记；配对门仅限单归约段；分段归约族保留屏障；仅「连续块核亲和指派」可独立实施，其余 3 子机制被自身红线封死，不得打包
范围：多核矩阵乘 tile 网格调度与累加器写回。
检索词：核亲和、连续块指派、面板复用、L0C 双槽、tile 间屏障、带宽膝、chunk 指派。
机会：轮转指派使共享 A/B 面板被对侧 tile 数放大重读，多核时长随聚合流量超线性增长，累加器单槽串行 tile 边界。
代价：写通路独占饱和时读流量削减收益减半，预期应下调。
