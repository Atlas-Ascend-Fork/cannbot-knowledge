# 性能优化策略：显式向量索引转置替代微码转置原语

> 库内状态：`active`。已进入可选择策略库并纳入自动路由。来源为一批 A5 向量核任务的自动探索脱敏归档：单一 Campaign 内完成构建、全量精度（22/22，与基线逐字节等价）与正式稳定配对验证（2 对平衡交替、全部用例两对同向加速、无回退用例），全集相对加速 10.732。实现过程中的修复轮约束已并入 §3 红线；验证记录见 §7。

> 单一优化点：高阶库转置原语（微码实现）内部按最小对齐块逐块「搬运 + 向量管栅障」的串行链主导全部用例时，放弃该原语，改为显式向量索引收集完成转置：常驻构造等差索引表（初值表 + 一次仿射修正生成，跨行共享），对每个输出行调用一次字节粒度索引收集原语，行间零栅障；整块暂存 scratch 缩减为单张索引表。

---

## 1. 原理

**微码转置原语的低效形态**：转置由库原语承担时，其内部把数据按最小对齐块逐块搬运，且每块紧跟一次向量管栅障（搬运引擎与向量管在同一原语内混用，块间无法流水）。块数随元素量线性增长，栅障链把转置段钉成串行段，成本近似「每元素常数斜率 × 元素量」。

**显式收集形态**：

- **共享等差索引表**：输出第 w 行第 j 个源位置 = j×源行距 + w，是等差数列。先以对齐安全的向量算术链构造初值索引表，再一次缩放把初值表变为「以源行距为公差」的共享表；表构造一次、跨行跨块复用。
- **每输出行一次收集调用**：目的 = 输出行起点，源 = 整块源的字节视图，偏移 = 共享表，基地址 = 行号。收集原语自身不插栅障；每块仅表生成后与循环尾部各一次栅障。
- **scratch 收缩**：整块数据暂存降为单张行宽量级索引表，片上预算大幅释放。

**定性归因**：向量管转置段的逐块栅障链消失，每输出行指令数降到个位数，转置吞吐由收集微码率决定。这是判断本策略是否对症的主判据。

## 2. 性能问题模式

低效形态：

```python
# 前：库转置原语（微码内逐块搬运 + 逐块栅障）
for tile in tiles:
    transpose(tile_src, tile_dst, big_scratch)   # 内部：每最小对齐块 copy + barrier

# 后：显式等差索引收集
build(iota_table); scale(table, src_row_pitch)   # 一次，跨块复用
for tile in tiles:
    for w in range(valid_out_rows):             # 每输出行一次收集，行间零栅障
        gather(dst_row(w), src_bytes, table, base=w)
```

指纹：

- 转置段耗时随元素量近线性且占 kernel 时间绝对主导；不同位宽类型同速率（无点态差异）是隔离出「转置原语本身是每元素成本主体」的证据。
- 时间线上向量管被逐块栅障切成碎片；整块暂存占用大。
- 库原语没有可关闭内部栅障链的参数。

## 3. 正确性红线

### 3.1 索引位宽上界（最易翻车）

收集原语按无符号半字截取偏移的形态下，单块最大偏移 (行数−1)×源行距 + 最大行内偏移 必须 < 2^16。tile 网格放大（行距或行数增大）时必须重核算，host 侧对超界形态守门回退。

### 3.2 向量指令对齐纪律

表生成与收集的目的/源起始地址须满足最小对齐粒度；「非对齐起始 + 子寄存器计数」组合可触发设备错误。等差表构造链必须全程对齐安全（对齐起步 + 整块倍增式构造）。

### 3.3 索引算术的支持面

索引乘加在无符号视图不被指令集支持时，用有符号视图 + 位重解释完成；视图切换不得改变表值语义。

### 3.4 数值等价

转置是纯重排：输出与基线逐字节等价；任何字节差异都是索引/基地址错误，优先排查 3.1/3.3。

### 3.5 尾块与有效行

输出行循环按有效行数截断；源行距沿用既有对齐取整契约；本策略不改装载/写回/pad 契约。

## 4. 泛化条件

必须同时满足：

- 转置段是向量管吞吐墙（占比/斜率证据，同位宽对比隔离证据更佳）。
- 库转置原语可被替换（框架不强制使用）。
- 源行距规则已知（对齐取整契约），单块索引上界满足位宽。
- 字节粒度收集原语可用，且跨行收集吞吐经配对实测证实。

禁止条件（任一即不实施）：

- 索引上界越界且无分段收集方案。
- 对齐不满足且表构造链无法保持对齐安全。
- 收集微码吞吐被配对实测证伪（预注册回滚条件命中）。
- 转置不在关键路径。

## 5. 实施步骤

1. 用时间线/占比证据确认转置原语逐块栅障链主导（不同位宽同速率是隔离证据）。
2. 从架构契约确认收集原语的偏移单位、位宽截取与对齐要求。
3. 构造共享等差索引表（对齐安全初值链 + 一次缩放），核算单块最大偏移。
4. 以输出行循环替换库转置原语；删除整块暂存，新增索引表缓冲。
5. 保持装载/写回/pad/tiling 契约零改动。
6. 覆盖尾行、非整块、最大 tile、多 dtype 的精度验证（预期逐字节等价）。
7. 平衡交替配对性能验证；预注册「收集吞吐证伪即回滚」条件。

## 6. LLM 前置问题

1. 转置段占比与每元素斜率证据是什么？库原语内部栅障链能否从实现/文档确认？
2. 收集原语的偏移单位、位宽截取与对齐契约是什么？单块最大偏移是否 < 位宽上界？
3. 索引表构造链是否全程对齐安全？索引算术是否需要视图切换？
4. 哪些形态（tile 放大/窄行）会越界？回退路径是什么？

## 7. 验收标准（验证记录）

- **构建**：目标硬件编译通过（来源 Campaign 在修复预算内通过；对齐与视图约束按 §3.2/3.3 处置）。
- **精度**：全量用例逐字节等价（来源 Campaign 22/22，all scope）。
- **性能**：正式配对口径相对加速 10.732（2 对平衡交替、每对两 run 同向、溯源干净；单用例加速范围约 7.0–25.9 倍、零回退用例）。
- **归因**：只替换转置原语与栅障链；装载/写回/tiling 零改动经差异核查。
- **回滚**：恢复库转置原语即回滚；预注册的收集吞吐证伪条件命中即回滚。

## 检索卡（短卡）

动作：放弃微码转置原语，改为常驻等差索引表（初值表+一次仿射修正）加每输出行一次字节粒度索引收集完成转置，行间零栅障，整块暂存缩为单张索引表。
适用：转置段是向量管吞吐墙且有占比/斜率证据；库原语可替换；源行距规则已知；收集吞吐经配对实测证实。
限制：单块最大偏移(行数−1)×源行距+行内偏移须<2^16，tile 放大重核算；表构造与收集须满足最小对齐；预期逐字节等价，差异先查索引/基地址。
范围：向量管转置段（微码原语主导）。
检索词：等差索引表、字节粒度 Gather、微码转置原语、向量管栅障、scratch 收缩、偏移位宽。
机会：转置原语内部按最小对齐块逐块搬运加逐块栅障，成本随元素量近线性主导全部用例，不同位宽同速率。
