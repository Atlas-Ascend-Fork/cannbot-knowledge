# 性能优化策略：归约分段跨 Block 扇出

> 库内状态：`active`。已在 A5 完成构建、全量精度和稳定配对验证，进入可选择策略库。

> 单一优化点：当单个输出块沿归约轴已有多个彼此独立的局部结果、但仍固定在一个矩阵核串行计算时，把这些分段作为独立任务扇出到空闲 Block，最后由属主按原合并树汇聚。

## 1. 原理

输出块数少于可用核数时，按输出块铺核会留下大量空闲核。若每个输出块内部已经被切成数值独立的归约分段，可把任务空间从“输出块”提升为“输出块 × 归约分段”，并保持每段内部乘加次序及最终合并树不变。非属主写独占完成标志，属主在确认全部分段可见后执行原有合并与写回。

## 2. 性能问题模式

- 输出块很少、归约轴很长，矩阵核利用率低。
- 单核顺序计算多个独立 partial，其他 Block 空闲。
- 分段计算占关键路径，最终合并占比相对较小。
- 输出块数已铺满核时，本策略没有收益。

## 3. 正确性红线

- 每个分段的归约区间、乘加顺序和 partial 存储地址必须唯一且不变。
- 属主合并的括号树与基线一致；不得借扇出改变浮点结合顺序。
- 完成标志必须由主机初始化，生产者在数据发布完成后写入；消费者读取前要有正确的跨流水与可见性保证。
- 忙等只允许轮询独占、对齐的控制区域，且必须有保守回退路径。
- 核已饱和、分段不可独立或跨 Block 可见性无法证明时禁用。

## 4. 泛化条件

适用：长归约、少输出块、存在固定数量独立 partial、目标设备仍有空闲 Block，且最终汇聚代价小于被并行化的计算。

不适用：输出网格已饱和；partial 间有数据依赖；跨 Block 协议会改变数值树；控制区无法可靠初始化或发布。

## 5. 实施步骤

1. 证明分段独立，并记录基线的段内计算序和最终合并树。
2. 在主机侧按空闲核数决定是否启用扇出和实际启动网格。
3. 建立“输出块 × 分段”到 Block 的唯一映射。
4. 为每个 partial 和完成标志分配互不重叠、满足对齐的区域。
5. 非属主发布 partial 后写完成标志；属主确认全部完成后按原树汇聚。
6. 对核饱和、短归约和尾分段保留原路径。

## 6. LLM 前置问题

1. 单个输出块内有多少个真正独立的归约分段？
2. 当前输出块数与可用 Block 数的差额是多少？
3. 每段乘加次序和最终合并树能否完全保持？
4. 跨 Block 发布与轮询的可见性、对齐和超时契约是什么？
5. 扇出后的冗余搬运与汇聚开销是否小于并行收益？

## 7. 验收标准

- 构建和全量精度通过，数值路径预期逐位一致。
- 至少两组平衡交替配对测量同向，非启用形态无稳定回退。
- 来源验证覆盖全部正确性用例，整体验证加速比为 `1.4469x`；长归约少块形态获得约 `2.0x–3.0x` 改善。
- 剖析确认活跃矩阵核数上升，且等待汇聚未成为新的关键路径。

## 检索卡（短卡）

动作：把输出块内彼此独立的归约分段作为独立任务扇出到空闲 Block，非属主写独占完成标志，属主确认全部分段可见后按原合并树汇聚。
适用：长归约、少输出块、存在固定数量独立 partial、仍有空闲 Block、汇聚代价小于被并行化计算。
限制：分段区间、乘加序、partial 地址唯一不变；合并括号树与基线一致不改浮点结合序；完成标志主机初始化、发布后写、读取有可见性保证；忙等须有保守回退。
范围：矩阵核串行多独立 partial 的归约环节。
检索词：分段扇出、属主合并、完成标志、跨 Block 可见性、partial、忙等轮询。
机会：输出块少归约轴长矩阵核利用率低，单核顺序算多个独立 partial 其他 Block 空闲，分段占关键路径合并占比小。
