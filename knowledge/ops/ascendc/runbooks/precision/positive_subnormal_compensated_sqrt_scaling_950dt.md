# 补偿归一化链中正 subnormal 的缩放平方根恢复

> **来源说明（2026-10-31）**：本卡结论来自车队私有实测/推理，暂无可公开复核的原始出处；按社区评审口径以 draft 收录，待补可复核来源后回升。
## 适用场景

在一个 Ascend950DT/CANN9.2 的 GDN 完整 forward 修复中，返回 API 被明确
隔离为独立 FP32 存储，原 native 输出合同及失败保持不变。原 50 组 native
输入/权重和未窄化 FP64 CPU 数学继续固定；不是通过改幅度、epsilon 或
把 gold 转成输出 dtype 来通过检查。

仅升 FP32 返回后，候选与新 Model 相等，CPU 比较却只有 25 组通过。后续
残差投影、双字递推/归一化修复了有限误差，但两个原本有限 gold 的测试变为
NaN。因此应该沿真实误差链查找，而不是把 Model 相等当作 CPU 准确。

## 保留表示值后再做 Newton 修正

固定源码的双字平方根先检查高分量量级。很小正数在求平方根与 Newton
修正前提升，过大值则缩小，使用精确的 2 的幂并在结果端恢复相应平方根
尺度。对于正 FP32 subnormal，源码从整数位域重构有效尾数，再执行提升，
避免提升输入本身已经被当成零。不能用任意夹断替代这个表示值。

这里的双字是本实现的 `h/l` 规范表示：正的高字承载量级，低字保留小残差；
不是允许任意 `h=0,l>0` 的输入。固定源码对高字绝对值位域小于
`0x1f800000`（2⁻⁶⁴）者先提升2⁶⁴，对大于`0x5f800000`（2⁶⁴）者
先缩小2⁻⁶⁴，最后分别恢复平方根尺度2⁻³²或2³²。对 FP32 subnormal，
先将尾数字段转为整数值并乘2⁻⁸⁵，得到提升后的表示值；这一步避免先用
可能失去小量的浮点乘法完成提升。高低两字都要按同一尺度处理。

归一化后的修正继续保留乘积和加法残差，不要把低分量立即加回已舍入的
高分量而丢失补偿。原实现的严格浮点编译约束也是源码合同的一部分。
这不是适用于任意负数、NaN、Inf 或任意非规范双字输入的通用数学库承诺。

## 已有结果及因果边界

上述完整新版本消除了两个观测到的 NaN，按原输入、当前比较器和实际 FP32
输出 dtype 完成 50 组 CPU 比较及重复检查。后续在原执行地重新捕获了实际
输出，既有非作者上下文以未窄化 FP64 比较得到 candidate/CPU 50 组通过；
Model/CPU 和 candidate/Model 均为 25 组通过、25 组失败。该检查不是盲会话，
也未新生成 CPU 数学。使用后数组已原地退休。

源码假设是极小正数的 seed 为零导致 Newton 修正除零；实际恢复支持的是
这个完整实现的效果。没有直接跟踪到某条硬件指令的 FTZ/DAZ 行为，不能把
源码注释当作硬件因果证明，也不能声称改变只影响一处指令。该版包含前序
补偿机制，未做逐项性能消融。

## 重用检查

先确认正数/量级和双字表示不变量，保持原输入、gold、epsilon 与完整返回
API。新二进制需要自己的完整人口精度、重复和同版性能；本例的独立 FP32
返回结果不能回填旧 native API、其他人口或另一个 GDN 模型。公开来源中
保留失败与完整版本历史，不据本例声称所有输出正确舍入或通用性能收益。
