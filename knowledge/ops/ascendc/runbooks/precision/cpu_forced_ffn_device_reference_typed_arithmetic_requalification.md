# 950DT 上 CPU 强制 FFN 基准的设备参考移植与舍入验证

> **来源说明（2026-10-31）**：本卡结论来自车队私有实测/推理，暂无可公开复核的原始出处；按社区评审口径以 draft 收录，待补可复核来源后回升。
## 适用场景

- **工程形态**：一个 FFN 基准的输入转换函数执行 `t.detach().cpu()`，算术因此实际发生在 CPU；给其外层套 NPU Event 不能把该算术变成设备时间。本卡讨论的是显式另建一个设备参考，并把放置变化与算术变化分开验证。
- **API 路径**：以通用原语隔离移植范围（见正文"以通用原语隔离移植范围"一节），不依赖官方 FFNV2 分支。
- **验证过的平台与 CANN 版本**：Ascend950DT，CANN 9.2，Torch 2.10。
- **适用粒度**：`exact_task`——该 CPU 强制 FFN 基准及其设备参考移植；原 CPU 强制版本与其不可测的设备基线仍保留。
- **路线优先级**：`recommended_fastpath`。
- **明确不适用或未验证场景**：不证明官方 FFNV2 支持该器件，也不改变精度标准；移植范围之外的算子与其他放置方式未验证。

## 触发信号与适用范围

在 Ascend950DT、CANN 9.2、Torch 2.10 的一个 FFN 基准中，输入转换函数执行
`t.detach().cpu()`。因此算术实际发生在 CPU；给其外层套 NPU Event 不能把该
算术变为设备时间。这里讨论的是显式建立一个新设备参考，原 CPU 强制版本及其
不可测的设备基线仍保留。它不证明官方 FFNV2 支持该器件，也不改变精度标准。

## 先区分放置变化与算术变化

只去掉 CPU 转移、换成常规 NPU matmul 和激活不是语义等价的充分条件。在本次
冻结的 53 例中，该直接移植仅有 7 例与原 Model 通过精度检查，另 46 例失败；
重复稳定仍不能证明其数值正确。

先核对真正执行的函数、结果 dtype 和中间转换，尤其是以下边界：

1. GEMM 的累加次序与结果写回 dtype；改变分组或仅在末尾转换可能改变输出。
2. 激活常数、表达式分解和每个有类型中间结果的舍入；不能仅因数学公式相同就
   用另一个激活 API 替代。
3. bias、反量化、伪量化、专家路由及最终 cast 的先后顺序；矩阵乘实现正确
   不等于整个 FFN 的输出合同正确。

## 以通用原语隔离移植范围

本次可用版本保留原 forward 签名、shape/native dtype 和上述 helper 编排，
只将 `_matmul` 与 `_apply_activation` 接入单独导出的设备原语。矩阵乘原语
接收 FP32 A 和原有 16 位 B、返回 FP32 累加量，包装层在原位置执行结果 dtype
转换；激活原语保持原有类型化舍入点。固定 CPU 实现的求和次序只作为这一版本
的适配目标，不能把本次采用的分组常量推广为其他形状的必要条件。

两个量化例使用 FP32 的整数点积路径时，另有逐项范围分析证明每个中间整数和
小于 `2**24`。只有在整数乘积和中间和均可精确表示等前提成立时，这个论证
才适用；不能仅用最终和较小来证明任意量化 FFN 精确。

原语借用了同一作者候选的算术模板，参考不调用候选的完整 FFN 入口。必须披露
这一共同血缘：参考与候选相等本身不是独立实现验证。原始 CPU Model 另行实际
执行，作为保留原语义的控制；高精度数学输出继续独立比较，不把 Model 一致性
说成 CPU 数学精度通过。

## 已有验证与能支持的结论

冻结的原 53 例保持输入、标量、RNG/状态和 native 输出 ABI。新设备参考对原
CPU Model 的全部输出逐字节相等，53 例重复稳定。两者对未窄化高精度 CPU
数学仍是 9 例通过、44 例失败。这证明的是该版本对原 Model 的移植一致性，
不是对全部用例的 CPU 精度修复，也不是 actual CANN 精度例外。

该版本后续完成了同输入、双腿独立 Event 与 host 的完整性能采集，各域各有
53 对样本组。Event 包围整个提交 callable，包含其中的调度和拷贝；它不是
kernel-only 时间，host 与 Event 的不同调用也不能解释为嵌套时钟。性能结果
只适用于这个明确改动的参考版本，不回填原 CPU 强制基线或其他 native 参考。

完整数组在执行地消费后退休，未进行独立的非作者数组复评。哈希和生成配方
不是保留的输出字节，不能据此声称旧输出仍能离线复评。

## 失效边界与下一位使用者的检查

- 这是一个固定 53 例、固定 CPU 算术和运行版本的经验；其他 Torch CPU 内核、
  shape、dtype、激活或器件需要重新检查适用性与测量。
- 不使用 CPU 张量算术桥、输入/权重/输出缓存或 golden 查询来替代设备计算。
  包装中的 host 元数据准备和拷贝仍计入整个 callable。
- 通用原语、host 包装和参考都要绑定实际加载版本；仅构建成功、源码 hash 相同
  或历史 PASS 不能建立新版本资格。
- 需要独立参考的任务不能把共享候选算术模板的这一参考充作独立实现。没有
  完成原 Model 控制和高精度诊断时，不可仅以两端相等作正确性结论。

## 回退与相关知识

新设备参考不能维持本版原 Model 语义时，保留失败并回退到原 CPU 语义检查，设备
性能基线继续标为未建立；不能拿另一套 native 参考成绩补齐它。

- [参考污染与 Scan 舍入证据](../../guides/testing/reference_mutation_and_scan_rounding_evidence.md)：不要静默改写原基准或把逐步舍入替换为末尾转换。
