# int16 位级 RNE 链在 L==0 时下溢回绕，误加 1 个 bf16 ULP

## 现象

一个 f32→bf16 的位级 RNE（round-to-nearest-even）转换链，用 int16 向量算子手工实现（取 f32 的低 16 位 mantissa 与 lsb，算 `t1 = L + 0x8000`，再用 `t1 + (lsb-1)` 的符号决定是否进位）。整套用例的大多数都通过，但边界 case 误差恰好在容差线上：`ours=6.2498e-2 vs gate=6.2490e-2`（FAIL），且三次重复运行**逐位一致**（确定性，不是竞态）。

把该链抽成 numpy 全枚举（2^17 个输入）对拍，得到：

```
iter0 maxerr 0.125000 nbad 25 / 16777216
 sample: [(24, 0, 78, 9.4375, 9.375), (54, 31, 204, -8.0625, -8.0), (69, 26, 108, 9.4375, 9.375), ...]
iter1 maxerr 0.125000 nbad 25 / 16777216   （与 iter0 完全相同）
iter2 maxerr 0.125000 nbad 25 / 16777216   （与 iter0 完全相同）
```

错误样本的形态是"我们的结果比参考大恰好 1 个 bf16 ULP"（9.4375 vs 9.375、-8.0625 vs -8.0，差 0.0625）。场景：kernel 直调、Ascend310P3（dav-m200）、CANN 9.1.0。

## 适用场景

- 工程形态：kernel 直调；向量管线上的位级 dtype 转换（int16/uint16 位运算模拟 RNE）。
- API 路径：`And / Adds / Sub / Add / Maxs`（LocalTensor<int16_t>），配合 `Gather` 交织表的 f32→bf16 位型链。
- 验证平台与 CANN 版本：Ascend310P3（dav-m200 / DAV_2002），CANN 9.1.0；未在其他平台实测。
- 适用粒度：platform_wide（任何在有符号 16 位域里做"加偏置再比较符号"的位级舍入）。
- 路线优先级：recommended_fastpath（在 t1 上补一条 `Maxs` 钳底；无替代路线）。
- 明确不适用/未验证场景：纯 uint16 域（无符号）不触发本下溢，但仍可能有上溢；IEEE f32→f16（半精度）链需要指数重偏置与 13 位尾数舍入（tie 点在 2^12 量级，不是 0x8000），与本链不是同一形态，未在本轨迹出现、未实测。

## 根因

链的进位判定是"`t3 = t1 + (lsb - 1)` 的符号"：

- `t1 = L + 0x8000`，其中 `L` 是 f32 mantissa 的低 16 位，按 **int16** 存（范围 -32768..32767）——"丢弃 f32 低 16 位、对低半字做 RNE"正是 f32→bf16 的标准舍入形态（bf16 恰为 f32 的高 16 位），内核源码注释亦明确写"位级 RNE（f32 → bf16, 11 op 精简链）"。
- 当 `L == 0` 时，`t1 = 0 + 0x8000 = 32768` 在 int16 里回绕为 `-32768`；
- 当 `lsb == 0` 时，`t2 = lsb - 1 = -1`，于是 `t3 = -32768 + (-1) = -32769`；
- int16 下溢：`-32769 mod 65536 = 32767`，是一个**正数**；
- 符号判定 `[t3 >= 0]` 得到 1（应得 0），于是给结果多加 1 个 bf16 ULP（尾数最低位）。

算术对上错误的稀疏性：只有 `L == 0 且 lsb == 0` 这一种组合会翻符号，而 `L == 0` 表示 mantissa 低 16 位全零（即被舍入的尾部恰为 0 或恰为 0x10000 的倍数），在随机数据里比例约 1/65536，与实测 25/16777216（≈1/671k，含数据分布偏置）同量级。误差形态是"**样本所在区间恰 1 个 bf16 ULP**"：多进的 1 落在 bf16 尾数最低位，绝对误差随样本区间变化——观测到的 0.0625 与 0.125 分别是 [8,16)（bf16 间距 2^-4，如 9.375→9.4375）与 [16,32)（间距 2^-3，如 16.25→16.375，位级对照见"验证信号"）的 1 个 ULP；`maxerr 0.125` 即 [16,32) 区间样本的 1 个 ULP，不按固定 ULP 数换算。（对照：fp16 在 [8,16) 的间距是 0.0078125，0.0625 折合 8 个 fp16 ULP——误差量级本身也印证目标是 bf16 而非 fp16。）

## 设计决策

- 选择"在 t1 上钳底 `Maxs(t1, -2)`"，而不是改判定式或换 uint16：钳底把 `t3` 的取值域压到 `[-3, 32767]`，**不再跨越 0 边界**，符号判定对 `L==0` 的两种 lsb 都正确（lsb=1 → t3=-2<0；lsb=0 → t3=-3<0），且不改变任何非零 L 的判定。
- 没有选择"特判 L==0 的 Select 分支"：多一次向量算子与一个比较结果，代价高于一条 `Maxs`。

## 系统信息

- 工具链：CANN 9.1.0，Ascend310P3（dav-m200 / DAV_2002）；kernel 直调 + torch 扩展。
- 涉及文件：`kernel/op44_jagged_bmm.cpp`（f32→bf16 出口 RNE 链，算子 JaggedJaggedBmm 的 bf16 输出通道）；numpy 全枚举对拍脚本（临时探针）。

## 完整代码

修复前（进位判定四行）：

```cpp
                And(inc, h16, ones, cnt);                     // lsb = H&1
                Adds(sa, l16, static_cast<int16_t>(0x8000),
                     cnt);                                    // t1 = L+0x8000
                Sub(ub, inc, ones, cnt);                      // t2 = lsb-1
                Add(tieF, sa, ub, cnt);                       // t3 = t1+t2
```

修复后：

```cpp
                And(inc, h16, ones, cnt);                     // lsb = H&1
                Adds(sa, l16, static_cast<int16_t>(0x8000),
                     cnt);                                    // t1 = L+0x8000
                // [溢出护栏] L==0 时 t1=-32768, t1+(lsb-1) 下溢回绕为正
                // → 误 +1（实测 25/16.7M 元素恰为此形）。t1 钳底
                // -2 后 t3 ∈ [-3, 32767] 无回绕, 符号判定不变（2^17 全
                // 枚举核对 0 失配）。
                Maxs(sa, sa, static_cast<int16_t>(-2), cnt);  // t1c
                Sub(ub, inc, ones, cnt);                      // t2 = lsb-1
                Add(tieF, sa, ub, cnt);                       // t3 = t1c+t2
```

函数级说明：该四行/五行位于内核出口的向量链中，处理一整段 f32 元素（`cnt` 个）；`h16/l16/inc/sa/ub/tieF` 均为 int16 视图。修复只插入一条 `Maxs`，其余步骤与顺序不变。

## 预防

- 在有符号 16 位域做"加偏置 → 减 1 → 判符号"时，先枚举极值：`L=0`、`L=0xFFFF`、`lsb=0/1` 四个组合手算一遍。
- 位级转换链上线前用 numpy 全枚举（2^16 或 2^17）对拍，而不是只跑随机样本；本例的错误密度在随机样本里几乎不可见。
- 误差形态是"恰好 1 个 LSB 且确定性强"时，优先找边界输入，而不是怀疑容差或精度策略。

## 失效边界

- 钳底值 `-2` 依赖"t1 的最负极端出现在 L==0"这一事实；若链上游改成别的偏置（不是 0x8000）或改成 uint16 域，钳底值需要重算。
- 若 `cnt` 段跨越 UB 尾部预留区，`Maxs` 会改写预留槽——本例预留槽不参与运算，其他实现需确认。
- 本卡链路即 f32→bf16（内核注释"位级 RNE（f32 → bf16, 11 op 精简链）"、测试用例 dtype=bfloat16）；IEEE f32→f16 链未在本轨迹出现，本卡结论不得外推到它。
- 剩余 6/16.7M 的偏差未追根因（未决项，**优先项**：复现并隔离该 6 例）：它在本次溢出修复后仍然存在，但尚未确认来源——可能是参考侧舍入差异，也可能是本链的另一个边界，不要先验归因任何一侧。

## 坏实践

- 用随机样本验证位级转换链：25/16.7M 的密度意味着随机 1e6 样本期望只命中 1~2 个，容易假阴。
- 在 int16 域用 `Adds` 加正偏置后直接比较符号，不做钳底：偏置本身会把一半取值域推到负数，任何后续减法都可能跨越 32767/-32768 边界。
- 因为误差是"1 个 LSB"就去放宽容差：本例的错误是确定性逻辑错，放宽容差会掩盖它。

## 误诊

- 一开始把 `ours=6.2498e-2` 当成"边缘 case 的舍入噪声"，因为只比 gate 大 0.001%；全枚举对拍后才确认是确定性的一 LSB 逻辑错（agent_reported → tool_observed 的纠正过程）。
