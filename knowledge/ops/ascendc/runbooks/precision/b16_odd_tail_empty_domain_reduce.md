# b16 奇偶拆分尾块的空域归约排查

## 适用场景

把 b16 数据拆为奇偶两个计算域时，最后一个有效元素可能只落入偶域。此时奇域元素数为零，不能把未定义的空域归约结果合入总结果。

## 症状与记录

dav-3510 工程中的 b16 归约路径曾在奇数尾部出现错误：最终块只剩一个元素，奇域仍执行归约并贡献陈旧值。另一个易混淆因素是长度辅助接口会更新剩余计数，之后再拿已更新变量计算奇偶长度会失去原始有效数。

## 定位与处理

1. 在消耗或更新剩余长度前保存本块有效数 n。
2. 若当前拆分确实按原序列偶位置、奇位置划分，分别计算 `even_len=(n+1)/2`、`odd_len=n/2`，使用整数除法；其他 lane 布局必须重推映射。
3. 对零元素域显式跳过归约，或在接口明确支持时使用对应运算的单位元。求和、最大值和最小值不能共享一个随意的初值。
4. 非空域按自己的有效长度建立掩码，不把屏蔽 lane 视为自动填零。

## 验证边界

测试 1、2、3、完整块±1，以及连续两次调用先大后小。给无效区写入极值或 NaN，检查尾部是否泄漏进结果。草稿：尚待目标版本确认空掩码和归约输出语义，不声明所有 b16 API 存在该问题。
