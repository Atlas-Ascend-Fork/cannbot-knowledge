# asc_mrgsort4 编译通过后 error 328 的参数探针

## 适用场景

调用 `asc_mrgsort4` 的组合 kernel 编译通过，并不证明其运行参数合法。遇到设备侧参数异常，应先把硬件归并调用缩减到可独立验证的一次操作，再恢复多行和队列组织。

## 症状与记录

CANN 9.3、dav-3510 的 TopK 多行归并候选曾编译通过，但 int32、长度 7 用例在设备侧报告 error 328、非 VF 参数无效。其他 dtype 的小探针通过，不能覆盖这组参数，也不能据此判断 int32 接口普遍不可用。原观测尚未把失败唯一归因到某个参数。

## 定位与处理

1. 固定一行、已排序的输入段和确定的输出缓冲，保留受测 dtype。
2. 按当前重载逐项核对重复次数、各输入段有效长度、队列及相关控制参数，区分元素数、重复数和字节数。
3. 先测单次归并；随后一次只增加一个变量：尾段、多行地址推进、重复调用或双队列。
4. 分别验证视图构造与归并参数。相同数据换视图后失败，不能直接归因于比较算法。
5. 在最小探针闭环前保留已验证的选择或归并路径，不让失败候选进入性能对比。

## 验证边界

覆盖长度 7、完整归并块、块边界前后，以及值与索引一致性。保存完整编译命令、实际参数和设备错误；错误码只作入口，不作为根因证明。草稿：尚未重放该故障或确认通用参数组合。
