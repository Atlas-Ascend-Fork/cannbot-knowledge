# asc_madd 替换乘加接口前先验证操作数角色

## 适用场景

相近的乘加名称不保证操作数角色相同。在某一 C API 头文件快照中，`fma`、`mula` 相关调用虽可找到声明，实际实例化未通过；`asc_madd` 路径可用，其受测更新关系为 `dst = dst * src0 + src1`。不能据此将其他接口不加检查地改名替换。

## 最小探针

1. 固定初始 `dst=2`、`src0=3`、`src1=5`。上述更新关系应得到 11；常见的 `dst += src0*src1` 则得到 17。
2. 每次调用前重置 dst，避免上一次结果掩盖原地更新的语义。
3. 在目标编译器中同时实例化真实 dtype、寄存器类型、掩码和调用作用域；单纯能搜索到声明不是可用性证据。
4. 再测试别名限制、尾部和多次更新，确认生成结果使用了预期输入。

## 替换边界

只有代数角色和接口前提匹配，才继续检查融合舍入、溢出和非有限值。上面的整数小值探针只识别操作数位置，不能证明单次融合舍入或与另一条算术链逐位等价。

## 验证状态

记录来自 dav-3510 的工程试用，头文件快照和具体重载尚待复核；本卡为草稿。不把一次实例化失败写成 `fma` 或 `mula` 在所有 CANN 版本上不可用，也不宣称改用 `asc_madd` 有性能收益。
