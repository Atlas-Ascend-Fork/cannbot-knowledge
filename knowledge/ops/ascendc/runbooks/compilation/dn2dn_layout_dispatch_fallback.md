# dn2dn 视图模式不匹配引发错误模板回退

## 适用场景

搬运模板错误出现在底层类型工具中时，首先检查高层视图是否匹配目标搬运路径。错误模板被实例化，可能是派发前提不成立的结果。

## 症状与记录

一组 dav-3510 工程中的 `dn2dn` 调用把 ND 与 DN 模式混配，未满足该实现对源、目标 `dn_layout_ptn` 的配对要求，落入 `asc_copy_ub2gm(ignore)` 回退。在受测 Bisheng 中，随后报出与 `is_same_v<Args..., void>` 有关的模板错误。该报错不能单独证明标准类型工具或所有搬运重载有缺陷。

## 定位与处理

1. 从第一处实例化栈回到自己的搬运调用，列出源目标地址空间、元素类型、布局模式与步长。
2. 对照当前实现的派发条件，确认是否真正命中预期的 `dn2dn` 分支；不能仅凭调用名称推断已命中。
3. 若逻辑上是相同模式复制，修正视图配对；若确实需要布局转换，选择受支持的转换路线。
4. 用一行的已知序列验证选路，再恢复多行。不要修改 SDK 的类型工具来掩盖回退分支报错。

## 验证边界

分别检查同模式搬运、真实布局变换、单行与多行。编译成功后仍需检查输出顺序、目标跨度和边界写入。本卡仅保留受测派发失败的诊断经验；草稿，具体实现及复现产物尚待复核。
