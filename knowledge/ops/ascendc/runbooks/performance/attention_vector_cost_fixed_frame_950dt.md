# 注意力在线累加的矢量成本与固定参考最大值

> **适用平台与版本**：Ascend950DT（dav-3510）、CANN 9.2.0；固定参考分支只覆盖 bf16、head dimension≤128、BLOCK_N=256、序列长度 512–4096。
>
> **来源说明（2026-10-31）**：成本探针、候选与回退数字来自作者私有实测/推理，暂无可公开复核的完整原始出处；保持 draft。下列官方文档仅支持明确标出的基础更新公式，不证明私有测量或固定参考路线的收益。

## 适用场景

- 工程形态：双缓冲 CV-ring 自注意力内核，QK^T、PV 由 Cube 承担，矢量路径逐 KV tile 更新输出累加器 O。
- API 路径：在线 softmax 与 O 累加/重缩放；SoftmaxFlashV2 更新公式仅作基础旁证，不是本卡固定参考路线的收益证据。
- 已验证平台与版本：作者记录为 Ascend950DT、dav-3510、CANN 9.2.0；固定参考分支仅覆盖 bf16、head dimension≤128、BLOCK_N=256、序列长度512至4096。
- 适用粒度（transfer_scope）：该内核的成本诊断、固定参考 M0 与动态最大值回退机制；迁移后须重新验证本版本完整人口、重复与性能。
- 路线优先级：先用成本探针确认 O 的读改写是否主要，再考虑减少更新次数，并保留原动态最大值回退。
- 不适用或未验证：fp16 固定参考、其他 tile/SoC/编译器、稀疏 mask、全遮行及更细粒度 lazy rescale；不把私有观测当公开独立复核或跨窗口因果收益。

## 症状与适用范围

Flash Attention 类内核的 `QK^T`、`PV` 已由 Cube 承担，继续替换 Exp 或广播指令却没有改善端到端性能时，先检查每个 KV tile 是否都读取、缩放并写回完整输出累加器 O。

本卡来自一个双缓冲 CV-ring 自注意力内核的开发记录，平台为 Ascend950DT、CANN 9.2.0、dav-3510。已报告的优化分支只覆盖 bf16、head dimension 不超过128、BLOCK_N=256、序列长度512至4096；不是所有注意力实现的统一选型。本文保持 draft：数字来自原作者固定版本记录，当前不能由本卡链接完成公众独立复核；成本剥离与否决试验的原始 profiling 尚未在本卡中独立复算，知识驱动的跨内核复现也未执行。

## 快速检查与诊断路径

1. 固定源、输入、候选与测量仪器，先观察 FA 内核总时间和 `aiv_vec`，区分内核时间与整个 forward。
2. 分别移除输出 merge、P 存储及转换、Exp、merge 内广播、merge 内乘法，作为成本探针；这些修改可能改变数值，不能作为合格候选。
3. 如果主要差值来自整个 O 的逐元素更新，再设计减少更新次数的算法。单项删除的耗时差存在流水交叠，不能直接相加为时间占比或用来保证最终收益。

原作者在 bf16、S=4096、H=32、head dimension=128 上报告的探针结果如下。每次采集包含两次 forward，单位均为微秒/forward。

| 探针 | FA总时间 | aiv_vec | 相对控制的FA差值 |
|---|---:|---:|---:|
| 控制 | 2986.2 | 2636.9 | — |
| 移除 `merge_output_reg` | 1987.2 | 633.0 | -33.5% |
| 移除fp32 P存储和UB转换 | 2669.4 | 2471.2 | -10.6% |
| 移除score Exp/Sub | 2847.7 | 2485.6 | -4.6% |
| merge内移除逐行广播读取 | 2887.7 | 2537.5 | -3.3% |
| merge内仅相加、移除乘法 | 2891.3 | 2543.5 | -3.2% |

这组探针支持先调查 O 的 UB 读改写；它不证明任意内核有“90%成本”，也不证明删除 merge 可直接保持正确性。

## 修复方向：固定参考最大值并保留回退

常规[在线softmax递推](../precision/online_softmax_per_row_state_recurrence.md)随 running max 更新而改变指数中心。这里实际采用的基础事实直接核对固定版本官方 SoftmaxFlashV2 的更新分支：`exp_max=exp(inmax-x_max)`，更新后的 sum 包含 `exp_max*insum`。实数代数中，输出分子的旧累加量也要转换到同一中心；本实现因此逐 tile 重缩放旧 O。这个推导不继承中间草稿的其他平台、mask 或数值断言。该内核尝试在第一个 KV tile 取得每行 M0，后续始终计算 `P_t=exp(S_t-M0)`，把 `P_t@V_t` 累加到同一 L0C 区域，同时累计 rowsum，最后一次性写出并归一化。

实数算术中分子与分母共用的常量指数因子可约掉；浮点范围、舍入、L0C累加及Pack布局仍需本版本完整精度验证。该实现发现后续任一行最大值超过 `M0+60` 时，重做并回退到旧的动态最大值路径，不能简单截断 logits。原作者还报告把 key 放大300倍的越界试验与旧路径逐位一致；这是该实现上的一次回退观测，不能外推为所有输入的安全证明。

候选记录中，同一DSO的五次完整50例运行，每次精度均50通过，Event逐例中位数加速比的等例几何均值为：1.095132、1.118635、1.126112、1.112056、1.111348，五次均达到0.996门槛。五次比值的几何均值为1.112609。旧版本五次聚合为1.012277、最低0.990318，只有3/5达门。两版本来自不同时间窗口，不据此作严格因果收益证明。

作者对单个FA案例另报告2989.4→2003.6微秒、aiv_vec 2641.5→553.3微秒；bf16低维分组的比值从0.8913变为1.1567。这些是有范围的观测，不是对所有dtype或shape的性能承诺。

## 保留的否决路线

- 在该内核fp16路径替换为 `SoftmaxFlashV2<half,true>`，报告FA从87增至114微秒；完整50例精度通过，整体Event几何均值0.9066。这个负结果只约束此调用、布局和内核，不能写成API普遍较慢。固定官方文档对应的[更新分支](../../apis/simd_api/adv_api/activation_functions/soft_max_interface/softmax_flash_v2.md)公式已包含旧sum的重缩放项；把它再当作当前tile的局部sum相加，会重复累计。
- 以整个128行block为单位实施 lazy rescale，只要任一行最大值增大就flush；作者报告FA反而约增3%。在“各行独立、各tile最大值连续同分布”的模型假设下，第k个后续tile不触发任何行更新的概率为 `(1-1/(k+1))^128`。16个tile的最后一步k=15时约为2.6e-4，解释了为什么块级OR可能几乎每tile都flush。概率式是建模，不是实测普适定律；行相关或分布改变时不成立。
- 直接从寄存器把P转换为half并写出曾产生错值/NaN。需要先核对Pack与消费者布局，不能把数值Cast当作布局转换。本卡不提供未经验证的通用Pack修法。

## 验证、回退与残留风险

复用时先确认M0选择、P实际存储dtype、L0C初始化/累加语义、rowsum中心和最后归一化是否一致，再以同一输入跑完整人口的精度、重复和同版本性能。超出范围时回退原动态最大值算法，保留失败集和原测量。

fixed-frame没有在fp16路径验证。若P以half存储，最大有限值65504使允许的指数差缩至约 `ln(65504)=11.09`；不能照搬bf16的60门槛。其他tile宽度、SoC、编译器、稀疏mask、全遮行，以及更细粒度8至16行的lazy rescale均未由本卡验证。
