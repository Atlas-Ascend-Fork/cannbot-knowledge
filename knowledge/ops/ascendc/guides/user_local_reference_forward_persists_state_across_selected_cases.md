# 要报一个【从选中子集测出来】的逐例数之前先问：参考/候选的 forward 往 self 回写吗？

> **来源说明（2026-10-31）**：本卡结论来自车队私有实测/推理，暂无可公开复核的原始出处；按社区评审口径以 draft 收录，待补可复核来源后回升。
> **来源与状态**：本卡结论全部来自本队**第一方实测**（catalog 24 / `16_LongformerAttention`），无可公开复核的外部出处 ⇒ `status: draft` 且 `sources: []`。卡内数字由 56 行基线表独立核对过（`device_event` 全 50 几何平均 0.3923187781、min 0.2585459570、门 0.96 ⇒ F FAIL、原 P 50/50 PASS）。黑盒复现未做、本轮未做优化，二者均单列保留。

## 当场自问（动作，不是对象）

1. 我这次只测了全部用例的一部分吗？（选中子集 vs 全 50）
2. 消费者是不是「生成一次 → 每臂构造一次 → 只迭代被选中例」？
3. 两臂的 `forward` 里有没有 `self.<attr> = f(self.<attr>, 本例形状)` 这种**回写**？

三条都成立 ⇒ **每例结果是分片组成的函数**，在报任何逐例数之前必须先把状态定下来。

一条命令的检测：`grep -n 'self\.' <reference>.py` 看 `forward` 段内有无赋值；
判别控制必须**两臂都跑**，且要选一个能区分的形状（见下）。

## 机制（实测）

消费者 `quickscan_consumer.py` **sha256 `aeb3fe55a317a0379133bad24f652c1f2646f2f47aaa8b389a1713dcc17b09a8`**
在 `:638` 对全部用例各生成一次，`:675`/`:676` 每臂各构造一次，`:694` 只迭代 `picked`。
⚠️ **行号只对上面那个 sha 成立**：可变文件里的行号不是稳定引用（同族另一版消费者
`3c435fbb5f4590913970be164eecf174fc22bd203c1da377a1424651bcd5eb54` 行号不同）。核对时先比 sha，
sha 不符就按「生成一次 / 每臂构造一次 / 只迭代选中例」这三个**行为**去找，不要按行号找。
而本行两臂的 `forward` 都这样写：

```python
self.window_size = min(self.window_size, S)
self.global_attention_indices = [min(idx, S - 1) for idx in self.global_attention_indices if S > 0]
```

单调只减、永不恢复。于是：

| 选择集 | case 所见 global | 原因 |
|---|---|---|
| 原全 50 升序 | 全部 `[0,255]` | case0 S=256 第一下钉死，其余 49 例继承 |
| 只选 2..48（新鲜实例） | case2/3 `[0,511]`，case4 起 `[0,383]` | 没有 S=256 的例在前；case4 S=384 再压一次 |

⇒ **46/47 例与原序状态不同**。`window_size` 不受影响（所有 S>=256 时 `min(32,S)=32`）。

## 修法与优先级

**先问不动点，再考虑整备。** 把状态恢复成原全序状态 `(32,[0,255])` 后，它对全部 50 例满足
`min(255,S-1)==255` 与 `min(32,S)==32`（实测 `min(seq_len)=256`）⇒ **是不动点**
⇒ 分片组成与顺序**不再改变 mask 状态**。

对比「在每片前面加一例小 S 做整备」：能到同一状态，但 (a) 每片多花一例的测量时间，
(b) 依赖「片内第一例是小 S」这个性质，下次重切分片时会**静默失效**。

实现落点：写在**调用方私有胶水**里（按 path 读+sha 绑定后执行原始字节，在两臂构造时各恢复一次），
**不改共享消费者**、不换模型/计时器/生成器。消费者 digest 的是胶水，胶水不匹配原始字节即拒 ⇒
跑的仍是原始字节，两个 digest 都要记。

## 判别控制（没有区分力的控制会假过）

```
未整备，S=512  -> global [0,511]
已整备，S=512  -> global [0,255]      两者不同 ⇒ 这步有区分力
已整备，乱序跑 16384/256/4096/512/2048 -> 仍 (32,[0,255])
```
**只报「整备后是 [0,255]」证明不了整备起作用**：S=256 的例两边都给 `[0,255]`，会假过。

## 第二条绑定事实：未初始化操作数不可重建，也不可证不同

参考 `model.py` sha256 `f9842c5915250258201a89fbe929141c2c4b4c8427f079fe656fee044b6ae4ae`、
候选 `model_new_ascendc.py` sha256 `c03aa22c03beb68d10957da1847ebb65980e9fe505f810bd8bcd8a568df86ef4`。

本行 case1 的三个操作数由 `torch.empty` 产生（未初始化内存）⇒ **既不可重建、也不能断言与某份
留存文件必然不同**。处置=按字节接入留存文件并断言其 digest；设备端用消费者自己的
`operand_digest`（组级，uint8_view）复算可证实际吃进去的就是那份字节。
⚠️ **组级 digest 与逐操作数字节 sha 是两个量，消费者 docstring 自己写着「永不互比」**——拿前者比
后者会把范畴错误读成缺陷。
⚠️ 该「必须接文件」的要求来自 msprof 血缘；**Event 消费者根本不写 .pt**（其 docstring：
`No .pt is written. Inputs are built from the row's own generator`）⇒ 不要跨域搬要求。

## 作用域与未知

- 不动点只覆盖 `window_size` / `global_attention_indices` 两个属性；**不**证明输出、`W_o` 缓存
  （按 d_model/device/dtype 建键、每 forward 重 seed 42）、分配器状态或计时与顺序无关。
- 两臂都镜像了同一状态机 ⇒ **臂间可比性不受影响**，已录的 0/25/49 内部一致。污染改的是
  「算了什么」，不是「两臂能不能比」；形状不变，所以**我没有测量支持「时间也错了」，就不说**。
- `mapped_dso` 证明的是进程里映射了哪个**文件**，**不是逐调用归属**。
