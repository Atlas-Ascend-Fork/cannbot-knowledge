# NMS 950 Direct Invoke 算子知识

## 算子速览

| 项目 | 内容 |
|---|---|
| 实际入口 | `cann_bench::nms` → `nms_npu` → `launch_nms_rank_chunk_float` / `launch_nms_scatter_ranks_float` / `launch_nms_reorder_float` / `launch_nms_mask_float` / `launch_nms_greedy_float`；Direct Invoke |
| 计算语义 | 对独立 `boxes[N,4]` 与 `scores[N]` 按 `scores` 降序做 greedy NMS，使用 `intersection/(area_i+area_j-intersection+1e-6)`，返回保留框的原始 INT64 索引 |
| 输入输出 | `boxes` 为 contiguous FP32 `[N,4]`、坐标顺序 `[x1,y1,x2,y2]`；`scores` 为 contiguous FP32 `[N]`；输出为动态长度 INT64 `[K]` |
| 执行类型 | rank-chunk 为 AIV 外壳内的 SIMT+UB；rank-scatter、reorder、pairwise-mask 为 SIMT；greedy 为 AIV Vector/MicroAPI；所有可达 entry 均为 `KERNEL_TYPE_AIV_ONLY`，无 Cube/AIC/MIX_CV |
| Kernel 路线 | P0 / R-001：`ceil(N/2048)` 个 rank-chunk → scatter → reorder/area → 20 核 pairwise byte mask → 单核 greedy；唯一 Host 可达路线 |
| 核心资源 | GM Tensor workspace；rank-chunk 单个 TBuf=`align_up(chunkLength*4,32)` B；greedy 的 depth-1 row Queue 与 alive TBuf 各 `align_up(N,256)` B；其余 SIMT 节点无 dynamic UB |
| 来源闭包 | `direct_implementation_closed`：转换交付件闭合 Torch schema、Host workspace/launcher、全部活跃 entry/body、逐阶段同步和动态输出；官方固定源码仅支撑相关 NMS 接口边界与“并行关系矩阵→有序传播”结构，不把派生 Direct 符号表述为官方实现 |
| 验证状态 | 已完成源码闭包检查；本次知识提取未执行编译、真机、数值或性能测试。 |

## 接口与语义

### 计算语义

令输入框 `b_i=[x1_i,y1_i,x2_i,y2_i]`，面积 `a_i=(x2_i-x1_i)(y2_i-y1_i)`。转换契约要求框坐标已合法化，即 `x1<=x2` 且 `y1<=y2`。对 `scores` 降序排列 `p_0...p_{N-1}`，实现先生成：

```text
inter(i,j) = max(0,min(x2_i,x2_j)-max(x1_i,x1_j))
           * max(0,min(y2_i,y2_j)-max(y1_i,y1_j))
iou(i,j)   = inter(i,j) / (a_i + a_j - inter(i,j) + 1e-6)
suppress(i,j) = !(iou(i,j) <= iou_threshold)
```

随后按 `i=0..N-1` 顺序扫描；若位置 `i` 仍 alive，则输出原始索引 `p_i`，并令所有 `suppress(i,j)==1` 的 `j` 失活。任一坐标为 NaN 时该 pair 直接抑制；非 NaN 坐标计算出的 IoU 为 NaN 时，`iou<=threshold` 仍为 false，因而也抑制。该语义不是官方 `NMSWithMask` 的原样调用：官方 950 接口接收 `[N,5] [y1,x1,y2,x2,score]`、保持输入顺序并输出 full-N boxes/INT32 indices/UINT8 mask；官方比较为 `intersection > threshold*union`，没有 `+1e-6`。

### 输入、输出与属性

| 参数 | shape/layout | dtype | 约束、默认值与语义 |
|---|---|---|---|
| `boxes` | `[N,4]`，contiguous ND | FP32 | `[x1,y1,x2,y2]`；与 `scores` 同设备；转换契约要求合法框 |
| `scores` | `[N]`，contiguous ND | FP32 | 长度等于 `N`；rank-count 路线要求比较关系形成无并列全序 |
| `iou_threshold` | Host 标量 | double 输入，launch 前窄化为 FP32 | Direct 校验为开区间 `(0,1)`；不同于官方 950 `NMSWithMask` 的闭区间 `[0,1]` |
| `output` | 初始 `[N]`，完成后 resize 为 `[K]` | INT64 | Device 已写原始索引；Host 只回读 `keepCount` 并修改 Tensor 元数据，`0<=K<=N` |

### 入口与版本

转换交付注册 `cann_bench::nms(Tensor boxes, Tensor scores, float iou_threshold) -> Tensor`，绑定 Meta 与 `PrivateUse1`，不是 ACLNN 两段式接口。目标为 CANN 9.1.0、950/Ascend 950。固定提交中的 950 `NMSWithMask` 公开支持 Ascend 950，并注册 `ascend950`、`arch35` tiling 与 key 10000；它只提供相关实现结构来源。`NonMaxSuppressionV6` 虽有独立 boxes/scores、降序 greedy 的接口语义，但固定仓 README 明确没有开放 AscendC kernel，且公开文档明确不支持 Ascend 950；它只能用于 ABI/语义差异核对，不能作为 950 Device body。A2 参考 `NMSWithMask` 为单核 UB、最多 2048 个框，也只能作为“独立 boxes/scores + 顺序 greedy”参考。

## Host/Launcher 执行流程

### 参数校验与前处理

`nms_meta` 依次检查 `boxes` 为二维且末维 4、`scores` 为一维且长度等于 `N`、两个输入均为 FP32、阈值在 `(0,1)`，并以输入设备/options 分配最大长度 `N` 的 INT64 输出。`nms_npu` 再设置 DeviceGuard，检查同设备与 contiguous；没有隐式 `Contiguous/ViewCopy`。`N` 直接窄化为 `uint32_t`，实现未在窄化前检查 `N<=UINT32_MAX`。

### 参数、Workspace 与生命周期

定义 `A=align_up(N,32)`，`P` 为不小于 `N` 的最小 2 次幂：

```text
orderWorkspace = P * sizeof(int32)                 = 4P B
sortedCoords   = 4A * sizeof(float)                = 16A B
sortedAreas    = A * sizeof(float)                 = 4A B
maskWorkspace  = N*A * sizeof(uint8)               = N*A B
countWorkspace = 8 * sizeof(int32)                 = 32 B
output capacity                                           = 8N B
temporary_tensor_total = 4P + 20A + N*A + 32 B
```

`sortedAreas` 在 rank-chunk 阶段先别名为每个原始 index 的 UINT32 rank 存储；scatter 完成后，reorder 节点覆盖同一物理 Tensor 为排序后 FP32 area。`orderWorkspace` 以 `P` 分配，但活跃节点只读写前 `N` 项。Host 计算的 `sortTmpBytes=15A+512` 不被 P0 / R-001 的任何 launcher 消费，因此不计入该 Route 的 Device 资源。所有临时 Tensor 由 Torch 持有，覆盖整个 lambda 与同步区间。

### 启动图与失败传播

```text
nms_npu
  -> for chunkStart=0; chunkStart<N; chunkStart+=2048
       K-001 nms_rank_chunk_kernel<<<1>>>
       aclrtSynchronizeStream
  -> K-002 nms_scatter_ranks_kernel<<<1>>>
     aclrtSynchronizeStream
  -> K-003 nms_reorder_kernel<<<1>>>
     aclrtSynchronizeStream
  -> K-004 nms_mask_kernel<<<20>>>
     aclrtSynchronizeStream
  -> K-005 nms_greedy_kernel<<<1>>>
     aclrtSynchronizeStream
  -> D2H countWorkspace[0] (4 B)
     aclrtSynchronizeStream
  -> validate 0<=keepCount<=N
  -> output.resize_({keepCount})
```

所有节点使用当前 NPU stream；每个节点后都做 Host stream 同步，因此 producer 完成后 consumer 才提交。任一同步错误由 `TORCH_CHECK` 立即阻断后续节点。launcher 与 kernel entry 返回 `void`，异步 Device 错误只由紧随其后的 stream synchronize 转成 Host 失败。D2H 只复制 keep count，框、`scores`、IoU/mask 和输出索引都不回 Host 计算。

| 边 | 介质与范围 | producer → consumer | ordering | owner/lifetime |
|---|---|---|---|---|
| E-001 | `sortedAreas[0:N]`，UINT32 rank 视图 | 所有 K-001 → K-002 | 每 chunk 后 Host stream sync，最后一 chunk 后再提交 scatter | Torch Tensor；scatter 完成后可覆盖 |
| E-002 | `orderWorkspace[0:N]`，UINT32 | K-002 → K-003/K-005 | scatter 后 stream sync | Torch Tensor；greedy 完成后释放 |
| E-003 | `sortedCoords[0:4A]` SoA FP32；`sortedAreas[0:N]` FP32 | K-003 → K-004 | reorder 后 stream sync | Torch Tensor；mask 完成后不再读 |
| E-004 | `maskWorkspace[0:N*A]` row-major UINT8 | K-004 → K-005 | mask 后 stream sync | Torch Tensor；greedy 完成后释放 |
| E-005 | `countWorkspace[0]` INT32 | K-005 → Host D2H | greedy sync；D2H async 后再次 sync | Torch Tensor；resize 后释放 |

## Route 与参数设计

### 分核与资源计算

活跃路线不查询硬件核数，也不生产传统 Tiling POD。rank chunk 大小固定 2048，chunk 数为 `ceil(N/2048)`；K-001/K-002/K-003 均启动一个 AIV block、SIMT `blockDim.x=2048`。K-004 固定启动 20 个 AIV block，每块 2048 SIMT lane：core `c` 处理 reference 行 `c,c+20,...`，lane `t` 处理 destination `t,t+2048,...`。K-005 固定单核顺序遍历排序位置。`A=align_up(N,32)` 只用于 SoA/mask GM 行跨度，`B=align_up(N,256)` 用于 greedy Vector buffer。

### Route 选择

Route 按知识复用重要性降序展示。`P0` 是卡内展示级别，不是 Host runtime selector：固定 Host 没有 priority/key 分支，校验成功即进入 R-001，失败即终止。

| 重要性 | Route | Route 特征 | 适用域与实现前提 | Host 顺序、短路与 fallback |
|---:|---|---|---|---|
| P0 | R-001 rank-count + byte-mask greedy | rank-chunk 计数、rank scatter、坐标重排、pairwise byte mask 与单核 greedy 组成固定五阶段图 | Meta/PrivateUse1 校验成功，输入 contiguous 且同设备，阈值 `(0,1)`；固定 FP32/UINT32/INT64 body | 唯一 Host 可达 Route；任一校验、launch、sync、D2H 或 count 检查失败即报错，无 fallback |

```text
if shape/dtype/device/contiguous/threshold invalid: fail before launch
else: P0 / R-001
```

### 模板/实现执行矩阵

| Route | key/selector | dtype/shape/platform 完整命中条件 | 执行拓扑与 Kernel 节点 | 实际模板/body | 内存与同步特征 | tail/fallback |
|---|---|---|---|---|---|---|
| P0 · R-001 | 无 key；唯一 Host 路线 | FP32 boxes `[N,4]`、FP32 scores `[N]`、950 Direct 构建、同设备 contiguous、阈值 `(0,1)` | `ceil(N/2048)`×K-001 → K-002 → K-003 → K-004 → K-005 | `RankChunkSimt`、`ScatterRanksSimt`、`ReorderSimt`、`PairwiseSuppressSimt`、`KernelGreedy::Process/ApplyRow` | GM Tensor 边；逐 stage Host stream sync；K-001 与 K-005 使用 UB | chunk、SIMT grid-stride、reference stride 与 MicroAPI mask 覆盖尾部；无 fallback |

### 隐藏性能 Guard

| Guard | Host/Tiling 条件 | Device/资源原因 | 影响 Route | 不满足时去向 | 源码符号 |
|---|---|---|---|---|---|
| score 全序 | 对任意 `i!=j`，`scores[i]!=scores[j]` 且 rank 比较具有全序 | `order[rank]=index` 无 atomic；并列 rank 会发生写冲突/空洞 | P0 / R-001 K-001/K-002 | 无 fallback；调用者必须满足转换契约 | `RankChunkSimt`、`ScatterRanksSimt` |
| rank chunk UB | `chunkLength=min(2048,N-chunkStart)` | 单 TBuf 必须容纳 `align_up(4*chunkLength,32)` B，最大 8192 B | P0 / R-001 K-001 | 固定分块；launch/sync 失败则报错 | `nms_rank_chunk_kernel` |
| 32 位尺寸 | `N`、`A`、`P` 及乘积进入 `uint32_t`/Tensor shape | `N*A` mask、`4A` coords 和 pointer offset 不得溢出 | 全路线 | 固定转换未显式守卫，超界不可复用 | `nms_npu` |

| 同上 | `sortedCoords` | `GM_ADDR`/工具链定义 | 同上 | GM address | `sortedCoords.data_ptr()` | K-003/K-004 | SoA，4 个 stride=A 平面 |

## Kernel 实现

### 公共执行流程

全部活跃 entry 都设置 `KERNEL_TASK_TYPE_DEFAULT(KERNEL_TYPE_AIV_ONLY)`。K-001 用 AIV 的 `TPipe/TBuf/DataCopyPad` 搬入一个 score chunk，再从同一 AIV block 内调用 2048-lane SIMT；K-002～K-004 直接从 AIV entry 调 SIMT；K-005 使用 AIV Queue、Vector Duplicate、MicroAPI mask/select 与标量 greedy。节点之间只以 GM Tensor 交接，不传 opaque Device workspace 或 Tiling buffer。

### Route R-001（P0）：rank-count + byte-mask greedy

#### 适用条件

| 优先级 / Route | 路线特征 | 适用域 | 实现前提 |
|---|---|---|---|
| P0 / R-001 | chunk rank-count 排序、SoA 重排、20 核 full byte mask、单核 Vector greedy | 950 Direct；FP32 `boxes[N,4]` 与 `scores[N]`；同设备 contiguous；阈值 `(0,1)` | 合法框；`scores` 比较形成无并列全序；所有尺寸乘积可表示；GM/UB 容量满足后文公式；逐 stage 同步保持不变 |

##### 选择证据

##### 源码等价伪码

```text
# 伪码；保持活跃源码顺序
ranks[0:N] = 0
for start in range(0,N,2048):
    L = min(2048,N-start)
    scoreLocal[0:L] = scores[start:start+L]
    wait MTE2 -> Vector/SIMT visibility
    parallel tid in [0,2048):
        for i=tid; i<N; i+=2048:
            rank = 0 if start==0 else ranks[i]
            for off=0; off<L; ++off:
                rank += (scoreLocal[off] > scores[i])
            ranks[i] = rank

parallel tid in [0,2048):
    for i=tid; i<N; i+=2048: order[ranks[i]] = i

parallel tid in [0,2048):
    for pos=tid; pos<N; pos+=2048:
        i=order[pos]
        coords[0*A+pos]=boxes[4*i+0]; coords[1*A+pos]=boxes[4*i+1]
        coords[2*A+pos]=boxes[4*i+2]; coords[3*A+pos]=boxes[4*i+3]
        areas[pos]=(x2-x1)*(y2-y1)

parallel core in [0,20), tid in [0,2048):
    for ref=core; ref<N; ref+=20:
        for dst=tid; dst<N; dst+=2048:
            if any coordinate is NaN: remove=true
            else:
                intersection=clamped_width*clamped_height
                iou=intersection/(areas[ref]+areas[dst]-intersection+1e-6)
                remove=!(iou<=threshold)
            mask[ref*A+dst]=uint8(remove)

alive[0:B]=1; keepCount=0
for pos in [0,N):
    wait previous Vector store -> scalar load
    if alive[pos]==0: continue
    output[keepCount++]=int64(order[pos])
    row[0:N]=mask[pos*A:pos*A+N]
    for vec in chunks of 256 bytes:
        alive = select(0, alive, row==1, active_tail_mask)
    Vector store/load barrier; wait Vector -> scalar
count[0]=int32(keepCount)
```

## 算子特定优化

### Trick T-001：并行关系生成与有序 greedy 解耦

#### 触发与源码依据

- 适用 Route：P0 / R-001。
- 触发条件：所有合法 `N`；先完成 pairwise suppression 介质，再按 `scores` 顺序传播。
- Golden 来源：[`image/nms_with_mask/op_kernel/arch35/nms_with_mask_regbase_multiprocess.h:72-83`](https://gitcode.com/cann/ops-cv/blob/bb717d075d129fd1fc7b96b2886824a1d153ed2f/image/nms_with_mask/op_kernel/arch35/nms_with_mask_regbase_multiprocess.h#L72-L83)

**官方源码（固定 Commit 连续逐字摘录）**：

```cpp
__aicore__ inline void NMSWithMaskRegbaseMultiProcess<T>::Process()
{
    if (blockIdx_ >= usedCoreNum_) {
        return;
    }
    PreProcess();
    // reset tque
    PipeBarrier<PIPE_ALL>();
    SyncAll();
    ReInit();
    PostProcess();
};
```

#### 机制与设计原因

greedy 选择存在严格的顺序依赖，不适合直接把 `position` 并行化；pairwise IoU 则彼此独立。官方 950 body 先由多核 `PreProcess` 计算上三角 packed mask，再 `SyncAll` 后 `PostProcess` 传播。转换路线保留“关系生成→全局可见→有序传播”的结构，但派生为 20 核 full byte matrix 与单核 greedy：K-004 每个 `(ref,dst)` 由唯一 SIMT lane 写入，K-005 只做 byte mask 的 Vector select，从而不在 greedy 内重复计算 IoU。full byte matrix、固定 20 核和 Host stage sync 均是转换选择，不是官方原实现。

#### 迁移边界

- 适用：pairwise predicate 可并行、最终选择必须保持全序的 NMS/过滤任务。
- 前提：可承担 `N*A` B 的 GM mask；producer 与 consumer 之间有明确 stream/event/barrier；排序顺序已闭合。
- 失效：mask GM 不可承受时需改用官方式 packed/triangular mask或分块流式 greedy，并重新证明同步与索引语义。
- 未验证：本次知识提取未执行编译、真机、数值或性能测试。

#### 错误做法

若省略 K-004→K-005 的完成同步，greedy 可能读取未完成的 row；官方源码以 `PipeBarrier + SyncAll` 明确证明这一边不能仅靠源码书写顺序替代。

### Trick T-002：为目标语义保留字面 FP32 除法与 epsilon

#### 触发与源码依据

- 适用 Route：P0 / R-001 K-004。
- 触发条件：所有非 NaN 坐标 pair；转换目标要求 `intersection/(union+1e-6)` 后再做 `<=threshold`。
- Golden 来源：[`image/nms_with_mask/op_kernel/arch35/nms_with_mask_regbase_multiprocess.h:480-483`](https://gitcode.com/cann/ops-cv/blob/bb717d075d129fd1fc7b96b2886824a1d153ed2f/image/nms_with_mask/op_kernel/arch35/nms_with_mask_regbase_multiprocess.h#L480-L483)

**官方源码（固定 Commit 连续逐字摘录）**：

```cpp
MicroAPI::Mul(intersection, minX2, minY2, preg);
MicroAPI::Sub(sumArea, sumArea, intersection, preg); // 视sumArea为并集大小
MicroAPI::Muls(sumArea, sumArea, iouThreshold_, preg);
MicroAPI::Compare<float, CMPMODE::GT>(pregIou, intersection, sumArea, preg);
```

#### 机制与设计原因

官方 950 `NMSWithMask` 用 `intersection > threshold*union` 避免除法；这与转换目标并不完全同构，因为目标分母额外加 `1e-6`，且 FP32 乘法交叉变换会改变边界舍入。转换 K-004 因此派生地保留 `denominator=union+1e-6`、`iou=intersection/denominator`、`remove=!(iou<=threshold)` 的字面顺序，并单独处理坐标 NaN。该选择服务数值语义，不声称比官方公式更快。

#### 迁移边界

- 适用：参考语义明确规定 epsilon、除法顺序和 NaN 比较方向的 NMS。
- 前提：FP32 输入/中间值；阈值先按 Direct ABI 窄化为 FP32；框面积定义一致。
- 失效：若调用契约就是官方 `intersection > threshold*union`，应保持官方交叉乘法；两者不能无证明互换。
- 未验证：本次知识提取未执行编译、真机、数值或性能测试。

#### 错误做法

直接把目标比较改写为官方交叉乘法，会丢失 `+1e-6` 并改变少量 FP32 阈值边界；固定官方源码本身正是该非同构边界的可验证反例。

## 限制与失败边界

- 转换目标与官方 `NMSWithMask`、`NonMaxSuppressionV6` 均不完全同构；不能用官方算子名替代对独立输入、坐标顺序、score sort、epsilon、NaN、INT64 动态输出的实现证明。
- rank-count 依赖 `scores` 无并列且比较可形成全序；并列或无序比较会使 `order[rank]` 写冲突。固定路线没有稳定 tie-break fallback。
- `N` 被窄化为 UINT32，keep count 又写 INT32；`P` 左移、`N*A`、`4A` 与各指针偏移均缺少显式溢出 guard。复用时应把 `N<=INT32_MAX` 与全部字节乘积可表示性作为前置条件。
- Host 校验阈值 `(0,1)`，比官方 950 `NMSWithMask` 的 `[0,1]` 更窄；空 `N=0` 未被显式拒绝，但 `P=1`、零节点/零 mask 与最终 count 的行为没有专门分支证明，不应外推。
- K-004 物化 `N*A` B full byte mask，空间为 O(N²)；K-001 rank count 计算为 O(N²)，K-005 最坏也逐保留框读取 N 字节。本文不声称性能收益。
- Host 每个 stage 都同步，保证诊断式失败传播，但也阻止跨 stage 异步重叠；不得擅自删除同步而不补充等价 stream/event 证明。
- 固定官方源码只证明相关算法结构、950 支持与差异边界；Direct selector、workspace Tensor 复用、rank-count、full byte mask、动态 resize 与 Torch 生命周期均为转换交付事实。
- `direct_implementation_closed` 只表示静态源码链闭合，不证明转换载荷在全部输入域可运行或可发布；本卡不得作为运行验收结论。
- 本次知识提取未执行编译、真机、数值或性能测试。

| workspace/内存 | `sortedAreas` rank→area 跨阶段复用；mask row stride=A | 必须在 scatter 后才覆盖 rank；mask extent=N*A；owner 覆盖所有同步 | `nms_npu`、`ReorderSimt`、`KernelGreedy::Init`（转换派生） |
| 同步 | MTE2_V、逐 stage stream sync、V_S、LocalMemBar | 不得仅依赖源码书写顺序或提前覆盖 Queue/TBuf | `nms_rank_chunk_kernel`、`KernelGreedy::Process/ApplyRow`（转换派生） |
