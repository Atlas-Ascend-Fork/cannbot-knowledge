# Pi0.5（π0.5 · 开放世界泛化 VLA · 昇腾训练/在线推理/OM 离线三链路）

`cann-recipes-embodied-ai` 的操作类（manipulation）VLA 模型样例，演示 **Pi0.5（π0.5）** 在昇腾上的 **训练（Atlas A2）/ 在线 torch 推理（A2/310P）/ OM 离线推理（310P）** 三条链路。

> 论文：π0.5: a Vision-Language-Action Model with Open-World Generalization（arXiv:2504.16054）。上游本体 OpenPI https://github.com/Physical-Intelligence/openpi；`cann-recipes-embodied-ai` 基于 HuggingFace LeRobot 的迁移实现，LeRobot v0.4.0 后重构了 pi0/pi0.5 代码结构。

## 模型简介

Pi0.5 是基于 Pi0 的升级 VLA 模型：通过在**异构任务上协同训练（co-training）**——整合多机器人平台数据、高层语义预测、网络数据、混合多模态样例（图像观测 + 语言指令 + 目标检测 + 语义子任务预测 + 底层动作），实现更强的**开放世界泛化**。论文首次展示端到端学习驱动机器人能在全新家庭环境完成长时序高灵巧操作（如陌生住宅厨房/卧室清洁）。

延续 Pi0 的「VLM 主干（PaliGemma，慢系统）+ 流匹配/扩散动作专家（Gemma，快系统）」双流结构，同样基于条件去噪扩散（默认 10 步去噪），但针对视觉输入、token 长度、网络结构做了升级。完整架构与昇腾算子融合机制见 [flow-matching-action-expert](../modules/flow_matching_action_expert.md)；动作块思想对照 [action-chunking](../modules/action_chunking.md)。

## 链路一：Atlas A2 训练（LIBERO 模仿学习 + profiling 优化）

`manipulation/pi05/train/`：基于 LeRobot 在 LIBERO 上做模仿学习训练，并针对昇腾做 profiling 与性能优化。

- 硬件：昇腾 Atlas A2；CANN 8.3.RC1。版本锁定（Python3.10 / CANN8.3 实测兼容）：LeRobot **v0.4.4**（commit `8fff0fde7c79f23a93d845d1a50e985de01f8b8a`）、torch 2.8.0、torchvision 0.23.0、torch_npu 2.8.0.post2、torchcodec 固定 0.7.0（aarch64 需 ffmpeg 7.1.1 源码安装）。
- `setup.sh` 总入口编排 `setup_lerobot.sh` / `setup_cmake.sh` / `setup_deps.sh`。
- 推荐训练命令：`./run_train.sh pi05 --nproc 2 --disable-outer-suffix-checkpoint`；profiling：`./run_profiling.sh pi05 --nproc 2 --foreground --disable-outer-suffix-checkpoint --profile-wait 1 --profile-warmup 1 --profile-active 2 --profile-repeat 1`。默认配置下稳定训练区间约 **5.75~5.85 s/it**。

profiling 暴露四类开销并对应四类优化（已吸收进 `modeling_pi05.py` 与脚本默认配置）：

| 优化项 | 默认 | 作用 | 实测 |
| --- | --- | --- | --- |
| `sample_beta` fast path | 开 | `Beta(1.5,1.0)` 时间采样避通用分布采样开销、避免退回 CPU | 影响较小 |
| `PI05_FUSE_PALIGEMMA_QKV=1` | 开 | PaliGemma q/k/v 投影融合一次线性层 | attention 计算明显下降 |
| `PI05_USE_NPU_FUSION_ATTENTION=1` | 开 | `torch_npu.npu_fusion_attention` 替 eager attention | 约 +5% |
| `PI05_USE_NPU_GROUPED_GEMMA_INPROJ=1` | 开 | Gemma MLP `gate_proj`/`up_proj` 合并 `npu_grouped_matmul`，反向手写标准线性层梯度 | 约 +1.0%~1.2% |
| DDP `static_graph=True` 等三项 | 文档声明开；固定快照接线缺陷见下文 | 固定训练图、关闭无用参数探测、复用 bucket view | 稳态收益，非主瓶颈 |
| `--disable-outer-suffix-checkpoint` | 推荐显式开 | 关闭外层 suffix 大 checkpoint，避免反向整段重算 | **当前单项收益最大** |

机制详见 [gradient-checkpoint-refine](../techniques/gradient_checkpoint_refine.md)（disable-outer-suffix-checkpoint + grouped GEMM）与 [ddp-static-graph](../techniques/ddp_static_graph.md)（DDP 静态图三项及固定快照导入/解析缺陷，须先修复接线再运行）。grouped GEMM 之所以有效：Pi0.5 默认开 gradient checkpointing，MLP 前向反向各算一次，合并后一个 step 内吃到「正向 + 反向重算」双份收益。

- **评测**：`run_eval.sh` 统一封装无头渲染（Xvfb + OSMesa）+ 多环境（libero/aloha/pusht），透传 `lerobot_eval` 选项。NPU 不支持 OpenGL，故仿真走离屏渲染：`Xvfb :1` + `MUJOCO_GL=osmesa` + `LD_PRELOAD=.../libOSMesa.so`，可经 VNC 实时查看。

## 链路二：在线 torch 推理（310P，~860 ms / A2 验证）

`manipulation/pi05/infer_with_torch/`：构造 mock 输入跑 Pi0.5 torch 推理（310P 使用 CANN 8.2.RC1；A2 使用 CANN 9.0.0 toolkit + 910b ops；共同使用 torch 2.5.1、torch_npu 2.5.1.post1（扩展版本7.1.0）、numpy 1.26.4，软件包需匹配 x86_64/aarch64）。

- 命令 `./run_pi05_inference.sh pi05_model float16 1 3 npu`，输出动作 `shape=[1,32]`（动作块 `[50,32]`，每次输出一组）。
- **性能：单次推理平均约 862 ms（throughput 1.16 FPS，float16，npu:0，3 次平均）**。
- 精度：mock 固定输入（全 0 图像 + 固定指令 token）下 NPU vs CPU/GPU 全局余弦相似度 1.000000、逐步最小 0.999999、MSE 0.000000（`verify_pi05_accuracy_ascend.py`，阈值 >0.99 通过）。

> 当前 README 的运行环境同时覆盖 310P 与 A2，分别选择对应 CANN/算子包；推理脚本 device 取 `npu`。此固定在线快照的 modeling_pi05.patch 保留 PaliGemma 与 Gemma 的 eager attention，不能套用 A2 训练侧的 QKV 融合 / npu_fusion_attention 默认值。不同链路的结构与算子边界见 [flow-matching-action-expert](../modules/flow_matching_action_expert.md)，图模式跨链 [npu-graph-mode](../../../inference/concepts/techniques/npu_graph_mode.md) 与 [torchair](../../../inference/concepts/frameworks/torchair.md)，注意力融合对照 [fused-infer-attention-score](../../../inference/concepts/kernels/fused_infer_attention_score.md)。

当前 torch 适配补丁的 4D mask 取 `dtype = self._inference_dtype()`，通过 `torch.where(mask, 0.0, torch.finfo(dtype).min)` 使用目标 dtype 的有限最小值屏蔽无效位置，不再直接复用 OPENPI_ATTENTION_MASK_VALUE 常量。

## 链路三：310P OM 离线推理

`manipulation/pi05/infer_with_om/`：PyTorch → ONNX → ATC → OM（CANN 8.0.0~8.2.RC1）。示例模型 `lerobot/pi05_libero_finetuned_v044`（MuJoCo/LIBERO 微调，2 路摄像头 256×256）；适配基于 LeRobot commit `58f70b6bd370864139a3795ac3497a9eae8c42d5`。

- **两段 OM 切分**：Part1 VLM（PaliGemma，输出 `past_kv_tensor` + `prefix_pad_masks`，每次 1 调用）+ Part2 action expert（Gemma，10 步去噪循环调用）。`convert_pi05_part1.py` / `convert_pi05_part2.py` 导出 ONNX（Part1 中间张量存 `runtime_save/`），`pi05_onnx_e2e.py`（CPU 端到端 baseline）→ `pi05_om_e2e.py`（NPU OM 端到端）→ `compare_action.py` 比对。
- **输入输出契约**（Part1 VLM）：state `[1,8]` f32、两路图像 `[1,3,256,256]` f32、language tokens `[1,200]` int64、prefix masks（1D `[1,968]` bool / 4D `[1,1,968,968]` f32）；其中拼接序列长度 **968 = 3×256（图像 token）+ 200（文本 token）**。Part2 输入 KV cache + masks + time `[1]` f16 + noise `[1,50,32]` f16，输出 action `[1,50,32]`（`max_action_dim=32`，按实际自由度截断，如 7）。
- ATC：`--soc_version=Ascend310P1`（或 310P3）、`--precision_mode_v2=origin`。Pi0.5 OM 额外需对 `transformers` 打 Gemma 补丁 + 对 `torch/onnx/symbolic_opset14.py` 打 ONNX symbolic(opset14) 补丁（apply_symbolic_opset14_patch.sh 针对 torch==2.7.1；其他版本需核对补丁内容）。
- 仿真评测：`lerobot_modified/lerobot_eval_om.py` 作为 OM backend 接入 LeRobot eval / LIBERO。

**已验证 OM 性能（310P）**：

| 模块 | 平均耗时 (ms) |
| --- | ---: |
| PaliGemma（Part1，1 次） | 223.08 |
| Gemma（Part2，单次调用；10 次共约 155.8 ms） | 15.58 |
| End-to-End（Part1 + 10×Part2 + KV 拷贝） | 410.2 |

OM 正确性：用 `input_data/start_obs_0.pt` 比对 OM vs PyTorch 动作（张量 `[1,50,7]`）平均余弦相似度 **0.999984**、最小 0.999850、最大 1.000000、标准差 0.000029。

算子退化、KV cache 展平、dtype/mask 约束与跨样例部署阻塞集中在 [om-atc-offline](../techniques/om_atc_offline.md)，平台见 [ascend-310p](../platforms/ascend_310p.md)。
