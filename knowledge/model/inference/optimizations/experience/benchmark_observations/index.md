# 基准观测

- [DeepSeek-V3.2-Exp 各量化档 (W8A8C16 / W8A8C8 / W4A8C8) 精度近 BF16 基准](benchmark_deepseek_v32_quant_accuracy.md)：DeepSeek-V3.2-Exp 各量化档 (W8A8C16 / W8A8C8 / W4A8C8) 精度近 BF16 基准。在 DSA 稀疏注意力 MoE 模型（DeepSeek-V3.2-Exp 及同结构）上评估「量化会不会掉精度、该选哪个档」时，用这组仓自报精度作验收目标 / 搜索先验：W8A8C16、W8A8C8、W4A8C8 三档在 MMLU/GPQA/DROP/MGSM 上均近 BF16、无明显回退。即「昇腾侧对该模型做低比特量化，近无损是可达标的预期」；据此可优先选更省显存的档、把评测精度阈值定在 baseline ±0.5 点内，而非一见量化就担心大幅掉分。
- [DSA/SFA 长序列服务化：跨步复用 top-k 索引（IndexCache）摊薄 indexer 选择开销换吞吐（GLM-5 W8A8 一次观测）](dsa_indexcache_topk_reuse_throughput.md)：DSA/SFA 稀疏注意力长序列服务化 decode 的一次可复现性能观测（benchmark_observation）：稀疏注意力每个前向步都要跑 top-k KV 索引选择（Lightning Indexer 从 KV 选参与稀疏注意力的位置），相邻解码步 top-k 索引时间稳定，可跨步复用缓存索引（IndexCache / index_topk_freq）摊薄 indexer 重算换吞吐。参考实现 vllm-ascend（vLLM NPU 适配仓，SFA 昇腾路径 sfa_v1.py + mla.py），开关 --hf-overrides '{"use_index_cache": true, "index_topk_freq": 4}'（每 4 步重算一次、复用 3/4 索引）。GLM-5 W8A8、random 输入 20480/输出 100 的 vllm bench serve 观测：Concurrency 1 总 token 吞吐 1289.57→1502.87 tok/s（+16.54%）、Mean E2EL -14.19%、Mean TTFT -17.06%；Concurrency 3 吞吐 +16.87%、P99 ITL -22.48%，两组 0 failed。C-Eval 0.9008→0.9063 精度未劣化。数据为 PR 作者自报、无独立复测（doc 披露），仅两组受控配置，不外推其它模型/序列长度/复用频率。昇腾 NPU、W8A8 量化、long_sequence decode 场景。
