# 优化案例

- [Attention-FFN 解耦（AFD）部署：把 MoE/FFN 剥到独立 rank，Send/Recv over SDMA 解除同卡多流控核约束降 decode TPOT](afd_attn_ffn_disaggregation.md)：Attention-FFN 解耦（AFD）部署：把 MoE/FFN 剥到独立 rank，Send/Recv over SDMA 解除同卡多流控核约束降 decode TPOT。大规模 MoE 在图模式 decode 阶段遇到 host-bound / TPOT 瓶颈，且现方案是 Attention 与 MoE 同卡、靠多流并行「控核」（limit_core_num 给 Attention 流与 MoE 流分配部分 Cube/Vector 核做流水）来取性能时。控核有固有代价——每条流只能用部分核、算子受算力约束。
- [AscendC 融合算子 Tiling 定块与片上 Buffer 预算：核间 m 轴取舍 + L1/L0 字节账 + UB double-buffer 全计入](ascendc_attention_op_tiling_budget.md)：给 ascendc 融合算子（sparse-flash-attention / lightning-indexer 等注意力算子、RoPE 类算子）定 Tiling 时。片上 Buffer 有限，任何计算都要切块；基本块大小直接决定右矩阵重复搬运次数、进而影响访存效率与算力利用率。定块的核心是精确核每块占多少片上 buffer（L1 / L0 / UB），预算算大 → 装不下或运行期越界。硬件参考 atlas-a3：L1 512KB、L0A/L0B 各 64KB、L0C 128KB、UB 为 Vector 核 buffer，均开 double buffer（pingpong）。
- [DSA decode 显存预算：Full MLA KVCache + 新增 Indexer Key Cache（勿漏）+ Indexer 权重](dsa_decode_memory_budget_indexer_cache.md)：DSA decode 显存预算：Full MLA KVCache + 新增 Indexer Key Cache（勿漏）+ Indexer 权重。部署 dsa 结构（mla + lightning-indexer 稀疏选择）做长序列 decode 显存规划时。相较无 indexer 的 MLA 模型，DSA 的 decode 显存不只是 Full MLA KVCache——Lightning Indexer 带来两笔新增显存（一笔 cache、一笔权重），漏算会低估显存需求。
- [变长 Prefill 的 MLA FlashAttention 布局选 NTD（免 padding 又避 TND 的转置 / 带宽损失）](mla_prefill_flash_attention_ntd_layout.md)：变长 Prefill 的 MLA FlashAttention 布局选 NTD（免 padding 又避 TND 的转置 / 带宽损失）。Prefill 里请求 seq_len 不定长（每请求长度不同），MLA 段的 FlashAttention 要选输入布局。三种候选在「免 padding」与「访存 / 转置效率」上此消彼长，选错会浪费算力或撞访存瓶颈。
- [多流并行后还要分核：limit_core_num 给两条重路径流配不同 Cube/Vector 核数、让时长趋近](moe_multi_stream_limit_core_num.md)：多流并行后还要分核：limit_core_num 给两条重路径流配不同 Cube/Vector 核数、让时长趋近。已经给 decode 开了多流并行（如把 MoE/共享专家旁路切到副流），但 profile 里两条流时长差很多、明显拖尾，整体关键路径没缩短时。尤其两条路径都很重（attention 主路径与 FFN/shortcut-MoE 副路径都吃算力）的模型。
- [评估 MTP 推测解码收益：稀疏注意力(DSA)按模块分化、SFA 不吃 MTP + 等效时延度量口径](mtp_benefit_sparse_attention_and_latency_metric.md)：评估 MTP 推测解码收益：稀疏注意力(DSA)按模块分化、SFA 不吃 MTP + 等效时延度量口径。在稀疏注意力结构上评估「要不要上 MTP、能加速多少」（mtp-speculative-decoding）。MTP 靠一次前向多推 token 提高计算访存比，但收益不是全网均匀：在 dsa（lightning-indexer + sparse-flash-attention）上按模块分化，别对 SFA 期待 MTP 加速。 同时给出 MTP 等效时延的正确度量口径，避免读错加速比。
- [online decode 调度防 KV 打满死锁：入场预留 + cheapest-victim retraction + break→continue](online_decode_kv_admission_retraction.md)：online-pd-inference 的 decode 实例、连续调度、共享 kv-cache-manager KV 池、高 QPS 突发负载。若无入场控制，高 QPS 突发会贪婪填满 KV cache，随后没有一个 running 请求能再长出下一个 token → 死锁；另有两种退化：running 非空但当前 step 预算装不下任何请求时永远 fall through 到 dummy batch（KV 一直满、无请求推进）；队首单个不可装的大请求阻断其后本可入场的小请求（head-of-line blocking）。
