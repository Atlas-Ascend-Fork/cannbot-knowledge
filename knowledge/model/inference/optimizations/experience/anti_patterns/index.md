# 反模式

- [310P 上 dense/VL 模型 bringup：须显式规避的不可用算子路径 + KV cache/mask 的 NZ 布局约束](ascend_310p_bringup_unusable_ops_and_nz_layout.md)：Ascend 310P 上部署 Qwen2.5/3 与 Qwen2.5-VL 时，应绕开当前不支持的 MLA、稀疏注意力、MLAPO、batch_matmul_transpose、ATB 预热、KV cache transfer 和共享 KV tensor 路径，并强制 eager 模式。310P attention 仅注册非 MLA、非 sparse 后端，相关 AscendC 算子还会在构建期剔除。可用路径要求 fp16 张量采用 ACL_FORMAT_FRACTAL_NZ，尾维按 16 对齐；KV cache 重排为 16-packing，prefill 与 chunked-prefill 的 mask 也须补齐后转 NZ。forward 仅覆盖 DecodeOnly、PrefillNoCache 和 ChunkedPrefill。以上限制只针对当前 310P 实现，不应外推到 A2/A3。
- [AscendC 算子入参校验的静默失效陷阱：可选输入漏 nullptr 守卫·&& 串联漏拦截·meta 侧漏守卫](ascendc_op_input_validation_pitfalls.md)：AscendC 算子入参校验的静默失效陷阱：可选输入漏 nullptr 守卫·&& 串联漏拦截·meta 侧漏守卫。你在为 AscendC 融合算子写/审 host-tiling 参数校验，或 PyTorch 绑定的输入守卫，想避免「非法入参不报错、静默穿过、到真实执行才崩」。以下三类写法都会让校验形同虚设，是需要修的缺陷（harden），不是风格问题。共同后果是错误被放行到更下游、根因与现象脱节，极难定位。
- [写 AscendC MicroAPI 向量核的静默正确性陷阱：多行 UB 地址步长·寄存器作用域](ascendc_vector_kernel_silent_correctness_pitfalls.md)：写 AscendC MicroAPI 向量核的静默正确性陷阱：多行 UB 地址步长·寄存器作用域。你在写 AscendC MicroAPI 向量核（__VEC_SCOPE__ register-level 向量编程，参考实现为 kv_compress_epilog / indexer_compress_epilog 这类逐行处理压缩 KV 的融合算子）。以下两类写法会在特定 shape/迭代下静默写错结果或成为需修的缺陷，编译期不一定报错。
- [C8 KVCache 与 PyPTO Lightning Indexer 互斥，不能叠加](c8_kvcache_disables_pypto_lightning_indexer.md)：在 DeepSeek-V3.2-Exp（DSA 架构）上，不要期望 C8 KVCache 量化 与 PyPTO 版 Lightning Indexer 加速 同时生效。二者当前互斥：一旦开启 C8（kv_cache_quant_mode == "int8"，早期实现里叫 kv_cache_c8），Lightning Indexer 的 decode 会被强制路由到 C8 量化算子 npu_lightning_indexer_quant，PyPTO 快路 npu_lightning_indexer_pto 永远不可达。想同时吃 C8 的显存收益和 PyPTO 的 LI 加速，会落空。
- [多网卡主机上对外通告的传输地址用启动配置固定、不靠运行时网卡探测](multinic_pd_advertise_address_launch_config.md)：多网卡主机上对外通告的传输地址用启动配置固定、不靠运行时网卡探测。你在多网卡（multi-NIC）主机上部署需要对端互连的分布式服务，要决定「本 rank 对外通告哪个 IP」。观测实例：PD 分离在线推理 的 prefill rank 把 ZMQ PULL socket 地址（rank_ip/rank_port）注册进 Bootstrap，供 decode 端 PUSH metadata；多网卡主机上「对端应连哪个 IP」有歧义。
- [昇腾适配禁用 tensor.is_cuda 作 CUDA/NPU 判别位：torch_npu 下 NPU 张量 is_cuda 恒为 True](npu_tensor_is_cuda_not_cuda_npu_discriminant.md)：在昇腾 NPU（torch_npu）上适配一份原为 CUDA 编写的框架 / 模型 / 算子链路，代码里出现形如 `if x.is_cuda: 走某条 CUDA 专属路径`（尤其「`if x.is_cuda: 调 torch.ops._C.<some_custom_op>`」按设备门控 custom op）时，本页适用。核对处境：你正在移植上游用 `is_cuda` 分派设备后端的入口，或已在 NPU 上撞到「明明在 NPU 上跑却进了 CUDA-only 分支、调到不存在的 op」的报错。
- [昇腾性能测量失真陷阱：不代表真实访存的测量输入·折算前被截断的度量口径](perf_measurement_distortion_input_and_metric.md)：昇腾性能测量失真陷阱：不代表真实访存的测量输入·折算前被截断的度量口径。你在昇腾上做算子/推理的性能测量或 profiling，要判断某优化是否真有收益。测量方法本身的两类缺陷会让性能数字系统性失真——测出的「快/慢」不代表真实 workload。测量代码要和被测算法一样被审。
