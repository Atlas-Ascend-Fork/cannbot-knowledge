# 模型

- [DeepSeek-R1](deepseek_r1.md)：DeepSeek-R1 是 2025 年 DeepSeek 开源的大语言模型，结构沿用 DeepSeek-V3 —— MLA (Multi-head Latent Attention) + DeepSeekMoE（1 个 shared expert + 256 个 routed expert，top-k=8）。在 cann-recipes-infer 中基于 DeepSeek HuggingFace modeling_deepseek.py 迁移到昇腾 Atlas A3，通过自研 executor/ 推理框架（非 SGLang/vLLM）承载，与 Kimi-K2 / kimi-k2-thinking 共享同一套 models/deepseek_r1/models/modeling_deepseek.py 代码路径（Kimi-K2-Thinking 的 runner_deepseek.py 直接复用）。
- [DeepSeek-V3.2-Exp](deepseek_v3_2_exp.md)：DeepSeek-V3.2-Exp 是 DeepSeek 2026 年发布的实验性长序列模型，在 DeepSeek-V3.1 基础上引入 DeepSeek Sparse Attention (DSA) —— 由 Lightning Indexer (LI) 与 Sparse Flash Attention (SFA) 两个核心模块组成 —— 通过"选前 TopK 个相关 token 再计算注意力"将长序列 Attention 从 O(S²) 降至 O(S·TopK)。DSA 的引入保留了完整 MLA KVCache，同时新增 Indexer Key Cache；MoE/MLA 主干继续沿用 V3.1 的结构。
- [DeepSeek-V4](deepseek_v4.md)：DeepSeek-V4 是面向长序列的 DeepSeek 新一代模型，包含 Flash 285B 与 Pro 1.6T。它以 C1A/SWA（窗口 128）、CSA（4:1 压缩后由 LI 选 Top512）和 HCA（128:1 压缩）交错组成 Hybrid Attention，统一使用 MQA/Shared-KV、Attention Sink 和 mHC；128K 序列下 HCA 约保留 1K KV，CSA 约保留 32K。MoE 每 token 激活 6 个路由专家和 1 个共享专家，Flash/Pro 分别有 256/384 个路由专家。Prefill 使用 CP+zigzag，Decode 使用 DP+EP，并支持 MTP1/MTP3。A3 主要采用 W8A8C16 或 INT8-INT4，950PR/DT 支持 FP8/MXFP4；图模式默认 npugraph_ex。性能数据必须同时限定平台、卡数、量化、序列长度和 MTP 配置。
- [Gemma-4-26B-A4B](gemma4_26b_a4b.md)：Gemma-4-26B-A4B 是 26.5B 参数、每 token 激活约 3.8B 的多模态 MoE；当前样例只适配语言 MoE Decoder，不含视觉塔，BF16 权重约 51.6GB，建议 8 卡。30 层按 5:1 交错 25 层 sliding GQA（window=1024）与 5 层 full GQA，full 层 K/V 共享；每层 Dense MLP 与 128-expert、top-8 MoE 并联。两类 Attention 使用不同维度的逐层连续 KV 缓存，不走 Paged Attention。Decode 的 EP8 可选 MC2 或 local_experts，后者保持静态 shape 以适配 GE fullgraph；默认选择还受 A2 每 rank ≤24 experts 限制。当前支持 GE/npugraph_ex，W8A8/W4A16 和视觉塔尚未适配，GEGLU 与 partial RoPE 仍有算子能力缺口。
- [GLM-5](glm_5.md)：GLM-5 是智谱（Z.ai）744B-A40B MoE 大模型，网络结构与 DeepSeek-V3.2-Exp 完全一致（DSA：MLA 主干 + Lightning Indexer 稀疏选择），cann-recipes-infer 在 Atlas A3 上的并行策略与性能优化方案直接沿用 V3.2-Exp。覆盖 GlmMoeDsaForCausalLM 规格（78 层、6144 hidden、256 路由+1 共享专家 top-8）、DSA 注意力（MLAProlog + MLA 吸收 + GlmMoeDsaIndexer index_topk 2048 + CP 路径）、MoE EP 三路实现（double-routing / dispatch_v2+combine_v2 + 独立通信域 fullmesh_v2 / multi-stream）、sigmoid+noaux_tc 路由、W8A8C16 量化、CP 长序列(65536)+Attention DP、Embed/LMHead TP16、MoE EP 64/128、MTP3、KVCache Offload。Atlas A3 W8A8 decode 64 chips TPOT 22.54ms / 177.46 tokens/p/s。
- [GPT-OSS](gpt_oss.md)：GPT-OSS 是 OpenAI 开源的 MoE 架构大语言模型家族，包含 **GPT-OSS-20B** 与 **GPT-OSS-120B** 两个规格。cann-recipes-infer 基于 HuggingFace Transformers 官方 `modeling_gpt_oss.py`，在 **Atlas A2 系列产品**上实现了单机单 batch 推理样例：GPT-OSS-20B 单 device 部署，GPT-OSS-120B 8 卡 TP 部署。 优化手段为经典"大 MoE 模型 NPU 推理"组合拳：Attention TP + MoE TP（`gate_up_proj` 合并）+ 固定 KV Cache + 融合算子（RMSNorm / AddRMSNorm / `fused_infer_attention_score_v2` / MoE routing 四件套 / GroupedMatmul）+ 集合通信 AIV 展开。**本样例仅支持 eager 单算子模式 + batch_size=1**，暂未引入图模式 / MTP / EP / W8A8 等更激进的优化。
- [HSTU](hstu.md)：HSTU（Hierarchical Sequential Transduction Unit）是 Meta 论文《Actions Speak Louder Than Words》提出的**生成式推荐（Generative Recommendation, GR）架构**，把推荐视为生成建模问题，以应对高基数、非平稳的数据流，同时**统一支持检索与排序**。基于 HSTU 的超大模型（1.5 万亿参数）在线 A/B 指标提升 **12.4%**，已在 Meta 多平台部署。 cann-recipes-infer 基于 NVIDIA recsys-examples `v25.11` 仓库进行 NPU 适配，替换了 GPU 算子与 tensorrt-llm KV Cache 管理逻辑，在 Atlas A2 系列产品上实现了 HSTU 单卡与多卡推理。与 LLM 模型不同，**HSTU 是生成式推荐模型**：输入是用户行为/物品的离散 ID 序列（jagged tensor），模型容量主要在**超大 Embedding 表**上，dense 部分相对较小。
- [HunyuanImage-3.0](hunyuan_image_3.md)：HunyuanImage-3.0 是腾讯混元发布的 MoE + DiT 文生图模型，cann-recipes-infer 提供 Atlas A2/A3 上的 TP 推理方案，并在其上叠加 **Attention TP、MoE TP、MoE EP（DoubleRouting）、MoE 多流、VAE 并行、CFG 并行、通算融合（AllGatherMM / MMReduceScatter）** 以及若干冗余 cast 消除。关键优化与相应源图并存，结构化拓扑用 mermaid 重绘。
- [HunyuanVideo](hunyuan_video.md)：HunyuanVideo 是腾讯发布的开源 DiT 文生视频模型；cann-recipes-infer 在 Atlas A2/A3 上实现了 NPU 适配与完整的推理性能优化方案。其 5s 720p（129 帧）生成任务里 **Attention 占 DiT 端到端 81%、DiT 占端到端 95%**，所以优化围绕长序列 Attention（FIA 融合算子、Ulysses / Ring SP、Ulysses Anything Attention、FP8 量化 FA、TopK / SVG 块稀疏）、DiT 多步缓存（FBCache / TeaCache / TaylorSeer）以及 VAE 侧（空间并行、mask 缓存、虚拟内存取消 offload）展开。叠加最优组合（ulysses8 + 融合算子 + VAE 并行 + VAE 优化 + 虚拟内存 + UAA）可在 Atlas A3 达到 **e2e 7.81×**（3768.91 s → 482.65 s）；量化叠加（MXFP8 A8W8 + FP8 Attn + ulysses8 + VAE 并行）在 950PR 上 **e2e 1.38×**。
- [Hy3-preview](hy3_preview.md)：Hy3-preview 是腾讯混元（Tencent Hy Team）的大规模 MoE 语言模型，总参 295B、激活 ~21B/token，结构为 Dense + Sparse MoE with Shared Expert + GQA 的 MoE Transformer。cann-recipes-infer 在 Atlas A3（8 卡 × 2 die = 16 die）上以 BF16 + ge_graph 图模式完成 NPU 推理适配，仓库内参考实现为 qwen3-moe（同 GQA+MoE+per-head QK Norm；Hy3-preview 相对多 shared expert + sigmoid router，QK Norm 为 Qwen3 系共性非差异）。最独特处：QK Norm（Q/K RoPE 前 per-head npu_rms_norm(128)）、Sigmoid Router（npu_moe_gating_top_k norm_type=1，e_score_correction_bias 在 sigmoid 后加 vs 算子内的 doc/impl 语义差异）、MTP layer(layer 80) 推理跳过、SuperKernel combine_v2 shared_expert_x 在 CANN 8.5.0 因 >2 stream 限制回退。80 层（layer 0 Dense FFN + layers 1-79 Sparse MoE，first_k_dense_replace=1）、192 experts top-8、Hidden 4096、词表 120832、最大上下文 256K、GQA 64Q/8KV。16 die：attn/dense/embed/lmhead_tp=4 + moe_ep=16（moe_tp=1）。Decode 28.44 ms/t（源内另记 30.8 ms/t 阶段值，并记不臆断）。
- [Kimi-K2-Thinking](kimi_k2_thinking.md)：Moonshot AI 于 11 月 6 日发布的最新思考模型 Kimi-K2-Thinking，擅长深度推理，打榜性能再创新高。其模型结构与 Kimi-K2 保持一致，**原生支持 MOE W4A16 + Attention BF16 混合精度模式**，兼顾推理性能与效果。 在 cann-recipes-infer 中，Kimi-K2-Thinking 结构与 Kimi-K2 基本一致，基础优化点可从 deepseek-r1 平滑继承——Kimi-K2-Thinking 与 DeepSeek-R1 共用自研 `executor/` 推理框架代码路径（`models/kimi-k2-thinking/` 只提供 config 和脚本，`runner_deepseek.py` 直接复用 DeepSeek 的 runner），本页重点描述其相对 R1 的差异点：原生 **MOE W4A16** 量化模式、Attention head 从 128 精简至 **64**、双配置（Prefill CP / Decode Attn-DP + MoE-EP + 局部 TP）、`enable_mla_prolog` 默认使能、CANN 0day 支持 256K 超长序列。
- [LongCat-Flash](longcat_flash.md)：LongCat-Flash 是美团 2025 年开源（arXiv 2509.01322）的 **560B MoE** 大语言模型，核心架构特色是 **ScMoE（Shortcut-connected MoE）**，每个 Transformer Block 内部存在 "第一段 Attention → FFN → 第二段 Attention → MoE" 的双段结构，天然存在可并行的计算路径。模型结构中与 Llama 类似的部分沿用通用优化点（固定 KV Cache 大小、cos/sin 优化、AddRMSNorm 融合）。 cann-recipes-infer 在 Atlas A3 上基于自研 `executor/` 推理框架对 LongCat-Flash 进行推理优化：除了沿用 DeepSeek-R1 的 MLA 融合算子 + EP MoE + 图模式 + SuperKernel + MTP 外，还引入了 **多流并行与控核**、**权重预取**、**o_proj TP K 轴切分**、**MLA KVP 切分**、**MLP dense-TP**、以及面向 Decode TPOT 极致优化的 **Attention-FFN Disaggregation (AFD)**，使能 AFD 后 TPOT 迈入 10 ms 内。 （MLA KVP 部署已于 2026-05 回退，kvp8 YAML/新 ParallelConfig.kvp_size 字段/优化文档移除，legacy modeling 代码残留）
- [LongCat-Flash-Lite](longcat_flash_lite.md)：LongCat-Flash-Lite 是 LongCat-Flash 的减配验证模型（顶层类 LongcatFlashNgramForCausalLM），保留 MoE + MLA + N-gram Embedding 核心结构、缩小到 14 层 / 256 routed+128 zero expert / top-12 规模，归档 EP 与 TP 两份终态部署报告。优化覆盖 MLA 压缩缓存 + Paged Attention（PA_NZ，省 55% KV）、MLA Prolog 融合（npu_mla_prolog_v3，decode）、算子融合、GE 图模式 decode 整图编译、MoE EP/MC2（dispatch_v2/combine_v2）与 Prefill double-routing；目标 Atlas A2/A3、BF16。config 变体：8ep / 8ep_b8 / 8tp / 8tp_4k1k（长输入）。
- [Qwen3.5-MoE](qwen3_5_moe.md)：Qwen3.5-MoE 是 Qwen3.5 系列中的混合专家模型，结构上同时包含 full attention、linear attention（Gated DeltaNet）和 MoE 三类 block，是 Qwen3-Next 混合注意力思路的延续与放大。cann-recipes-infer 基于 transformers 的 Qwen3.5-MoE 结构完成文本侧推理适配，跑在 Atlas A3 上，由仓库自研 executor 驱动多卡推理。与 Qwen3-Next 的关键差异在于 Prefill 阶段的 Gated DeltaNet 走 torch_npu.npu_chunk_gated_delta_rule 这一 torch_npu 原生融合算子，而非 Qwen3-Next 的 PyPTO ChunkGDN；Decode 阶段两者都用 npu_recurrent_gated_delta_rule。提供 35B-A3B(EP8) / 122B-A10B(TP8) / 397B-A17B(TP16) 三规格部署模板。
- [Qwen3-MoE](qwen3_moe.md)：Qwen3-MoE 是阿里千问 2025 年开源的 MoE 大语言模型，包括 Qwen3-235B-A22B 与 Qwen3-30B-A3B 两个版本。结构相对直接——标准 Softmax Attention + MoE FFN（无 shared expert、无 MLA、非 linear attention），是经典的 Dense Attention + Routed-Only MoE 架构。
- [Qwen3-Next](qwen3_next.md)：阿里千问团队发布了 Qwen3-Next 模型，使用混合注意力架构，结合 GatedAttention 和 GatedDeltaNet 模块，实现超长上下文长度的有效上下文建模。以 `Qwen3-Next-80B-A3B-Instruct` 为代表规格，总参数 80B，激活参数 ~3B。后续 Qwen3.5-MoE 延续了这一混合注意力 + MoE 思路，但 Prefill GDN 改用 torch_npu 原生 ChunkGDN 算子（非 PyPTO），且引入 full attention（merged_qkv 同时产 gate）层。cann-recipes-infer 在 Atlas A3 上基于 SGLang 框架完成 Qwen3-Next 的推理优化实践，重点介绍针对混合注意力架构设计的并行策略、高性能融合算子、MTP 投机推理及 W8A8C8 量化方案，以实现长序列场景下的高性能表现。Prefill 并行：Gated Attention 走 CP+TP 混合（CP 复用 SGLang DP 通信域、与 DP 互斥，激活方式 infer_prefill.sh `--cp-size` 替 `--dp-size`），ZigZag 负载均衡由 `CP_USE_ZIGZAG=1` 使能面向长序列单 batch；GDN 默认纯 TP（Conv1d 沿 Sequence 卷积不适合切分），但设 `ENABLE_CONTEXT_PARALLEL_GDN=1`（默认 false）后 GDN 不再强制 full TP、改走 CP+TP 混合（stage6 patch：cp_rank 切序列 + overlap 窗口 P2P + conv_state 末 rank 广播）。
- [Qwen Dense (Qwen2 / Qwen3 非 MoE)](qwen_dense.md)：Qwen Dense 是 Qwen2/Qwen3 非 MoE 模型的统一昇腾实现，通过 HuggingFace 配置识别 Qwen3-8B（有 QK-Norm）和 Qwen2.5-7B-Instruct（无 QK-Norm），由 CANN Executor 支持单卡或多卡 TP、Packed Sequence 与 Paged KV Cache。实现以 merged_qkv_proj、gate_up_proj、Add+RMSNorm、预计算 RoPE 和 FIA v2 减少 kernel 下发，并可编译 Decode 静态图；Dense MLP 随 attn_tp_size 切分，moe_tp_size 不生效。W8A8 路径采用权重 per-channel、激活 per-token 量化，并以 npu_dequant_swiglu_quant 合并反量化、SwiGLU 与再量化。模型适配范围是稠密 Qwen，不包含 Qwen MoE 变体。
- [Sana-Video](sana_video.md)：Sana-Video 是 NVIDIA SANA 家族的视频生成模型，在 cann-recipes-infer 中作为轻量级多模态生成样例接入昇腾 NPU。相关优化集中在两类：**VAE 侧的 conv 改写**（1×1 conv2d 转 matmul、时序 conv2d 的 HW 轴调换）与 **通用融合算子适配**（npu_rms_norm / npu_rotary_mul / npu_fusion_attention）。优化逻辑全部以 monkey patch 方式落在 `models/sana-video/patches/npu_patches.py`，通过 `inference_video_scripts/` 下的脚本调用。此外提供 **MX 块级量化推理**（`quant_type` a8w8=MXFP8 / a4w4=MXFP4，QuantLinear / Conv-as-Linear，`patches/quant_module.py`）。
- [Wan2.2-I2V](wan2_2_i2v.md)：Wan2.2-I2V 是阿里万相 2.2 的 Image-to-Video 生成模型，cann-recipes-infer 在 NPU 上提供融合算子适配、8 卡 VAE 并行、CFG 并行、Ring Attention Overlap、DiT-Cache（FBCache / TeaCache）等优化。代码入口为 `models/wan2.2-i2v/generate.py` + `run.sh`，DiT 结构位于 `models/wan2.2-i2v/wan/`。Cache 框架通过 `models/wan2.2-i2v/wan/cache/cache_config.json` 热切换。
