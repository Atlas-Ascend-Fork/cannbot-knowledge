# 框架

- [AscendC 算子编程机制](ascendc.md)：AscendC 的计算调度与片上缓冲区管理，以及受产品和版本限制的 L2 缓存配置；以 DeepSeek-V4 说明 A3 与 950PR/DT 的实现差异，提供 Top-k 理论周期推导、对照口径和实测方法。
- [AutoFuse（Inductor NPU 自动融合编译组件）](autofuse.md)：AutoFuse 是面向昇腾 NPU 的 PyTorch Inductor JIT 自动融合组件，将 InductorLoopIR 降为 AscendLoopIR，经 Schedule 模板选择、UB 复用和 ATT 自动 Tiling 后生成 AscendC Kernel。调度以 ComputeType、AxisGroup 和 Merge 规则产生 TilingCase，求解器结合 LocalBuffer、核数、切分与流水耗时选择方案。它主要覆盖 Pointwise/Reduce 等可连续编译区域，避免断图和反复编译；当前 152 个 LoopIR 中覆盖 46 个。DeepSeek-V4 的 hc_post 片段在 Atlas A3 典型 shape 下由 30 us 降至 7.5 us（dynamic=False）或 10 us（dynamic=True），但端到端收益尚未验证。AutoFuse 与 GE/npugraph_ex 图后端是并列路径。
- [CANN Executor（cann-recipes-infer 自研 executor）](cann_executor.md)：CANN Executor 是 cann-recipes-infer 自带、无需 vLLM/SGLang 的轻量推理执行框架；本页聚焦新执行器路径。它以 OfflineInference/OnlineInference→Scheduler→ExecutionEngine→ModelWorker→Model 五层组织离线批处理与在线 PD 分离，统一由 InferenceConfig 配置，并支持 eager、ge_graph、npugraph_ex、Packed Sequence、Paged KV Cache、Profiler 与通信域管理。图模式仅覆盖 Decode，Prefill 走 eager。模型需实现 forward、init_cache、load_weights，并通过 CommManager 注册 attention、FFN、MoE、embedding、lm_head、MC2 等计算组；OnlineInference 另建 Gloo 调度组。仓内还保留 legacy ModelRunner 和 HSTU 独立路径，它们不受本页接口约束。
- [KV Cache Manager（框架级 Paged Attention KV Cache 管理）](kv_cache_manager.md)：KV Cache Manager 是 CANN Executor 的 Paged Attention 缓存层，采用 KVCacheManager→SingleTypeKVCacheManager→BlockPool 三层结构协调请求、逻辑块与物理块。allocate_slots 先全局预检再统一分配，避免部分成功；SlidingWindow 使用固定块数，FullAttention 随序列增长，离线按 max_len、在线按显存预算计算，并以 _null_block 保证 block table 索引合法，MTP 额外预留 2×next_n 缓存。缓存按 manager_key 分组，同一注意力类型可因 block_size 不同拆成多个 manager；block_table 与 slot_mapping 也按该键生成。模型未返回 ModelCacheInfo 时回退到模型自管缓存。
- [MM Inference Launch（多模态生成模型统一推理拉起架构）](mm_inference_launch.md)：MM Inference Launch 是 cann-recipes-infer 为 Wan2.2-I2V、HunyuanVideo、SANA-Video 和 HunyuanImage-3.0 提供的统一多模态推理启动层。各模型以 infer.sh 和场景 YAML 为入口，mm_function.sh 负责字段校验、环境合并、cache/sparse 参数生成，并选择 torchrun 或 accelerate，日志统一写入模型 res 目录。YAML 对必填键、未知键、端口/卡数类型以及 Dit-Cache 和 sparse 方法枚举做校验；环境优先级为 NPU 默认→YAML→MODEL_BASE 派生→HCCL→用户 export。HunyuanVideo 的块稀疏 Attention 可配单卡或 Ulysses，但不支持 Ring，且与 cache 互斥。该体系独立于 LLM 的 CANN Executor。
- [PyPTO机制](pypto.md)：PyPTO 以声明式 Tensor 图表达融合算子，经 PTO-ISA、MPMD 调度和后端编译实现不同硬件的适配；本卡维护框架机制，Duration 与 VF 收益由独立观测记录。
- [SGLang](sglang.md)：开源 LLM 推理服务框架，在 cann-recipes-infer 中作为多个模型的基础推理引擎，提供原生的并行能力（TP、EP、DP）和在线推理服务能力。
- [TileLang](tilelang.md)：TileLang 是基于 TVM、面向 GPU/NPU/CPU 的 Tile 级算子语言，以类 Python 语法分离数据流与线程绑定、布局、张量化和流水调度。CANN 对接路径经多级 Lowering 生成 Ascend 代码、毕昇编译为 .so，再由 torch_npu 加载；已用于 DSA 的 Lightning Indexer、Sparse Flash Attention。DeepSeek-V4 Developer 模式提供 AscendC 与 PTO-AS 两个后端，通过自动 CV/核内同步、32B 对齐的生命周期内存复用及 CV 指令拆分，将样例代码量降至传统后端约 20%。当前 V4 样例覆盖 Sparse Flash Attention、mHC Sinkhorn、Int8 GEMM 和激活量化；T.Pipelined 是文档能力，但在该批样例中未发现调用。
- [TorchAir 图编译机制](torchair.md)：TorchAir 提供昇腾 torch.compile 后端；解释 GE 与图重放的机制及版本命名差异，模型部署和收益分别查阅对应入口。

- [在线 PD 分离推理执行机制：多机实例、DP 分发与 KV 传输（Online PD Inference）](online_pd_inference.md)：CANN Executor 的在线 PD 分离机制：Prefill 与 Decode 实例可跨机，各自配置并行拓扑，通过 Bootstrap 发现 Rank，DPDispatcher 分发请求，KVTransferManager 传送 KV。说明 Router、调度与入场控制；不由该机制推定任意 DP+EP 组合均已验证。
