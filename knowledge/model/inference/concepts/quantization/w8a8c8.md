# W8A8C8

## Summary

W8/A8/C8描述权重、激活与cache的量化组合；粒度和覆盖模块随实现不同，不能从位宽标签保证精度或端到端收益。

> C8 粒度随模型而异：DeepSeek-R1 为 Per-Tensor、DeepSeek-V3.2-Exp 为 Per-Token-Head-Tile-128（见下方 R1 / V3.2-Exp 路径差异小节）。

cann-recipes-infer 中三个代表性落地：

- **Qwen3-Next-80B-A3B-Instruct**：SGLang 路径，`ASCEND_USE_C8=1` + stage2 patch 挂载 `k_scale`/`v_scale`。
- **DeepSeek-R1**：自研 executor 路径，`convert_model.py --quant_mode w8a8c8` 离线转换权重；Decode 融合算子 `npu_mla_prolog_v3` 内嵌 `kv_cache_quant_mode=1` 与 `query_quant_mode=1` 完成 KV per-tensor + Q per-token-head 反量化。**仅 DeepSeek-R1 支持 C8，Kimi-K2 不支持。**
- **DeepSeek-V3.2-Exp**：自研 executor 路径 + DSA，覆盖面最广的量化设计 —— **W8A8C8**（MLAProlog C8 动态 Per-Token-Head-Tile-128、SFA KV Int8 存 BF16 算、IndexerProlog A8C8、LI Int8 BatchMatmul、MoE W8A8、MLAEpilog W8A8）或**W4A8C8**（MoE 路由专家切 W4A8 节约显存 2×，其余同 W8A8C8）。见 [deepseek-v3.2-exp](../models/deepseek_v3_2_exp.md) / [w4a8c8](w4a8c8.md)。

> **不覆盖 Kimi-K2-Thinking**：[kimi-k2-thinking](../models/kimi_k2_thinking.md) 采用同架构思路的独立建模副本，但其**原生量化模式为 MoE W4A16 + Attn BF16**，不支持 C8。Future Plan 中提到"未来可针对 Attention 开发低比特量化版本"。
>
> **LongCat-Flash**：使用标准 W8A8（不带 C8）量化，`convert_model.py --output_hf_path LongCat-Flash-Chat-W8A8` 转换；MLA 融合算子内部不使用 C8 分支（见 [longcat-flash](../models/longcat_flash.md)）。

## Mechanism

Qwen3-Next 路径下 W8A8C8 整体架构（各子模块量化边界与 scale 传递路径）源图如下：

![W8A8C8 量化架构](https://raw.gitcode.com/cann/cann-recipes-infer/raw/2f82d10467e6fe8dae81c97a2cdac78d733a6703/docs/models/qwen3-next/figures/w8a8c8_quantization.png)
*来源：[`docs/models/qwen3-next/figures/w8a8c8_quantization.png`](https://gitcode.com/cann/cann-recipes-infer/blob/2f82d10467e6fe8dae81c97a2cdac78d733a6703/docs/models/qwen3-next/figures/w8a8c8_quantization.png)（cann-recipes-infer @ 2f82d10）*

- **W8（权重）**：静态 Per-Channel 对称 Int8 量化，权重转换由 `convert_model_qwen3_next.py` 离线完成。
 - 覆盖：Gated Attention / Gated DeltaNet（conv1d 除外）/ MoE 路由专家 / Linear 等；
 - 不覆盖：LM_Head、GDN 的 conv1d、LayerNorm/RMSNorm 权重。
- **A8（激活）**：Per-Token 动态 Int8，DeepEP dispatch 路径通过 `DEEP_NORMAL_MODE_USE_INT8_QUANT=1` 切换到 Int8 版本（替代原 `SGLANG_DEEPEP_BF16_DISPATCH=1`）。Linear 层走 `w8a8_int8` quantization config（`--quantization w8a8_int8`）。
- **C8（KVCache）**：Per-Tensor 动态 Int8。
 - `ASCEND_USE_C8=1` 使能；memory_pool 的 `store_dtype = dtype = torch.int8`。
 - 写入：`torch_npu.npu_quantize(cache_k, reciprocal(k_scale), None, torch.qint8, -1, False)`，`k_scale`/`v_scale` 为逐层可学习参数（BF16，初始 1），由离线校准得到并通过 `attn_c8_scale.zip` 分发。
 - 读出：注意力算子走 `key_antiquant_scale=k_scale, value_antiquant_scale=v_scale` 的 FIA 路径进行反量化。
- **LM_Head**：保持高精度，不量化。
- **校准流程**：下载 `attn_c8_scale.zip` → 解压 → `convert_model_qwen3_next.py --c8 --quant_param_path ...` 生成 W8A8C8 权重包。

## Accuracy Impact

Qwen3-Next-80B-A3B-Instruct 四项基准：

| 基准 | BF16 | W8A8C8 | Δ |
| ---- | ---- | ------ | - |
| MMLU | 89.9 | 89.8 | −0.1 |
| GPQA | 73.6 | 74.0 | +0.4 |
| DROP | 88.9 | 88.4 | −0.5 |
| MGSM | 92.4 | 92.0 | −0.4 |

源表GPQA略高、DROP/MGSM略低；缺少重复测量，不能判断噪声范围或统计显著性。

## DeepSeek-R1 路径差异

R1 不走 SGLang 而走自研 `executor/`，量化入口由融合算子 [mla-prolog](../kernels/mla_prolog.md) 内部承担：

- **W8**：`weight_quant_mode=2` 让 `weight_dq`、`weight_uq_qr`、`weight_dkv_kr` 全部按 int8 参与 Q/K/V 前置 matmul；对应三组 `dequant_scale_w_*`。
- **A8**：`enable_mm_quant_a8w8 → npu_dynamic_quant(hidden_states)` 产生 `hidden_states_int8 + pertoken_scale`，传入 `dequant_scale_x`；MoE `npu_moe_init_routing_v2(quant_mode=1)` 与 dynamic quant 融合。
- **C8**：`kv_cache_quant_mode=1`（per-tensor），`quant_scale_ckv = self.ckv_scale_reci` 在 prolog 内完成 KV 量化后直接写入 NoPE cache；读出由 FIA `dequant_scale_key/value = self.ckv_scale` 做反量化。
- **Q-side C8**：`query_quant_mode=1` 在 prolog 输出 `dequant_scale_q_nope`，透传给下游 FIA 的 `dequant_scale_query`。
- 与 MTP **不互斥**（`decode_r1_rank_128_128ep_a8w8c8_mtp*.yaml` 多个配置同时启用）；与 Qwen3-Next 场景（C8 与 MTP 互斥）不同。
- 离线转换：`utils/weight_convert.sh --quant_mode w8a8c8`（脚本逻辑见 `convert_model.py`）。

## DeepSeek-V3.2-Exp 路径差异

V3.2-Exp 相对 R1 进一步把 C8 下沉到 **DSA 各子模块**，不同模块的量化粒度不同（源：`docs/models/deepseek-v3.2-exp/deepseek_v3.2_exp_inference_guide.md` 量化策略）：

| 模块 | W 侧 | A 侧 | KVCache |
| ---- | ---- | ---- | ---- |
| MLAProlog | 仅 `Q_b_proj` W8A8 | — | **Per-Token-Head-Tile-128** C8 |
| Sparse Flash Attention | — | — | Int8 **存 8 算 16**（BF16 计算） |
| IndexerProlog | 仅 `Q_b_proj` W8A8 | Indexer Q **Per-Token-Head** A8；Hadamard 变换前量化 | Indexer Cache **Per-Token-Head** C8 |
| Lightning Indexer | — | BatchMatmul **Int8 计算**（Mat-Duce 算法，见 [lightning-indexer](../kernels/lightning_indexer.md)） | — |
| MoE 路由专家 | W8A8（或 W4A8，见 [w4a8c8](w4a8c8.md)） | — | — |
| MoE 共享专家 | W8A8 | — | — |
| MLAEpilog | O_proj W8A8 | — | — |
| LM_Head | **不量化** | — | — |

设计理由（源文档）："IndexerProlog 融合算子设计成 `weights_proj` 出 FP16 且不做量化，因此 MLA 输入关联的 Linear 统一不做量化，好处是可将同一份 BF16 数据输入 IndexerProlog 和 MLAProlog。"

V3.2-Exp精度数字由[既有观测草稿](../../optimizations/benchmark_observations/benchmark_deepseek_v32_quant_accuracy.md)维护，评测条件仍有缺口，不在机制卡重复表格。

与 R1 的关键差异：V3.2-Exp 有 **DSA 专属的 A8C8 分量化粒度**（Per-Token-Head / Per-Token-Head-Tile-128）和 **Hadamard outlier 消除**；MLA KV Cache 与 SFA 的 C8 均按“存 8 算 16”理解；局部 W8A8 Linear 和 Lightning Indexer A8C8 的整数计算另行区分，不能把整个 MLA 概括为“算 8”。见 [sparse-flash-attention](../kernels/sparse_flash_attention.md)。

## Applicable Scenarios

- Atlas A3 上 Qwen3-Next 长序列 Decode（256K+）性能优先场景。
- R1 C8/MTP的大EP实践见[模型Guide](../../guides/models/deepseek_r1_deployment.md)，完整组合性能和卡数分歧见[R1 Decode 来源观测](../../optimizations/benchmark_observations/deepseek_r1_a3_decode_source_benchmark.md)。
- V3.2-Exp量化、长序列与Offload实现见[模型Guide](../../guides/models/deepseek_v3_2_exp_deployment.md)，历史时延/容量见[V3.2-Exp 来源观测](../../optimizations/benchmark_observations/deepseek_v32_a3_source_benchmark.md)。
- 大 EP + DeepEP Int8 dispatch 的吞吐部署。
- Qwen3-Next 不启用 MTP 的场景（Qwen3-Next 路径下 MTP 与 C8 互斥，见 [mtp-speculative-decoding](../techniques/mtp_speculative_decoding.md)）。

## Constraints

- **Qwen3-Next 场景下 C8 与 MTP 互斥**（ascend_backend C8 路径未打通 MTP 验证流）；**DeepSeek-R1 场景下 C8 + MTP1 可同开**。
- Qwen3-Next 需要离线 `attn_c8_scale` 校准文件（由 CANN 社区提供）。
- `SGLANG_DEEPEP_BF16_DISPATCH` 与 `DEEP_NORMAL_MODE_USE_INT8_QUANT` 互斥，启用 A8 必须替换（Qwen3-Next 路径）。
- Qwen3-Next 只有 attention 层挂了 `k_scale`/`v_scale` 参数（stage2 patch 在 `_is_npu` 下挂载到 `self.attn`）；R1 则由 mla_prolog 内部统一承担 KV scale，权重端持有 `ckv_scale` / `ckv_scale_reci`。
- Qwen3-Next 的 Conv1d 不量化以避免精度崩塌；R1 无 conv1d。
- R1 C8 权重转换：**仅 DeepSeek-R1 支持 `--quant_mode w8a8c8`，Kimi-K2 不支持**（README 明确限制）。
