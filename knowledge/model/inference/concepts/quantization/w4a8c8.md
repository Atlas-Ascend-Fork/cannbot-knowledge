# W4A8C8

## Summary

W4A8C8 是 DeepSeek-V3.2-Exp 上推出的混合精度量化方案：**MoE 路由专家的权重**使用 **W4A8**（4-bit 权重 + 8-bit 激活）量化，其余（Attention、MLAProlog、IndexerProlog、MLAEpilog、KVCache）沿用 [w8a8c8](w8a8c8.md) 配置。相比纯 W8A8C8，W4A8C8 将 **MoE 权重显存占用优化 2×** —— 在大 EP 场景下同一张卡可以装下更多专家，节约资源、提高计算访存比、优化单机部署能力。

为缓解 W4A8 的离群值量化困难问题，本方案针对 V3.2-Exp **使用基于学习的量化算法优化 Clamp 参数**，在 MMLU / GPQA / DROP / MGSM 四项基准上与 BF16 基本无损。

## Mechanism

### 逐模块量化策略

逐模块量化矩阵沿用 W8A8C8（见 [w8a8c8](w8a8c8.md)），**仅替换 MoE 路由专家**为 W4A8：

| 模块 | W8A8C8 | **W4A8C8 差异** |
| ---- | ---- | ---- |
| MLAProlog | Q_b_proj W8A8；KVCache C8 | 同 |
| Sparse Flash Attention | KVCache Int8 存、BF16 计算 | 同 |
| IndexerProlog | Q_b_proj W8A8；Indexer Q A8、Cache C8；Hadamard 变换 | 同 |
| Lightning Indexer | Int8 BatchMatmul（Mat-Duce） | 同 |
| **MoE 路由专家** | **W8A8** | **W4A8**（权重 4-bit、激活 8-bit） |
| MoE 共享专家 | W8A8 | W8A8 |
| MLAEpilog | O_proj W8A8 | 同 |
| LM_Head | 暂不量化 | 同 |

### 基于学习的 Clamp 优化

源文档："W4A8C8 量化版本针对 DeepSeek-V3.2-Exp 使用基于学习的量化算法优化 Clamp 参数，缓解 W4A8 离群值量化困难的问题，实现了较优的量化模型精度。"

### W4A8 MoE GMM 算子

大 EP + W4A8 场景依赖 **W4A8 MoEGMM 算子**作为路由专家计算的主路径 —— 源文档："在大 EP 场景下，利用 W4A8 MoEGMM 算子，同一张卡可以装下更多的专家，节约资源，优化计算访存比，实现单机部署。"

DeepSeek-V4 在两类平台复用 W4A8 概念对 MoE 路由专家量化（共享专家仍 W8A8），但配置不同于 V3.2-Exp 的 W4A8C8：A3 Pod 的 Hybrid INT8-INT4 走整数 W4A8 且 **KV 为 C16（非 C8）**（见 [int8-int4-hybrid](int8_int4_hybrid.md)）；950PR/DT 的 Hybrid MXFP8-MXFP4 走 **MXFP4 浮点变体**的 W4A8（代码 `W4A8MxFp4MoEGMMMethod`，见 [hybrid-mxfp8-mxfp4](hybrid_mxfp8_mxfp4.md)）。V3.2-Exp 的 W4A8C8 内容不受影响。

## Accuracy Impact

相对 BF16 的四项基准（源文档）：

| 模型 | MMLU | GPQA | DROP | MGSM |
| ---- | ---- | ---- | ---- | ---- |
| DeepSeek-V3.2-BF16 | 90.8 | 75.85 | 87.57 | 90.9 |
| DeepSeek-V3.2-Exp-W8A8C8 | 90.62 | 75.90 | 87.41 | 90.87 |
| **DeepSeek-V3.2-Exp-W4A8C8** | **90.66** | **76.5** | **87.68** | **91.3** |

W4A8C8 在 GPQA / DROP / MGSM 上反超 W8A8C8 与 BF16（落点在 BF16 的 ±1 以内，可视为基本无损）；该数据点"待验证"：源文档未披露量化数据集、校准过程、seed 与抽样条件。

## Applicable Scenarios

- **大 EP + MoE 权重主导的场景**：单芯片权重越大、性能提升越明显（见下表）。
- **单机部署需求**：W4A8 可把原需要多机承载的专家组装入单机 / 更小集群。
- **高序列 Decode**：配合 W8A8C8 主流量化与 [kvcache-offload](../techniques/kvcache_offload.md)，可在更小集群上跑更长序列。

## Constraints

- **算法依赖 Clamp 学习过程**：Clamp 参数通过学习得到，量化权重转换流程应对应一个专门的 W4A8 calibration 管线（源文档未展开细节，见 `utils/weight_convert.sh --quant_mode w4a8c8`）。
- **仅测试了 V3.2-Exp 路径**：Clamp 参数是针对 V3.2-Exp 优化的；其他模型套用需重新校准。
- **Attention 侧保持 W8A8C8**：源文档未讨论 Attention W4A8 路径；本次实践显式只对 MoE 权重做 W4A8。

## Known Results

基于 Atlas A3、DeepSeek-V3.2-Exp、序列长度 65536、MTP3、perfect eplb（源文档 Benchmark）：

| MoE Quant Mode | Global Batch Size | Chips | TPOT (ms) | Throughput (tokens/p/s) |
| ---- | ---- | ---- | ---- | ---- |
| W8A8 | 64 | 32 | 20.81 | 96 |
| W4A8 | 64 | 32 | 20.18 | 99 |
| W8A8 | 32 | 16 | 24.39 | 82 |
| W4A8 | 32 | 16 | 22.51 | 89 |

相同规模/配置下 W4A8 优于 W8A8，**单芯片权重越大、性能提升越明显**（16 卡场景 TPOT 24.39→22.51 ms，吞吐 82→89 tokens/p/s）。
