# 量化

- [FP8 Per-Block Dynamic Quant Attention](fp8_attention.md)：HunyuanVideo 在 DiT Attention 上引入的 FP8 量化方案：对 Q/K/V 做 **per-block 动态量化**（Q 用 `group_size=128`、K/V 用 `group_size=256`，FP8 E4M3 格式），再调用 `torch_npu.npu_fused_infer_attention_score_v2` 在算子内部完成反量化 + 注意力计算，输出 BF16。显著降低注意力的显存带宽，适合带宽受限场景。Benchmark（950PR，ulysses8）：在 `matmul + fa` 双量化下相比 baseline speedup 1.38×（dit 1.45×）。 另含 MXFP8 量化注意力变体（npu_mxfp8_attn，缩放因子 E8M0 1 字节，Q/K quant_mode=6 按 hidden-dim 分组、V quant_mode=8 按 seq_len 分组，TND 布局，fa_mxfp8 开关，仅 Ulysses 不支持 Ring），区别于 per-block FP8（quant_mode=7，BNSD）。
- [Hybrid FP8-MXFP4 / Hybrid MXFP8-MXFP4 (DeepSeek-V4 Ascend 950PR/DT)](hybrid_mxfp8_mxfp4.md)：DeepSeek-V4 在 Ascend 950PR/DT 上采用 FP8 与 MXFP4 混合量化。原生 FP8-MXFP4 可直接加载 HuggingFace 权重；面向 Flash/Pro 的 MXFP8-MXFP4 将部分 Linear 改为 MXFP8，并以 MXFP4 W4A8 执行 MoE 路由专家，共享专家仍为 W8A8。MLA/Indexer 的 KV Cache 可用 Per-Group-64 FP8、E8M0 Scale 的 C8 伪量化，实现存 8 位、算 16 位并约减半 KV 占用；Compressor 与 LMHead 不量化。950DT 16 卡 DP+EP、8192 token、MTP3 条件下，MXFP8-MXFP4 为 9.84 ms/1625 TPS，原生方案为 11.06 ms/1447 TPS。该方案限定 950 平台，不等同于 HunyuanVideo DiT 的 mxfp8-a8w8。
- [Int8 / Hybrid INT8-INT4 (DeepSeek-V4 Atlas A3 Pod)](int8_int4_hybrid.md)：DeepSeek-V4 在 Atlas A3 Pod 平台的两档整数量化方案，均以原生 Hybrid FP8-MXFP4 权重为转换起点。Int8（W8A8C16，推荐 Flash）：仅对参数量多的部分 Linear（MLA q_b_proj/o_b_proj、Indexer q_b_proj）做静态 Per-Channel W8 + 动态 Per-Token A8，**KV Cache 维持 C16（BF16 存算）而非 C8**，LI 经 A8C8（Indexer Q/Cache 动态 Per-Token-Head Int8）降时延，LightningIndexer batch_matmul Int8 计算，Compressor Linear/IndexerProlog indexer_weight 不量化，LMHead 不量化。Hybrid INT8-INT4（推荐 Pro 1.6T）：在上策略基础上仅 MoE 路由专家 Linear 改 W4A8（静态 Per-Channel Int4 + 动态 Per-Token Int8）、共享专家保持 W8A8，缓解 MoE 访存墙。权重转换 convert_model.py --quant_type w8a8-int / w4a8-int(--quant_param_path)；argparse choices=['w8a8-int','w4a8-int','bfloat16','w4a8-mx']，docstring/assert 另列 w8a8-mx 但 choices 未含（doc≠runnable flag）。KV C16 ≠ V3.2-Exp 的 C8 属代际选型差异不互相覆盖。Known Results：A3 Pod 64卡 DP+EP W8A8C16 Flash 8192 序列 TPOT 27.82/29.17ms、吞吐 4025/4388 TPS（MTP1）。
- [MXFP8 A8W8 (DiT Linear)](mxfp8_a8w8.md)：HunyuanVideo 针对 DiT 中 Linear 层（MLP / 投影层）的 Micro-scaling FP8 矩阵量化方案：权重按 group（默认 `group_size=32`）per-group 量化为 FP8 E4M3FN，激活按 token 维度 per-token 量化为同格式，scale 采用 E8M0（纯指数，1 字节）。实现 8-bit × 8-bit 矩阵乘（A8W8），权重显存减半、带宽需求 -50%。调用 `torch_npu.npu_dynamic_mx_quant` + `torch_npu.npu_quant_matmul` 完成量化与量化 GEMM。
- [W4A8C8 (MoE W4A8 + Attention W8A8C8)](w4a8c8.md)：W4A8C8 是 DeepSeek-V3.2-Exp 上推出的混合精度量化方案：**MoE 路由专家的权重**使用 **W4A8**（4-bit 权重 + 8-bit 激活）量化，其余（Attention、MLAProlog、IndexerProlog、MLAEpilog、KVCache）沿用 w8a8c8 配置。相比纯 W8A8C8，W4A8C8 将 **MoE 权重显存占用优化 2×** —— 在大 EP 场景下同一张卡可以装下更多专家，节约资源、提高计算访存比、优化单机部署能力。 为缓解 W4A8 的离群值量化困难问题，本方案针对 V3.2-Exp **使用基于学习的量化算法优化 Clamp 参数**，在 MMLU / GPQA / DROP / MGSM 四项基准上与 BF16 基本无损。
- [W8A8C8](w8a8c8.md)：组合量化方案：权重 Per-Channel 静态 Int8（W8），激活 Per-Token 动态 Int8（A8），KVCache 动态 Int8（C8）。相对 BF16 推理显著降低 Decode 端到端时延并提升吞吐，同时在主流评测集上精度几乎无损。
