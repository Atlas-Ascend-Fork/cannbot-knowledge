# 并行策略

- [CFG Parallel](cfg_parallel.md)：Classifier-Free Guidance (CFG) 在 DiT 每个采样 step 内需要做两次前向：一次条件（cond，带 prompt）、一次无条件（uncond，空 prompt），再按 `noise_pred = noise_pred_uncond + w·(noise_pred_cond - noise_pred_uncond)` 融合。CFG Parallel 把这两个样本分别放到两张卡上同时跑，每卡只做一次模型推理，最后通过 all_gather 互相拿对方的结果，端到端相当于把 DiT 每步耗时减半。HunyuanImage-3.0、Wan2.2-I2V 均采用该并行。
- [Context Parallel](context_parallel.md)：将输入序列沿 Sequence 维度切分到多个 Rank 并行处理的策略，用于解决长序列场景下单卡激活值内存不足的问题。通常与 TP 组合使用。
- [Data Parallel](data_parallel.md)：将不同的请求/batch 分配到不同的模型副本上并行推理的策略，用于提升推理吞吐量。在推理场景中通常以 DP 通信域的形式与 TP/EP 配合使用。
- [Embedding Tensor Parallel](embedding_tp.md)：Embedding Tensor Parallel（Embedding TP）是针对**稀疏参数占主导**的推荐/生成式推荐模型的并行策略：把超大规模的 **Embedding Tables 按 vocab 维度切分**到多张 NPU 上，以减少单卡显存负担，支撑超大 Embedding 词表的推理。在 cann-recipes-infer 中首次用于 hstu（Meta 生成式推荐模型）。 与 LLM 的 tensor-parallel 切 Attention Head / FFN 隐藏维度不同：LLM 参数主要集中在 dense Transformer 权重里，输入 token 来自相对固定的文本词表；而**生成式推荐往往把用户、物品、上下文等离散特征统一建模为 token，模型容量绝大部分来自超大规模的稀疏参数（Embedding Tables），词表规模可达千万甚至上亿**。
- [Expert Parallel](expert_parallel.md)：将 MoE（Mixture of Experts）模型的专家分布到不同的卡上，每张卡负责一部分专家的计算。适用于参数规模大但每个 token 只激活部分专家的 MoE 架构。
- [KV Parallel (KVP)](kvp.md)：KVP (KV Parallel) 是面向**长序列推理场景**的 KV Cache 切分并行策略：通过将 KV Cache **沿 S (sequence) 维度切分**到多个 rank 上，缓解单 rank 的 KV Cache 访存压力，从而降低时延并扩大单请求可处理的序列长度上限。 LongCat-Flash 在长序列 Decode / Prefill 场景使用 KVP，通过 YAML `kvp_size` 开关控制（当前仅 LongCat-Flash 支持）。该策略与 DP MLA（每卡存完整 KV）和 CP（沿 seq 切 token，每 rank 计算部分 query）都不同——**KVP 切的是 KV Cache 本身**。 （KVP 部署已于 2026-05 回退：kvp8 YAML/新 ParallelConfig.kvp_size 字段/文档移除；legacy modeling_longcat_flash.py 代码残留但无 shipped 配置）
- [Ring Attention Sequence Parallelism](ring_attention.md)：Ring Attention 是另一种长序列 SP 方案：与 Ulysses 不同，**attention 内部也保持序列切分**，每张卡仅维护自己那 1/SP 的 Q；通过 概念上以 P2P 环形逐跳传 KV，但本仓 module/unified_sp/core.py 实际用一次 all_gather_into_tensor 把其他 rank 的 1/SP KV 一次性收齐，对本地 FA 与远端合并 FA 两路输出做 LSE（Log-Sum-Exp）合并（非逐跳 P2P）。适合 Ulysses 规模受限（`num_heads` 不够切）或与 Ulysses 组成 2D hybrid SP 的场景。 Wan2.2-I2V 在此基础上实现了 ring-attention-overlap：异步 AllGather + 本地 FA 并行，用计算掩盖通信。
- [SP-TP-SP Hybrid Split (Prefill MLA)](sp_tp_sp.md)：DeepSeek-R1 Prefill 阶段 MLA 部分针对 DP 切分在短序列混合/请求数少场景下 **计算负载不均 + TTFT 被拉长** 问题提出的混合切分策略：把 batch 与 seq_len 合轴变为 token 数，按卡数 **SP** 切 token 均匀分发；FlashAttention 计算走 **TP** 切 head；FA 结束后 AllToAll 再转回 **SP** 给 o_proj。"SP → TP（FA）→ SP" 三段式得名。
- [Tensor Parallel](tensor_parallel.md)：将模型权重沿 Head 或隐藏维度切分到多张卡上并行计算的策略，是 NPU 推理中最基础的并行方式。几乎所有模型的 Attention 和 FFN 层都使用 TP。
- [Ulysses Sequence Parallelism](ulysses.md)：Ulysses 是面向**长序列多头注意力**的序列并行策略：在 attention 以外的部分沿 S（sequence）维度切分，在 attention 处通过一次 all-to-all 把切分维度从 S 换到 N（num_heads），attention 内部按 head 并行、attention 输出再 all-to-all 换回 S。相比于 Ring Attention 依赖 P2P 循环传 KV，Ulysses 用集合通信 all-to-all 实现，简单高效，是 HunyuanVideo / HunyuanImage-3.0 / Wan2.2-I2V 长序列 DiT 推理的首选序列并行。 cann-recipes-infer 在 `module/unified_sp/` 提供统一 SP 框架，支持 Ulysses / Ring / Hybrid（Ulysses × Ring）三种模式，并通过 **Ulysses Anything Attention (UAA)** 支持任意头数的灵活配置。
- [VAE Patch Parallel](vae_patch_parallel.md)：多模态生成模型的 VAE Decoder 处理大尺寸（720p/1080p，视频还叠加时间维度）pixel 输出时显存与算力消耗巨大。VAE Patch Parallel 把 latent/pixel 张量沿 H、W 空间维度切分到多卡并行处理，搭配**卷积的边界交换**、**注意力的全局 K/V 聚合**、**上采样的边界扩展+裁剪** 三种针对性通信策略，使各卡局部结果最终拼接成完整输出。HunyuanVideo、HunyuanImage-3.0、Wan2.2-I2V 均使用此策略（脚本 `module/vae_patch_parallel.py` / `models/wan2.2-i2v/wan/vae_patch_parallel.py`）。
- [ZigZag Context Parallel (Load-Balanced Causal Attention)](zigzag_cp.md)：ZigZag 是 context-parallel 下针对**因果 Attention 负载不均**的切分变体：将输入 Sequence 切成 `2·cp_size` 个 block，每个 CP rank 负责头尾对称的两个 block（如 rank 0 负责 block 0 与 block 2·cp_size-1），从而让所有 rank 的历史 KV 计算量近似相等。通过两次 AllToAll 在"因果序"和"ZigZag 序"之间切换。 定位：ZigZag 是 CP 的**并行切分策略**（不是正交的通用技术），放在 parallelism 目录下；与 Ulysses/Ring Attention SP 并列作为长序列并行的一个方案族。
