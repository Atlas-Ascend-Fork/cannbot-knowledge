# 融合 Kernel

- [Compressor (C4A / C128A KV 压缩融合算子)](compressor.md)：Compressor 是 DeepSeek-V4 的 KV 压缩融合算子，将 Linear、分组 softmax、Hadamard/reduce、RMSNorm 和 Partial RoPE 合并为单一算子，为 SAS 与 Lightning Indexer 生成压缩缓存。C4A 以 4:1 压缩 CSA，需处理相邻组 overlap 和错位写入；C128A 以 128:1 压缩 HCA。AscendC 在 A3 采用不同 C4A/C128A 基本块与双缓冲，950PR/DT 使用 256³ 基本块；PyPTO 按 compress_ratio/rotate 分支并以 split-K、子图分区和 scatter_update_3d 刷新状态。Epilog 负责量化、拼接 scale 并写回 KV/Indexer Cache，FP8 与非 FP8 路径不同。
- [Deepseek Indexer Attention Kernel](deepseek_indexer_attention.md)：`Deepseek Indexer Attention` (DIA) 是 cann-recipes-infer 用 **PyPTO** 实现的**大融合算子** —— 把 DSA 的 4 个相对独立子算子 MLAProlog + IndexerProlog + Lightning Indexer + Sparse Flash Attention 融合成单一 kernel，在整网范围内挖掘更大并行度、提升内存利用率。这是 PyPTO "MegaKernel" 能力在 DeepSeek-V3.2-Exp 上的典型实例。 PyPTO 源码：`ops/pypto/src/deepseek_indexer_attention/op_kernel/deepseek_indexer_attention.cpp`。
- [npu_fused_infer_attention_score (v1 / v2)](fused_infer_attention_score.md)：昇腾推理侧的通用 FlashAttention 融合算子（简称 **FIA**），覆盖 Softmax-Attention 的主体计算：`softmax(QKᵀ/√d)·V`，支持 Paged KVCache、Block-Table、分离的 NoPE/RoPE Query/Key 输入、以及 Query / Key / Value 三端的动态 Int8 反量化（dequant_scale_*）。在 DeepSeek-R1 decode 路径中作为 mla-prolog 之后的主 FA 算子。 v2 相对 v1 增加了 TND_NTD 布局支持、更灵活的 sparse_mode、分离的 NoPE/RoPE Key 路径与 C8 量化反量化入口。
- [GatherSelectionKvCache](gather_selection_kv_cache.md)：`npu_gather_selection_kv_cache` 是 cann-recipes-infer 为 DeepSeek-V3.2-Exp **KVCache Offload** 场景新开发的 AscendC 自定义算子。在 Decode 阶段，根据 lightning-indexer 返回的 TopK（2048）个相关 token index，**从 Host 内存上的 Full KVCache 中选出参与计算的 KV 并搬回设备**，再喂给 sparse-flash-attention。 其核心优化是利用**前后 Token 在同一层上 TopK 命中率（相似度）特性**复用设备上已有 cache：若当前步 TopK 与前一步 TopK 有 60% 重叠，仅从 Host 读取 40% 未复用的 KV，60% 直接从设备上读，显著减少 H2D 耗时。 算子源码：`ops/ascendc/src/gather_selection_kv_cache/`。自定义算子文档 `ops/ascendc/docs/custom-npu_gather_selection_kv_cache.md`。
- [Indexer Prolog Kernel](indexer_prolog.md)：`Indexer Prolog` 是 LightningIndexer 之前的准备算子，为 LI 提供输入 q、weight、q_scale，处理 Indexer Q / Indexer Cache(K) / Indexer Weight 三条独立计算流（各含 Matmul/RoPE/LayerNorm/Hadamard/动态 Per-Token-Head 量化）。DeepSeek-V3.2-Exp(DSA)：PyPTO 单一大融合算子 npu_lightning_indexer_prolog_pto，4 batch×MTP1×64K 逼近理论极限（Indexer Q 四段理论拆解、瓶颈在搬运、Q 掩盖 Cache/Weight）；配合 torchair npu_stream_switch 多流。DeepSeek-V4 适配（PyPTO）：IndexerProlog 仅出现在 compress_ratio=4 的 CSA 层（C128A/HCA 无 LI 模块，代码 cmp_ratio:4 only c4a have li module）。Query q_hadamard/Quant 流程：q_tmp=qr@idx_wq_b·scale → q_hadamard=Cat(q_tmp[:,:nope_dim],Rope(q_tmp[:,nope_dim:]))@hadamard → q,q_scale=Quant；代码实际展开为 wq_b→inplace_partial_rotary_mul(interleave)→rotate_activation(hadamard_matrix=get_had_pow2)→量化（int8 走 npu_dynamic_quant 转 FP16 / FP8 走 npu_dynamic_block_quant）。Weights=x@weights_proj·1/sqrt(idx_nq·head_dim)（代码 softmax_scale=head_dim**-0.5·n_heads**-0.5 一致），不量化转 FP16/FP32。doc 描述 fused 而 code 为展开步骤（V4 图模式是否回落单一融合 PyPTO 算子源未明示，待验证）。
- [Lightning Indexer Kernel](lightning_indexer.md)：`LightningIndexer` 是 DeepSeek-V3.2-Exp / DeepSeek-V4 稀疏 Attention 的前置算子 —— 完整执行 `BatchMatmul → ReLU → Broadcast × W → ReduceSum → Top-k` 五步，为每 query token 精确（非近似）选出 TopK 个相关 KV index 喂给下游稀疏 Attention，将 Top-k 计算融合进单一算子（相较外置收益 ~20%）。K 随模型而异：V3.2-Exp DSA 在完整上下文选 TopK=2048 喂给 SparseFlashAttention；V4 仅在 C4A(compress_ratio=4,CSA)层对 Compressor 压缩后 cmp_KV 做 Top-k（运行时取 config.index_topk，guide 例 512）喂给 SAS 的 SCFA（不同模型不同 K 并列保留）。提供 AscendC/PyPTO/TileLang 三路实现。V4 CSA 层增强：A3 LI Tiling 沿用 V3.2-Exp，适配 compress_ratio 阶梯形状 mask 产 cmp_sparse_indices；950PR/DT 量化版 LI（INT8/FP8 共用 torch.ops.custom.npu_quant_lightning_indexer，非独立 FP8 算子；FP8 区别在上游 q 经 npu_dynamic_block_quant 量化、INT8 经 npu_dynamic_quant）；Top-k 两套平台分支并列：Atlas-A3 sort32+mrgsort（S_k=16384,k=512 约 28375 cycle，沿用 V3.2-Exp）/ 950PR/DT Histograms 直方图（保序变换+多级直方图分桶 value_k=a1·2^24+a2·2^16+a3·2^8+a4+向量化筛选，理论 (S_k/256·111+192) cycle，S_k=16384 约 7296 cycle，cycle 前提为 950PR/DT 平台）。阶梯 mask 形状参数源未给（待验证）。
- [mambav2_rmsnormgated](mambav2_rmsnormgated.md)：AscendC 实现的 Mamba v2 风格 RMSNorm + SiLU(z) + Mul 融合算子，Qwen3-Next gated-deltanet 输出段使用。BF16 输入输出（`x`, `z`, `w`），FP32 内部计算，单 AIV kernel 完成归一化、门控激活、权重缩放和逐元素相乘，消除三次独立 kernel launch 和两次中间 BF16 转存。
- [HcPre / HcPost (mHC 融合算子)](mhc_hcpre_hcpost.md)：`HcPre` 与 `HcPost` 是 DeepSeek-V4 mHC 残差结构的成对融合算子，完成 Attention/MoE 子层前后的多路↔单路变换。HcPre 融合 RMSNorm、hc_fn 线性变换、Sinkhorn-Knopp 和 pre 加权求和，输出 y、post、comb；HcPost 用 post 扩展子层输出并与 comb 残差合并，目标是让中间数据留在 UBuffer。A3 AscendC 采用 Cube:Vector=1:2 流水，Decode 切 K、Prefill 切 token；PyPTO 以 MPMD 并行 Vector RMSNorm 与 Cube MatMul，并用 split-K 和静态展开。hc_post 的 VF 报告提升 22.7%。Native 与 PyPTO 的首轮 Sinkhorn 归一顺序不同，应以各自代码为准。
- [npu_mla_prolog (v2 / v3)](mla_prolog.md)：`npu_mla_prolog` 是 DeepSeek-V3/R1/Kimi-K2 的 MLA 前置融合算子，在单个 kernel 中完成 Q、KV 两级投影、RMSNorm、RoPE，并按 cache_index 写入 Paged NZ KV Cache，以减少 Decode 下发和 kernel gap。R1 Decode 使用 v3 接口，支持权重、KV Cache 和 Query 量化模式，并与 FIA v2 配合。DeepSeek-V4 虽改为 MQA/Shared-KV，仍以 PyPTO 版本完成 Q/KV 前置投影，加入 interleaved Partial RoPE、动态 shape 静态展开、buffer 合图、split-K 和 MPMD 流水。独立的 AscendC RoPE+Quant 算子尚未证实接入生产路径，v2/v3 的完整语义差异也仍待确认。
- [recurrent_gated_delta_rule](recurrent_gated_delta_rule.md)：Decode/MTP 阶段 Gated DeltaNet 的融合算子，用于混合注意力模型（Qwen3-Next、Qwen3.5-MoE）线性注意力层的单步/少量 draft token 递推。一次 kernel launch 完成 Sigmoid + L2Norm + Gated Delta 递推注意力 + ssm_state 选择性更新，消除 Decode GDN 路径多个小算子的 Launch 和中间搬运开销。BF16 输入输出、FP32 累加，AIV 单元执行。Qwen3-Next 通过 AscendC 自研算子使用；Qwen3.5-MoE 通过 torch_npu.npu_recurrent_gated_delta_rule 调用同名算子。
- [SparseAttnSharedKV (SAS) Kernel](sparse_attn_sharedkv.md)：`SparseAttnSharedKV`（SAS）是 DeepSeek-V4 的统一 Shared-KV Attention 融合算子，一套接口覆盖滑窗、压缩及压缩后稀疏 Attention，并原生支持 Attention Sink。A3 非量化路径采用 QK MatMul→online softmax→PV MatMul→rescale 四阶段；950PR/DT 伪量化路径增加前置反量化，共五阶段。场景由原始/压缩 KV、窗口、压缩比、稀疏索引、sink 和 metadata 等参数组合控制，AICPU metadata 算子负责值依赖分核。PyPTO 分为 SWA、CFA、SCFA 三种场景，TileLang 另有 block=64 的 V4-Flash 实现。SAS 不等同于 V3.2-Exp DSA 使用的 SparseFlashAttention。
- [Sparse Flash Attention Kernel](sparse_flash_attention.md)：`SparseFlashAttention` 是 DeepSeek-V3.2-Exp **DSA** 的主 Attention 算子 —— 在 lightning-indexer 产出的 TopK index 基础上，`Gather` 出稀疏 KV 子集并执行 Flash Attention 计算。沿用 FlashAttention 的 `C_1 (Q@K^T) → V_1 (online softmax) → C_2 (P@V) → V_2 (rescale)` 四阶段流程，但面向**离散访存**进行了专门优化。模块语义见 sparse-flash-attention。 cann-recipes-infer 提供 AscendC + TileLang 两路实现；PyPTO 侧则作为 deepseek-indexer-attention 大融合算子内的子流程出现。
