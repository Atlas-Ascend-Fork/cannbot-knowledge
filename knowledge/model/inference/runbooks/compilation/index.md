- [MLA 开图模式硬约束 num_heads/num_kv_heads ∈ {32,64,128}（每 rank 比值出集合则图编译期 EZ9999 / CheckMlaAttrs 失败）](mla_graph_mode_queries_per_kv_head_ratio_set.md)：MLA 结构模型（DeepSeek V2-Lite/V3/R1）启用 torchair 图模式（npu-graph-mode, torchair_graph_config.enabled）时，昇腾 MLA/FusedInferAttentionScore（FIA）融合算子有固有 shape 契约：每 rank 的 num_heads/num_kv_heads（queries-per-kv 比值，按 tensor-parallel/TP 切分后计）必须 ∈ {32,64,128}。比值出集合会在图编译期（fx2ge_converter.compile → graph.compile，非运行期）由 tiling 校验 CheckMlaAttrs（incre_flash_attention_tiling_check.cc）抛 EZ9999 "numHeads / numKvHeads = 8, MLA only support {32, 64, 128}"、Compile graph failed。DeepSeek-V2-Lite 只有 16 个 attention head、比值恒出集合，图模式恒不支持（源标 TODO: support numHeads/numKvHeads<16 in MLA kernel）；V3/R1 头数够但 TP size 选得不当会把每 rank 比值推出集合。修法：开图模式前先核 TP 切分后每 rank num_heads/num_kv_heads 是否 ∈ {32,64,128}——V2-Lite 改走 eager/非图模式，V3/R1 调整 TP size 使比值落回集合。参考实现 vllm-ascend 在 attention.py/mla_v1.py 用 _ALLOWED_NUM_QUERIES_PER_KV=[32,64,128] 断言把算子内层报错前移成框架 fail-fast + FAQ，但约束本身来自融合算子、非框架限制。区别于 FIA 无量化 MLA 路径 group_num ∈ 2 的幂（561002/CheckFeatureMlaNoQuantShape）那条不同约束。
