# minimax_h3 fl2va 重复运行耗时双峰波动：denoise 逐 step 均匀移位的日志取证诊断

## 适用场景

- 平台范围依据：source 0 seq 69的实际环境/设备记录确认本次为Atlas A3；这里不扩展未记录的产品或版本。

- 模型/任务：MiniMax-H3（`models/minimax_h3`，fl2va 文本到音视频生成），工作负载固定：768x1280、video_length 129、infer-steps 50、seed 42、cfg-scale 6.0（source 0 seq 14、seq 46）。
- 硬件/环境：Atlas A3（Ascend 910_9382 V1），推理使用 4 个 device（1,3,5,9，各物理卡 chip1）；npu-smi 25.5.1；torch_npu 环境。
- 症状：同一命令 `bash infer.sh fl2va` 重复执行，端到端总耗时在 1205.368–1272.866s 间波动（约 5.5%），需要归因。
- 本文是日志取证型诊断规则（validation_scope: source_read），不依赖在线重放即可复用。

## 触发与观测

用户报告最近 3 次测试耗时 1272.866 / 1260.764 / 1205.648s，差异大（source 0 seq 1，user_reported）。

分阶段计时（print_summary 的 `Time Elapsed` 行，tool_observed，source 0 seq 32/38）：

```
log_20260817_113326 (total 1272.866s): denoise 1233.609s | decode.video 35.009s | decode.audio 1.238s
log_20260817_115708 (total 1260.764s): denoise 1221.717s | decode.video 34.998s | decode.audio 1.229s
log_20260817_140927 (total 1205.648s): denoise 1166.505s | decode.video 35.002s | decode.audio 1.235s
```

文本编码/VAE 编码/准备段各 <1.5s，运行间波动 <0.1s（source 0 seq 38）。

逐 step 稳态速率（progress bar `s/it`，tool_observed，source 0 seq 52/85）：

- SLOW 运行（113326）：第 10–49 步稳定在 24.68–25.22 s/it，末行均值 24.67 s/it；
- FAST 运行（140927）：第 10–49 步稳定在 23.35–23.84 s/it，末行均值 23.33 s/it；
- 运行内部步间波动仅 ±0.05–0.07s。

全天 9 次运行汇总（tool_observed，source 0 seq 63）：denoise 1166.0–1233.6s、final_rate 23.32–24.67 s/it，FAST/SLOW 交替出现；前一日（20260814）连续运行 24.13→24.90→25.91 s/it 逐步恶化、间隔后恢复 23.26 s/it（source 0 seq 102，tool_observed）。

## 探针与操作

探针 1：分阶段耗时提取（source 0 seq 37，逐字）：

```bash
for f in log_20260817_113326.log log_20260817_115708.log log_20260817_140927.log; do echo "======== $f (total: $(grep 'pipeline_start.*pipeline_end' $f | grep -oE '[0-9]+\.[0-9]+s' | head -1)) ========"; grep "Time Elapsed" "$f" | grep -v "pipeline_start\|pipeline_end" | grep "print_summary"; echo ""; done
```

探针 2：批量运行汇总（total/denoise/final_rate/起始时间，source 0 seq 62，逐字）：

```bash
for f in $(ls -t log_20260817_*.log); do total=$(grep 'pipeline_start.*pipeline_end' "$f" | grep -oP '\[\K[0-9.]+' | head -1); denoise=$(grep 'denoise.denoise.*after_denoise' "$f" | grep -oP '\[\K[0-9.]+' | head -1); rate=$(grep -oP '\d+/49 \[.*?, \K[0-9.]+s/it' "$f" | tail -1); start=$(grep "Args:" "$f" | head -1 | grep -oP '\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}'); mode="FAST"; awk -v d="$denoise" 'BEGIN{if(d>1200) print "SLOW"}' | xargs -I{} echo {}; echo "$f | start=$start | total=${total}s | denoise=${denoise}s | final_rate=${rate}"; done
```

探针 3：运行内逐步波动（source 0 seq 84，逐字）：

```bash
echo "=== Check within-run step variation (SLOW run) ==="; grep -oP '\d+/49 \[.*?, \K[0-9.]+s/it' log_20260817_113326.log | awk 'NR>=10 && NR<=49 {print NR, $0}'; echo "=== Check within-run step variation (FAST run) ==="; grep -oP '\d+/49 \[.*?, \K[0-9.]+s/it' log_20260817_140927.log | awk 'NR>=10 && NR<=49 {print NR, $0}'
```

探针 4：设备热/频率/占用状态（source 0 seq 75，逐字）：

```bash
echo "=== Device 1 (used in inference) sensors ==="; npu-smi info -t sensors -i 0 -c 1 2>/dev/null; echo "=== temp ==="; npu-smi info -t temp -i 0 -c 1 2>/dev/null; echo "=== Device 3 ==="; npu-smi info -t temp -i 1 -c 1 2>/dev/null; echo "=== Device 5 ==="; npu-smi info -t temp -i 2 -c 1 2>/dev/null; echo "=== Device 9 ==="; npu-smi info -t temp -i 4 -c 1 2>/dev/null
```

## 机制与判别

- 判别一（阶段隔离）：波动全部集中在 denoise 段，decode.video/audio 与编码/准备段跨运行稳定（<0.1s）→ 排除 host 侧 IO、后处理与数据准备抖动（source 0 seq 32/38）。
- 判别二（移位形态）：逐 step 速率在运行内恒定（±0.07s）、在运行间整档跳变（~1.3–1.8 s/it，约 5.7%），全 49 步均匀 → 排除运行中动态软件干扰（如后台进程、内存碎片逐步累积），指向设备级速率状态在运行开始时（或早期）即已确定（source 0 seq 52/85）。
- 判别三（时序相关）：连续运行偏慢、间隔冷却后恢复，两日数据一致（source 0 seq 63/102）→ 与热累积/恢复行为吻合。
- 设备状态佐证：诊断时段（空闲）推理用 4 device 温度 39–42°C、AI Core 800MHz、HBM 占用约 4%（source 0 seq 69/76/93）。
- 根因假设（未验证）：agent 判读为 NPU 热降频（DVFS，固件在温度超阈值时降 AI Core 频率一档）（source 0 seq 106，agent_narrative）。备选未区分解释：推理用 chip1 所在物理卡的 chip0 及相邻卡存在其他租户重负载（HBM 55–59GB 占用、AICore 19–59%，source 0 seq 69），同卡电源/热预算争用同样可产生运行间速率差异。
- 后续确认手段（本诊断未执行）：推理期间后台循环采样 `npu-smi info -t temp -i 0 -c 1` 及频率，对比 FAST/SLOW 运行曲线（source 0 seq 106 建议）。

## 验证信号

- 全部信号来自历史运行日志与 npu-smi 的事后读取（source_read 级，tool_observed）：阶段表（seq 32/38）、逐 step 序列（seq 52/85）、9+4 次运行汇总（seq 63/102）、设备空闲态（seq 69/76/93）。
- 单 workload、单机型、两日 12 次运行的双峰观测；未做受控重放，无负载期间频率/温度采样。
- 根因（热降频）与备选（同卡租户争用）均为解释层，非观测层；引用时不应表述为已证实的降频事实。

## 适用与失效边界

- 适用于：Atlas A3（Ascend 910_93xx）上长时（约 20 分钟级）持续重负载的视频/多模态生成推理出现运行间 5% 量级、运行内均匀的总耗时漂移的归因筛查。
- 失效/不适用：运行内部逐步抖动（本模式为运行内恒定）；波动出现在 decode/编码段（本模式 denoise 独占）；单次运行孤例（需多运行日志对比才能看到双峰）。
- 停止/回退条件：若负载期间采样显示频率恒定且温度未超阈值，应转向同卡租户争用或供电/散热环境因素；本诊断不修改任何模型代码（`这不是代码问题`，source 0 seq 106）。

## 附：断言存档

- 同负载 fl2va 推理（768x1280、129 帧、50 步、seed 42）重复运行的总耗时差异（1205.368-1272.866s）几乎全部来自 denoise 去噪阶段（1166.038-1233.609s）；decode.video（34.950-35.074s）、decode.audio（1.229-1.238s）、文本编码/VAE 编码/准备各段（各 <1.5s）在运行间波动 <0.1s，可排除这些阶段及 host 侧 IO 抖动。
- denoise 逐 step 稳态耗时呈 FAST/SLOW 双峰而非随机抖动：FAST 运行 49 步全程稳定在约 23.33-23.84 s/it，SLOW 运行稳定在约 24.68-25.22 s/it；运行内部步间波动仅 ±0.05-0.07s，速率在一次运行内恒定、只在运行之间整体跳变（整档移位 ~1.3-1.8 s/it，约 5.7%），说明慢速因子在运行期间不变、属设备级速率状态而非逐步动态切换。
- 模式与运行时序相关：20260817 当天 9 次运行 denoise 步均耗在 23.32-24.67 s/it 间呈连续运行偏慢、间隔后恢复的双态；20260814 连续运行 24.13→24.90→25.91 s/it 逐步恶化、间隔后 23.26 s/it 恢复。诊断时段外设备空闲态：推理所用 4 device 温度 39-42°C、AI Core 800MHz（空闲降频）、HBM 占用约 4% 无争用。综合指向设备侧频率/热状态在运行间变化；热降频（DVFS）为最可能解释但负载期间频率/温度未采样，未直接验证。
