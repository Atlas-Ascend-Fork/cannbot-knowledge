- [AFD 后 FFN 侧成新瓶颈：Attention 侧 Recv EVENT_WAIT 拖尾 → 对 FFN 侧 MoE-GMM 权重做通信间隙预取](afd_ffn_side_bottleneck_prefetch.md)：AFD 后 FFN 侧成新瓶颈：Attention 侧 Recv EVENT_WAIT 拖尾 → 对 FFN 侧 MoE-GMM 权重做通信间隙预取。在 Attention-FFN 解耦（AFD）部署下（Attention 侧解除控核、计算算子提速后），profiling 里 Attention 侧的 Recv 算子长时间收不到 FFN 侧发回的数据，计算流上出现 EVENT_WAIT 间隙的拖尾。
- [MoE 长序列 prefill 峰值显存 / OOM：专家负载不均 + dispatch 中间量放大；分块 / 均衡 / double-routing 处置](moe_prefill_oom_peak_memory.md)：MoE 长序列 prefill 峰值显存 / OOM：专家负载不均 + dispatch 中间量放大；分块 / 均衡 / double-routing 处置。expert-parallel MoE 模型在长序列 prefill 阶段 device OOM（EL0004 Failed to allocate memory / out of memory），常发生在 MoE 的 grouped_matmul 或 dispatch 展开处；同配置换短输入 / 小序列不复现。
- [MoE token dispatcher 把中间张量挂 self. 属性阻止 GC：aclgraph 峰值内存虚高触发 OOM，token_combine 末尾置 None 释放](moe_token_dispatcher_self_attr_oom_aclgraph.md)：在 aclgraph 下运行 expert-parallel MoE 时，若 token dispatcher 把 dispatch、expert compute、combine 之间传递的大量中间张量保存为 self 属性，长寿命实例会持续持有强引用，Python GC 无法释放，图按虚高峰值预留显存并在临界负载触发 OOM。典型对象包括路由结果、dispatch/combine 辅助信息、split 映射、MC2 mask 和 shared-expert 临时张量。修复是在各 token_combine 生成最终 hidden states 后，将已无消费者的 self 属性逐一置为 None，缩短其图内生命周期；不改变计算结果，删除置空语句即可回滚。该结论适用于 aclgraph 的 EP、MC2、all-to-all 与 shared-expert 路径，来源未提供前后峰值数字。
- [profile_run 峰值显存低估致运行期 OOM：profiling 未实际走一遍所有影响峰值的路径/均衡步（MC2 通信 / force_load_balance）](profile_run_peak_memory_underestimate_untraversed_path.md)：failure_signature 动态页：推理引擎用 profile_run / dummy forward 估计昇腾 NPU 推理期峰值显存并按估计值预留 device 显存 / KV cache 容量（aclgraph NPU 图模式尤其依赖此预留），若 profiling 阶段没有实际走一遍所有会拉高真实峰值的路径或均衡步，峰值被低估、运行期 device OOM。根本判据：profile_run 必须把所有会额外吃 NPU 内存的路径和会改变显存分布的均衡步都在 profiling 阶段实际跑一遍。汇聚两个具体信号：(1) profiling 不走 MC2 融合 MoE dispatch/combine 通信（npu_moe_distribute_dispatch/combine）路径 → 漏计 MC2 通信 buffer 显存 → aclgraph 下 MoE 运行期 OOM；修法是在 profile_run 里当 _select_moe_comm_method(mc2_tokens_capacity) == MoECommType.MC2 时补跑一次经 MC2 的 _dummy_run 完成初始化 / 内存分配，SOC/world_size 判据由选路函数内部承担。(2) MoE force_load_balance（仅 profile run 激活、用 torch.randint_like 随机重写 topk_ids 把 token 均匀铺到所有 expert 避免堆到单 rank）曾因 aclgraph 图捕获模式不支持 torch.randint_like 而被 self.use_aclgraph 门控关掉 → profile 显存不反映均衡分布 → OOM；修法是随算子可用拆掉 aclgraph 门控让 force_load_balance 图模式生效。参考实现 vllm-ascend（model_runner_v1.py profile_run、fused_moe.py AscendUnquantizedFusedMoEMethod）。关联 expert-parallel EP、moe-dispatch-combine-v2、npu-graph-mode aclgraph、eplb。
