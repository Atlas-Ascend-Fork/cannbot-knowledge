# A3 共享设备上 507033/E39007 TSD 启动超时与 507018 HCCL AICPU 初始化失败的判别与恢复（Healthy die ≠ 空闲）

## 适用场景

- 平台范围依据：source 0 seq 272、source 0 seq 273的实际环境/设备记录确认本次为Atlas A3；这里不扩展未记录的产品或版本。

- 模型/框架：Qwen3 投机推理实验（cann-recipes-infer，TP2×DP4 八 rank，逻辑设备 4,5,8,9,10,11,14,15）。
- 硬件/环境：Atlas A3 物理卡 4—7 共 8 die，Docker 容器（宿主进程对容器不可见），多租户共享。
- 目标：正式性能实验前的设备健康/占用判别与失败恢复。

## 触发与观测

- 全量 AR 首检在加载模型前报错（逐字）："全量 AR 首次检查在加载模型前报 `507033 / E39007`，逻辑设备 8、9 的 TSD 子进程启动超时。失败作业已收尾，八 rank 退出码为 `[1,1,137,137,137,137,137,137]`，保留完整日志及 10 份驱动日志。最新检查八 die 均 Healthy，但物理卡 4—7 存在非本次作业的外部进程占用，当前容器不可见。"（source 0 seq 2629）
- MTP 全量检查在首次目标 Prefill 失败："MTP 全量检查在首次目标 Prefill 的 HCCL AICPU 初始化失败（507018），新启动器在 5.407 秒内自动收尾，全部真实退出码已保存。两次健康检查均 Healthy，但最新检查卡 6、7 仍有归属未确认的进程占用，故未继续启动模型。"（source 0 seq 3019）

## 探针与操作

- 启动前只读设备预检：`npu-smi info`（健康 + 进程表）、物理卡/die/逻辑设备映射核验；容器内无法确认宿主 PID 归属时按"占用未确认"处理，不启动模型。
- 恢复操作：占用澄清并重新核验后以新 run_id 重试（不覆盖旧失败记录）；重试通过："新源码已冻结，完整 AR 重试通过：80 请求、20,480 token、八 rank 退出 0"（source 0 seq 3019）。
- 配套修复（启动器有界收尾）：每 rank 启动即保存 parent/starttime，失败时 pidfd 绑定原子进程、再次核验身份后 TERM 5s→KILL 5s；不使用组信号、不触碰其他 PID；CPU 回归"4 passed in 5.85s"覆盖 137/143/7 真实 wait 状态、外部进程存活、错误 starttime/owner 不发信号（source 0 seq 2689/2690）。

## 机制与判别

- 判别规则：八 die `Healthy` + 设备进程表存在容器不可见宿主 PID + 模型加载前 507033/E39007（TSD 子进程启动超时）或首次通信 507018（HCCL AICPU 初始化失败）→ 判共享设备资源争用/外部占用，而非代码或模型问题。
- 反向区分：同源码同配置在确认空闲后重试成功（AR 80 请求全通过），证明失败由环境争用触发。
- 未验证推断：宿主占用的具体负载类型未知（缓存占用小不代表计算/带宽/AICPU 负载小）。

## 验证信号

- tool_observed：两次不同错误码（507033/E39007 与 507018）均在"Healthy + 未知占用"现场出现；空闲重试成功（八 rank 退出 0、20480 token）；退出码 [1,1,137×6] 为 TERM 后 KILL 的真实收尾状态。
- 单现场两次观测 + 一次成功重试对照。

## 适用与失效边界

- 适用于：A3 多租户共享 Docker 环境下八 rank 推理实验的启动前预检与失败分类。
- 失效边界： Healthy 检查无法证明空闲；若错误在确认独占设备后仍复现，应转入代码/驱动排查而非继续归因占用。
- 停止/回退条件：持续占用时挂起调度（等空闲窗口）并保留失败现场；不重置设备、不操作外部进程。

## 附：断言存档

- A3 共享设备上八 die 均 Healthy 但物理卡存在容器不可见宿主进程时，模型加载前 507033/E39007（逻辑设备 8、9 TSD 子进程启动超时，八 rank 退出码 [1,1,137×6]）与首次目标 Prefill 507018（HCCL AICPU 初始化失败）均为设备争用症状；占用澄清后同源码重试成功（AR 80 请求 20480 token 八 rank 退出 0）。
