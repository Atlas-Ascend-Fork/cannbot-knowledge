# qwen3_moe force_eplb 关闭 SP 时 MoeInitRoutingV3 expert_idx 行数错位的模型侧修复

## 适用场景

适用于 cann-recipes-infer / torchturbo 类推理框架中 qwen3_moe（或同构 MoE 模型）同时开启 force_eplb（强制专家负载均衡）与关闭序列并行（enable_sp=False）的部署组合。当 worker 侧预生成路由 topk 列表与模型侧实际 MoE 输入 token 数来自两套不同的切分假设时，本条给出定位与模型侧最小修复。


## 触发与观测
warm-up prefill 阶段直接失败并报算子参数校验错误（EZ0024）。观测事件：日志 tail 中 MoeInitRoutingV3 的 expert_idx dim[0]=4096 与 should be 8192 的配对数字是本 bug 的指纹——两数之比恰为 attn_tp_size。

### 结论与证据边界

在 MoeBlock.forward 内把 cur_topk_list 行数对齐到本 rank 实际 MoE 输入 token 数（topk_idx.shape[0] 与 hidden_states_flat.shape[0] 不等时：偏长截断、偏短按 ceil 重复后截断，轮转周期==num_experts=128 故 repeat 保持各专家负载均衡）后，同配置复跑 bash executor/scripts/infer.sh --model qwen3_moe --yaml qwen3_235b_mxfp48_attn4tp_moe4ep.yaml：Warm-up completed successfully、qwen3_moe decode average inference time cost is 3.49 ms，EZ0024 不再出现。

## 探针与操作
1) tail/grep 业务 log_0.log 找 EZ0024 与调用链（MoeBlock.forward → moe_infer_double_routing → npu_moe_init_routing_v2）；2) 读 executor/core/model_worker/model_worker.py 的 gen_force_eplb_topk_idx，确认 prefill 行数公式 (total_tokens+attn_tp_size-1)//attn_tp_size（SP 切分假设）；3) 读 models/qwen3_moe/models/modeling_qwen3_moe.py，确认 sp_shard 仅在 sp_config.enabled 时生效、SP 关闭时每 rank 送全量 token 进 moe_infer_double_routing；4) 核对 yaml：world_size=2, attn_tp_size=2, moe_ep_size=2, enable_sp=False, batch 2×input_len 4096=8192 token。

## 机制与判别
见上方结论原文与下方机制片段；判别性证据与边界适用讨论见“适用与失效边界”节。

### 补充机制片段

```
topk_idx, topk_weight, _ = self._forward_gate(hidden_states_gate_flat)
        if self.force_eplb:
            topk_idx = cur_topk_list
            # The force-EPLB topk list is generated by ModelWorker with the
            # per-rank token count (total // attn_tp). When SP is disabled each
            # rank feeds the full sequence to the MoE, so align the row count
            # to the actual MoE input tokens: truncate when longer, otherwise
            # repeat the periodic round-robin pattern (period == num_experts)
            # to preserve per-expert load balance.
            local_tokens = hidden_states_flat.shape[0]
            if topk_idx.shape[0] != local_tokens:
                if topk_idx.shape[0] > local_tokens:
                    topk_idx = topk_idx[:local_tokens]
                else:
                    reps = (local_tokens + topk_idx.shape[0] - 1) // topk_idx.shape[0]
                    topk_idx = topk_idx.repeat(reps, 1)[:local_tokens]
        topk_idx = topk_idx.to(torch.int32)
```

## 验证信号
修复后同命令复跑：日志出现 Warm-up [Main]: executing model prefill step → decode step → graph compilation → Warm-up completed successfully，且 qwen3_moe decode average inference time cost is 3.49 ms，grep MoeInitRouting/EZ0024 无命中。

## 适用与失效边界
适用：force_eplb 开启且 worker 无法修改（公共文件）的场景；行数对齐放模型侧 MoeBlock.forward，对所有 MoE 路径统一生效。局限：repeat 补足依赖 worker 轮转周期==num_experts（128）且列表行数是其整数倍时才与原公式严格等价（本例 4096=32×128 成立）；行数一致场景直通零行为变化；偏长截断为防御分支。修复在本轨迹内以单配置复跑验证闭合，未覆盖 SP 开启组合的回归矩阵。
