- [aclgraph replay 静默挂死无报错时：用 acl_graph_print 图内打点二分定位挂点](aclgraph_print_bisect_silent_hang.md)：昇腾 NPU 上开 aclgraph（npu-graph-mode 的 acl_graph / cudagraph_mode: FULL_DECODE_ONLY）后 decode 阶段静默挂死、无 HCCL 报错无 traceback（典型伴 shm_broadcast 60s 超时循环、plog 空只有 TBE subprocess 空 error）时的图内定位干预配方。先排除 eager 路径确认问题在图捕获/replay 侧；因图在 device 上 replay、host 侧 Python 栈与 print 失效，须用图内打印原语 acl_graph_print(<msg>) 作探针随图 replay 输出，再二分挂点：探针成对包夹可疑段（如 event.wait 前后）、多机只 rank0 打印，看哪条不再输出即为挂点上界，把探针不断前移直到第一个仍能输出的位置，挂点夹在最后一个能打印与第一个打不出之间；某 forward 内探针全无输出则挂点在进入该 forward 之前，边界继续上移（参考实现即由 attention 推进到 MoE finalize 跨 DP 组通信不匹配）。关键约束：acl_graph_print 只能在 custom op 内部用（放外面过不了 dynamo trace 而失效），只依赖 CANN/torch_npu 版本、调用无需额外参数，此约束绑定 acl_graph_print+dynamo 参考实现、换 torchair GE 图路径机制不同但探针必须进图的原理不变。纯诊断只定位不改行为、无 rollback 负担、调试完移除即可；GDB 因缺 debug symbol 常徒劳。场景涉及 vLLM-Ascend DP+TP+EP aclgraph decode、MLA、MoE decode。
- [块稀疏 Attention 与 Ulysses 序列并行同时使能（看全序列 + 规范序重映射 + head 负载均衡）](blockwise_sparse_attention_ulysses_integration.md)：块稀疏 Attention 与 Ulysses 序列并行同时使能（看全序列 + 规范序重映射 + head 负载均衡）。长序列视频 DiT 想同时吃到两种降本：块稀疏 Attention（TopK/SVG 丢弃低注意力块）减计算量，Ulysses 序列并行摊显存/时延。两者天然冲突，直接叠加会算错，须解决三处问题。单卡稀疏使能本身见 video-dit-blockwise-sparse-attention，Ulysses 本体见 video-dit-ulysses-sequence-parallel。

- [CFG 类生成模型用与 TP 正交的样本级并行摊平每步两次前向](cfg_parallel_sample_level_diffusion.md)：CFG 类生成模型用与 TP 正交的样本级并行摊平每步两次前向。模型在每个去噪/生成步做 classifier-free guidance（CFG）——需要一份 unconditional 预测和一份 conditional 预测，再按 guided = uncond + scale·(cond − uncond) 合成。默认无 CFG 并行时，同一组设备把两个样本拼进 batch（batch ×2）串行跑两次网络，每步前向时延翻倍。当集群卡数还能多分一维时，可把这两次独立前向摊到两组设备上并行。 适用：任意每步做 CFG 的生成模型（扩散 dit、文生图/图生视频 pipeline），且愿意用 2 倍设备换单步时延。
- [把 decode 逻辑塞进图前消除 graph break：host 同步 / host 构造张量 / 图后端不支持算子的图安全改写](graph_break_elimination_host_sync_unsupported_ops.md)：把 decode 逻辑塞进图前消除 graph break：host 同步 / host 构造张量 / 图后端不支持算子的图安全改写。要把一段 decode 逻辑整图编译进 GE 图 / aclgraph（npu-graph-mode），但它含 host 依赖或图后端不支持的算子，捕获失败 / 断图 / 走 CPU fallback。上图前先按下面几类逐条排查、把图中断（graph break）改成图安全等价——这是把 decode 从 eager 迁到图模式的核心适配工作。是否值得为某模块付这份适配见 graph-mode-enable-decision-profiling。
- [图模式多流并行的跨流同步：ge_graph 控制边 vs aclgraph tagged-event 及 API 选型](graph_mode_multi_stream_cross_stream_sync_api.md)：图模式多流并行的跨流同步：ge_graph 控制边 vs aclgraph tagged-event 及 API 选型。在图模式 decode 下用多流（multi-stream / moe-multi-stream）让互不依赖的计算 overlap 掉时延（典型：MoE 共享专家计算掩盖路由专家 TP 通信、indexer prolog 的 q/kv 侧流）。该 overlap 哪些计算、怎么控核平衡是另一层（见 decode-multi-stream-overlap-core-balance）；本页只解决"跨流数据依赖在不同图后端下怎么正确表达、别把 API 混写"。

- [KVP — 长序列 memory-bound decode 沿 S 维切 KV Cache（lse-softmax 在线归约 + 耦合配置约束）](kvp_longseq_decode.md)：适用：长序列 decode 且 KV Cache 内存/访存是瓶颈（单 rank 存完整 KV Cache 触发 device OOM 或抬高 decode 时延，memory-bound）；结构为 mla + MoE（KV 沿 S 维可切），本仓在 longcat-flash 落地。维护者确认收益针对 decode / PD 混合部署。
- [给新模型接入 MTP 推测解码：draft 模型构造 / 权重共享 / prev_hidden_states / 三元组注册 / 无损 verify](mtp_speculative_decode_model_onboarding.md)：给新模型接入 MTP 推测解码：draft 模型构造 / 权重共享 / prev_hidden_states / 三元组注册 / 无损 verify。decode 尚未达计算 bound、想用推测解码（一次主模型前向多产出 token）压等效时延 / 提吞吐：把一个复用主模型输出头的 draft（MTP）模型接入通用 executor 的推测路径，每步预测 next_n 个推测 token（mtp-speculative-decoding）。 参考实现：cann-executor 的通用 MTP 路径，参考接入模型 deepseek-r1（MoE），prefill+decode 全程。
- [多机/多进程 DP+EP MoE 推理的集合通信一致性对齐（phase 对齐 + 变长换定长）](multimachine_dp_ep_moe_collective_alignment.md)：多机/多进程 DP+EP MoE 推理的集合通信一致性对齐（phase 对齐 + 变长换定长）。MoE 模型多机 / 多进程 DP + EP 推理里，单进程组内多个 DP rank 各自持请求、又要在 MoE 层做跨 rank 集合通信。凡相互做 MoE 集合通信的 DP 进程，必须在同一状态下发起集合通信；一旦各进程按各自本地请求独立推进，请求数/token 数不整除进程数时进程会错开 → 集合通信不一致（对不齐 / 挂起）。有两处对齐要做。
- [Prefill 用 micro-batch 双流把 MoE dispatch/combine 通信藏进计算](prefill_micro_batch_dual_stream_moe_overlap.md)：Prefill 用 micro-batch 双流把 MoE dispatch/combine 通信藏进计算。大 EP MoE 模型 prefill：整体是计算 bound，但 MoE 的 dispatch/combine 两段 AllToAll 通信仍占一定比例（本仓一手优化文档称 prefill 通信耗时占比可达约 30%）。计算与通信由不同硬件单元完成、可并行——把它们错开就能用计算掩盖通信、把 prefill 推向纯计算 bound。 拓扑：MLA 走 DP 切分、MoE 走 EP 切分（DP+EP），或更一般的「EP + 可切 micro-batch」场景。 目标：用一路的计算穿插另一 micro-batch 的通信，隐藏 MoE EP 的通信空洞。

- [SFA/DSA 稀疏注意力叠加 Context Parallel：跨 CP 组重建完整 KV 的 all_gather 路径](sfa_dsa_cp_cross_group_kv_allgather.md)：在 SFA/DSA 稀疏注意力叠加 PCP/DCP 时，各 rank 只保存局部 KV block，而 indexer 会按全局 topk_indices 取块，直接使用本地 block_table 会漏取并造成精度错误。修复是在注意力与 indexer 前按 valid_block_ids 选出有效块，依次执行 DCP all_gather、PCP all_gather 重建完整 KV；顺序不可互换。block_table_cp 通过 unique(return_inverse) 虚拟化，并为各 CP 分片增加 num_blocks 偏移。硬约束是 kv_cache_interleave_size 必须等于 block_size；写 KV 时先 all_gather，再按 restore index 恢复顺序后落 cache。该路径限定 SFA 与 paged KV 的 PA_BSND 布局，gsm8k 在 TP2+PCP2+DCP2+EP、block_size=128 下为 96.35%，未提供吞吐或显存收益。
