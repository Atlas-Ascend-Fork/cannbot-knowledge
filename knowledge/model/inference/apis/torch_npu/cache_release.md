# NPU缓存释放API：虚拟地址与Host物理缓存

## 固定版本与证据范围

文档固定为OpPlugin发布dedc316708372c9a8bfde4527abd2a94b74840f5及主线d84e9b1d6a558e5f27973cd4329f62968e46fdda，区分发布中文与主线中英文。发布配对TorchNPU为f3ecfe4a7ef7395754da7ca2e35661a7132b519b；补充的独立主线ac0e1564ca6ffb00c1f4fb834fc4b41a601862bf不视为与OpPlugin main已配套。

产品逐接口、参数和版本消费；主线新增950DT不回推发布、不扩到950PR。旧Atlas产品保留来源身份，不由其名字推定其他型号。以下为静态审阅，没有导入上游、加载库、操作设备、采集或性能测试，知识卡stable不代表运行verified。


## 两个不同入口

empty_virt_addr_cache()要求expandable_segments=True，未满足文档列RuntimeError；解除设备虚拟地址映射并保留空闲物理句柄供下次申请，不实际归还全部物理内存。两固定memory.py在未初始化时直接不调用底层，初始化后转发_npu_emptyVirtAddrCache。发布A2/A3训练，主线另列950DT。

host_empty_cache()释放Host缓存分配器持有的未占用物理内存；不释放活跃Tensor、全部CPU进程内存或所有Device缓存。发布A2/A3训练/推理及旧Atlas，主线增加950DT；Python直接转发_npu_hostEmptyCache。

## 使用与观测

两者都不是统计计数器复位或泄漏修复器，也不能保证下次申请不OOM。虚拟地址示例的大分配只作调用演示，不作为内存占用或性能证据；不照搬其import后设置环境顺序为任意配置均可晚配，按分配器首次初始化读取时机核对。

需要减少物理保留、定位峰值或检查Host锁页池时，先区分[allocated/reserved与统计窗口](../../guides/optimization/torch_npu/torch_npu_memory_counters.md)及[分配器环境](../../guides/optimization/torch_npu_allocator_options.md)。未进行分配或清缓存试验。
