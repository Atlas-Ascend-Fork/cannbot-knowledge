# Profiler analyse：离线输入、进程上限与导出回退

## 固定版本和支持范围

文档分别来自OpPlugin发布dedc316708372c9a8bfde4527abd2a94b74840f5中文及主线d84e9b1d6a558e5f27973cd4329f62968e46fdda中英文；实现分别核对TorchNPU发布f3ecfe4a7ef7395754da7ca2e35661a7132b519b与独立主线ac0e1564ca6ffb00c1f4fb834fc4b41a601862bf。发布组合ascend_26_0_pt28有独立配套证据，两个仓库主线提交不自动配套，不能用新参数回推发布版。

本卡平台限定A2/A3。部分OpPlugin主线接口页列950DT，但同一固定PyTorch主线原生Profiler支持页对相关入口另有明确不支持说明，且不同方法产品表并不相同；版本与命名空间冲突见[采集指南](../../guides/optimization/torch_npu/torch_npu_profiler_capture_schedule.md)，不以类级表扩展全部方法。旧Atlas条目不自动映射新型号。这里只做静态来源审阅，未导入上游、运行设备采集、解析或性能实验。


## 调用合同

from torch_npu.profiler.profiler import analyse，传profiler_path。文档默认原型含未定义max_process_number变量仅为占位，实际profiler_path必选；目录中应有{worker}_{timestamp}_ascend_pt采集目录。文档限制字母数字下划线、无软链接，示例同时带./分隔符，不据文字拒绝所有路径分隔符。

max_process_number默认CPU核数//2，非法类型或≤0回默认，超过CPU核数则截断；默认值没有额外max(1,...)保证，不能宣传在任意单核环境始终至少1。export_type接受str或list，字符串转列表、列表去重；仅text/db，空或非法整体回None。文档None/非法时读取profiler_info.json里的导出设置，区别于_ExperimentalConfig非法值直接回Text。

## 数据及结果边界

两版公开analyse没有return内部调用，正常返回None；日志、产物和解析错误才是验收信号。主线内部NpuProfiler查找数据子目录，没有则直接返回；daemon进程不解析、给出离线提示。它会选择fork并启动进程池，不能在宿主不允许这种启动方式时仅凭API合法就保证解析成功。

Text/Db语义及配套Toolkit限制见[回调导出](profiler_trace_handler.md)。此卡没有打开或解析性能数据，也未证明每个原始目录可以被任意另一版本解析。解析资源和耗时与模型Kernel测量分开统计。
