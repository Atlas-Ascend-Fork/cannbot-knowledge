# NPU Dump接口：初始化、JSON配置与收尾落盘

## 固定版本与证据范围

文档固定为OpPlugin发布dedc316708372c9a8bfde4527abd2a94b74840f5及主线d84e9b1d6a558e5f27973cd4329f62968e46fdda，区分发布中文与主线中英文。发布配对TorchNPU为f3ecfe4a7ef7395754da7ca2e35661a7132b519b；补充的独立主线ac0e1564ca6ffb00c1f4fb834fc4b41a601862bf不视为与OpPlugin main已配套。

产品逐接口、参数和版本消费；主线新增950DT不回推发布、不扩到950PR。旧Atlas产品保留来源身份，不由其名字推定其他型号。以下为静态审阅，没有导入上游、加载库、操作设备、采集或性能测试，知识卡stable不代表运行verified。


## 顺序与版本差异

```text
init_dump() -> None
set_dump(cfg_file) -> None
finalize_dump() -> None
```

cfg_file包含JSON文件名。主线流程为init_dump→set_dump(JSON)→模型执行→finalize_dump，未初始化即set/finalize会出错，finalize结束并触发数据落盘。发布init页要求预先NPU_DUMP_ENABLE=1并调用set_dump_config(path,mode)，发布finalize也有环境要求；主线删除这些文字，不据删除推定所有旧版本可以省略。

发布产品为A2/A3训练和旧Atlas，主线新增950DT。set_dump主线把外链规范换到Runtime9.2路径；该外部JSON schema、完整dump_mode、目录权限/数据格式及磁盘恢复机制不在本卡来源内，需按Runtime 9.2文档核对。

## 同名函数必须追公共导出

两固定TorchNPU的utils.py有直接_npu_initDump/_setDump/_finalizeDump封装，而npu_config.py同名函数写mdldumpswitch/mdldumpconfigpath选项。两份npu/__init__.py先显式导入utils，再星号导入npu_config的__all__，覆盖这三个名字；不能因文档写utils.py就把公共入口实际调用链标错。

该导出路径的set_dump检查文件存在、realpath后交底层，不在Python层完整解析JSON；init/finalize写开关。源码存在这些包装不取消底层初始化、同步和配置要求，finalize成功也不能代替逐文件完整性验证。未生成或读取任何dump数据。
