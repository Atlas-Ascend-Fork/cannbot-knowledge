# Profiler profile：活动、回调和实际默认采集行为

## 固定版本和支持范围

文档分别来自OpPlugin发布dedc316708372c9a8bfde4527abd2a94b74840f5中文及主线d84e9b1d6a558e5f27973cd4329f62968e46fdda中英文；实现分别核对TorchNPU发布f3ecfe4a7ef7395754da7ca2e35661a7132b519b与独立主线ac0e1564ca6ffb00c1f4fb834fc4b41a601862bf。发布组合ascend_26_0_pt28有独立配套证据，两个仓库主线提交不自动配套，不能用新参数回推发布版。

本卡平台限定A2/A3。部分OpPlugin主线接口页列950DT，但同一固定PyTorch主线原生Profiler支持页对相关入口另有明确不支持说明，且不同方法产品表并不相同；版本与命名空间冲突见[采集指南](../../guides/optimization/torch_npu/torch_npu_profiler_capture_schedule.md)，不以类级表扩展全部方法。旧Atlas条目不自动映射新型号。这里只做静态来源审阅，未导入上游、运行设备采集、解析或性能实验。


## 入口及构造

torch_npu.profiler.profile继承_KinetoProfile。两实现均为关键字参数：activities=None、schedule=None、on_trace_ready=None，record_shapes/profile_memory/with_stack/with_flops/with_modules均False、experimental_config=None；发布实现仍接受废弃use_cuda=None并提示NPU环境无效。发布文档的with_modules未写默认值、排在默认参数后，不能当可执行Python签名。

主线增加execution_trace_observer=None、custom_trace_id_callback=None，仍有use_cuda兼容形参；主线文档省略use_cuda不证明实现已经删除。默认activities或空容器使用supported_activities()，并非空列表表示完全不采。

## schedule和回调的实际行为

schedule应为step→ProfilerAction的可调用对象。两实现省略时选择_default_schedule_fn，每步返回RECORD，start后持续记录，且record_steps=False，不自动生成ProfilerStep标记。不可调用的非空schedule也告警后走该默认行为。接口页“默认不执行操作”不能理解为不采；ProfilerAction页直接传枚举的例子不能作为有限窗口配方。

on_trace_ready接受可调用对象，非法非空值告警后变None；具体文档只推荐tensorboard_trace_handler，但实现未把函数身份限制为这一种。start/stop或with上下文配对，逐轮step推进状态；stop后step只告警。状态转换及保存条件见[schedule](profiler_schedule.md)。

## 主线观测器与证据强度

主线profile.start/stop直接调用观测器start/stop；代码没有在每次WARMUP/RECORD状态转换时启停它。因此文档“同一时间窗口”不能保证观测器只覆盖schedule的active区间，wait/warmup与多repeat须分开核对。它不负责替业务执行回放。

trace ID构造回调、setter/getter属于各自版本/类，见[trace ID](profiler_trace_id.md)。细粒度开关的CPU活动前提、额外开销和实际产物须一起检查，不以profile对象成功构造判定已采集。
