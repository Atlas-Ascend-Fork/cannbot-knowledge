# NPUGraph任务组API：捕获句柄与异流更新顺序

## 固定版本与证据范围

文档固定为OpPlugin发布dedc316708372c9a8bfde4527abd2a94b74840f5及主线d84e9b1d6a558e5f27973cd4329f62968e46fdda，区分发布中文与主线中英文。发布配对TorchNPU为f3ecfe4a7ef7395754da7ca2e35661a7132b519b；补充的独立主线ac0e1564ca6ffb00c1f4fb834fc4b41a601862bf不视为与OpPlugin main已配套。

产品逐接口、参数和版本消费；主线新增950DT不回推发布、不扩到950PR。旧Atlas产品保留来源身份，不由其名字推定其他型号。以下为静态审阅，没有导入上游、加载库、操作设备、采集或性能测试，知识卡stable不代表运行verified。


## 四个入口与配对

```text
graph_task_group_begin(stream) -> None
graph_task_group_end(stream) -> handle
graph_task_update_begin(stream,handle) -> None
graph_task_update_end(stream) -> None
```

group begin/end必须在同一捕获流成对，end返回不透明句柄；update begin/end在同一更新流成对，**更新流必须不同于捕获流**，用句柄定位既有任务组。两固定graphs.py包装只转发_C并返回end句柄，没有在Python这几行实现所有流/句柄合法性检查。发布列A2/A3训练/推理，主线另列950DT。

## 示例实际展示的更新

四页重复示例为FP16 QKV [1,32,1,128]、BNSD融合注意力，预分配workspace/out，捕获ExternalEvent wait/reset和任务组，然后在另一流将actual_seq_lengths从29改100，再record并replay。它展示一次指定参数的更新，不证明任意shape、dtype、拓扑或输出容量变化都可用，也不保证workspace会自动扩容。

样例torch.equal只打印比较，没有完整异常、容量、数值与多轮复用验收；手工reset还与[ExternalEvent独立说明](external_event.md)相冲突。auto_dispatch_capture与[NpuGraphOpHandler](npugraph_op_handler.md)是框架组织这类更新的另一层，不因本API存在就支持所有自定义算子。
