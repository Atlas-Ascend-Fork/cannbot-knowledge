# ProfilerLevel与AiCMetrics：成员、采集层次和指标单位

## 固定版本和支持范围

文档分别来自OpPlugin发布dedc316708372c9a8bfde4527abd2a94b74840f5中文及主线d84e9b1d6a558e5f27973cd4329f62968e46fdda中英文；实现分别核对TorchNPU发布f3ecfe4a7ef7395754da7ca2e35661a7132b519b与独立主线ac0e1564ca6ffb00c1f4fb834fc4b41a601862bf。发布组合ascend_26_0_pt28有独立配套证据，两个仓库主线提交不自动配套，不能用新参数回推发布版。

本卡平台限定A2/A3。部分OpPlugin主线接口页列950DT，但同一固定PyTorch主线原生Profiler支持页对相关入口另有明确不支持说明，且不同方法产品表并不相同；版本与命名空间冲突见[采集指南](../../guides/optimization/torch_npu/torch_npu_profiler_capture_schedule.md)，不以类级表扩展全部方法。旧Atlas条目不自动映射新型号。这里只做静态来源审阅，未导入上游、运行设备采集、解析或性能实验。


## Level成员

ProfilerLevel是包含字符串常量的Python类，Level0默认，含应用、NPU与部分算子字段；Level1增加AscendCL、AI Core指标及HCCL通信分析；Level2再增加Runtime与AI CPU，数据预处理文件需实际任务。Level_none关闭这组Level控制的数据，不等于停掉所有观测，MSTX仍另有规则。

主线独立成员页删去旧默认值段落不说明默认已改变。真正传入值及最终值见[_ExperimentalConfig](profiler_experimental_config.md)。主线产品表增加950DT只是一份文档的范围，不能覆盖其他版本入口限制。

## AiCMetrics一次选择一组

| 成员 | 用途 |
| --- | --- |
| AiCoreNone | 关闭AI Core指标 |
| PipeUtilization | 计算/搬运单元耗时占比 |
| ArithmeticUtilization | 计算类指标占比 |
| Memory、MemoryL0、MemoryUB | 不同存储层读写指令占比 |
| ResourceConflictRatio | 流水线队列相关指标 |
| L2Cache | 命中及缺失后重新分配次数 |
| MemoryAccess | 核上访存带宽数据量 |

Memory成员不是设备总内存占用，指令占比也不是整个模型耗时比例；MemoryAccess与Memory不能互换。l2_cache=True独立生成l2_cache.csv，不等同AiCMetrics.L2Cache。固定实现Level0/none会关闭非空AI Core指标，目标PMU需显式Level1/2并验收所选组。

引用的msprof指标明细与硬件公式不在这三个固定仓快照内，需另查msprof文档；文件存在、合法成员及支持查询不保证所有计数可用。选择方法和CANN Text/Db能力见[指标指南](../../guides/optimization/torch_npu/torch_npu_profiler_metrics_selection.md)。
