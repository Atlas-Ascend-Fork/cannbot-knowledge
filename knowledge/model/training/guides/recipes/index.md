# 实践指南

- [DeepSeek-R1 veRL + MindSpeed + vLLM-Ascend 全共卡 GRPO RL 训练](deepseek_r1_rl.md)：DeepSeek-R1（671B）强化学习后训练在 Atlas A3 SuperPoD 超节点 128 卡集群跑通。整套系统以 verl 为前端（单控制器调度 RL 控制流）、mindspeed + Megatron-LM 为训练后端（actor / ref 的 update 与 log_prob）、vllm-ascend 为 rollout 推理后端（采样生成），用 grpo-dapo 算法在 ActorRolloutRef 三模型全共卡、分时复用部署下完成训练，加载真实权重时系统吞吐达 120+ TPS/卡（初始 112，长稳后 120+，单点详测 123.16），随机权重峰值场景达 250.2 TPS/卡。
- [DeepSeek-V3.2 TorchTitan 32K 长序列预训练](deepseek_v32_pretrain.md)：基于 torchtitan + torchtitan-npu 插件（样例版本 v0.2.2），DeepSeek-V3.2（671B / 61 层，DSA 稀疏注意力）32K 长序列预训练 / CPT 在 64 卡 Atlas A3 集群上达到 148 TPS/卡。训练使用 5D 混合并行（FSDP2+TP+PP+EP+自定义 CP）、DSA 反向算子 SLIG / SFAG，以及 torch.compile + Inductor 的模型到算子编译路径。DeepSeek-V3.2 与推理侧 deepseek-v3.2-exp 同属 DSA 模型谱系。
- [DeepSeek-V3 裁剪模型 MXFP8/HiF8 低精度预训练（MindSpeed · Atlas 950 950DT · 8K）](deepseek_v3_low_precision_pretrain.md)：cann-recipes-train 在 Atlas 950 950DT 上跑通的 8-bit 混合精度预训练：基于 mindspeed 框架（MindSpeed Core + MindSpeed-LLM 组件，底座对接 NVIDIA Megatron-LM core_v0.12.1），用一个 DeepSeek-V3 裁剪模型（2 层：1 dense + 1 MoE，hidden 7168、256 专家、MLA），在 8 卡 950（950DT，单卡 486 TFLOPS）、序列长 8K、GBS=64 下，分别用 HiF8 与 MXFP8（E4M3） 两种低精度格式量化整网的 MatMul（MM）/ Grouped MatMul（GMM） 算子，与 BF16 混合精度做长稳精度对齐与性能对比。HiF8/MXFP8 损失与梯度范数都基本对齐 BF16，HiF8 端到端提速 29.5%、MXFP8 提速 14.05%、HiF8 相对 MXFP8 再快 11.3%。
- [DeepSeek-V4 TorchTitan-NPU + AutoFuse 极简续训练（Flash 64 卡 / Pro 192 卡 A3）](deepseek_v4_continue_pretrain.md)：DeepSeek-V4 在昇腾 A3 上做续训练（CPT）。CANN 在 torchtitan-npu v0.2.2-dev 分支上为两个规格做了快速训练支持：DeepSeek-V4-Flash（285B / 43 层，最小 8 机 64 卡 A3 = 128 die）与 DeepSeek-V4-Pro（61 层，最小 24 机 192 卡 A3 = 384 die）。整套方案围绕三条主线——「极简并行」（纯 FSDP + 大 EP，舍弃 TP/PP）、「自动融合」（torch.compile + Ascend C AutoFuse 训练入图）、「定制算子」（针对 DSA / mHC 稀疏结构的 SAS / SASG / LI / SLIG 融合算子）。4K 序列 BF16 + MTP1 训练下，Flash 在 A3 SuperPods 64 卡集群上吞吐从初始 397 tokens/p/s 提升到 1100 tokens/p/s，其中定制融合算子与 AutoFuse 分别贡献约 90% 与 30% 的吞吐增益。该实践对应的推理部署见跨域页 deepseek-v4。
- [Ascend-TLA · DeltaNet 线性注意力 NLP 预训练样例](deltanet_pretrain.md)：昇腾 NPU 上 DeltaNet（Delta Rule）线性注意力的训练侧入门样例：一个基于 DeltaNet 线性注意力、面向昇腾 NPU 的实践样例，配套 NLP 语言建模训练流程与 Quick Start Notebook，更完整工程见上游仓库 Ascend-TLA（https://gitcode.com/SMULL_Group/Ascend-TLA.git）。其定位与同域其它 recipe 不同：不是大规模分布式实践，而是一条「先读 Notebook、再跑 GPT-2 风格语言建模」的算子+训练上手梯子，配 demo_config.zip 演示配置即可在单机体验 DeltaNet 算子与 NLP 训练评测全流程。
- [Qwen2.5-1.5B veRL GRPO 单卡 A2 数学 RL 入门样例](qwen2_5_rl.md)：昇腾 RL 训练的最小上手样例：用 verl（release/v0.6.1）框架，对 Qwen2.5-1.5B-Instruct 在 MATH-lighteval 数学推理数据集上跑 grpo-dapo（GRPO），最低只需单卡 Atlas A2（A3 同样可跑）即可完整走通「数据预处理 → RL 训练 → 权重合并 → 效果验证」全流程。它与 128 卡 A3 上的 671B 大规模实践 deepseek-r1-rl 同属一套框架（veRL + GRPO）：后者是工程极限，本样例面向用最少的卡、最少的步骤把昇腾 RL 跑通的入门场景。
- [veRL + ScaleBox 沙盒长上下文 Code RL（DeepSeek-R1-Distill-1.5B / Qwen3-4B / Qwen3-30B-A3B）](qwen2_code_rl_scalebox.md)：昇腾平台上 基于代码沙盒的 Code RL（代码强化学习） 端到端实践：用 veRL 强化学习框架 + 适配昇腾的代码沙盒服务 ScaleBox，跑 长上下文 Code RL 训练。「长上下文」体现在 prompt 2048 + response 8192 的 2k+8k 序列配置（recipe agent_rl/qwen2_code_rl）。Code RL 走的是 RLVR（可验证奖励）路线——模型对编程题生成代码、在 ScaleBox 沙盒里真跑测试用例、按通过率打可验证奖励回填 GRPO 优势计算（三脚本均 algorithm.adv_estimator=grpo，仅借用 DAPO 的 clip-higher，非纯 DAPO）——因此一个能扛 rollout 海量并发、可跨机扩展的安全执行沙盒是训练主回路的一环。
- [Qwen3-1.7B 多轮工具调用 Code RL（verl + ScaleBox 沙盒 + EAGLE3/Suffix 投机解码）](qwen3_code_toolcall_rl.md)：基于 Qwen3-1.7B，用 verl RL 框架 + 适配昇腾的代码执行沙盒 ScaleBox，在 Atlas A2/A3 单机八卡上实现长上下文多轮工具调用 Code RL 训练，是首个开源的、基于 verl 支持多轮工具调用的 Coding Agent RL 实践。训练时模型把 ScaleBox 沙盒当成「Python 工具」在推理过程中多轮调用（写代码→执行→看结果→续推），由含工具调用奖励的奖励信号驱动策略提升。实践分两部分——(1) 基础样例：SFT 冷启动 + 含工具调用奖励的多轮工具调用 Code RL；(2) 推测解码扩展：把 EAGLE3 + Suffix 投机解码集成进 verl + vLLM-Ascend 的 rollout 流水线，端到端吞吐最高 +38%、训练步时间 -25%、精度无损。
- [Qwen3 长序列 RL 训练实践（235B-A22B 2K 推 32K + 32B SAM 投机，veRL/MindSpeed/vLLM-Ascend，GRPO/DAPO）](qwen3_rl.md)：Qwen3-235B-A22B（MoE，22B 激活）：在 64 卡 A3（128die） 上跑 GRPO/DAPO，Prompt/Response 最大 2K / 32K 的长序列场景，加载真实权重的 GRPO 系统吞吐达 122 TPS/卡（recipe README 标称 120 TPS/卡）。技术栈为 veRL 前端 + Megatron+MindSpeed 训练引擎 + vLLM+vLLM-Ascend 推理引擎，全共卡部署。 Qwen3-32B（dense）：在 16 卡 A3（32die） 上跑 GRPO/DAPO 2K 推 34K，使能 SAM 无模型投机解码，端到端约 +10%、叠加 npugraph_ex 后首步推理时间提升 29%~33%。
- [Qwen3-1.7B MindSpeed-LLM SFT 单卡 A3 alpaca 入门样例](qwen3_sft.md)：Qwen3-1.7B（dense）使用 MindSpeed-LLM + Megatron-LM core_v0.12.1 的 mcore 训练栈，在单卡 A3 上对 alpaca 指令数据集执行 SFT（监督微调）。流程包含 HF 模型转 mcore、alpaca 数据转换、SFT 训练及 mcore 转回 HF，需要 HF↔mcore 权重格式互转。与 Qwen2.5 的 veRL 原生 FSDP+vLLM 单卡 RL 路线不同，SFT 不包含 rollout 或奖励函数环节。
- [Qwen3-30B-A3B torchtitan-npu SFT（GSM8K + Ulysses CP 开箱配置）](qwen3_sft_torchtitan.md)：Qwen3-30B-A3B torchtitan-npu SFT 开箱配置（MODULE=torchtitan_npu.models.qwen3 CONFIG=sft_qwen3_30ba3b_math，GSM8K）：seq_len4096/bs1/steps100/lr1e-5 cosine，selective AC，EP8+context_parallel_degree4(Ulysses CP)+dp_shard-1，converters npu_rms_norm/rope/permute/gmm。SFT chat 数据流水：chat-template 渲染→增量前缀重 tokenize 定位 prompt/response 边界并 label-mask（loss 仅 assistant）→短样本贪心 packing 进一个 seq_len 窗口（EOS 分隔+逐文档 position 重置）→超长样本丢弃。Qwen3 thinking 经 reasoning_content。仅单轮。区别既有 MindSpeed 版 qwen3-sft（1.7B dense/alpaca）。
- [Qwen3 Tool Agent RL（verl-retool：SFT→RL 两阶段 Sandbox 工具 Agent，昇腾 A3）](qwen3_tool_agent_rl.md)：基于 veRL recipe/retool 项目，在昇腾 NPU 上完成端到端 agent RL 训练：让 Qwen3-4B-Instruct-2507 学会在推理过程中调用 Sandbox 代码工具进行 python 编程，把代码执行结果回灌为新一轮输入，辅助自身推理思考。整条流程使能 veRL 的 asyncLLM（异步生成）+ agent_loop（多轮工具调用）特性，这两个执行特性的机制见 Agent RL 执行范式。
