# 优化技术

- [Agent RL 执行范式（asyncLLM 异步生成 + agent_loop 多轮工具调用）](agent_rl_loop.md)：Agent RL 与朴素 RLVR 的根本区别在 rollout 阶段的执行形态：朴素 RL 一个 prompt 一次性生成完整 response 再算 reward；Agent RL 让模型在生成过程中调用外部工具/代码沙盒，把工具返回结果作为新一轮输入继续推理，多轮交互收敛后才算 reward。veRL 通过参考其 recipe/retool 项目，用两个特性把这套执行机制落到昇腾 NPU 上：asyncLLM（异步生成——以 HTTP Server 形态暴露 vLLM 引擎，让每个 prompt 的 request 独立异步推进）+ agent_loop（多轮 agent 循环——ToolAgentLoop 驱动「模型推理 → 检查是否要调工具 → 执行工具 → 结果回灌」状态机直到终止）。
- [Auto-Settings（并行/重计算/内存配置自动搜索）](auto_settings.md)：MindSpeed Auto-Settings 联合搜索并行、重计算和内存配置。白盒用profiling建模估算候选，黑盒/混合也由裁剪profiling与公式推导完整配置，均不是推荐配置的直接实测。实际拉起用nnodes，目标规模用target-nnodes；黑盒与混合输出会丢失部分CP/ZeRO/重计算/MC2字段，须补齐并验证。型号支持矩阵未明，保留草稿。
- [训练入图：torch.compile + Inductor + AutoFuse（Bypass Triton → AutoFuse）](autofuse_train.md)：当前训练 AutoFuse：两级后端、torch_npu 内置 AscendC、逐 Block 编译、AC 副作用、缓存隔离与来源报告的 A3 收益边界。
- [DCP / HF Checkpoint（torchtitan-npu 断点恢复与权重导出）](checkpoint_dcp_hf.md)：当前 TorchTitan checkpointer 配置、DCP/HF 格式与加载优先级、量化 HF 模型限制、NPU 同步 writer、NovaSwap 异步边界及 SHA-256 完整性校验。
- [Chunk Loss（分块 LM-Head + 损失，规避全量 logits 显存）](chunk_loss.md)：Chunk Loss 把训练末端 LM-Head 投影 + 交叉熵沿序列维切成 chunk_size 子段，逐段在前向内即时求导后累加损失与梯度，任意时刻只驻留一段 [B,chunk_size,V] 的 logits 而非全量 [B,S,V]，规避大词表(vocab_size≫hidden_size)下 logits 一次性 materialize 的显存峰值。实现为 torch.autograd.Function：用 torch.func.grad_and_value(argnums=(0,1),has_aux=True) 当场算 grad_input/grad_weight，该段计算图即建即销不为 backward 保留，backward 仅按上游标量缩放回放;常驻仅 grad_inputs[B,S,H] 与 grad_weight[V,H]，与 S·V 无关。logits 峰值从 B·S·V·bytes 降到 B·chunk_size·V·bytes(缩减因子 S/chunk_size)。alpha 按全局有效 token 数归一并同值传每段，同一 alpha 下分段 sum 与不分块 mean 数学等价，浮点舍入可能不同。LM-Head bias 不支持。接入：MindSpeed-LLM 经 --loss-compute-mode chunk / --loss-chunk-size，gpt_model 与 deepseek4_model 在 TP=1 且 CP=1 时启用([S,B,H]→[B,S,H] transpose);MindSpeed-MM 经 model.json loss_cfg 的 compute_mode(default/chunk/dynamic_chunk)，dynamic_chunk 用 calculate_chunk_size 在正整数且 batch_size≤预算时取满足预算的最大2的幂；其他输入回退1，不保证预算，FSDP2 路径以 chunkloss_lm_head 替换 DTensor Linear forward。关键术语：fixed_cross_entropy、calculate_lm_loss、grad_and_value、chunk_size、alpha 归一、动态分块。
- [CoC（Communication over Computation：计算通信重叠）](coc.md)：MindSpeed CoC（Communication over Computation，计算通信重叠）把 TP 线性层（Column/RowParallelLinear）前反向中顺序依赖的 matmul 与集合通信沿左矩阵 m 轴切成 2/4/8 片细粒度子任务交织，填掉计算流与通信流的互等空闲。两条实现：Python 脚本流水（COCParallel，compute_first 用于 AllReduce/ReduceScatter、communicate_first 用于 AllGather，--coc-parallel-num；矩阵切片靠 shuffle_as_coc_* 还原布局）与 LCAL 融合算子（--coc-fused-kernel，基于 MTE 单大 Kernel 内重叠，依赖 ATB、仅 TP=8；coc_ops 提供 matmul_all_reduce/matmul_reduce_scatter/all_gather_matmul(_v2)/pure_matmul，matmul_all_reduce 支持 w8A16 伪量化）。总开关 --use-ascend-coc，coc_mode×sequence_parallel 在六种 ModuleType（ORIGINAL/REWRITE/COC × ALL_REDUCE/SEQ_PARALLEL）间选型，tp=1 强制关。约束：m 须为切分数倍数、切分过细易 host bound；与 MC2、unaligned-linear、TP-2D 的 use-ascend-coc 互斥（但 TP-2D 复用同一套 coc_ops 融合算子），当前未适配 MoE，Ascend 950 不支持融合算子。收益：BLOOM 7B +3.20%、176B +5.47%、LLAMA2 70B +7.85%，精度相对误差 2% 内。
- [训练数据效率（EOD Reset + 变长 Flash Attention + 多样本 Packing）](data_packing_varlen.md)：MindSpeed-LLM 用三项协同机制提升训练数据利用率：EOD Reset 在文档边界重置 attention mask 与 position_ids，阻断跨样本注意力；变长 Flash Attention 以 TND 布局和 actual_seq_len 减少跨样本注意力计算；多样本 Packing 用贪心装箱减少 padding，并通过 neat-pack 编号重建 position_ids 和序列边界。Packing 发生在预处理阶段，EOD/varlen 在训练运行时保证样本隔离；neat-pack 依赖 pack 与 reset-attention-mask。
- [EPLB（专家并行负载均衡器，MoE 专家动态负载均衡）](eplb.md)：EPLB（Expert Parallelism Load Balancer，专家并行负载均衡器）最早由 DeepSeek 针对大规模 MoE 模型训练中的负载不均推出，通过分层 / 全局调度及历史负载估计，动态调整专家复制与分配，缓解热/冷专家随数据批次、领域变化而漂移导致的节点利用率失衡。Qwen3-235B 32K 长序列 RL 训练优化文档 §2.3.2 的实验中，Qwen3-30B / 235B 真实权重 rollout 各卡负载无明显不均，开启 EPLB 无明显性能收益；人为构造极端不均时推理耗时降低 17.78%，收益取决于实际负载分布。MindSpeed-RL workers/eplb 在 RL 训推共卡下采集专家负载、重排/复制热专家并更新 device 映射，与训练态 balanced/placement（moe-load-balance）互补。
- [GRPO / DAPO（组相对策略优化 RL 算法）](grpo_dapo.md)：GRPO（Group Relative Policy Optimization，组相对策略优化）去掉 PPO 的 critic（价值网络），对同一 prompt 采样一组 rollout，以组内相对奖励估计 advantage，省去独立 value model 的前反向与显存。数据流为 rollout → reward → advantage → 策略更新；同批仅做一次参数更新时才支持免计算 old_log_prob。DeepSeek-R1 671B 在 Atlas A3 128 卡上使用 veRL + MindSpeed + vLLM-Ascend 执行全共卡 GRPO。DAPO 在 GRPO 骨架上叠加解耦 clip 上下界、token-level 重要性采样与动态样本过滤。MindSpeed-RL 以继承 RayBaseTrainer 的 Ray 共卡 trainer（grpo/dapo/ppo_trainer_hybrid）实现 GRPO/DAPO/PPO，损失按 (stage,role) 注册 LossFuncFactory，compute_group_norm_advantage_return 计算组内 z-score；DAPO kl_loss≡0，PPO 使用 CriticWorker+GAE+apply_kl_penalty，DPO 委托 mindspeed_llm 离线 DPOTrainer。
- [分层解耦训练 LDT（Layerwise Disaggregated Training / U 形拆分学习）](ldt_disaggregated_training.md)：LDT（Layerwise Disaggregated Training，分层解耦训练，又称边云协同分布式安全训练）面向「运营商出租算力、企业数据不愿上云」的合规场景：在普通 PP 之上把模型首层与尾层同时部署在企业本地（边侧）、大量中间隐藏层放运营商（云侧），形成 U 形拓扑；边侧读原始样本、只把前向激活与反向梯度发往云侧，原始数据不出园、边侧仅需少量算力跑首尾层。实现在 MindSpeed-LLM（--layerwise-disaggregated-training，Qwen2.5/Qwen3 文本 LLM）与 MindSpeed-MM（model.json 的 patch.layerwise_disaggregated_training，Qwen2.5-VL 多模态；边侧 stage0 落直接吃原始图文的输入侧模块——视觉编码器靠前若干层+图像 patch embedding+text 输入 embedding，尾层为 unembedding/LM-Head，vit 主体按 PP 铺云侧）。二者共用机制：U 形拆分靠 VPP 在 PP stage0 摆首尾两虚拟 stage、跨域激活/梯度 P2P 接力、流水编排掩盖边云通信、支持边云非对称 TP/DP。本质是高级流水并行的 U 形 PP 变体，与异构并行（同卡异并行）互补。关键术语：U 形拓扑、边云协同、VPP stage0、激活/梯度 P2P、vit_pp_layers、非对称 TP/DP。
- [长度感知重采样（Length-Aware Resampler：按历史 response 长度的 rollout 重排）](length_aware_resampler.md)：On-policy RL 训练的 rollout（generate）阶段普遍存在 response 长尾：不同 prompt 的生成长度差异极大，而一个 generation batch 内往往同时混入极长与极短样本。这带来两个直接问题——同批次内短样本很快结束、长样本持续占用推理资源，整体吞吐被少量长尾样本拖慢；某些 batch 的生成长度远高于平均值，放大 step 时间抖动。长度感知重采样（length-aware resampler）是在 verl 的 RL 数据采样路径上新增的 LengthAwareEpochSampler：它利用上一轮 rollout 收集到的 response 长度统计，在下一轮 epoch 开始时对样本顺序重排，把预估长度接近的 prompt 尽量放到邻近 batch，从而在 batch 级别减少长短样本混排。
- [MC2（Matmul + Communication 算子级融合）](mc2.md)：MindSpeed MC2 是昇腾自研的 Matmul+Communication 算子级融合：把 TP+SP 下「matmul 紧挨集合通信、后者输入即前者输出」的强依赖融进单个 torch_npu 融合算子，算子内部把计算/通信切子任务流水互掩，压掉暴露通信。两处应用各有开关。TP 线性层 --use-ascend-mc2：MC2Feature patch Column/RowParallelLinear，列并行前向 npu_all_gather_base_mm(AG+matmul)、行并行前向 npu_mm_reduce_scatter_base(matmul+RS)，权重冻结走 *WithFrozenWeightFunction；须 TP>1 且开 sequence_parallel，与 use_ascend_coc(raise 'mc2 and coc can not be used together')、unaligned_linear、use_pipe_experts、use_nanopipe 互斥，MoE 模型与 Atlas 900 A3 不支持。MoE 层 --moe-alltoall-mc2：EP All2All 与专家 GMM 融合，fc1 npu_alltoallv_gmm、fc2 npu_gmm_alltoallv，dispatcher alltoall(需 ETP=1、dropless)/alltoall_seq(需 TP=1)，与 use_ascend_mc2、moe_alltoall/allgather_overlap_comm、moe_fb_overlap、moe_tp_extend_ep 互斥。MC2 是硬件融合算子、CoC 是框架层软件流水/LCAL 算子，二选一；前提 CANN 8.0.RC2/HDK 24.1.RC2。关键术语：MC2Feature、MoEAlltoAllMC2Feature、hcomm_info、gradient_accumulation_fusion、npu_matmul_add_fp32。
- [MindSpeed-MM 激活显存优化（Chunk-MBS 微批切块 + 异步激活 Offload）](mm_activation_memory.md)：MindSpeed-MM FSDP2 后端的两个互补激活显存优化。异步激活 Offload（enable_activation_offload）以 torch saved_tensors_hooks（async_save_on_cpu 的 _pack_to_cpu/_unpack_from_cpu）把前向保存的 layer 入口 hidden_states 在独立 swap_stream 上 D2H 换出 Host pinned 内存、反向 prefetch 预取 H2D 换回；SwapTensor 拷完才滞后一个 block 做 storage().resize_(0) 释放显存，custom_check_fn 只放行入口激活，末层不换出。Chunk-MBS（enable_chunk_mbs）在一次 FSDP Unshard 后沿 batch_dim 把单 micro-batch 切成 ceil(full/chunk_mbs) 个微块依次前向再 torch.cat 拼回，反向由自动微分另行执行，把动态激活峰值压到单微块量级；核心收益是允许 micro_batch_size=GBS、grad_acc=1，每次更新每个 block 只 Unshard 一次，省掉梯度累积的重复 AllGather，Qwen3.5 35B 整网约 5% 提速。二者建立在 recompute 之上，pre_fully_shard_apply 固定包装顺序 recompute→offload→chunk_mbs（chunk_mbs 最外层先切片）。长序列换出 self-attn 激活端到端 20%+，FSDP2 短序列腾显存增大 MBS 端到端 60%+。关键术语：saved_tensors_hooks、SwapTensor、OffloadManager、prefetch、batch_dim、chunk_arg_indexs。
- [MoE 通信掩盖（Dispatch 调度 + AllToAll/AllGather Overlap + 前反向跨 MicroBatch 掩盖）](moe_comm_overlap.md)：MindSpeed 把 MoE 在 EP 下的 dispatch/combine 通信瓶颈分三档掩盖。dispatcher 内部异步（--moe-permutation-async-comm：alltoall 走 repeat_interleave 新流并行+逐专家通算并行，allgather 走 gather/scatter→index/index_put 替换+三路 AllGather async）；层内 overlap（--moe-alltoall-overlap-comm / --moe-allgather-overlap-comm 把 MoELayer 重写成 autograd.Function，前向异步通信让专家计算掩盖 dispatch/combine、反向子图切分通算并行，+10%，带共享专家自动开 shared-expert-overlap 再+4%）；跨 microbatch 前反向掩盖（--moe-fb-overlap：单层拆 Attention/Dispatch/MLP/Combine 四阶段，用无依赖的另一 microbatch 计算掩盖 A2A，配 WeightGradStore 做 dw/dx 分离，实现 1F1B 阶段 A2A 100%、warmup/cooldown 50% 掩盖，是 DualPipeV 全掩盖机制本体）。dispatch=token_permute1/All2All-v/token_permute2，combine 对称。两种 dispatcher 取舍：alltoall 通信量小但需 device-host 同步，allgather 全量 token 简单但通信/显存大。permute/unpermute 各融一算子（--moe-permute-fusion，仅 alltoall/alltoall_seq）。fb-overlap 与 alltoall-overlap-comm 互斥；fb-overlap 仅 alltoall+ETP=1+EMP>1、流水限 VPP/DualPipeV/无 PP。
- [MoE 负载均衡（Balanced-MoE 路由均衡 + 专家放置 + Router 修正）](moe_load_balance.md)：MindSpeed 训练态 MoE 负载均衡的三套独立机制。balanced-moe-experts（数参互寻）：每层选 N 个热专家（≤本地专家数）把权重广播复制到所有 EP rank，远端热专家 token 改本地副本计算降 All-to-All，热专家用 SharedParamsForHotExperts 共享且运行时 requires_grad=True、梯度异步 reduce 回持有者，靠 trans_hot_expert_group_num 份 EP 组并发广播；依赖 moe-fb-overlap+grouped-gemm+alltoall、ETP=1、Dropless、非二进制对齐，推荐 EP 较大（如≥32）且负载不均，收益需实测。enable-expert-placement（专家迁移）：EMA(θ=0.9) 预测负载、DP allgather 求均值、贪心打散热专家，按 expert_placement_freq=50 触发，细粒度门控用变异系数(std/mean)下降阈值 0.08 跳过低收益层，专家权重 all2all 互换、router 逆映射重排、优化器状态 allgather+all2all 迁移；须分布式优化器+EP>1。fix-router：patch topk_softmax_with_capacity 用 arange%num_experts round-robin 覆盖真实路由尽可能均匀，作基准对照。关键术语：热专家复制 vs 物理迁移 vs 路由覆盖、EMA 负载预测、变异系数门控、与 DeepSeek EPLB 同类不同实现（训练态 vs vLLM-Ascend RL rollout 推理）。
- [MoE 训练优化（TP-Extend-EP / Zero-Memory / GMM 分组矩阵乘 / Shared-Experts）](moe_training_optim.md)：MindSpeed MoE 训练专家层四项优化合页。TP-Extend-EP（--moe-tp-extend-ep）专家层 TP 组不切专家权重改切专家数量，把 TP 域并进 EP，专家 GEMM 跑完整权重、通信由 TP AllGather/ReduceScatter 改 EP All2All，patch TopKRouter.routing→routing_tp_extend_ep（路由后 _split_along_first_dim 沿 token 维切给 TP），需 num_experts%(tp*ep)==0、依赖 permutation-async-comm+grouped-gemm、仅 alltoall_seq，DeepSeek-V2 细粒度小专家提升 10%+。GMM 分组矩阵乘（--moe-grouped-gemm）把多专家变长 token batch 沿 m 轴（group_type=0）按 group_list 拼成一次 npu_gmm/npu_gmm_v2 融合算子，减少多次 launch；显式 drop-pad 仍按容量补零，gemm_fusion 走 GMM+ADD 累加 main_grad；FFN 越大收益越小、TP 大 EP 小收益越大（grok/Mixtral 表）。Zero-Memory（level0/level1）专家段细粒度重计算+重通信+swap 被计算掩盖，节省量约为全 MLP 重计算可节省内存的 70%+/90%+，含共享专家，依赖 alltoall-overlap-comm 或 fb-overlap，resize_(0) 释放激活反向重算。共享专家与路由专家并行计算、结果相加、降参数冗余，shared_expert_overlap 与路由 All2All 重叠。关键术语：tp-extend-ep、grouped-gemm、group_list、group_type、moe-zero-memory、shared-expert、alltoall_seq dispatcher、routing_tp_extend_ep。
- [MindSpeed-MM 数据流水（在线重排 + 异步预处理 + 序列 Packing）](multimodal_data.md)：MindSpeed-MM 数据流水含在线重排、流式异步预处理和序列Packing。固定GBSImageDataBalance按图像patch长度平方装桶，MBSImageDataBalance在microbatch粒度跨DP均衡图像；不能等同于文本LLM算力均衡。Packing按本地buffer逼近共同目标长度，不保证各rank token数相等。异步预处理先DP分片，再并发处理并按sequence_idx恢复顺序。

- [优化器显存优化（Reuse-FP32-Param / 低精度优化器 / LayerZeRO）](optimizer_memory.md)：MindSpeed 三条正交的优化器显存压缩路线。Reuse-FP32-Param：BF16 混合精度下 FP32 master 与 BF16 工作权重数值一一对应（FP32=BF16高16位+Residual低16位），用 reuse_data_ptr 把 FP32 那 4 字节 storage 同时重解释为 BF16/INT32 视图，前向前 view().transpose() 重排分离出 BF16 工作权重、更新前重新交错精确恢复 FP32，魔法常量 TRANSPOSE_BF16_BIT=0x8000 在 INT32 视图加减配合重排，普通分支不处理向偶数舍入的中点，deterministic 分支另行修正；省 sizeof(bf16)×参数量/DP，性能损耗<1%，依赖 bf16、与 enable_zero3 互斥。低精度优化器：动量量化到 FP8(一阶E4M3/二阶E5M2)/HiF8/MXFP8(块量化 block_size=32)、梯度量化到 FP16，QuantAdamW/ScaleMeta 更新时先反量化回 FP32 再算再 requantize，量化仅用于存储；与 swap-optimizer、梯度累加融合互斥，兼容 reuse-fp32-param。LayerZeRO：ZeRO1 域(全DP)存优化器状态、ZeRO3 域(DP子集/机内,zero3_size)运行时 all-gather 重建参数视图用后销毁，hook 驱动梯度/参数双向同步，LayerZeRO3 替换 MegatronModule 封装；多模态 OpenSoraPlan1.3 下 CP=8+LayerZeRO 对比 TP=8+ZeRO1 显存持平、端到端+9.7%。关键术语：master weight、Residual、round-to-nearest-even、quant_states、dequantization、ZeRO1/ZeRO3 通信域、ModuleWrapPolicy。
- [Partial Rollout（长尾 rollout 暂停续跑）](partial_rollout.md)：MindSpeed-RL Partial Rollout 保存未完成 response token，在后续迭代重新 prefill 续推。同步引擎单次生成新增 token 预算为 max_tokens//N，生成循环可多次调用，不保证整轮耗时或 N 轮完成。同步停止看完成组数，异步回调可额外检查 age==N-1 的样本；该检查可关闭，不能据此保证全局 age 上界。末迭代仅扩大取数规模，不保证一次收完。
- [PEFT / LoRA 家族（LoRA / CC-LoRA / QLoRA / LU-LoRA / LoRA-MoE）](peft_lora.md)：MindSpeed-LLM 参数高效微调（PEFT）的 LoRA 家族。LoRA 基线：冻结基座 W₀，只训低秩 A(降维到 rank r)·B(升回输出维)，前向叠 (α/r)·B(Ax)，反向只更新 A,B；旋钮 lora-r(16)/lora-alpha(32)/lora-target-modules(linear_qkv/proj/fc1/fc2)，适配器 FP32，经 peft LoraConfig+get_peft_model 接入。CC-LoRA(--lora-fusion)把低秩分支与 TP/SP 通信异步重叠、按 BS<H/BS≥H 决定 W_combine 合并(ctx.combine)，用 npu_mm_reduce_scatter_base/npu_all_gather_base_mm，与 overlap-param-gather 冲突，Llama2/Mixtral 吞吐 +9~47%。QLoRA(--qlora+--qlora-nf4)把冻结基座量化成 NF4(bitsandbytes Params4bit)、前向实时 dequantize_4bit，仅权重量化、Llama-2-70b 129→35GB，不支持 lora-fusion。LU-LoRA(--lu-lora-final-layer-index)把第 0–k 浅层 LoRA 从反向传播换成 Oja 局部规则(OjasRule，Δ=η(yx−y²w))就地更新、置 requires_grad=False 不入反向图省激活，lr 用 lu-lora-lr(1.25e-6)/lu-lora-lr-ratio。LoRA-MoE(LoraParallelLinearMoE)让低秩适配器适配 TP/EP 专家线性层(Row/Column 切分策略)，MoE 须 alltoall_seq。关键术语：低秩适配、scaling=α/r、NF4、通算重叠、Oja/Hebb 局部学习规则、累积窗口更新、权重合并落 FP16。
- [QAT 量化感知训练（Quantization-Aware Training）](qat_train.md)：QAT 量化感知训练在 MindSpeed 中由 qat-quant-engine 特性实现：前向对权重做伪量化（fake-quant，量化→反量化）注入部署侧量化误差，反向用直通估计（STE，伪量化算子 backward 返回恒等梯度）让梯度落到原始高精度（BF16/FP32 master）权重上；权重高精度存储更新、矩阵乘仍跑 16-bit，训练收敛出对低比特鲁棒、可部署的低比特权重。开关 --qat-scheme 四取值按「位宽×作用域」展开：w4a16-mxfp4 / w8a16-mxfp8（全部线性层+MoE 专家层）与对应 -moe-only（仅专家层），实际进入 QAT 分支时激活保留 16-bit；低精度 GMM 优先路径可跳过专家 QAT，即纯权重量化 W4A16/W8A16。两个伪量化核按 MX 块量化（块大小 32、每块一个 2 的幂 shared exponent 夹到 E8M0 范围±127）：W4A16 元素 MXFP4/E2M1（max_norm=6），W8A16 元素 MXFP8/E4M3（max=448，先 pad 到 32 整数倍再 narrow）。整网线性层通过 patch megatron LinearWithGradAccumulationAndAsyncCommunication 前反向注入（需先开 gradient-accumulation-fusion/async-allreduce/sequence-parallel 之一），MoE 走 GMM experts 路径。与 PTQ 区别在把量化误差提前进优化目标用训练换部署精度；与低精度训练区别在 QAT 只模拟部署量化不真正降低比特计算/存储，而低精度优化器压动量省显存、TE/HiF8 把 GEMM 真降低比特求吞吐。

- [Rollout Rebalance（RL On-Policy rollout 序列级均衡调度引擎）](rollout_rebalance.md)：RLHF 的 rollout（数据生成）阶段面临典型的「木桶效应」：同一批 prompt 生成的 response 长度呈长尾分布，少数极长的生成任务远超普通任务耗时，拖慢整个 DP 组的同步进度；先完成短序列的卡只能空转等待，造成算力浪费。Rollout Rebalance 是 cann-recipes-train 在 vllm-ascend 推理引擎内实现的一套序列级均衡调度引擎：在每个推理 Step 前周期性感知全局 DP 组负载，当检测到组间负载不均满足条件时，主动把单个请求（Sequence，含其 KVCache）在 rank 间迁移、重排，配合 vLLM-Ascend 的多档位编图能力让全局尽快切换到更小 BatchSize 档位（更低 TPOT），从而提升进入长尾状态后的整体推理效率。
