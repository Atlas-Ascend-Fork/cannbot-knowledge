# 优化技术

- [Agent RL 执行范式（asyncLLM 异步生成 + agent_loop 多轮工具调用）](agent_rl_loop.md)：Agent RL 与朴素 RLVR 的根本区别在 rollout 阶段的执行形态：朴素 RL 一个 prompt 一次性生成完整 response 再算 reward；Agent RL 让模型在生成过程中调用外部工具/代码沙盒，把工具返回结果作为新一轮输入继续推理，多轮交互收敛后才算 reward。veRL 通过参考其 recipe/retool 项目，用两个特性把这套执行机制落到昇腾 NPU 上：asyncLLM（异步生成——以 HTTP Server 形态暴露 vLLM 引擎，让每个 prompt 的 request 独立异步推进）+ agent_loop（多轮 agent 循环——ToolAgentLoop 驱动「模型推理 → 检查是否要调工具 → 执行工具 → 结果回灌」状态机直到终止）。
- [Auto-Settings（并行/重计算/内存配置自动搜索）](auto_settings.md)：MindSpeed Auto-Settings (OOTB) via --auto-settings 自动搜索 TP/PP/VPP/DP/ZeRO/CP/EP/mbs/重计算 配置组合, 完全基于 profiling 不假设网络结构, 支持以小仿大. 三档 white/black/mixed. 白盒三阶段: profiling 裁剪配置, 黑盒建模 tensor 切分与算子 shape 与通信效率回归与重计算代价, build_search_spaces stage-1 prune 后逐配置估内存与耗时含重计算求解推荐 top-3. 算子性能知识库 sqlite, 覆盖不足补采. 注入 patch megatron pretrain, OOTB_OPTIMIZER 环境标记分阶段 profiling. 与 --load/--save 互斥.
- [训练入图：torch.compile + Inductor + AutoFuse（Bypass Triton → AutoFuse）](autofuse_train.md)：训练入图（torchtitan-npu）：torch.compile+Inductor 缓解 host-bound，Bypass Triton(npu_bypass_triton_codegen 清空 lowerings/decompositions 使 Aten fallback 原实现)；full-compile 仅 V3/V3.2/V4，其余模型须开 bypass。inductor_npu_ext Codegen 后端经 AutoFuse 从 Inductor IR 生 AscendC kernel。CompileConfig(enable,components model+loss)。坑：NameError _world 用 TORCHINDUCTOR_FX_GRAPH_CACHE=0+AUTOGRAD_CACHE=0 修(禁 FxGraphCache→每次启动全量重编译预热,稳态不受影响)，结构变更后清 /root/.cache 与 /tmp。未来对接 Ascend C AutoFuse/DualPipeV/Async TP。
- [DCP / HF Checkpoint（torchtitan-npu 断点恢复与权重导出）](checkpoint_dcp_hf.md)：torchtitan-npu Checkpoint：DCP（.metadata+*.distcp，存 model+optimizer+lr_scheduler+dataloader+train_state，可跨并行重分片，最适断点续训）vs HF safetensors（仅权重，用于开源初始化/导出）。CheckpointManager.Config + NPU 扩展项 sync_files(True)/drop_page_cache_after_save(False)/empty_cache_after_save(True)/create_seed_checkpoint/enable_first_step_checkpoint/enable_ft_dataloader_checkpoints。tyro CLI（--checkpoint.no-<field>、列表逗号串）。seed checkpoint 单卡 CPU 生成 step-0 供多卡重分片。离线转换 scripts/checkpoint_conversion/convert_to_hf.py。与 Swap Optimizer DCP 集成（pending swap 等待 + CPU cache 保存）。
- [Chunk Loss（分块 LM-Head + 损失，规避全量 logits 显存）](chunk_loss.md)：Chunk Loss 把训练末端 LM-Head 投影 + 交叉熵沿序列维切成 chunk_size 子段，逐段在前向内即时求导后累加损失与梯度，任意时刻只驻留一段 [B,chunk_size,V] 的 logits 而非全量 [B,S,V]，规避大词表(vocab_size≫hidden_size)下 logits 一次性 materialize 的显存峰值。实现为 torch.autograd.Function：用 torch.func.grad_and_value(argnums=(0,1),has_aux=True) 当场算 grad_input/grad_weight，该段计算图即建即销不为 backward 保留，backward 仅按上游标量缩放回放;常驻仅 grad_inputs[B,S,H] 与 grad_weight[V,H]，与 S·V 无关。logits 峰值从 B·S·V·bytes 降到 B·chunk_size·V·bytes(缩减因子 S/chunk_size)。alpha 按全局有效 token 数归一并同值传每段，分段 sum 与不分块 mean 逐位等价、损失曲线不变。LM-Head bias 不支持。接入：MindSpeed-LLM 经 --loss-compute-mode chunk / --loss-chunk-size，gpt_model 与 deepseek4_model 在 TP=1 且 CP=1 时启用([S,B,H]→[B,S,H] transpose);MindSpeed-MM 经 model.json loss_cfg 的 compute_mode(default/chunk/dynamic_chunk)，dynamic_chunk 用 calculate_chunk_size 取不超过 token 预算的最大 2 的幂，FSDP2 路径以 chunkloss_lm_head 替换 DTensor Linear forward。关键术语：fixed_cross_entropy、calculate_lm_loss、grad_and_value、chunk_size、alpha 归一、动态分块。
- [CoC（Communication over Computation：计算通信重叠）](coc.md)：MindSpeed CoC（Communication over Computation，计算通信重叠）把 TP 线性层（Column/RowParallelLinear）前反向中顺序依赖的 matmul 与集合通信沿左矩阵 m 轴切成 2/4/8 片细粒度子任务交织，填掉计算流与通信流的互等空闲。两条实现：Python 脚本流水（COCParallel，compute_first 用于 AllReduce/ReduceScatter、communicate_first 用于 AllGather，--coc-parallel-num；矩阵切片靠 shuffle_as_coc_* 还原布局）与 LCAL 融合算子（--coc-fused-kernel，基于 MTE 单大 Kernel 内重叠，依赖 ATB、仅 TP=8；coc_ops 提供 matmul_all_reduce/matmul_reduce_scatter/all_gather_matmul(_v2)/pure_matmul，matmul_all_reduce 支持 w8A16 伪量化）。总开关 --use-ascend-coc，coc_mode×sequence_parallel 在六种 ModuleType（ORIGINAL/REWRITE/COC × ALL_REDUCE/SEQ_PARALLEL）间选型，tp=1 强制关。约束：m 须为切分数倍数、切分过细易 host bound；与 MC2、unaligned-linear、TP-2D 的 use-ascend-coc 互斥（但 TP-2D 复用同一套 coc_ops 融合算子），当前未适配 MoE，Ascend 950 不支持融合算子。收益：BLOOM 7B +3.20%、176B +5.47%、LLAMA2 70B +7.85%，精度相对误差 2% 内。
- [训练数据效率（EOD Reset + 变长 Flash Attention + 多样本 Packing）](data_packing_varlen.md)：MindSpeed-LLM 用三项协同机制提升训练数据利用率：EOD Reset 在文档边界重置 attention mask 与 position_ids，阻断跨样本注意力；变长 Flash Attention 以 TND 布局和 actual_seq_len 只计算真实 token；多样本 Packing 用贪心装箱减少 padding，并通过 neat-pack 编号重建 position_ids 和序列边界。Packing 发生在预处理阶段，EOD/varlen 在训练运行时保证样本隔离；neat-pack 依赖 pack 与 reset-attention-mask。
- [EPLB（专家并行负载均衡器，MoE 专家动态负载均衡）](eplb.md)：EPLB（Expert Parallelism Load Balancer，专家并行负载均衡器）最早由 DeepSeek 针对大规模 MoE 模型训练中「负载不均」核心痛点推出，是一种动态负载均衡解决方案。MoE 门控网络把样本分配给适配专家，导致专家负载两极分化（热/冷专家分化），且「冷热」身份随数据批次切换动态漂移形成负载热点；在专家并行架构下专家固定分配至 NPU 节点，这种冷热分化直接传导为节点利用率失衡。EPLB 的核心目标是通过智能调度策略消除专家模块及计算节点间的负载差异、最大化 NPU 资源利用率。它提供分层 / 全局两种调度模式，并依托历史负载估计动态调整专家复制与分配方案，快速适配批次切换、领域迁移导致的负载热点漂移。 本页是 EPLB 概念的 canonical 页，依 Qwen3-235B 32K 长序列 RL 训练优化文档 §2.3.2 讲透其现象分析、双模式调度、动态估计机制，以及——最关键的实测诚实结论：在 Qwen3-30B / 235B 加载真实权重的 RL rollout 推理场景下，实测各卡负载本身并无明显不均衡，开启 EPLB 无明显性能收益；只有在人为构造的极端负载不均场景下 EPLB 才带来推理耗时 -17.78% 的提升。即「负载均衡时 EPLB 不带收益，仅极端不均才有效」。MindSpeed-RL workers/eplb 在 RL 训推共卡下做 MoE 专家负载均衡：采集各专家负载→重排/复制热专家→更新 device 映射，与训练态 balanced/placement（moe-load-balance）互补。
- [GRPO / DAPO（组相对策略优化 RL 算法）](grpo_dapo.md)：GRPO（Group Relative Policy Optimization，组相对策略优化）是 DeepSeek-R1 RL 训练采用的核心策略梯度算法：它去掉 PPO 的 critic（价值网络），改用「同一 prompt 采样一组（group）rollout，用组内奖励的相对高低估计 advantage」。少了独立 value model，省去其前反向与显存，特别契合 671B 级大模型的全共卡 RL 部署。本页讲清 GRPO 的 rollout → reward → advantage → 策略更新 数据流与其 on-policy 性质，并把 DAPO 作为同族变体先占位（后续 Qwen3 recipe 会丰富 DAPO 细节）。本页以 deepseek-r1-rl 实践（verl + MindSpeed + vLLM-Ascend，Atlas A3 128 卡）中 GRPO 的真实用法为据。 > 本页是 GRPO/DAPO 算法的 唯一 canonical 页：讲算法机制本身。verl 框架的单/多控制器调度、D2D 数据流加速、训推切换 reshard 等 工程优化 归 verl 与 deepseek-r1-rl，本页只在与 GRPO 算法语义耦合处（如 on-policy 免计算 old_log_prob）引用。 MindSpeed-RL 把 GRPO/DAPO/PPO 做成继承 RayBaseTrainer 的 Ray 共卡 trainer（grpo/dapo/ppo_trainer_hybrid），损失按 (stage,role) 注册 LossFuncFactory、组优势 compute_group_norm_advantage_return 组内 z-score；DAPO kl_loss≡0、PPO 用 CriticWorker+GAE+apply_kl_penalty；DPO 委托 mindspeed_llm 离线 DPOTrainer。
- [分层解耦训练 LDT（Layerwise Disaggregated Training / U 形拆分学习）](ldt_disaggregated_training.md)：LDT（Layerwise Disaggregated Training，分层解耦训练，又称边云协同分布式安全训练）面向「运营商出租算力、企业数据不愿上云」的合规场景：在普通 PP 之上把模型首层与尾层同时部署在企业本地（边侧）、大量中间隐藏层放运营商（云侧），形成 U 形拓扑；边侧读原始样本、只把前向激活与反向梯度发往云侧，原始数据不出园、边侧仅需少量算力跑首尾层。实现在 MindSpeed-LLM（--layerwise-disaggregated-training，Qwen2.5/Qwen3 文本 LLM）与 MindSpeed-MM（model.json 的 patch.layerwise_disaggregated_training，Qwen2.5-VL 多模态；边侧 stage0 落直接吃原始图文的输入侧模块——视觉编码器靠前若干层+图像 patch embedding+text 输入 embedding，尾层为 unembedding/LM-Head，vit 主体按 PP 铺云侧）。二者共用机制：U 形拆分靠 VPP 在 PP stage0 摆首尾两虚拟 stage、跨域激活/梯度 P2P 接力、流水编排掩盖边云通信、支持边云非对称 TP/DP。本质是高级流水并行的 U 形 PP 变体，与异构并行（同卡异并行）互补。关键术语：U 形拓扑、边云协同、VPP stage0、激活/梯度 P2P、vit_pp_layers、非对称 TP/DP。
- [长度感知重采样（Length-Aware Resampler：按历史 response 长度的 rollout 重排）](length_aware_resampler.md)：On-policy RL 训练的 rollout（generate）阶段普遍存在 response 长尾：不同 prompt 的生成长度差异极大，而一个 generation batch 内往往同时混入极长与极短样本。这带来两个直接问题——同批次内短样本很快结束、长样本持续占用推理资源，整体吞吐被少量长尾样本拖慢；某些 batch 的生成长度远高于平均值，放大 step 时间抖动。长度感知重采样（length-aware resampler）是在 verl 的 RL 数据采样路径上新增的 LengthAwareEpochSampler：它利用上一轮 rollout 收集到的 response 长度统计，在下一轮 epoch 开始时对样本顺序重排，把预估长度接近的 prompt 尽量放到邻近 batch，从而在 batch 级别减少长短样本混排。
- [MC2（Matmul + Communication 算子级融合）](mc2.md)：MindSpeed MC2 是昇腾自研的 Matmul+Communication 算子级融合：把 TP+SP 下「matmul 紧挨集合通信、后者输入即前者输出」的强依赖融进单个 torch_npu 融合算子，算子内部把计算/通信切子任务流水互掩，压掉暴露通信。两处应用各有开关。TP 线性层 --use-ascend-mc2：MC2Feature patch Column/RowParallelLinear，列并行前向 npu_all_gather_base_mm(AG+matmul)、行并行前向 npu_mm_reduce_scatter_base(matmul+RS)，权重冻结走 *WithFrozenWeightFunction；须 TP>1 且开 sequence_parallel，与 use_ascend_coc(raise 'mc2 and coc can not be used together')、unaligned_linear、use_pipe_experts、use_nanopipe 互斥，MoE 模型与 Atlas 900 A3 不支持。MoE 层 --moe-alltoall-mc2：EP All2All 与专家 GMM 融合，fc1 npu_alltoallv_gmm、fc2 npu_gmm_alltoallv，dispatcher alltoall(需 ETP=1、dropless)/alltoall_seq(需 TP=1)，与 use_ascend_mc2、moe_alltoall/allgather_overlap_comm、moe_fb_overlap、moe_tp_extend_ep 互斥。MC2 是硬件融合算子、CoC 是框架层软件流水/LCAL 算子，二选一；前提 CANN 8.0.RC2/HDK 24.1.RC2。关键术语：MC2Feature、MoEAlltoAllMC2Feature、hcomm_info、gradient_accumulation_fusion、npu_matmul_add_fp32。
- [MindSpeed-MM 激活显存优化（Chunk-MBS 微批切块 + 异步激活 Offload）](mm_activation_memory.md)：MindSpeed-MM FSDP2 后端的两个互补激活显存优化。异步激活 Offload（enable_activation_offload）以 torch saved_tensors_hooks（async_save_on_cpu 的 _pack_to_cpu/_unpack_from_cpu）把前向保存的 layer 入口 hidden_states 在独立 swap_stream 上 D2H 换出 Host pinned 内存、反向 prefetch 预取 H2D 换回；SwapTensor 拷完才滞后一个 block 做 storage().resize_(0) 释放显存，custom_check_fn 只放行入口激活，末层不换出。Chunk-MBS（enable_chunk_mbs）在一次 FSDP Unshard 后沿 batch_dim 把单 micro-batch 切成 ceil(full/chunk_mbs) 个微块串行前反向再 torch.cat 拼回，把动态激活峰值压到单微块量级；核心收益是允许 micro_batch_size=GBS、grad_acc=1，每次更新每个 block 只 Unshard 一次，省掉梯度累积的重复 AllGather，Qwen3.5 35B 整网约 5% 提速。二者建立在 recompute 之上，pre_fully_shard_apply 固定包装顺序 recompute→offload→chunk_mbs（chunk_mbs 最外层先切片）。长序列换出 self-attn 激活端到端 20%+，FSDP2 短序列腾显存增大 MBS 端到端 60%+。关键术语：saved_tensors_hooks、SwapTensor、OffloadManager、prefetch、batch_dim、chunk_arg_indexs。
- [MoE 通信掩盖（Dispatch 调度 + AllToAll/AllGather Overlap + 前反向跨 MicroBatch 掩盖）](moe_comm_overlap.md)：MindSpeed 把 MoE 在 EP 下的 dispatch/combine 通信瓶颈分三档掩盖。dispatcher 内部异步（--moe-permutation-async-comm：alltoall 走 repeat_interleave 新流并行+逐专家通算并行，allgather 走 gather/scatter→index/index_put 替换+三路 AllGather async）；层内 overlap（--moe-alltoall-overlap-comm / --moe-allgather-overlap-comm 把 MoELayer 重写成 autograd.Function，前向异步通信让专家计算掩盖 dispatch/combine、反向子图切分通算并行，+10%，带共享专家自动开 shared-expert-overlap 再+4%）；跨 microbatch 前反向掩盖（--moe-fb-overlap：单层拆 Attention/Dispatch/MLP/Combine 四阶段，用无依赖的另一 microbatch 计算掩盖 A2A，配 WeightGradStore 做 dw/dx 分离，实现 1F1B 阶段 A2A 100%、warmup/cooldown 50% 掩盖，是 DualPipeV 全掩盖机制本体）。dispatch=token_permute1/All2All-v/token_permute2，combine 对称。两种 dispatcher 取舍：alltoall 通信量小但需 device-host 同步，allgather 全量 token 简单但通信/显存大。permute/unpermute 各融一算子（--moe-permute-fusion，仅 alltoall/alltoall_seq）。fb-overlap 与 alltoall-overlap-comm 互斥；fb-overlap 仅 alltoall+ETP=1+EMP>1、流水限 VPP/DualPipeV/无 PP。
- [MoE 负载均衡（Balanced-MoE 路由均衡 + 专家放置 + Router 修正）](moe_load_balance.md)：MindSpeed 训练态 MoE 负载均衡的三套独立机制。balanced-moe-experts（数参互寻）：每层选 N 个热专家（≤本地专家数）把权重广播复制到所有 EP rank，远端热专家 token 改本地副本计算降 All-to-All，热专家用 SharedParamsForHotExperts 共享且 requires_grad_(False)、梯度异步 reduce 回持有者，靠 trans_hot_expert_group_num 份 EP 组并发广播；依赖 moe-fb-overlap+grouped-gemm+alltoall、ETP=1、Dropless、非二进制对齐，EP≥32 且不均才有收益。enable-expert-placement（专家迁移）：EMA(θ=0.9) 预测负载、DP allgather 求均值、贪心打散热专家，按 expert_placement_freq=50 触发，细粒度门控用变异系数(std/mean)下降阈值 0.08 跳过低收益层，专家权重 all2all 互换、router 逆映射重排、优化器状态 allgather+all2all 迁移；须分布式优化器+EP>1。fix-router：patch topk_softmax_with_capacity 用 arange%num_experts round-robin 覆盖真实路由强制均匀，作基准对照。关键术语：热专家复制 vs 物理迁移 vs 路由覆盖、EMA 负载预测、变异系数门控、与 DeepSeek EPLB 同类不同实现（训练态 vs vLLM-Ascend RL rollout 推理）。
- [MoE 训练优化（TP-Extend-EP / Zero-Memory / GMM 分组矩阵乘 / Shared-Experts）](moe_training_optim.md)：MindSpeed MoE 训练专家层四项优化合页。TP-Extend-EP（--moe-tp-extend-ep）专家层 TP 组不切专家权重改切专家数量，把 TP 域并进 EP，专家 GEMM 跑完整权重、通信由 TP AllGather/ReduceScatter 改 EP All2All，patch TopKRouter.routing→routing_tp_extend_ep（路由后 _split_along_first_dim 沿 token 维切给 TP），需 num_experts%(tp*ep)==0、依赖 permutation-async-comm+grouped-gemm、仅 alltoall_seq，DeepSeek-V2 细粒度小专家提升 10%+。GMM 分组矩阵乘（--moe-grouped-gemm）把多专家变长 token batch 沿 m 轴（group_type=0）按 group_list 拼成一次 npu_gmm/npu_gmm_v2 融合算子，避免多次 launch 与 drop-pad 补零，gemm_fusion 走 GMM+ADD 累加 main_grad；FFN 越大收益越小、TP 大 EP 小收益越大（grok/Mixtral 表）。Zero-Memory（level0/level1）专家段细粒度重计算+重通信+swap 被计算掩盖，省内存 70%+/90%+，含共享专家，依赖 alltoall-overlap-comm 或 fb-overlap，resize_(0) 释放激活反向重算。共享专家与路由专家并行计算、结果相加、降参数冗余，shared_expert_overlap 与路由 All2All 重叠。关键术语：tp-extend-ep、grouped-gemm、group_list、group_type、moe-zero-memory、shared-expert、alltoall_seq dispatcher、routing_tp_extend_ep。

- [Partial Rollout（长尾 rollout 暂停续跑）](partial_rollout.md)：MindSpeed-RL 的 Partial Rollout：同步 on-policy RL 一轮 rollout 必须等整批生成完毕才能进 ref/update，长尾长序列拖死同步点。机制是给单步生成设 token 预算上限——开关 partial_rollout_max_split=N（N>1 启用，单步预算 max_tokens//N），到达上限仍未结束（未遇 eod、未触 max_model_len/总 max_tokens）的长样本就地暂停，把已生成 token 序列连同 age/rollout_completed 状态存回 TransferDock，下一轮把 prompt+已生成 token 重新 prefill 续推，跨多轮分段推完。停止条件为「完成组数≥GBS_train（组内 n 条样本全完成才算组完成）」，下游 ref/update 经 global_ready_mask 只取整组完成样本，actor_rollout 自身反复续推未完成样本。clear 时 age+1 并 sort_every_n_samples_by_age 按 age 降序重排，实现优先续推老样本的混合采样。续推引入有界 off-policy（age 上界 N-1），require_max_age_all_finished 默认 True 强制踩 max_age 线样本本迭代收完保收敛。异步引擎用 stop_singal_func/get_update_ready 动态中断。与 Rollout Rebalance 正交：partial rollout 在时间/迭代维截断续跑、跨迭代靠重新 prefill 恢复（不持有 KV），rollout rebalance 在空间/rank 维带 KVCache 搬迁重排不截断。约束：须 guarantee_order=False、须提供 GBS_train、暂不支持 VPP。关键符号 partial_rollout_max_split、max_age、rollout_completed、age、global_ready_mask、find_all_consumed_n_samples_groups、get_update_ready、sync/async_generate_process。

- [RL 训推切换（Train/Rollout Switch：reshard / offload / D2D）](train_rollout_switch.md)：大模型 on-policy RL 训练中，同一组卡要在「训练态」（actor update / ref log_prob，由 Megatron+MindSpeed 承载）与「推理态」（rollout/generate，由 vLLM+vLLM-Ascend 承载）之间反复交替——这就是训推切换。两态对同一份 671B 权重采用不同并行策略：训练侧 TP4EP8PP8，推理侧 DP64TP2EP128（真实权重场景）甚至 DP128TP2EP256（随机权重场景）。每完成一次训练更新，新权重必须先重新切分（reshard）成推理布局再喂给 rollout；又因本实践选了 ActorRolloutRef 三模型全共卡部署（分时复用计算资源），切换时还要把上一态模型 offload 到 host、把下一态模型 onload 到 device。本页是 RL 训推切换的 canonical 页，讲清三件事：reshard 优化（训→推权重重切分，［doc §4.1］(#reshard-优化训推权重重切分)）、offload 优化（训练态权重/KV 显存卸载，［doc §4.2］(#offload-优化全共卡分时复用显存)），以及任务间训推权重 D2D 高速数据传输（device 间直传消除 host 中转，［doc §3.2］(#d2d-数据传输任务间张量直传)）。 MindSpeed-RL 原生侧：resharding（MegatronShardingManager）做训练态 Megatron 切分↔推理态 vLLM 切分的权重重切，offload 在训练后卸载权重/优化器降峰值（base_worker onload/offload）。

- [TransferDock（RL 数据面：训推各 worker 间样本调度交换）](transferdock_data_scheduling.md)：TransferDock 是 MindSpeed-RL 在 rollout、reward、advantage、reference 与 actor worker 之间交换样本的数据面。GRPOTransferDock 以列存保存 prompts、responses、rewards、log-prob 和 advantages，用数据就绪矩阵与各 consumer 独立消费位图驱动异步取放；不足一批时等待，满足条件后可随机或按序列长度均衡采样。DAPO 通过双 dock 过滤零方差组，partial-rollout 复用同一状态结构处理续推与逐出。
- [TTP 高可用容错（故障检测 + 状态 Dump + 训练恢复）](ttp_high_availability.md)：TTP（Training Tolerance Platform，源自 MindIO TTP）是 MindSpeed 在 verl RL 训练栈上的高可用容错机制，降低大规模长训练因单卡硬件/通信故障导致整任务作废的算力损失。架构为 rank-0 Controller（服务端）+ 每卡 Processor（worker 端）的中心化协调：HeartbeatManager/HeartbeatChecker 按 interval/timeout/max-missed 检测心跳超时，ttp_exception_handler 装饰器捕获在途 UCE/HBM/HCCL/NCCL 异常并自报 ABNORMAL；_on_worker_fault 先 WAIT_RELEASE 暂停全员，经 choose_rank_inner_rl 选一组健康副本（REPLICA_NUM=2，DP-CP/DP-EP 拓扑）下发 DUMP_REQUEST；tft_save_callback 用 dump_group 替换默认通信域、apply_dump_patches 打 6 个 Megatron checkpoint 补丁绕过一致性校验，从单份副本写出含 model/optimizer/extra 的完整分布式 checkpoint（global_step=step//ppo_epochs）；成功后 Controller 发 EXIT、各 rank os._exit，由外部脚本从 dump 目录续训。开关 --ttp-enabled，经 MindSpeedFeature optimization_level=2 + verl repatch 两阶段生效。关键术语：Controller/Processor、heartbeat、WorkerStatus、replica group、dump_group、tft_save_callback、apply_dump_patches。
- [Virtual Optimizer（优化器显存虚拟化）](virtual_optimizer.md)：Virtual Optimizer（torchtitan-npu）：基于 Ascend NPU 原生虚拟内存映射卸载 AdamW 一二阶动量 exp_avg/exp_avg_sq——内存在 Host、地址可映射 Device 仍可参与多数 NPU 算子，'不改训练代码'省显存。核心 torch_npu.empty_with_swapped_memory 替代 torch.zeros_like 的 NPU 显存分配。派生自 MindSpeed VirtualOptimizer，要求 NPU 驱动 25.5.2+。配置 OptimizerConfig.virtual_optimizer(bool)/virtual_optimizer_size('all' 卸全部)。与 swap_optimizer 互斥。区别 swap-optimizer（三流水手动 H2D/D2H+resize_(0)）：virtual 是地址映射、对代码透明。V4 285B 续训实采 virtual_optimizer=true。 MindSpeed 原生 VirtualOptimizerFeature 用 torch_npu.empty_with_swapped_memory 把 AdamW 动量 exp_avg/exp_avg_sq 放 Host、按 PP stage 逐张量字节预算（--virtual-optimizer all/标量/list）映射 Device，与 fused_ema_adamw 互斥。
