# X146: CV 环墙归属三步探针：字节不是约束

## 核心思路
CV 融合环（AIC 产中间量 S → GM ring → AIV 归约）常被误判为"中间量往返带宽墙"，因为不同 shape 的 `(S 字节 × 2 / 墙钟)` 会诡异地落在同一条常数带宽线上。那是**结果不是约束**：shape 是按总算力/总字节配平的，任何常量成本都会被读成常量带宽。

判定办法是**直接删字节**，用三个同窗口探针：

1. **探针 A：完全不发 Fixpipe**（中间量写字节从 N 字节/元素降到 0）。若墙在写带宽，应显著变快。
2. **探针 B：只写偶数 chunk**（写字节减半）。
3. **探针 C：AIV 侧环读砍掉大部分**（若已有实现）。
4. **噪声带**：对照组必须同设备同窗口，并用同一二进制做 A/A，得到测量噪声带。没有噪声带的 A/B 不足以判定小收益。

若三条探针的收益合计很小，则"字节墙"是伪墙；此时更可能的墙是两条并行链的平衡点（需用同时削减两条链的阳性对照确认）：

- AIC 链：L1→L0A/L0B + Mmad；
- AIV 链：vector 发射与归约。

单侧削减任何一条都不赚，只有**同时**降低两条链的工作量才可能移动墙。

## 适用场景
- A2/910B 上的 CV 融合 attention / indexer / topk 类算子（AIC 出中间量、AIV 消费）。
- per-iteration 成本已确认恒定（见 X141）；否则先做 X141 的判据。

## 实现要点
1. 三个探针都要保持其它条件不变（同 shape、同调度、同编译选项），否则字节收益会被调度漂移淹没。
2. 对照组除了 A/A 噪声带，还应加入"task 数 ×2/×0.5""ring 深度加深""每 task 减少若干同步"等非字节变量。若这些也都不单调，进一步支持"墙是两条链的平衡点"。
3. 观察 ring 的**预跑字节数**（深度 × 槽大小）：它可能是少数单调相关量。若加深已过平台期，继续加深无效、变浅则立罚。
4. 行动结论：不要只在"少写字节/少发指令/加深环"上花轮次；要同时削减 AIC 链的 MTE1 字节与 AIV 链的向量发射次数（例如把多次 Axpy 换成一次 Mul + 一次 WholeReduceSum 的转置布局）。

## 验证方法
- 同设备同窗口、交错 A/B、正反序至少两轮。
- 每个探针单独跑，不要一次叠多个改动。
- 记录 A/A 噪声带；小于噪声带的收益判为中性。
- 若探针 A 的收益很大，说明确实是写带宽墙，应转向提高写率或减少中间量本身。
