# X183: 自适应回退路径必须与被回退分支逐字对齐

## 现象

为了吃满大 shape 的收益，内核常做成“快路径 + 回调路径”的自适应结构：例如 L1 容量允许时用 3 槽 K 预取，容量不足时回退到 2 槽同步语义。

一次看似无害的重构把两条路径的公共代码合并后：

- 2 槽分支的 K 下标从原来的 `t & 1` 变成运行期 `t % k_slots`；
- 原本只在 3 槽路径上成立的 P 载入同步 flag，被无条件平移到公共位置。

结果：快路径正常，回退路径“能跑通、精度也对”，但某个回退 case 从 1139us 变成 710us 的水平直接丢掉 21%；几何平均只反映 1-2%，很容易被当成噪声放过。

## 根因

- 自适应路径的“公共化重构”改变了回退分支的同步语义和下标表达式，但正确性测试只验证数值，不验证**时序等价**。
- 回退分支通常只覆盖少数 shape；单 case 的严重回归在几何平均里被稀释。
- “能跑通”只证明依赖关系没有死锁，不证明没有多等一拍、没有把可重叠的搬运串行化。

## 判据

1. **逐字对齐检查**：回退分支必须与重构前的原分支在以下四件事上完全一致：
   - slot 下标表达式（例如 `t & 1`，不是运行期 `t % k_slots`）；
   - flag id 的分配与复用；
   - `SetFlag/WaitFlag` 的条数与先后顺序；
   - 尾部 drain / PRELAUNCH 的次数。
2. **分支强制测试矩阵**：构造能强制走回退分支的 shape（例如刚好超出 L1 容量的 head_block/dim），对每个分支单独测墙钟，而不是只测混合 case。
3. **与重构前二进制对比**：回退分支的收益/回退要相对重构前版本测，不要只相对当前 champion。
4. 如果无法把回退分支恢复成逐字等价物，宁可对不满足条件的 shape 关闭快路径、走独立的老内核，也不要在共享代码里发一个降级版回退。

## 实现要点

1. 快/慢路径用编译期模板或独立函数分派，不要用运行期 `if` 把两套同步协议揉进同一段热循环。
2. 回退分支保留原实现的 slot 下标、flag 序列和 drain 次数；公共化只允许发生在纯计算/常量部分。
3. 在测试矩阵中显式标注“本 case 走 2 槽/3 槽”，避免只报总 geomean。
4. 每次改快路径后，回退分支至少跑一个固定 case 的墙钟回归。

## 边界

- 只在“快路径存在回退”时适用；单一路径的内核不需要。
- 回退分支的 shape 很少时，单 case 回归容易被 geomean 掩盖，必须强制单测。
- 如果回退分支本身已被新硬件淘汰，可以直接删除，而不是强行对齐。

## 实测证据

- 在一个 paged MLA decode 内核中，3 槽快路径重构后，2 槽回退分支的某个长序列 case 从 1139us 恢复到 710us（1.60x），几何平均 13.61→13.86x（+1.8%）。
- 回归原因是回退分支的 K 下标被改成运行期 `%k_slots`，且 P 载入 flag 被无条件平移到公共位置；快路径不受影响，因此只测总 geomean 时几乎看不出来。
