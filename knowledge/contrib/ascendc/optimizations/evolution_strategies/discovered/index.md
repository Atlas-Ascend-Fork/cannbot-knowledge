# 进化发现策略（X 系列）

AscendC 算子性能进化运行期自动发现的策略记录，117 条按发现编号平铺（原 evolution-strategies `references/discovered/`）。X 系列是单算子实战发现（draft），晋升后的精选卡见同级 `cards/` 目录（P/D/A/R 策略卡）；已晋升条目（X17-X20 → P128-P131）标记 deprecated 并指向继任卡。

- [X1: Inline Target Capture](disc_x1.md)：在 Online Softmax 的前向流式扫描过程中，当处理到包含目标索引的 tile 时，立即捕获目标元素的原始值（如 target logit），避免在扫描完成后再用一次独立的 DataCopy 回读目标 tile。
- [X2: 大张量驻留 Device、仅小索引过总线](disc_x2.md)：host 协调的 gather/scatter/routing 类算子应让大张量驻留 device，仅把小索引张量过总线交给 CPU 排序，再由 NPU kernel 按索引搬运；避免大数据张量 device→host→device 往返。
- [X3: 端到端 dtype 直传下沉 (End-to-End Dtype Passthrough)](disc_x3.md)：多 dtype elementwise/foreach 算子应把 dtype 转换从 wrapper 下沉到 kernel：DMA 按原 dtype 直传，UB 内 Cast 升 fp32 计算后再 Cast 回原 dtype；避免 wrapper 的全量升/降 cast 与 kernel 的 fp32 读写放大 HBM 流量。
- [X4: Concat-Fused Strided DMA + Two-Level Skv Reduction](disc_x4.md)：decode/MTP attention（单行/小批量 Q、长 Skv）受 DMA launch latency/per-key 同步支配时，把 concat 折叠进 K-tile DMA、Skv 用两级向量归约、online softmax 单遍化，把 per-key DMA/sync 从 O(Skv) 降到 O(tiles)。
- [X5: GQA-Decode GEMV->GEMM (M=N_q)](disc_x5.md)：GQA/MLA decode 或 MTP 在 N_kv=1（或 N_kv≪N_q）时，把 decode 注意力的 M 维取为 N_q 而非 S，使 QK^T 与 PV 都成为稠密 cube GEMM，替代 N_q 条独立归约型 GEMV。
- [X6: Merge Partial + Reduce Kernel for Split-KV FlashDecode](disc_x6.md)：Split-KV FlashDecode 的 partial+reduce 两阶段在 reduce 计算量小、launch 头开销占比高时，可把最后一次归约内联到 partial kernel，由指定 block 完成状态合并并写回，从而合并为一次 launch。
- [X7: Token Block Size (TB) Tuning for Pure-Vector Attention](disc_x7.md)：纯 AIV 实现的 decode/quantized-KV attention 中，token block（TB）决定标量循环占比、向量利用率和 UB 压力；在 UB 预算内动态增大 TB（尤其 MSE 路径）可降低 scalar bound。
- [X8: Host-Side Precomputation of Constant Offset Tables](disc_x8.md)：Init 阶段仅由超参数决定的常量表（量化 offset、gather 索引、stride 修正、RoPE 频率等）移到 host/Tiling 预计算，device 只做一次 DataCopy，消除每次 launch 的标量循环与 UB 占用。
- [X9: Deferred Scaling — 反量化仿射结构的代数重排（延迟缩放）](disc_x9.md)：反量化 decode 中 per-token/per-row 的 Muls/Adds 若只被归约或加权累加消费，可利用分配律把缩放推迟到归约后的低维量上，消掉大量 D-wide 向量指令。
- [X10: 设备侧分组调度 + NZ plane 权重缓存（Grouped Matmul Cube 化）](disc_x10.md)：Grouped matmul（group_list 为 device 端 cumsum）的 Cube 化不要在 host 侧展开分组计划：每个 AIC 核在设备侧自行从 group_list 构建本核的 (group, M-block) 调度（empty group 自然跳过，无 host 同步）；每个专家的 weight 以 NZ plane 形式作为静态缓存放入 GM workspace，tile 排序采用 m-fastest，使多核共享同一 weight strip，weight 流量按 ceil(m_g/baseM) 量级下降；epilogue 放独立 AIV kernel 全向量流水完成。
- [X11: ND-drain + L0B 喂给率驱动 baseM 扩升（量化 Matmul Cube 利用率修复）](disc_x11.md)：c220 (910B) 上 MatmulImpl 的多 fragment NZ drain 存在芯片缺陷，而 ND int32 多行 drain 正确——Cube 输出格式应路由到 ND；配合 L0B 喂给率驱动的 baseM 扩升，可恢复量化 Matmul 的 Cube 利用率。
- [X12: 量化 GEMV 纯 VEC 流式路径（小 M 分流）](disc_x12.md)：对 weight-quant matmul（y = x @ ((w+o)*s) + b，w 为 int8），当 M 小（1-8，GEMV 类）时放弃 cube，走纯 VEC streaming：代数重构把 per-N scale 提出 K 循环，int8 weight 仅 cast 到 half 并用 mixed-precision Axpy 直接累加 fp32；大 M 受 VEC 指令发射延迟上限约束，必须分流到 cube 路径。
- [X13: Shape 自适应双引擎分流 (M-Threshold Hybrid Routing)](disc_x13.md)：当单一执行引擎（cube / vector）无法覆盖全部输入 shape 时，在 host 侧（op plugin）按 shape 特征（如 M 维度）路由到两条完整的独立 kernel 路径：小 M（GEMV 类）走纯 VEC streaming 内核吃带宽极限，中大 M 走 cube 内核吃 MAC 吞吐；分发阈值按边界 shape 的设备时间校准后固化。
- [X14: Mix-Kernel 跨核生产者/消费者融合 (Pairwise AIV-Producer/AIC-Consumer Fusion)](disc_x14.md)：当流水线中存在独立的前置 VEC pass（如 dequant/cast），且硬件融合路径不可用时，将该 VEC pass 与 cube kernel 融合进单个 mix kernel：AIC ci 与其配对 AIV（2ci, 2ci+1）组成生产者/消费者对，AIV 按 AIC 的消费顺序生产中间数据到 write-once GM workspace，用 GM flag 协议同步，实现跨核软件流水，launch 数减 1 且 cast 与 cube 计算重叠。
- [X15: 递归拆分-并行投影外提 (Recurrent Split: Hoist Parallel Projection)](disc_x15.md)：对 RNN/LSTM/GRU/scan 类含串行循环的算子，将计算拆为"非递归部分"与"严格串行部分"：非递归投影（如全部时间步的 x@W_ih）与循环无关，可一次性合并为单个大 GEMM，外提到 host 侧调用框架/库的高性能 GEMM（自动走 Cube 单元）；自定义内核只保留严格串行的递归残差（如每步 h@W_hh + 门激活 + 状态更新），并将递归权重（W_hh）在 UB 常驻、超规格时回退分块。串行链上的计算量从 O(seq×(I+H)×4H) 降到 O(seq×H×4H)，且大头走了 Cube。
- [X16: 循环算子 H-slice 多核切分 (Recurrent H-Slice Multi-Core Split)](disc_x16.md)：对 LSTM/GRU/RNN/scan 类含串行循环的算子，时间维不可并行，并行度只能从 batch×hidden 中榨取；小 batch 时将 hidden 维度切分到多个 AIV 核，各核独占隐藏单元及对应门控列，递归权重切片 UB 常驻，c/h 状态分片独立更新，零核间通信。
- [X21: 910B2C Cube 化平台纪律 + 数据驱动 Kahan 精度路由](disc_x21.md)：在 910B2C（DAV_2201）上把 AIV 算子 Cube 化时，正确性杀手往往不是算法而是平台纪律：若干平台陷阱会静默产出垃圾或 hang，且 CANN 不报错。
- [X22: Depthwise 直接卷积（绕过 im2col+GEMM）](disc_x22.md)：depthwise（groups==Cin, cig==1）卷积在 im2col+GEMM 流水线中极低效：GEMM 退化为 M×Kpad @ Kpad×1 逐通道点积，fp16 hi/lo 分裂使 Cube 工作量约 3 倍，且 4 阶段流水线物化 4 个 GM workspace。
- [X23: Batched Spatial 全宽向量化 + 编译器驱动标量预取](disc_x23.md)：滑窗卷积/相关类算子（kw==1、W 维逐点 FMA）若按「逐输出位置」切任务，每个 Axpy 只利用部分向量 lane，且每个 (co,tap) 一次权重 GetValue() 的 S-pipe 标量读串行化，是大 K 用例的性能杀手。
- [X24: AIC_ONLY 任务类型压设备 launch 地板（固定开销主导算子）](disc_x24.md)：微小 shape、固定开销主导的算子（kernel 时间与 shape 几乎无关，cube_util 极低、标量占比高）其设备时间大部分是「每 AIC 调度启动」的固定开销，不是计算。
- [X25: 向量权重广播（Brcb + MulAddDst）替代 S-pipe 标量读](disc_x25.md)：滑窗卷积/小 GEMM 的瓶颈常是每 (co,tap) 一次权重 GetValue()（S-pipe UB→标量寄存器读，延迟高且依赖链串行）。
- [X26: Col2im Tap-Batch 事件化（散射类 per-tap 流水重构）](disc_x26.md)：col2im/gather 散射类算子逐输出行按 (kh,kw) tap 循环时，基线每 tap 一次 PipeBarrier<PIPE_ALL> 会同时排空 MTE2/MTE3/V 三管道，把 MTE2 加载与 V 计算完全串行化；改为 tap-batch 事件化可把每行 barrier 降到常数次。
- [X27: transpose-on-load 分形加载 + 全 shape 手动 mmad 二维 tile 网格（免 host 预转置）](disc_x27.md)：在手动 mmad + host B 预转置 + MatmulImpl fallback 方案基础上做两个关键替代，把手动 mmad 的可覆盖范围从单 tile 微小 shape 扩展到全 shape 覆盖、不依赖 fallback。
- [X28: 小 S Prefill FA 自适应 KV Chunk 粒度](disc_x28.md)：FA/GQA prefill 的 host 侧常把 kvPad = align_up(S, nChunk)，nChunk 取 cube 列分形友好的 256(fp16)/128(fp32) 大块。
- [X29: Shift-Free Tap-Comb 稠密直算（stride=1 反卷积消 Gather）](disc_x29.md)：对 stride==1 的反卷积/ConvTranspose2d，利用数学恒等变换把转置卷积化为零填充输入 + 180° 翻核的标准 cross-correlation，再用 shift-free tap-comb 稠密 Axpy 取代逐 tap Gather 与 col2im 散射。
- [X30: 头维-minor Q 布局免 heads-merge kernel（token-major 折叠 head 合并）](disc_x30.md)：多头注意力的 heads-merge kernel（O[BHS, hdPad] → Om[M, HhdPad] 转置+cast）本质是行序 (b,h,s) → (b,s,h) 的 shuffle，纯搬运。
- [X31: bounded logits softmax 去 max 减法（平移不变 + 数值有界时跳过 max-trick）](disc_x31.md)：softmax(z)=softmax(z-max(z)) 的平移不变性使 max 减法仅用于防 exp 溢出；当 logits 上界可证明且远低于溢出阈值时，可删除 WholeReduceMax+Brcb 广播+Sub，直接缩放后 Exp，并配合行求和 chunk 化与树形合并降低 barrier。
- [X32: fp32 投影 GEMM 的精度安全替代与真实瓶颈（MTE2-bound 修正）](disc_x32.md)：fp32 投影 GEMM 可能主导 GQA prefill 耗时，但 profiling 若显示 GM→L1 搬运饱和，则它实际是 MTE2-bound 而非 compute-bound；此时 bf16/fp16 hi/lo 3/4-GEMM 提升的 cube 吞吐不会转化为端到端收益，正确方向是增大搬运块、L1 双缓冲与消除 GM 往返，并受 L0C/L0B 容量约束。
- [X33: attention workspace-ring 握手延迟 bound 的 Q-tile 放大 + 投影 GEMM group A-reuse](disc_x33.md)：跨核 AIC↔AIV workspace-ring 流水的 attention 在管道利用率低、耗时高时受握手延迟约束；按任务放大 Q-tile 可减少握手次数，投影 GEMM 在 MTE2-bound 时可用 by-group A-reuse 降低 A 侧 over-read。两者的前提分别是 L0C/L1 容量与瓶颈判定。
- [Col2im 相位化行归约（stride-s 反卷积散射重构，GEMM 中间矩阵上向量化）](disc_x34.md)：反卷积 fallback（GEMM + col2im）的瓶颈常不是 im2col 带宽，而是 col2im 散射（逐输出行 undersize 加载 + Gather + parity 过滤 + PIPE_ALL 屏障）。将 col2im 改为按输出相位分解：每相位对相位内 G 行做全长对齐向量 Add 归约，列移位经 DataCopyPad src offset 与 left/rightPadding 落地，最后行粒度批量写回。
- [X35: MatmulImpl Host Fixed-Overhead Elimination + Coverage-Aware Serial Multi-Tile](disc_x35.md)：MatmulImpl 高阶 API 的每次调用含固定 host/device 开销：GetTiling 主机计算、TilingHeader 阻塞 H2D copy、workspace 清零 kernel 与 workspace 分配。对小到中 shape（输出规模 ≤ 4×L0C），这些 launch-bound 开销可占运行时的绝大部分，需通过 workspace 免零初始化、per-shape tiling 缓存、workspace 复用与核内串行多 tile 遍历消除。
- [X36: Zero-Host-Padding AIV Small-Matmul（消除 host 零填充的 Vector 精确小 matmul）](disc_x36.md)：matmul 系算子在 host 侧常把 M/N/K 零填充到 Cube 对齐粒度，constant_pad_nd 会发射独立的 pad kernel，其时间被计入算子总时长。对小 shape，pad kernel 可能完全主导评测指标；改为 host 不下发 pad、由 AIV 精确计算原始 shape，并做 32B 对齐行展开与多核切分，可消除该固定开销。
- [X37: FP32-via-FP16 Hi/Lo 4-GEMM（fp32 精度要求的 Cube 重构路径）](disc_x37.md)：Cube 的 Mmad 不直接消费 fp32 输入。要求 fp32 allclose 时，bf16 hi/lo 3-GEMM 的误差不够；改用 fp16 hi/lo 拆分并保留 lo@lo 项的 4 次 fp16 Mmad，可在 fp32 L0C 累加下把误差压到约 1e-5 量级，代价是 4 倍 cube FLOPs 与额外的 split 预 pass。
- [X38: GM-Workspace-Ring KV-tile 宽度缩放 + Host 批量权重打包](disc_x38.md)：FA 算子若采用 GM workspace ring 队列而非 L1 常驻，每 KV tile 会产生固定次数的 GM 往返、跨核握手与标量开销；放大 KV tile 宽度可直接减半往返次数并增大 cube GEMM 尺寸。融合 QKV/out 投影且 heads 多时，host 侧 per-head 权重打包可批量化为 cat + pad + reshape + 单次 strided copy。
- [X39: host 侧全写 workspace 免零初始化（at::zeros → at::empty）](disc_x39.md)：算子 host 侧每次 forward 分配大块 workspace 或输出 buffer 时，若 kernel 会写满全部区域（无读前未写），可用 at::empty 替代 at::zeros，消除每次调用对数百 MB~GB 级内存的 memset。必须逐区域审计；存在 padded/未写行被后续读取时禁用。
- [X40: MatmulApiTiling 单核陷阱 + singleN/singleM hint 前置多核化（totalBlock=1 → per-M 自适应 24 blocks）](disc_x40.md)：小 shape GEMM 用 MatmulApiTiling::GetTiling(TCubeTiling&) 时，API 会为整块能塞进单核的 shape 返回 singleCoreM=M、singleCoreN=N（totalBlock=1），使 GEMM 只跑在 1 个 AIC 核上。修复是在 GetTiling 之前设置 singleN/singleM hint，让 API 自洽重排依赖字段；严禁在 GetTiling 之后手改。
- [X41: singleCoreN 对齐 baseN 倍数（量化 Matmul L0B 填充利用率修复）](disc_x41.md)：量化 Matmul 大 shape 的 AIC 瓶颈可能不是 MAC，而是 L0B-fill:mad 比与 L2→L1 喂给率；当 singleCoreN 不是 baseN 整数倍时，尾部 masked partial tile 浪费 L0B 填充，将 singleCoreN 对齐到 baseN 倍数可修复。
- [X42: 路由选中分支消除（one-hot selector 预计算 → 只算被选中分支）](disc_x42.md)：当算子在主计算之前由廉价 router/selector 产生 one-hot 选择向量（如 MoE expert router、条件计算），且输出只取被选中分支时，按 batch/token 分发任务、只执行被选中分支，可跳过其余分支的完整计算链。
- [X43: Cube 输出 FixPipe 融合 Epilogue（C_TYPE=输出 dtype + SetBias，acc 不落 GM）](disc_x43.md)：Matmul 流水最后一段是 L0C → FixPipe → GM 的输出通路；将独立 epilogue（bias-add/cast/requant）下沉进 FixPipe：C_TYPE 设为输出 dtype 并 EnableBias/SetBias，使 fp32 acc 不落 GM，消除 epilogue kernel launch 与 acc 的 GM 往返。
- [X44: fp32 Cube mmad 全量重写替代向量模拟 matmul（SetHF32(false) 全精度）](disc_x44.md)：若内核用 AIV 向量标量模拟 matmul（16×16 tile 逐点 GetValue 累加），会完全绕过 Cube 矩阵单元，成为数量级性能瓶颈；改用 Matmul 高阶 API 走 fp32 Cube，并用 SetHF32(false) 关闭 HF32 截断获得全精度。
- [X45: 融合管线 GM 往返消除（split-into-GEMM-load + B 侧 weight-stationary + attention 软件流水）](disc_x45.md)：大 fp32 投影 GEMM 可能受 MTE2(GM→L1) 喂给率限制（cube/fixpipe idle）；融合管线中每个中间张量落 GM 再读回都是纯浪费，可从 A 侧 split-into-GEMM-load、B 侧 weight-stationary 混合网格、attention 软件流水三个方向消除 GM 往返。
- [原生 fp32 Cube 单 pass 投影/attention 替代 fp16 hi/lo 3-mmad（对齐 PyTorch fp32 参考路径）](disc_x46.md)：融合 GQA prefill 的 fp32 投影 GEMM 若用 fp16 hi/lo 3-mmad（3 次 fp16 mmad/k-step + split 双平面 GM 往返），计算量和数据通路都高于原生 fp32 matmul；改为原生 fp32 cube 单 pass（1 mmad/k-step）后 mmad 次数从 3 降为 1，并省去 split GM 往返。手动 Mmad 已是全精度，不要调用全局 SetHF32Mode(false)（per-core 持久寄存器会跨 kernel launch 污染后续 MIX kernel）。
- [X47: 融合 attention 的结构消除 + core_softmax 块向量化 + launch 合并](disc_x47.md)：融合 attention 的可复用正交结构杠杆：消除未被下游消费的中间 GEMM、稠密 per-head 投影 + no-prep 路由、fp32 投影用 SetHF32(false) 单 GEMM 替代 hi/lo 3-GEMM，以及 core_softmax 块向量化与 launch 合并。
- [X48: 链式 GEMM M-block 归属调度（第一阶段输出复用）](disc_x48.md)：两阶段 GEMM 链若按 (mi, ni) 输出 tile 划分任务，第一阶段会被重复计算 nBlocks 次；按 M-block 归属调度，让每个 M-block 的第一阶段只算一次，中间结果在核 group 内复用，可消除这一冗余。
- [X49: 两阶段 GEMM 跨核生产/消费切分（N-split stage-split + GM-volatile flag）](disc_x49.md)：两阶段 GEMM 链若按 M-block 归属或 (mi,ni) tile 分任务，阶段一并行度受 mBlocks 限制（小 M 大 N2 时仅少数核工作）；把 h 的生产与消费拆到不同核（N-split stage-split + GM volatile flag 跨核同步）可提高并行度。
