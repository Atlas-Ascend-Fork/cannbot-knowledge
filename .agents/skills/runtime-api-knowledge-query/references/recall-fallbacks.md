# 召回判定与兜底

承接 [SKILL.md](../SKILL.md) §3、§4。处理“查到了什么算查到”，以及查不到时怎么回答。

## 先分清错误与零命中

退出码 `2` 是参数、索引或输入错误，按原因处理或报告阻塞，**不触发**任何跨平台复查或
放宽条件。退出码 `0` 且无结果才是有效零命中。零命中不证明 API 不存在。

## 什么算“找到准确接口定义”

`literal` 会匹配接口名前缀，也会匹配其他卡正文里的提及。下列都**不算**找到目标定义：

- 只命中同前缀的其他接口（例如查 `aclrtMallocAlign32` 命中 `aclrtMalloc`）。
- 目标接口只在别的卡正文里被提到，没有自己的声明卡。
- 命中了同名但不同接口层的卡（C 与 C++ 扩展），而问题问的是另一层。

结果已返回 k 条而仍无目标定义时，先适当扩大 k，或按已知接口层细化查询，再判断是否需要
下一步。已找到准确定义就不触发复查。

## 跨平台复查

条件：用户给出准确接口名，目标平台查询退出码为 `0`，核验候选后仍未找到准确接口定义。
结果为空、只有前缀接口、只有正文提及都适用。

做法：**去掉 `--platform`，改用 `--all-platforms` 复查一次**，保留同一知识根、准确 API 名、
`--match literal`、`--domain runtime`、`--type apis`、status 和其他过滤条件。`stable` 与
`draft` 使用同一判断。按[平台模式](platform-modes.md)在独立诊断上下文中发起，只做一次。

## 草稿与未定位线索

准确名在 stable 未找到定义，或候选不足且需要固定来源的草稿证据时，说明理由，保持 domain
和 Profile，独立用 `--status draft` 再查。目标已知时先带原平台，核验后仍无准确定义再按
上节复查；目标未知时保留原全平台模式。不能漏掉已有平台的 Runtime 草稿，也不放宽为
`--status all`。

准确名在 stable 未找到定义时，还要独立补搜未定位草稿，包含 Query 契约要求的零命中场景：

```bash
python3 <query-skill-dir>/scripts/knowledge_query.py search \
  --query "<准确 API 名>" --domain runtime --type apis --match literal \
  --include-unlocated --status draft -k 5 --text
```

**跨平台复查与未定位草稿补搜是两条独立查询，不能把 `--all-platforms` 和
`--include-unlocated` 叠加成一个请求。** 未定位查询不带 `--platform`，只返回空平台草稿，
不会返回已有平台的草稿。它是线索，不是对原目标的支持证明，不能混入目标平台 receipt。

## 三种回答分支

核验候选后按下列分支作答。正文提及或其他接口层的同名卡都不算命中目标定义。

| 复查结果 | 怎么回答 |
|---|---|
| 找到准确接口定义 | 明确回答“该接口已收录”，从卡片 `platforms` 逐项列出声明支持的平台，核对正文、固定来源和版本 |
| 来源明确排除目标平台 | 回答“该接口存在，但在该来源版本下不支持目标平台”，并给目标平台的替代路径 |
| 仅平台字段未列出目标，或证据不完整、相互冲突 | 回答“目标平台支持情况未确认”，**不能推导为“不支持”** |
| 复查后仍无准确接口定义 | 只表述为“当前查询范围内未找到准确接口定义”，继续草稿补搜；`stable` 未找到不等于未收录 |
| 合理补搜后仍无定义 | 回答“当前知识库未收录该接口的可用知识”，**不说该 API 不存在** |
| 已收录草稿但平台待核验 | 回答“已收录草稿，但平台待核验”，不再称未收录 |

`agnostic` 按平台中立处理。多个目标平台逐一核对，不把多平台 AND 的零命中解释为所有目标
都不支持。

## 替代路径

目标平台不支持或尚未确认时，另用原目标平台检索同一能力的替代路径，读全文后说明替代接口、
必要组合和差异。没有证据时明确回答“当前知识库未找到该目标平台上有依据的替代路径”，
不编造替代。
