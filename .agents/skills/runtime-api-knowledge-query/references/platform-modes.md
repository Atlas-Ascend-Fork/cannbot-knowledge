# 平台模式细则

承接 [SKILL.md](../SKILL.md) §2。只解释 Runtime 专用流程的平台判定和候选扩展，
不改变普通 Query 对其他领域的平台要求。

## 判定缺省平台

目标未能确定为登记平台时，按 [CLI](../../knowledge-query/references/cli.md) 的配置规则
核对项目缺省平台：先看进程环境的 `CANNBOT_KNOWLEDGE_PLATFORM`；无值时再只读查看从当前
目录向上找到的最近 `.cannbot/knowledge.env` 中的同名值，不执行配置文件。配置非法或读取
失败时报告配置问题，不修改项目配置来启用全平台。

缺少判型证据、只有含糊的芯片或架构简称、产品尚未登记，都属于“无法唯一映射”。保留用户
原始描述和未确认的原因，不把未解析文本传给 `--platform`。

## `--all-platforms`

该选项只允许与 `--domain runtime` 同用，不能与显式平台、项目缺省平台或 `--include-unlocated`
并用。平台缺失或无法解析且无项目缺省时，第一条 API 查询就可以直接加上它，不要求先执行
一次失败查询。默认 `--status stable` 不变，其他过滤条件和排序保持原样。

该模式召回支持任一登记平台的 Runtime 候选并集，**不包含空平台草稿**。并集不证明用户产品
适用，也不等于每个接口同时支持全部平台：读卡后按各接口卡的真实 `platforms` 回答，并在
「平台注意」段逐接口列出。

请求及其 `filters` 会同时记录 `all_platforms: true`，纳入请求指纹和重放；其 `platforms`
为 `[]`，不能生成要求明确目标平台的 ready。确认目标平台后按该平台重新查询并保存新 receipt。

## 目标平台保持不变

有明确目标或项目缺省平台时，推荐保留该平台。只有在用户给出准确接口名、目标平台查询
成功、核验候选后仍未找到准确接口定义时，才按[召回与兜底](recall-fallbacks.md)独立发起
一次跨平台复查，用于区分“是否收录”与“声明支持范围”，不把其他平台的命中当作目标平台可用。

明确的目标冲突、具体版本可用性或废弃、能力本身是否存在等决定性歧义仍需澄清，不用全平台
候选代替澄清。

## 复查的独立诊断上下文

项目缺省平台会被脚本自动补入，只删掉 `--platform` 参数再重试是无效的。按
[CLI 的 Runtime 全平台候选扩展](../../knowledge-query/references/cli.md#runtime-全平台候选扩展)
发起复查：仅该诊断子进程不继承 `CANNBOT_KNOWLEDGE_PLATFORM`，其工作目录及各级父目录均无
`.cannbot/knowledge.env`，用绝对脚本路径和 `--knowledge-root <同一绝对知识根>` 固定原知识
与索引，审计文件使用独立绝对路径。

不得修改配置文件、父进程或全局环境。原配置非法或不可读等错误不能借这个上下文绕过。
复查结果和 receipt 独立保存，保留原始目标与配置，不作为目标平台 ready 的证据。
