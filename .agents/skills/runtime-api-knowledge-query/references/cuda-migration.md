# CUDA 替代核对

承接 [SKILL.md](../SKILL.md) §5。映射表只提供候选入口，结论仍由目标 API 卡的正文决定。

## 读映射表

按当前知识根 `knowledge/runtime/apis/index.md` 的导航找到已收录的映射表，读取完整
Frontmatter 和正文，用准确 CUDA 名定位候选 Runtime 接口。表中的候选关系、草稿状态和空
平台都不证明接口等价或目标产品支持。

映射表缺失或没有相应条目时说明映射证据缺口。仍可按用户明确的原生能力需求走
[SKILL.md](../SKILL.md) §3 查 Runtime API，但不能据此宣称替代关系，也不按
`cuda`→`aclrt` 拼接口名。

## 迁移专属核对项

用候选的精确 CANN 名重做 §3、§4 之后，在 §4 六轴之上再核对迁移特有的两项：

- **原入口层级**：CUDA Runtime（`cuda*`）还是 CUDA Driver（`cu*`）；目标是 CANN 公开 C
  接口、C++ 扩展，还是迁移兼容层入口。两侧都要写明，不能只给目标名。
- **证据性质**：原生文档、头文件声明、固定实现、兼容层实现，还是真实实验。兼容层的成功
  标记、Mock、fallback 和被忽略的参数**不等于**原生等价。

只有来源支持时才能在对应语义范围内说等价，不扩展为整体行为、性能或生产兼容保证。

## 结论五分类

| 分类 | 适用条件 | 措辞要求 |
|---|---|---|
| 功能相近可直接替换 | 六轴全部对齐且来源支持 | 首句答“能”，给出目标接口名 |
| 组合改写 | 单个接口不足，需要固定来源支持的多接口组合 | 首句答“不能仅改名”，再给调用顺序 |
| 条件支持 | 仅在特定平台、版本、运行形态或非试验特性下成立 | 首句答“不能无条件替换”，写明成立条件 |
| 参考范围内无映射 | 固定映射来源未给出该条目 | 说明映射证据缺口；若用户要原生实现方案，另给有依据的原生改写 |
| 证据冲突 | 来源之间对同一接口结论不一致 | 分别说明 revision、接口层和原文，不抹去冲突、不取更宽结论 |

否定直接替换后仍可给有证据的工程改写：说明具体步骤和不保留的语义。仅需找功能相近候选时，
区分映射线索和原生证据即可，不必展开全部轴。
