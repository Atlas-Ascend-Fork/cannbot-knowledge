# Runtime API 推荐

完成 **定型 → 模块收口 → 同族排除 → 简洁作答**。复用相邻
[knowledge-query](../knowledge-query/SKILL.md) 的索引、平台识别、Contract 与审计；
本 Skill 不存 API 事实表，也不启动第二套检索。`<query-skill-dir>` 指同装的
`knowledge-query`，知识根由其项目配置定位；参数与配置错误查
[CLI](../knowledge-query/references/cli.md)，不遍历目录找脚本。

通过 §3 的模块收口和 §4 的同族核对降低误选风险，结论以已读原文为依据。
§4 的排除推理是内部工作，默认不进入答案。

## 1. 定型

| 问题形态 | 判定标志 | 主路径 | 首句必须给出 |
|---|---|---|---|
| 契约核对 | 给了准确接口名，问语义、参数或限制 | §3 literal → §4 轴 1-4 | 该接口的结论，不是接口清单 |
| 场景选型 | 描述要做的事，没点名接口 | §3 模块收口 → §4 全轴 | 唯一主接口及必要配套 |
| 多接口比较 | 同时点名两个以上接口 | §3 逐个 literal → §4 轴对照 | 选哪个，及决定性差异 |
| CUDA 替代 | 出现 `cuda*`/`cu*` 名或迁移意图 | §5 | 能否仅改名：能或不能 |

只问会改变本次推荐的缺项，一次最多一个问题，问完即停。目标产品优先从用户上下文读取；
需要规范型号时按[平台识别](../knowledge-query/references/platform-identification.md)核对。
平台缺失不触发追问，按 §2 走全平台候选。

CANN/CUDA 版本未给出不等于“最新”或“全部版本”。可基于固定来源给有条件候选并标注版本待核验；
问题本身就是某版本可用性、生产兼容或随版本变化的 flags/重载时，先澄清或保留缺口。
Git commit 不是发行版本号。

## 2. 平台模式

发起 API 查询前选定一种，不中途混用：

| 平台信息 | 查询方式 |
|---|---|
| 可确定为登记平台 | 显式 `--platform`，优先于项目缺省值 |
| 无明确目标，但有适用于本任务的项目缺省平台 | 沿用普通 Query 的缺省平台过滤 |
| 未提供、无法唯一映射为登记值，且无项目缺省 | `--domain runtime --all-platforms` |

**平台缺失或无法解析不阻断推荐**，也不要求先拿到一次 `platform is required` 错误。
保留用户原始描述和未确认原因，不把未解析文本传给 `--platform`；不选 Agent 所在机器、
不默认 a2、不用 `agnostic` 代表未知、不枚举全部平台模拟 OR。比较多个产品分别查询，
只有用户明确要求共同适用才用多平台 AND。候选并集不证明用户产品适用。

模式判定细则、`--all-platforms` 的互斥关系、诊断上下文与 receipt 规则见
[平台模式](references/platform-modes.md)。

## 3. 两段式召回：先收口模块，再定接口

首次运行 `python3 <query-skill-dir>/scripts/knowledge_query.py discover`；同一知识根和
索引指纹可复用。索引缺失、损坏、stale、依赖不可用或必要权限被拒绝时停止并报告，
不扫描知识树、不改用其他工具读技术卡、不自动重建索引、不下载资源、不凭记忆回答技术结论。

**场景选型和多接口比较先收口模块。** `knowledge/runtime/apis/index.md` 按能力列出全部模块
及其接口数；选定模块后读该模块的 `index.md`，它按子能力完整列出模块内每个接口和一句
差异化摘要。这一步用一次廉价阅读拿到**同族候选全集**，作为 §4 排除的输入。不要跳过它
直接用 `-k 5` 在 500 余张高度相似的接口卡上做文本匹配——同族接口的描述彼此接近，
文本召回窗口本身不足以区分。给了准确接口名时先 literal 定位，再读其所在模块
`index.md` 补齐同族。

**同族可能跨模块，用标签而不是目录区分接口层。** 卡片按官方文档章节归置，与语言无关：
`cpp_extension_apis/` 对应独立的 C++ 扩展章节，而能力模块里同样可能收录 C++ 接口。27 对
同名 C/C++ 接口因此分处两个目录（`aclrtMemcpy`、`aclrtMalloc`、`aclrtMemcpyFromSymbol`、
`aclrtSynchronizeStream` 等）。目录位置不能用来判断接口层，标签可以：

```text
--tag topic.implementation.api_layer.c_api     # 公开 C 接口
--tag topic.implementation.api_layer.cpp_api   # C++ 扩展封装
```

用户明确要求公开 C 接口或 C++ 扩展时，带上对应标签；仅说明程序使用 C++ 不代表要求
C++ 扩展，仍保留公开 C 接口候选。没有明确接口层且存在同名两版时，核对两版声明，
按 §4 轴 2 判断适合的接口，不要只凭先读到的那一侧作答。

选定模块的 `index.md` 里没有可信候选时**不要硬选**：按 `apis/index.md` 的能力描述换到相邻
模块（例如 Event 等待的超时配置落在 Event 管理，而非 Stream 管理），或退回本节的 `search`
查询重新定位。模块收口是加速手段，不是必须命中的唯一入口。

Runtime API 是领域直属路径，用 `--domain runtime --type apis`，不指定技术路径：

```bash
python3 <query-skill-dir>/scripts/knowledge_query.py search \
  --query "<准确 API 名，或实体 + 一个约束>" --domain runtime --type apis \
  --status stable --match <literal或text> -k 5 --text
```

准确接口名用 `literal`，场景用“实体 + 一个约束”的短 `text` 查询。按 §2 追加平台参数或
`--all-platforms`。`literal` 也会匹配接口名前缀和正文提及，结果非空不代表已找到目标定义。

零命中判定、扩大 k、跨平台复查、草稿与未定位线索补搜，以及“未收录 / 支持待确认 /
来源明确不支持”三种回答分支见[召回与兜底](references/recall-fallbacks.md)。

## 4. 收敛到唯一推荐

对与需求相关的同族候选逐轴核对，选出主接口和必要配套。结论必须来自完整读过的卡片：
按返回路径选卡，完整读 Frontmatter 和正文，输出截断就分段连续读到结尾。只读摘要、标题
或末页不算读全文。模块 `index.md` 的摘要只用于初筛，决定取舍的差异须读对应卡片验证，
不把摘要缺少某项描述当作接口没有该能力。

| 轴 | 排除要回答的问题 |
|---|---|
| 1 时序 | 同步还是异步？返回即完成，还是仅表示下发成功？需要配对哪个等待接口？ |
| 2 接口层 | 公开 C、C++ 扩展封装，还是迁移兼容层？同名卡分开核对，不默认 C++ 的可选参数适用于 C |
| 3 参数契约 | 容量和长度分别是哪个参数、单位是什么？flags/枚举语义与句柄表示能否直接强转？ |
| 4 资源归属 | 谁分配谁释放、配套销毁接口是哪个？Context/Device 归属与跨线程/进程条件？ |
| 5 调用序位 | init/finalize、Context、Stream 等前置条件，以及必须的调用顺序？ |
| 6 适用范围 | 各接口卡的 `platforms`、版本和试验特性是否覆盖目标？逐接口核对，不把主接口的范围套给配套接口 |

同族差异常常只落在一两条轴上：对齐粒度、是否隐式同步、是否批量、是否带 cfg、是否带
Stream 参数。轴 1-5 全部相同才可能是真的等价。排除后对自己说明“为什么不是最接近的那个候选”；
该推理是内部工作，除非用户要求比较，不写进答案。

收敛门槛：

- **剩 1 个**：正常作答。
- **剩 2 个**：核对是否有决定分支的缺失条件；有则写出条件和两个分支各一行，必要时询问。
  若两者都满足需求，按已有约束和最少额外前提推荐其一，不强造差异或唯一性。
- **剩 3 个及以上**：补读决定性差异；仍无法收敛时，问一个能缩小范围的问题或说明证据缺口，
  不无限补搜，也不把并列清单当答案。用户明确要求多种方案时可按需求分组比较。
- **剩 0 个**：按[召回与兜底](references/recall-fallbacks.md)判断属于未收录、支持待确认还是
  来源明确不支持，并给目标平台的替代路径或明确缺口，不编造接口或替代。

按问题需要沿普通链接补读配套 API、来源或示例，不遍历整张邻接图。卡片 `sources` 的本地路径
相对知识仓根，`source_headers` 相对**已确认的 Runtime 源码根或对应组件根**，不能套
Ascend C 包根，也不能把源码头路径猜成安装包布局。文件缺失、越界或版本不明就报告缺口，
不扫描其他 SDK、不下载、不编译或运行上游代码。

答前用原文反查：每个接口名和参数名逐字对过卡片声明；轴 1、3、4 的结论各有原文支撑；
`platforms` 按接口逐项取自卡片原值。来源冲突分别说明 revision、接口层和原文，不抹去冲突、
不扩大“不支持”的范围、不采用更宽的结论。

## 5. CUDA 替代

先按 `knowledge/runtime/apis/index.md` 的导航读已收录的映射表，用准确 CUDA 名取候选 CANN 接口。
映射表缺失或没有该条目时说明映射证据缺口；仍可按用户明确的原生能力需求走 §3，但不据此宣称
替代关系。映射候选不证明等价或目标产品支持：必须用候选的精确 CANN 名重做 §3 和 §4，
再按 §4 六轴逐项对照 CUDA 原入口与目标入口。

兼容层的成功标记、Mock、fallback 和被忽略的参数都不等于原生等价。只有来源支持时才能在对应
语义范围内说等价，不扩展为整体行为、性能或生产兼容保证。没有映射证据就说明缺口，不按
`cuda`→`aclrt` 拼接口名。结论五分类及各类措辞见[CUDA 替代](references/cuda-migration.md)。

## 6. 作答

四段固定顺序，逐项可辨。**以下每段的条数和行数限制是主控**，逐段遵守即可；全局参考上限是
正文汉字不超过 350 个（代码块不计入，API 名与路径等西文标识不计入，表格内文字照计）。
不得把正文拆成表格或清单来绕过预算。首次作答前先读[作答样例](references/answer-examples.md)
对齐长度与写法。

| 段 | 内容与预算 | 省略条件 |
|---|---|---|
| 推荐结论 | 1-3 句。首句直接给接口名和动作，必要配套用一行写调用顺序。问“能否直接替换/仅改名”时首句必须是“能”或“不能” | 不可省 |
| 关键注意事项 | 至多 4 条，每条 1 行。只写会改变用户代码的点：不写会编译错、泄漏、时序错或结果错 | 没有此类点时整段省略 |
| 平台注意 | 一行，或接口与 `platforms` 一一对应的小表 | 目标平台已确认且全部覆盖时压成一句 |
| 自验证 | 1 句，指向卡内「最小调用示例」路径 | 卡内无示例时写明“该卡未附最小示例”，不自造 |

末尾一行给影响结论的卡片链接，至多 4 条。草稿、未定位线索和影响落地的未知项各一句，
只写一次，不在多段重复。

**不要写**：检索过程（查了几次、用了什么参数、读了哪些索引）、复述用户问题、摘抄卡片的
功能说明和参数表、与本题无关的通用免责、同一条限制在多段重复、被排除候选的清单和排除推理、
自检过程，以及“建议您”“需要注意的是”“综上所述”这类填充语。参数本身是结论时才给字段、
数值和单位。**逐参数转抄签名的表格一律不写**：签名放代码块，只在正文点出会出错的那一两个
参数；同一个参数不在表格、正文和代码注释里讲三遍。只有已读声明足够时才给最小代码，处理返回值和资源生命周期，注明未编译未实机；
不为填格式强行生成代码。

版式骨架：

> **推荐结论**：用 `<主接口>` 完成 `<动作>`，配 `<配套接口>`。调用顺序：A → B → C。
>
> **关键注意事项**
> - `<会导致失败的前提或单位>`
> - `<时序或资源生命周期约束>`
>
> **平台注意**：`<逐接口的 platforms 核对结果>`
>
> **自验证**：按 `<卡片>` 的「最小调用示例」自行编译运行。
>
> 证据：`<至多 4 条卡片链接>`

## 边界

全程只读：不修改卡片状态、索引、SDK、项目配置或全局环境，不联网，不编译或运行，
不自行提交发布，不自称验证通过。不读取评测 gold、参考答案或评分标签。本机 SDK 可用性
需要实际组件版本、include/库归属和声明，未读取时标为未核验。复杂多决策或正式交接复用
Query 的[证据工作流](../knowledge-query/references/query-workflows.md)；未定位映射不能
冒充目标平台 ready 证据，ready 也不是运行验证。
