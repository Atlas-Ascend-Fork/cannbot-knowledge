# 平台识别

平台过滤影响证据适用性，不应根据名称相似度猜测。

## 顺序

1. 优先使用用户明确给出的 `a2`、`a3`、`950`、`310p` 或 `910`。产品旧称 Atlas A5、配置值 `A5` 和 `atlas-a5` 都规范化为平台 ID `950`；Query 不注册第二个 `a5` 平台 ID。
2. 只有产品型号、SocVersion、NPU arch 或编译 target 时，先用 `discover` 判断知识库是否有平台映射卡；有卡时读取正文和固定来源，没有卡时使用用户提供的设备事实或固定权威来源。
3. 同一代号存在多种映射、当前知识无覆盖、缺少可核验来源或配置与设备信息冲突时，向用户确认，不移除平台过滤来扩大搜索。
4. 确认结论按定义与硬件无关时才使用 `agnostic` 卡；它不是“平台未知”的替代值。

诊断任务应尽量同时记录硬件产品、SocVersion、CANN 版本、编译 target 和实际运行设备。源码宏分支只能证明分支条件；缺少构建或产品映射证据时，不能直接推导到某个平台 ID。
