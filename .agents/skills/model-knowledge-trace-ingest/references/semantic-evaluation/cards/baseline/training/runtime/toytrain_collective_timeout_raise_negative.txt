# 合成评测样例：ToyTrain 集合通信超时提高 timeout_s 未修复

本卡来自合成评测记录（SYNTHETIC evaluator fixture, not technical guidance），不构成真实框架事实；状态为 draft，待独立审查，未发布。知识形态：negative_result。

## 适用场景

ToyTrain 训练框架在 cp=2、offload=true（CPU-offload）配置下的训练超时问题（合成评测场景）。任务目标为完成 3 步训练；轨迹未给出框架版本与硬件信息。

## 触发与观测

第一步训练即发生集合通信超时（逐字）：

```text
training step 1: collective timeout at 300s; exit before step 2
```

## 探针与操作

尝试修改单元（逐字）：

```yaml
train.yaml BEFORE
cp: 2
offload: true
timeout_s: 60
AFTER
cp: 2
offload: true
timeout_s: 300
run: python train.py --config train.yaml --steps 3
```

验证命令为 `python check.py`。

## 机制与判别

在 ToyTrain 框架 cp=2、offload=true 的训练配置下，把 train.yaml 的 timeout_s 从 60 提高到 300 后，第一步训练仍在 300 秒处发生 collective timeout，进程在进入 step 2 前退出，未观察到成功训练。

该失败结论只覆盖本次 CPU-offload 开启且 CP=2 的三步训练尝试；延长超时未能修复此尝试，不构成对其他超时原因或配置有效的判断。
